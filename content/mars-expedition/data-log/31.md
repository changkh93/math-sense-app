# Data Log 31 - 임시 코드를 정리하고 최종 출격


파이썬 → **게임 스튜디오**에서 실습합니다. 정지 → main.py 수정 → 실행 → 게임 화면 클릭 순서로 진행하세요. 게임 화면에 포커스가 있어야 방향키와 Space가 전달됩니다. 각 단계의 편집을 모두 마친 다음 실행합니다. 게임이 작거나 아래쪽 HUD가 잘리면 게임 화면 오른쪽 위의 **크게 보기** 버튼으로 전체 화면에서 확인하세요.

이전 단원의 마지막 main.py에서 이어갑니다. 누적 코드는 스크롤 창에서 읽거나, 스튜디오의 **화성 탐사대 단계 비교·수업 자료**에서 에셋을 포함한 별도 프로젝트로 열 수 있습니다. 직접 작성한 초안을 먼저 백업하세요.

## 코드를 읽고 작성하는 방법

코드 안의 `#` 뒤 문장은 **이해를 돕는 설명용 주석**입니다. 주석은 따라 적지 않아도 게임이 똑같이 실행됩니다. 먼저 주석을 읽고 그 아래 코드의 목적을 이해한 뒤, 실행되는 코드와 들여쓰기를 작성하세요. 따옴표 안의 글자, 변수 이름, 괄호와 콜론은 주석이 아니므로 생략하면 안 됩니다. 누적 코드에는 길 찾기에 필요한 핵심 주석만 남겼습니다.

각 편집의 ‘왜 이렇게 쓰나요’를 읽고, 입력하기 전에 결과를 예상해 보세요. 이번 단계의 편집을 모두 마친 다음 실행합니다. 중간에 아직 정의하지 않은 이름을 참조할 수 있으므로 편집 하나마다 실행하지 않습니다. 실행 후에는 화면이 맞는지만 보지 말고, **어떤 값이 바뀌어 그 결과가 생겼는지** 한 문장으로 설명해 보세요. 누적 코드는 먼저 직접 시도한 뒤 비교·복구할 때 사용합니다.

## 31-A - 임시 생성키 제거

이번 편집의 목표는 **임시 생성키 제거**입니다. 아래 수정 위치를 모두 반영한 다음 실행 결과를 확인합니다.

**이 단계의 연결:** 출발 코드는 **30-B**의 누적 코드입니다. 아래 편집은 위에서부터 모두 적용합니다. 이미 완성한 나머지 메서드는 지정된 교체 범위 밖이면 그대로 둡니다.


### 입력 전에 결과를 예상해 보세요

Enter 생성 두 줄을 없앨 때 Enter 분기 전체를 지우면 안 되는 이유는 무엇인가요?

먼저 답을 한 문장으로 적고 아래 해설과 비교하세요.

**생각 확인:** 시작·다음 탐사·새 게임도 Enter를 사용합니다. playing 상태의 임시 생성만 제거해야 합니다.

### 수정 위치와 입력할 코드

**편집 1.** **수정 위치:** running = True부터 파일 마지막 pygame.quit()까지의 실행 루프 전체. 아래 코드로 교체합니다. 클래스나 메서드 안에 넣지 않습니다.

**왜 이렇게 쓰나요 — 이 편집을 읽는 순서**

- **입력과 상태 변화, 그리기를 매 프레임 반복합니다.** 한 프레임은 게임을 한 번 갱신해서 표시하는 주기입니다. 준비 코드·그룹 생성은 while 위에서 한 번만 실행하고, 입력과 이동·그리기는 while 안에서 반복합니다. 물체를 매 프레임 새로 생성하면 위치가 초기화되거나 개수가 계속 늘어납니다. 반복문의 들여쓰기가 게임의 시간 구조를 정합니다.

- **지난 프레임 이후 쌓인 입력 이벤트를 처리합니다.** `event.get()`은 이번에 도착한 사건들을 꺼냅니다. KEYDOWN은 누르기 시작한 사건이고 `key.get_pressed()`는 지금 계속 누르고 있는 상태입니다. 점프·발사 한 번은 이벤트로, 연속 좌우 이동은 누름 상태로 처리하는 이유가 여기에 있습니다. 스튜디오 게임 화면을 클릭해야 입력이 게임으로 전달됩니다.

- **밀리초를 초로 바꾸고 지나치게 긴 프레임을 제한합니다.** `clock.tick(FPS)`는 최대 프레임 속도를 제한하고 경과 밀리초를 줍니다. 16밀리초는 16/1000=0.016초입니다. `min(..., 0.05)`는 긴 탭 전환 시간을 한 번의 큰 이동으로 적용하지 않기 위한 상한입니다. 따라서 오래 다른 탭에 머문 실제 시간과 게임 안 경과 시간이 항상 같지는 않습니다.

- **그룹의 image와 rect를 사용해 화면에 그립니다.** 그룹의 `update()`는 각 객체의 update를 호출하고, `draw(screen)`은 image를 rect 위치에 그립니다. update만 하면 값만 바뀌고, draw만 하면 같은 그림이 같은 위치에 남습니다. 배경 → 물체 → HUD/안내 순서로 그려야 뒤에 그린 배경이 물체를 덮지 않습니다. 마지막 display.update가 그린 화면을 표시합니다.

```python
running = True
# 입력과 상태 변화, 그리기를 매 프레임 반복합니다.
while running:
    # 밀리초를 초로 바꾸고 지나치게 긴 프레임을 제한합니다.
    seconds = min(clock.tick(FPS) / 1000, 0.05)
    # 지난 프레임 이후 쌓인 입력 이벤트를 처리합니다.
    for event in pygame.event.get():
        if event.type == pygame.QUIT:
            running = False
        elif event.type == pygame.KEYDOWN:
            if event.key == pygame.K_RETURN:
                if mission.state == 'title':
                    mission.state = 'playing'
                    pygame.mixer.music.play(-1)
                elif mission.state == 'round_clear':
                    mission.start_new_round()
                elif mission.state == 'game_over':
                    mission.reset_game()
            elif mission.state == 'playing':
                if event.key == pygame.K_SPACE:
                    explorer.jump()
                elif event.key == pygame.K_UP:
                    explorer.fire()
    if not running:
        break
    if mission.state == 'playing':
        all_tiles.update(seconds)
        gates.update(seconds)
        explorers.update(seconds)
        pulses.update(seconds)
        robots.update(seconds)
        crystals.update(seconds)
        mission.update(seconds)
    screen.blit(background, (0, 0))
    # 그룹의 image와 rect를 사용해 화면에 그립니다.
    all_tiles.draw(screen)
    # 그룹의 image와 rect를 사용해 화면에 그립니다.
    gates.draw(screen)
    # 그룹의 image와 rect를 사용해 화면에 그립니다.
    explorers.draw(screen)
    # 그룹의 image와 rect를 사용해 화면에 그립니다.
    pulses.draw(screen)
    # 그룹의 image와 rect를 사용해 화면에 그립니다.
    robots.draw(screen)
    # 그룹의 image와 rect를 사용해 화면에 그립니다.
    crystals.draw(screen)
    mission.draw()
    pygame.display.update()

pygame.quit()
```


### 코드가 하는 일

Enter 분기의 playing에서 Robot을 만들던 두 줄을 제거합니다. 다른 상태의 Enter 분기는 그대로 유지합니다. 완성 버전에서 적은 자동 생성 또는 결정 손실로만 추가됩니다. 5초 주기의 한 번 생성, 로봇 회수 25점, 결정 회수 100점과 에너지 10 회복을 다시 확인합니다.

### 여기서 실행하세요

플레이 중 Enter를 연속으로 눌러도 적이 늘지 않아야 합니다. 시작 화면·탐사 완료·종료 화면의 Enter는 계속 동작해야 합니다.

**이 시점의 정상 상태:** 게임 스튜디오의 정지 버튼은 게임 내 Enter와 별개입니다.

**예상과 다를 때:** 제목에서 시작도 안 되면 KEYDOWN 전체를 삭제하지 않았는지 확인합니다.

## 31-B - 고난도 시험 후 기본값 복원

이번 편집의 목표는 **고난도 시험 후 기본값 복원**입니다. 아래 수정 위치를 모두 반영한 다음 실행 결과를 확인합니다.

**이 단계의 연결:** 출발 코드는 **31-A**의 누적 코드입니다. 아래 편집은 위에서부터 모두 적용합니다. 이미 완성한 나머지 메서드는 지정된 교체 범위 밖이면 그대로 둡니다.


### 입력 전에 결과를 예상해 보세요

고난도 시험 뒤 새로 실행했을 때 확인할 기본값은 무엇인가요?

먼저 답을 한 문장으로 적고 아래 해설과 비교하세요.

**생각 확인:** 탐사 1,생성 간격 5초입니다. 임시 두 줄을 지우지 않으면 생성자 기본값이 정상이어도 setup에서 다시 덮어씁니다.

### 수정 위치와 입력할 코드

정식 코드 변경은 없습니다. 아래 실행 관찰을 순서대로 확인합니다.

### 코드가 하는 일

아래 시험은 정식 설정이 아닙니다. 로봇 속도는 탐사 번호에 의존하므로 탐사 5에서는 5~10 범위를 사용합니다. 생성 간격 2초로 충돌·재부팅·회수 경쟁을 빠르게 관찰합니다. 시험을 마치면 추가한 두 줄을 지우고 새로 실행하여 기본 탐사 1과 5초 간격을 확인합니다. 직접 작성한 프로젝트를 다운로드하고, 완성 비교 프로젝트는 별도로 열어 차이를 살펴봅니다.

### 여기서 실행하세요

시험 설정에서 좌우 이동, 점프, 천장, 네 게이트, 발사, 피격, 재부팅, 25점 회수, 100점 결정, 회복 상한, 탐사 완료, 종료·재시작을 차례로 확인합니다. 복원 후 첫 적이 약 5초에 한 대 나오는지 마지막으로 확인합니다.

**이 시점의 정상 상태:** 완성 버전에서도 로봇 색·방향·속도는 무작위이므로 실행마다 배치가 달라집니다.

**예상과 다를 때:** 다음 실행도 너무 어려우면 시험 두 줄이 남아 있는지 확인합니다. 완성 누적 코드에는 그 줄이 없습니다.

### 잠깐 시험하고 복원하기

정지한 뒤 `running = True` 바로 위에 아래 블록을 추가합니다.

```python
mission.round_number = 5
mission.spawn_interval = 2
```

빠른 로봇과 2초 생성으로 시험합니다. 정지한 뒤 두 줄을 삭제하고 다시 실행하여 탐사 1과 5초 간격으로 복원합니다.

**복원:** 정지 → 방금 넣은 시험 블록만 삭제 → 다시 실행합니다. 다음 단계로 시험 설정을 가져가지 않습니다.
