## 코드를 읽고 작성하는 방법

코드 안의 `#` 뒤 문장은 **이해를 돕는 설명용 주석**입니다. 주석은 따라 적지 않아도 게임이 똑같이 실행됩니다. 먼저 주석을 읽고 그 아래 코드의 목적을 이해한 뒤, 실행되는 코드와 들여쓰기를 작성하세요. 따옴표 안의 글자, 변수 이름, 괄호와 콜론은 주석이 아니므로 생략하면 안 됩니다. 누적 코드에는 길 찾기에 필요한 핵심 주석만 남겼습니다.

각 편집의 ‘왜 이렇게 쓰나요’를 읽고, 입력하기 전에 결과를 예상해 보세요. 이번 단계의 편집을 모두 마친 다음 실행합니다. 중간에 아직 정의하지 않은 이름을 참조할 수 있으므로 편집 하나마다 실행하지 않습니다. 실행 후에는 화면이 맞는지만 보지 말고, **어떤 값이 바뀌어 그 결과가 생겼는지** 한 문장으로 설명해 보세요. 누적 코드는 먼저 직접 시도한 뒤 비교·복구할 때 사용합니다.

## 26-A - 5초마다 로봇 자동 생성

이번 편집의 목표는 **5초마다 로봇 자동 생성**입니다. 아래 수정 위치를 모두 반영한 다음 실행 결과를 확인합니다.

**이 단계의 연결:** 출발 코드는 **25-B**의 누적 코드입니다. 아래 편집은 위에서부터 모두 적용합니다. 이미 완성한 나머지 메서드는 지정된 교체 범위 밖이면 그대로 둡니다.


### 입력 전에 결과를 예상해 보세요

spawn_elapsed=5.02,간격=5에서 생성 뒤 남길 시간은 얼마인가요?

먼저 답을 한 문장으로 적고 아래 해설과 비교하세요.

**생각 확인:** 0.02초입니다. 표시 초의 배수 검사가 아니라 누적 간격 소비를 사용하므로 같은 초에 연속 생성하지 않습니다.

### 수정 위치와 입력할 코드

**편집 1.** `class Expedition` 안의 `__init__` 메서드 전체를 아래 코드로 교체합니다. 다음 `def` 직전까지가 교체 범위입니다. `def` 앞 4칸, 본문 앞 8칸을 유지합니다.

```python
    # 객체를 생성할 때 필요한 초기 값과 참조를 준비합니다.
    def __init__(self, explorer, robots, platforms, gates, pulses, crystals):
        self.round_duration = 30
        self.score = 0
        self.round_number = 1
        self.remaining = self.round_duration
        self.elapsed = 0.0
        self.title_font = pygame.font.Font('assets/fonts/DoHyeon-Regular.ttf', 42)
        self.hud_font = pygame.font.Font('assets/fonts/DoHyeon-Regular.ttf', 23)
        self.explorer = explorer
        self.robots = robots
        self.platforms = platforms
        self.gates = gates
        self.pulses = pulses
        self.crystals = crystals
        self.initial_spawn_interval = 5
        self.spawn_interval = self.initial_spawn_interval
        self.spawn_elapsed = 0.0
```

**편집 2.** `class Expedition` 안의 `add_robot` 메서드 전체를 아래 코드로 교체합니다. 다음 `def` 직전까지가 교체 범위입니다. `def` 앞 4칸, 본문 앞 8칸을 유지합니다.

**왜 이렇게 쓰나요 — 이 편집을 읽는 순서**

- **표시 시간과 별개로 적 생성까지의 경과 시간을 누적합니다.** ‘남은 시간이 5의 배수’는 같은 초의 여러 프레임에서 참입니다. 생성용 누적 시간을 따로 두면 간격을 넘은 순간 한 번만 생성할 수 있습니다. 생성 후 간격만큼 빼서 작은 나머지 시간을 다음 주기에 이월합니다. 현재 게임은 프레임 시간 상한 0.05초, 생성 간격 하한 1초라 한 프레임에 여러 번 생성할 필요가 없습니다.

```python
    # 생성 간격을 확인해 새 로봇을 추가합니다.
    def add_robot(self, seconds):
        # 표시 시간과 별개로 적 생성까지의 경과 시간을 누적합니다.
        self.spawn_elapsed += seconds
        if self.spawn_elapsed + 1e-9 >= self.spawn_interval:
            self.spawn_elapsed = max(0.0, self.spawn_elapsed - self.spawn_interval)
            self.robots.add(Robot(self.platforms, self.gates, self.round_number, self.round_number + 5))
```

**편집 3.** `class Expedition` 안의 `update` 메서드 전체를 아래 코드로 교체합니다. 다음 `def` 직전까지가 교체 범위입니다. `def` 앞 4칸, 본문 앞 8칸을 유지합니다.

**왜 이렇게 쓰나요 — 이 편집을 읽는 순서**

- **실수 누적 시간에서 화면에 표시할 정수초를 계산합니다.** elapsed가 2.7초, round_duration이 30이면 int(2.7)=2이므로 남은 표시는 28초입니다. max(0, ...)는 0보다 작은 표시를 막습니다. 프레임마다 1씩 빼면 60FPS에서 30초가 아니라 약 0.5초 만에 끝나므로 실제 초 단위 누적을 사용합니다.

```python
    # 그룹에서 호출하는 한 프레임의 처리 순서입니다.
    def update(self, seconds):
        self.check_collisions()
        self.elapsed += seconds
        # 실수 누적 시간에서 화면에 표시할 정수초를 계산합니다.
        self.remaining = max(0, self.round_duration - int(self.elapsed + 1e-9))
        self.add_robot(seconds)
```


### 코드가 하는 일

`spawn_elapsed`가 간격에 도달하면 로봇 한 대를 만들고 간격만큼 빼 줍니다. 남은 시간 `% 5 == 0`을 매 프레임 검사하면 같은 초에 60대가 생길 수 있습니다. 별도 누적 시간으로 그 문제를 피합니다. 실수 오차를 감안해 비교한 뒤 `max(0, 경과 시간 - 간격)`으로 정리하여 경계에서 연속 두 번 생성되는 오류도 막습니다. 속도 범위는 탐사 번호부터 번호 + 5입니다. Enter 임시 생성도 최종 정리까지 남겨 둡니다.

### 여기서 실행하세요

Enter를 누르지 않고 약 16초 기다려 5, 10, 15초에 각 한 대가 추가되는지 확인합니다. 중간에 Enter를 누르면 자동 생성과 별도로 한 대가 추가됩니다.

**이 시점의 정상 상태:** 다음 탐사는 아직 없고, 시간 0 뒤에도 자동 생성은 계속됩니다. 29단원에서 상태 전환으로 멈춥니다.
