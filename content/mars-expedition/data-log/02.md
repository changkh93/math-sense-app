### 수정 위치와 입력할 코드

**편집 1.** **수정 위치:** clock 아래에서 첫 class 위까지의 그림·소리 준비 함수 구간. 아래 코드로 추가합니다. 클래스나 메서드 안에 넣지 않습니다.

**왜 이렇게 쓰나요 — 이 편집을 읽는 순서**

- **파일 경로와 요청 크기를 묶어 캐시의 열쇠로 씁니다.** 캐시는 이미 준비한 결과를 다시 쓰는 보관함입니다. `image_cache = {}`는 빈 딕셔너리이고, `(path, size)`는 경로와 크기를 묶은 튜플입니다. 같은 파일도 32×32와 64×64로 요청하면 서로 다른 결과가 필요하므로 두 값을 함께 열쇠로 씁니다. 첫 호출에는 저장하고, 다음 같은 요청에는 저장한 그림을 돌려줍니다. 캐시는 그림만 공유하며 각 타일의 위치는 별도 rect에 저장합니다.

- **처음 요청한 그림만 읽고 크기를 맞춥니다.** `key not in image_cache`는 그 열쇠로 저장한 결과가 아직 없는지 묻습니다. 처음에는 참이어서 if 안을 실행하고, 같은 요청의 두 번째 호출에는 거짓이어서 건너뜁니다. 아래 `return image_cache[key]`는 if 바깥이므로 처음 요청과 재요청 모두 그림을 받습니다. return을 if 안에 넣으면 두 번째 호출은 그림 대신 None을 돌려주는 오류가 생깁니다.

- **PNG의 투명한 여백을 유지합니다.** `image.load`로 읽은 Surface를 `convert_alpha()`로 투명도를 유지하는 표시 형식으로 바꿉니다. 투명한 여백까지 배경색 사각형으로 그리지 않기 위한 준비입니다. `smoothscale(그림, (가로, 세로))`은 그다음 표시 크기를 맞춥니다. 여러 함수가 한 줄에 겹쳐 있으면 가장 안쪽 호출부터 읽으세요.

- **매개변수로 요청을 받고 return으로 결과를 돌려주는 함수입니다.** def는 함수 정의입니다. load_image에 넘긴 첫 값은 path, 두 번째 값은 size가 됩니다. 예를 들어 load_image("assets/tiles/2.png", (32,32))를 호출하면 해당 경로와 크기로 함수 본문이 실행되고 return한 그림이 호출한 자리의 결과가 됩니다. 정의 자체는 본문을 바로 실행하지 않습니다. 함수 안의 key는 이 호출에서 만드는 지역 이름이고 image_cache는 함수 밖에서 준비한 공용 딕셔너리입니다.

```python
image_cache = {}


# 그림을 준비하고 같은 요청에는 저장한 그림을 재사용합니다.
def load_image(path, size):
    # 파일 경로와 요청 크기를 묶어 캐시의 열쇠로 씁니다.
    key = (path, size)
    # 처음 요청한 그림만 읽고 크기를 맞춥니다.
    if key not in image_cache:
        # PNG의 투명한 여백을 유지합니다.
        image_cache[key] = pygame.transform.smoothscale(pygame.image.load(path).convert_alpha(), size)
    return image_cache[key]
```

**편집 2.** 준비 함수 아래, 그룹과 지도 코드 위의 **클래스 정의 구간 전체**를 아래로 추가합니다.

**왜 이렇게 쓰나요 — 이 편집을 읽는 순서**

- **역할이 같은 객체를 만드는 설계도입니다.** `class`는 설계도이고 `Terrain(...)`이나 `Scout(...)` 같은 호출이 실제 객체를 만드는 순간입니다. 클래스 정의만으로 화면에 나타나지 않습니다. `__init__`은 생성할 때 초기 값을 준비하고, `self`는 지금 준비 중인 바로 그 객체를 뜻합니다. 서로 다른 두 객체는 같은 메서드를 사용하지만 위치·속도 같은 값은 각각 가질 수 있습니다.

- **부모 Sprite의 내부 준비를 먼저 실행합니다.** `super().__init__()`은 상속받은 Sprite 내부를 준비합니다. 괄호 안에 그룹이 있으면 그 그룹에 이 객체를 바로 등록합니다. `super().__init__(tiles)`는 tiles에 자동 등록하지만 인수가 없는 `super().__init__()`은 자동 등록하지 않으므로 나중에 `그룹.add(객체)`가 필요합니다. 이 차이를 확인하고 중복 생성하지 마세요.

- **그림의 크기와 화면 위치를 담을 상자를 만듭니다.** `image`는 그림이고 `rect`는 그 그림을 놓을 사각형입니다. `get_rect(topleft=(x, y))`는 왼쪽 위, `midbottom=(x, y)`는 발 가운데를 해당 위치에 맞춥니다. 예를 들어 64×64 그림의 midbottom이 (100, 200)이면 왼쪽 위는 (68, 136)입니다. 같은 좌표라도 기준점이 다르면 표시 위치가 달라집니다. Group.draw는 각 객체의 image와 rect를 읽습니다.

- **선택 그룹을 받았을 때만 충돌 대상으로도 등록합니다.** `subgroup=None` 또는 `platforms=None`은 인수를 생략할 수 있게 한 기본값입니다. None은 ‘전달된 그룹이 없음’이며 빈 Group과는 다릅니다. 빈 그룹도 정상 등록 대상이므로 `if subgroup:`로 검사하지 않고 `is not None`으로 검사합니다. 한 타일이 그리기 그룹과 발판 그룹에 함께 들어가도 객체가 두 개로 복제되는 것은 아닙니다.

- **호출 결과를 이 객체의 그림 속성에 보관합니다.** 대입은 오른쪽을 먼저 계산하고 그 결과를 왼쪽 이름에 저장합니다. self.image는 이번 객체가 사용할 그림입니다. load_image가 그림을 반환해야 그다음 get_rect를 호출할 수 있습니다. self.x처럼 self가 붙은 값은 메서드가 끝나도 객체에 남아 다른 메서드에서 사용할 수 있습니다.

- **문자열 안에 현재 종류나 번호를 넣어 에셋 경로를 만듭니다.** 문자열 앞 f는 중괄호 안의 값을 글자로 끼워 넣습니다. kind가 2이면 f'assets/tiles/{kind}.png'는 assets/tiles/2.png가 됩니다. 파일명을 직접 여섯 번 쓰는 대신 같은 생성자를 다른 kind로 호출할 수 있습니다. 중괄호 안의 변수는 이 호출에서 먼저 값을 받아야 합니다.

```python
# 지형 한 칸: 그림·위치와 소속 그룹을 준비합니다.
class Terrain(pygame.sprite.Sprite):
    # 객체를 생성할 때 필요한 초기 값과 참조를 준비합니다.
    def __init__(self, x, y, kind, tiles, subgroup=None):
        # 부모 Sprite의 내부 준비를 먼저 실행합니다.
        super().__init__(tiles)
        # 호출 결과를 이 객체의 그림 속성에 보관합니다.
        self.image = load_image(f'assets/tiles/{kind}.png', (TILE_SIZE, TILE_SIZE))
        # 그림의 크기와 화면 위치를 담을 상자를 만듭니다.
        self.rect = self.image.get_rect(topleft=(x, y))
        # 선택 그룹을 받았을 때만 충돌 대상으로도 등록합니다.
        if subgroup is not None:
            subgroup.add(self)
```

**왜 이렇게 쓰나요 — 이 편집을 읽는 순서**

- **같이 갱신하거나 검사할 객체들을 담을 그룹을 만듭니다.** Group은 Sprite들을 묶는 관리 목록입니다. 변수마다 `Group()`을 호출하면 별개의 빈 그룹을 만듭니다. 화성의 tiles/all_tiles는 그릴 타일 전체, platforms는 착지 대상, hazards는 위험 접촉 대상입니다. 우주 방어대의 양쪽 탄환 그룹도 분리해야 아군과 적의 탄환을 다른 규칙으로 검사할 수 있습니다. 그룹을 준비하는 것과 실제 객체를 넣는 것은 별개입니다.

- **각 행을 따로 만들어 칸 변경이 다른 행에 번지지 않게 합니다.** 지도는 행을 담은 바깥 리스트와 각 행의 칸을 담은 안쪽 리스트입니다. 안쪽 반복이 한 행을 만들고 바깥 반복이 새 행을 여러 번 만듭니다. `level_map[2][3]`은 세 번째 행, 네 번째 열입니다. `[[0] * 30] * 20`은 같은 행을 공유하므로 한 칸 수정이 다른 행에도 나타날 수 있습니다. 이 수업의 중첩 리스트 생성식을 그대로 구분해 읽으세요.

- **지도 숫자는 이미지가 아니라 칸의 종류를 나타내는 약속입니다.** `[2] * 10`은 숫자 2를 열 번 담은 리스트이고 `+`는 리스트들을 이어 붙입니다. `[4:12]`는 4열부터 11열까지 8칸이며 끝값 12는 포함하지 않습니다. 같은 길이의 리스트로 교체해야 행의 열 수가 바뀌지 않습니다. 숫자와 실제 그림의 연결은 아래 지도 해석 반복문에서 이루어집니다.

- **행 번호와 그 행의 칸 목록을 하나씩 꺼냅니다.** `enumerate(level_map)`은 (행 번호, 그 행의 리스트)를 차례로 줍니다. `row, cells`는 두 값을 나누어 받습니다. 안쪽 `enumerate(cells)`는 (열 번호, 칸 숫자)를 줍니다. 안쪽 반복을 끝까지 마친 뒤 다음 행으로 이동합니다. 이름만 바꾸어 외우기보다 현재 row와 column이 각각 어디를 가리키는지 손으로 표시해 보세요.

- **열은 x좌표, 행은 y좌표로 바꿉니다.** 32픽셀 타일에서 3행 4열은 x=4×32=128, y=3×32=96입니다. row와 column은 칸 번호이고 x와 y는 픽셀 위치입니다. 둘을 바꾸면 지도가 가로세로 뒤바뀝니다. 숫자 0은 어떤 생성 분기에도 들어가지 않아 빈칸으로 남고, 다른 숫자는 해당 분기에서 객체로 바뀝니다.

- **2·3·4·5를 모두 발판 종류로 처리합니다.** `2 <= kind <= 5`는 kind가 2 이상이면서 5 이하인지 검사합니다. 2·3·4·5는 그림 모양은 달라도 같은 발판 충돌 그룹에 들어갑니다. if/elif는 처음 참인 분기 하나만 실행하므로 한 칸에서 같은 타일을 여러 번 만들지 않습니다.

```python
# 화면에 그릴 타일 전체입니다.
tiles = pygame.sprite.Group()
# 착지 검사에 사용할 발판만 담습니다.
platforms = pygame.sprite.Group()
# 위험 접촉을 검사할 타일만 담습니다.
hazards = pygame.sprite.Group()
# 탐사원을 갱신하고 그릴 그룹입니다.
explorers = pygame.sprite.Group()
# 각 행을 따로 만들어 칸 변경이 다른 행에 번지지 않게 합니다.
level_map = [[0 for column in range(30)] for row in range(20)]
# 지도 숫자는 이미지가 아니라 칸의 종류를 나타내는 약속입니다.
level_map[19] = [1] * 30
# 지도 숫자는 이미지가 아니라 칸의 종류를 나타내는 약속입니다.
level_map[18] = [2] * 10 + [6] * 10 + [2] * 10
# 지도 숫자는 이미지가 아니라 칸의 종류를 나타내는 약속입니다.
level_map[14][4:12] = [3] + [4] * 6 + [5]
# 지도 숫자는 이미지가 아니라 칸의 종류를 나타내는 약속입니다.
level_map[10][14:22] = [3] + [4] * 6 + [5]
# 지도 숫자는 이미지가 아니라 칸의 종류를 나타내는 약속입니다.
level_map[6][5:13] = [3] + [4] * 6 + [5]

# 행 번호와 그 행의 칸 목록을 하나씩 꺼냅니다.
for row, cells in enumerate(level_map):
    for column, kind in enumerate(cells):
        # 열은 x좌표, 행은 y좌표로 바꿉니다.
        x, y = column * TILE_SIZE, row * TILE_SIZE
        if kind == 1:
            Terrain(x, y, kind, tiles)
        # 2·3·4·5를 모두 발판 종류로 처리합니다.
        elif 2 <= kind <= 5:
            Terrain(x, y, kind, tiles, platforms)
        elif kind == 6:
            Terrain(x, y, kind, tiles, hazards)
```

**편집 4.** **수정 위치:** running = True부터 파일 마지막 pygame.quit()까지의 실행 루프 전체. 아래 코드로 교체합니다. 클래스나 메서드 안에 넣지 않습니다.

**왜 이렇게 쓰나요 — 이 편집을 읽는 순서**

- **입력과 상태 변화, 그리기를 매 프레임 반복합니다.** 한 프레임은 게임을 한 번 갱신해서 표시하는 주기입니다. 준비 코드·그룹 생성은 while 위에서 한 번만 실행하고, 입력과 이동·그리기는 while 안에서 반복합니다. 물체를 매 프레임 새로 생성하면 위치가 초기화되거나 개수가 계속 늘어납니다. 반복문의 들여쓰기가 게임의 시간 구조를 정합니다.

- **지난 프레임 이후 쌓인 입력 이벤트를 처리합니다.** `event.get()`은 이번에 도착한 사건들을 꺼냅니다. KEYDOWN은 누르기 시작한 사건이고 `key.get_pressed()`는 지금 계속 누르고 있는 상태입니다. 점프·발사 한 번은 이벤트로, 연속 좌우 이동은 누름 상태로 처리하는 이유가 여기에 있습니다. 스튜디오 게임 화면을 클릭해야 입력이 게임으로 전달됩니다.

- **밀리초를 초로 바꾸고 지나치게 긴 프레임을 제한합니다.** `clock.tick(FPS)`는 최대 프레임 속도를 제한하고 경과 밀리초를 줍니다. 16밀리초는 16/1000=0.016초입니다. `min(..., 0.05)`는 긴 탭 전환 시간을 한 번의 큰 이동으로 적용하지 않기 위한 상한입니다. 따라서 오래 다른 탭에 머문 실제 시간과 게임 안 경과 시간이 항상 같지는 않습니다.

- **그룹의 image와 rect를 사용해 화면에 그립니다.** 그룹의 `update()`는 각 객체의 update를 호출하고, `draw(screen)`은 image를 rect 위치에 그립니다. update만 하면 값만 바뀌고, draw만 하면 같은 그림이 같은 위치에 남습니다. 배경 → 물체 → HUD/안내 순서로 그려야 뒤에 그린 배경이 물체를 덮지 않습니다. 마지막 display.update가 그린 화면을 표시합니다.

```python
running = True
# 입력과 상태 변화, 그리기를 매 프레임 반복합니다.
while running:
    # 밀리초를 초로 바꾸고 지나치게 긴 프레임을 제한합니다.
    seconds = min(clock.tick(FPS) / 1000, 0.05)
    # 지난 프레임 이후 쌓인 입력 이벤트를 처리합니다.
    for event in pygame.event.get():
        if event.type == pygame.QUIT:
            running = False
    if not running:
        break
    screen.fill((15, 25, 42))
    # 그룹의 image와 rect를 사용해 화면에 그립니다.
    tiles.draw(screen)
    pygame.display.update()

pygame.quit()
```


### 코드가 하는 일

load_image는 경로와 크기를 키로 삼아 첫 요청에만 그림을 읽습니다. 같은 타일을 수백 번 읽는 일을 피합니다. convert_alpha는 투명도를 유지하고 smoothscale은32×32로 맞춥니다. Terrain의 super().__init__(tiles)는 현재 객체를 전체 그룹에 넣습니다. subgroup이 전달되면 발판 또는 위험 그룹에도 같은 객체를 넣습니다. 행(row)에 TILE_SIZE를 곱해 y좌표를, 열(column)에 TILE_SIZE를 곱해 x좌표를 구합니다. enumerate는 순번과 값을 함께 제공합니다.

## 02-B - 화성 배경을 마지막에 붙이기

타일 배치가 맞는지 확인한 뒤 배경을 교체합니다.

**이 단계의 연결:** 출발 코드는 **02-A**의 누적 코드입니다. 아래 편집은 위에서부터 모두 적용합니다. 이미 완성한 나머지 메서드는 지정된 교체 범위 밖이면 그대로 둡니다.


### 입력 전에 결과를 예상해 보세요

배경 load를 while 안에 두는 것과 blit을 while 안에 두는 것은 왜 다른가요?

먼저 답을 한 문장으로 적고 아래 해설과 비교하세요.

**생각 확인:** load는 파일 준비라 한 번이면 되고 blit은 현재 화면에 그리기라 매 프레임 필요합니다. 배경을 먼저 그린 뒤 타일을 그려야 타일이 덮이지 않습니다.

### 수정 위치와 입력할 코드

**편집 1.** **수정 위치:** 마지막 클래스 아래에서 running = True 위까지의 그룹·지도·객체 준비 구간. 아래 코드로 교체합니다. 클래스나 메서드 안에 넣지 않습니다.

**왜 이렇게 쓰나요 — 이 편집을 읽는 순서**

- **같이 갱신하거나 검사할 객체들을 담을 그룹을 만듭니다.** Group은 Sprite들을 묶는 관리 목록입니다. 변수마다 `Group()`을 호출하면 별개의 빈 그룹을 만듭니다. 화성의 tiles/all_tiles는 그릴 타일 전체, platforms는 착지 대상, hazards는 위험 접촉 대상입니다. 우주 방어대의 양쪽 탄환 그룹도 분리해야 아군과 적의 탄환을 다른 규칙으로 검사할 수 있습니다. 그룹을 준비하는 것과 실제 객체를 넣는 것은 별개입니다.

- **각 행을 따로 만들어 칸 변경이 다른 행에 번지지 않게 합니다.** 지도는 행을 담은 바깥 리스트와 각 행의 칸을 담은 안쪽 리스트입니다. 안쪽 반복이 한 행을 만들고 바깥 반복이 새 행을 여러 번 만듭니다. `level_map[2][3]`은 세 번째 행, 네 번째 열입니다. `[[0] * 30] * 20`은 같은 행을 공유하므로 한 칸 수정이 다른 행에도 나타날 수 있습니다. 이 수업의 중첩 리스트 생성식을 그대로 구분해 읽으세요.

- **지도 숫자는 이미지가 아니라 칸의 종류를 나타내는 약속입니다.** `[2] * 10`은 숫자 2를 열 번 담은 리스트이고 `+`는 리스트들을 이어 붙입니다. `[4:12]`는 4열부터 11열까지 8칸이며 끝값 12는 포함하지 않습니다. 같은 길이의 리스트로 교체해야 행의 열 수가 바뀌지 않습니다. 숫자와 실제 그림의 연결은 아래 지도 해석 반복문에서 이루어집니다.

- **행 번호와 그 행의 칸 목록을 하나씩 꺼냅니다.** `enumerate(level_map)`은 (행 번호, 그 행의 리스트)를 차례로 줍니다. `row, cells`는 두 값을 나누어 받습니다. 안쪽 `enumerate(cells)`는 (열 번호, 칸 숫자)를 줍니다. 안쪽 반복을 끝까지 마친 뒤 다음 행으로 이동합니다. 이름만 바꾸어 외우기보다 현재 row와 column이 각각 어디를 가리키는지 손으로 표시해 보세요.

- **열은 x좌표, 행은 y좌표로 바꿉니다.** 32픽셀 타일에서 3행 4열은 x=4×32=128, y=3×32=96입니다. row와 column은 칸 번호이고 x와 y는 픽셀 위치입니다. 둘을 바꾸면 지도가 가로세로 뒤바뀝니다. 숫자 0은 어떤 생성 분기에도 들어가지 않아 빈칸으로 남고, 다른 숫자는 해당 분기에서 객체로 바뀝니다.

- **2·3·4·5를 모두 발판 종류로 처리합니다.** `2 <= kind <= 5`는 kind가 2 이상이면서 5 이하인지 검사합니다. 2·3·4·5는 그림 모양은 달라도 같은 발판 충돌 그룹에 들어갑니다. if/elif는 처음 참인 분기 하나만 실행하므로 한 칸에서 같은 타일을 여러 번 만들지 않습니다.

```python
# 화면에 그릴 타일 전체입니다.
tiles = pygame.sprite.Group()
# 착지 검사에 사용할 발판만 담습니다.
platforms = pygame.sprite.Group()
# 위험 접촉을 검사할 타일만 담습니다.
hazards = pygame.sprite.Group()
# 탐사원을 갱신하고 그릴 그룹입니다.
explorers = pygame.sprite.Group()
# 각 행을 따로 만들어 칸 변경이 다른 행에 번지지 않게 합니다.
level_map = [[0 for column in range(30)] for row in range(20)]
# 지도 숫자는 이미지가 아니라 칸의 종류를 나타내는 약속입니다.
level_map[19] = [1] * 30
# 지도 숫자는 이미지가 아니라 칸의 종류를 나타내는 약속입니다.
level_map[18] = [2] * 10 + [6] * 10 + [2] * 10
# 지도 숫자는 이미지가 아니라 칸의 종류를 나타내는 약속입니다.
level_map[14][4:12] = [3] + [4] * 6 + [5]
# 지도 숫자는 이미지가 아니라 칸의 종류를 나타내는 약속입니다.
level_map[10][14:22] = [3] + [4] * 6 + [5]
# 지도 숫자는 이미지가 아니라 칸의 종류를 나타내는 약속입니다.
level_map[6][5:13] = [3] + [4] * 6 + [5]

# 행 번호와 그 행의 칸 목록을 하나씩 꺼냅니다.
for row, cells in enumerate(level_map):
    for column, kind in enumerate(cells):
        # 열은 x좌표, 행은 y좌표로 바꿉니다.
        x, y = column * TILE_SIZE, row * TILE_SIZE
        if kind == 1:
            Terrain(x, y, kind, tiles)
        # 2·3·4·5를 모두 발판 종류로 처리합니다.
        elif 2 <= kind <= 5:
            Terrain(x, y, kind, tiles, platforms)
        elif kind == 6:
            Terrain(x, y, kind, tiles, hazards)

background = load_image('assets/background.png', (SCREEN_WIDTH, SCREEN_HEIGHT))
```
