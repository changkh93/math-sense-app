### 수정 위치와 입력할 코드

**편집 1.** `class Crystal` 안의 `__init__` 메서드 전체를 아래 코드로 교체합니다. 다음 `def` 직전까지가 교체 범위입니다. `def` 앞 4칸, 본문 앞 8칸을 유지합니다.

**왜 이렇게 쓰나요 — 이 편집을 읽는 순서**

- **부모 Sprite의 내부 준비를 먼저 실행합니다.** `super().__init__()`은 상속받은 Sprite 내부를 준비합니다. 괄호 안에 그룹이 있으면 그 그룹에 이 객체를 바로 등록합니다. `super().__init__(tiles)`는 tiles에 자동 등록하지만 인수가 없는 `super().__init__()`은 자동 등록하지 않으므로 나중에 `그룹.add(객체)`가 필요합니다. 이 차이를 확인하고 중복 생성하지 마세요.

- **그림의 크기와 화면 위치를 담을 상자를 만듭니다.** `image`는 그림이고 `rect`는 그 그림을 놓을 사각형입니다. `get_rect(topleft=(x, y))`는 왼쪽 위, `midbottom=(x, y)`는 발 가운데를 해당 위치에 맞춥니다. 예를 들어 64×64 그림의 midbottom이 (100, 200)이면 왼쪽 위는 (68, 136)입니다. 같은 좌표라도 기준점이 다르면 표시 위치가 달라집니다. Group.draw는 각 객체의 image와 rect를 읽습니다.

- **이동하기 전 위치를 별도로 기억합니다.** 현재 rect를 바로 대입하면 같은 상자를 가리킬 수 있으므로 `.copy()`로 별도 상자를 만듭니다. 이전 발 높이 90, 현재 발 높이 110, 발판 윗면 100이라면 중간에 발판을 통과했다는 것을 알 수 있습니다. 현재 위치만 검사할 때 놓칠 수 있는 빠른 낙하를 이 두 시점으로 잡습니다.

- **위치·속도·가속도를 구별하고 이번 프레임 힘을 준비합니다.** position은 어디 있는지, velocity는 한 기준 프레임 동안 얼마나 움직이는지, acceleration은 속도가 얼마나 변하는지입니다. Vector2는 x와 y를 묶어 두 방향을 함께 계산합니다. 이동 시작마다 가속도를 다시 정해야 이전 프레임의 입력·마찰이 계속 누적되지 않습니다. 중력이 있는 단계에서는 y 가속도에 gravity를 넣습니다.

- **소리 파일을 준비하는 일과 재생하는 일을 구분합니다.** Sound 또는 load_sound는 소리를 사용할 준비입니다. .play()를 호출하는 순간 재생을 시도합니다. 생성자에서 준비하고 실제 발사·충돌 사건에서 재생해야 매 프레임 파일을 읽거나 준비만 했는데 소리가 날 것으로 기대하지 않습니다.

```python
    # 객체를 생성할 때 필요한 초기 값과 참조를 준비합니다.
    def __init__(self, platforms, gates):
        # 부모 Sprite의 내부 준비를 먼저 실행합니다.
        super().__init__()
        self.gravity = 3
        self.frames = load_frames('crystal', (32, 32))
        self.frame = 0.0
        self.image = self.frames[0]
        # 그림의 크기와 화면 위치를 담을 상자를 만듭니다.
        self.rect = self.image.get_rect(midbottom=(SCREEN_WIDTH // 2, 100))
        self.platforms, self.gates = platforms, gates
        self.position = Vector(self.rect.midbottom)
        self.velocity = Vector(random.choice([-5, 5]), 0)
        # 위치·속도·가속도를 구별하고 이번 프레임 힘을 준비합니다.
        self.acceleration = Vector(0, self.gravity)
        # 이동하기 전 위치를 별도로 기억합니다.
        self.previous_rect = self.rect.copy()
        # 소리 파일을 준비하는 일과 재생하는 일을 구분합니다.
        self.portal_sound = load_sound('portal')
        self.portal_remaining = 0.0
```

## 27-B - 로봇 회수로 결정 떨어뜨리기

이번 편집의 목표는 **로봇 회수로 결정 떨어뜨리기**입니다. 아래 수정 위치를 모두 반영한 다음 실행 결과를 확인합니다.

**이 단계의 연결:** 출발 코드는 **27-A**의 누적 코드입니다. 아래 편집은 위에서부터 모두 적용합니다. 이미 완성한 나머지 메서드는 지정된 교체 범위 밖이면 그대로 둡니다.


### 입력 전에 결과를 예상해 보세요

같은 로봇으로 매 프레임 결정을 만들지 않으려면 어떤 처리가 필요하나요?

먼저 답을 한 문장으로 적고 아래 해설과 비교하세요.

**생각 확인:** 회수한 로봇을 즉시 그룹에서 제거해야 다음 프레임의 충돌 대상에서 빠집니다. 결정 생성은 실제 회수한 로봇 하나당 한 번입니다.

### 수정 위치와 입력할 코드

**편집 1.** `class Crystal` 안의 `update` 메서드 전체를 아래 코드로 교체합니다. 다음 `def` 직전까지가 교체 범위입니다. `def` 앞 4칸, 본문 앞 8칸을 유지합니다.

```python
    # 그룹에서 호출하는 한 프레임의 처리 순서입니다.
    def update(self, seconds=1 / FPS):
        self.portal_remaining = max(0, self.portal_remaining - seconds)
        self.animate(seconds)
        self.move(seconds)
        self.check_collisions()
```

**편집 2.** `class Crystal` 안의 `move` 메서드 전체를 아래 코드로 교체합니다. 다음 `def` 직전까지가 교체 범위입니다. `def` 앞 4칸, 본문 앞 8칸을 유지합니다.

**왜 이렇게 쓰나요 — 이 편집을 읽는 순서**

- **이동하기 전 위치를 별도로 기억합니다.** 현재 rect를 바로 대입하면 같은 상자를 가리킬 수 있으므로 `.copy()`로 별도 상자를 만듭니다. 이전 발 높이 90, 현재 발 높이 110, 발판 윗면 100이라면 중간에 발판을 통과했다는 것을 알 수 있습니다. 현재 위치만 검사할 때 놓칠 수 있는 빠른 낙하를 이 두 시점으로 잡습니다.

- **이전 속도로 위치를 계산한 뒤 다음 줄에서 속도를 갱신합니다.** `scale=seconds*FPS`는 기준 60FPS 한 프레임에 대한 시간 비율입니다. scale=1, 이전 속도 4, 가속도 2이면 위치 변화는 4+0.5×2=5, 다음 속도는 6입니다. 속도를 먼저 6으로 바꾼 뒤 같은 위치 식을 쓰면 7이 되어 가속도를 중복 반영합니다. position은 소수를 보존하고 rect는 화면 표시용 정수 위치를 받습니다.

- **화면의 한쪽 끝을 반대쪽 끝으로 이어 줍니다.** 나머지 연산은 x를 0 이상 화면 폭 미만으로 돌려놓습니다. 폭이 960이면 -5 % 960은 955, 965 % 960은 5입니다. 벽에서 멈추는 방식과 다른 규칙입니다. 고친 position을 rect에 반영해야 화면에서도 이동이 보입니다.

```python
    # 입력 또는 정해진 속도로 위치를 갱신합니다.
    def move(self, seconds):
        # 이동하기 전 위치를 별도로 기억합니다.
        self.previous_rect = self.rect.copy()
        scale = min(seconds * FPS, 3)
        # 이전 속도로 위치를 계산한 뒤 다음 줄에서 속도를 갱신합니다.
        self.position += self.velocity * scale + 0.5 * self.acceleration * scale * scale
        self.velocity += self.acceleration * scale
        self.velocity.y = min(self.velocity.y, 25)
        # 화면의 한쪽 끝을 반대쪽 끝으로 이어 줍니다.
        self.position.x %= SCREEN_WIDTH
        self.rect.midbottom = self.position
```

**편집 3.** `class Crystal` 안의 `check_collisions` 메서드 전체를 아래 코드로 교체합니다. 다음 `def` 직전까지가 교체 범위입니다. `def` 앞 4칸, 본문 앞 8칸을 유지합니다.

**왜 이렇게 쓰나요 — 이 편집을 읽는 순서**

- **낙하 경로가 발판 윗면을 지나갔는지 검사합니다.** 가로 지지 범위가 발판과 겹치는지 먼저 확인한 뒤 세로 통과를 검사합니다. 착지하면 위치를 발판 윗면으로 맞추고 y속도를 0으로 바꿉니다. rect만 고치면 다음 이동에서 position의 옛 값이 되살아나므로 둘 다 맞춰야 합니다. 위쪽 발판부터 검사하고 첫 착지에서 break하는 순서도 필요합니다.

- **도착 즉시 같은 문으로 되돌아가는 연쇄 이동을 막습니다.** 게이트 이동은 같은 channel이면서 자기 자신이 아닌 상대 문을 찾습니다. 도착 위치를 문의 안쪽으로 띄우고 잠금 시간을 두어 한 번의 접촉이 왕복을 반복하지 않게 합니다. 화면에 그릴 rect와 물리 위치 position을 함께 바꿔야 다음 프레임에 되돌아가지 않습니다.

- **조건에 맞는 첫 상대 게이트를 찾고 없으면 None을 받습니다.** `(other for other in self.gates if ...)`는 조건에 맞는 후보를 차례로 내는 표현입니다. `next(..., None)`은 첫 후보를 꺼내며 없을 때 None을 돌려줍니다. `other is not gate`는 동일 객체를 제외하고 `channel == gate.channel`은 같은 색 계열을 고릅니다. target이 None이 아닌지 확인한 뒤 좌표를 읽어야 합니다.

- **높은 발판부터 검사하도록 비교 기준을 지정합니다.** sorted는 원래 그룹을 바꾸지 않고 정렬된 목록을 줍니다. lambda tile: tile.rect.top은 타일 하나를 받아 윗면 높이를 반환하는 짧은 함수입니다. 화면의 작은 y가 위쪽이므로 작은 top부터 검사합니다. 한 프레임에 여러 발판 높이를 통과했을 때 먼저 만난 윗면에 착지시키려는 순서입니다.

- **이번 대상의 나머지 검사를 건너뛰고 다음 대상으로 갑니다.** continue는 가장 가까운 반복문의 다음 반복으로 이동합니다. 발판과 가로 범위가 겹치지 않으면 그 발판의 세로 착지 검사를 생략합니다. break는 반복문 전체를 끝내고 return은 메서드를 끝냅니다. 세 명령이 어느 범위를 빠져나가는지 들여쓰기를 따라 확인하세요.

```python
    # 접촉 대상을 검사하고 이 단계의 충돌 규칙을 적용합니다.
    def check_collisions(self):
        # 높은 발판부터 검사하도록 비교 기준을 지정합니다.
        for tile in sorted(self.platforms, key=lambda tile: tile.rect.top):
            if self.rect.right <= tile.rect.left or self.rect.left >= tile.rect.right:
                # 이번 대상의 나머지 검사를 건너뛰고 다음 대상으로 갑니다.
                continue
            # 낙하 경로가 발판 윗면을 지나갔는지 검사합니다.
            if self.previous_rect.bottom <= tile.rect.top + 1 <= self.rect.bottom + 1:
                self.position.y = tile.rect.top
                self.velocity.y = 0
                self.rect.midbottom = self.position
                break
        for gate in self.gates:
            if self.portal_remaining <= 0 and self.rect.colliderect(gate.rect):
                # 조건에 맞는 첫 상대 게이트를 찾고 없으면 None을 받습니다.
                target = next((other for other in self.gates if other is not gate and other.channel == gate.channel), None)
                if target is not None:
                    self.position.update(target.rect.centerx + (80 if target.rect.centerx < SCREEN_WIDTH / 2 else -80), target.rect.bottom)
                    self.rect.midbottom = self.position
                    # 도착 즉시 같은 문으로 되돌아가는 연쇄 이동을 막습니다.
                    self.portal_remaining = 0.4
                    self.portal_sound.play()
                    break
```

**편집 4.** `class Crystal` 안의 `animate` 메서드 전체를 아래 코드로 교체합니다. 다음 `def` 직전까지가 교체 범위입니다. `def` 앞 4칸, 본문 앞 8칸을 유지합니다.

```python
    # 표시할 애니메이션 프레임을 선택합니다.
    def animate(self, seconds):
        self.frame = (self.frame + seconds * 6) % len(self.frames)
        self.image = self.frames[int(self.frame)]
```

**편집 5.** `class Expedition` 안의 `check_collisions` 메서드 전체를 아래 코드로 교체합니다. 다음 `def` 직전까지가 교체 범위입니다. `def` 앞 4칸, 본문 앞 8칸을 유지합니다.

**왜 이렇게 쓰나요 — 이 편집을 읽는 순서**

- **두 그룹의 충돌 결과를 받아 맞힌 대상 수를 셉니다.** `groupcollide(A, B, 지울A, 지울B)`는 A의 객체를 열쇠로, 그 객체가 맞힌 B 목록을 값으로 돌려줍니다. 두 True/False는 각각 어느 쪽을 그룹에서 제거할지 정합니다. 우주 방어대는 양쪽 제거, 화성의 로봇 피격은 펄스만 제거하고 로봇을 남겨 상태를 바꿉니다. values()로 얻는 것은 객체 하나가 아니라 대상 목록이라는 점에 주의하세요.

- **객체 하나와 그룹을 비교하고 충돌한 대상 목록을 받습니다.** `spritecollide(객체, 그룹, 제거여부)`는 겹친 대상들의 리스트를 반환합니다. 빈 리스트는 if에서 거짓, 한 개 이상은 참입니다. if 본문을 한 번 실행하는 규칙과 len(목록)만큼 보상을 계산하는 규칙은 다릅니다. 여러 탄환 피격은 생명 한 번 차감, 결정 여러 개 회수는 개수별 보상이라는 해당 단계의 의도를 읽으세요.

```python
    # 접촉 대상을 검사하고 이 단계의 충돌 규칙을 적용합니다.
    def check_collisions(self):
        # 두 그룹의 충돌 결과를 받아 맞힌 대상 수를 셉니다.
        collisions = pygame.sprite.groupcollide(self.pulses, self.robots, True, False)
        for targets in collisions.values():
            for robot in targets:
                if robot.state == 'walking':
                    robot.hit_sound.play()
                    robot.state = 'falling'
                    robot.frame = 0.0
                    robot.down_elapsed = 0.0
        # 객체 하나와 그룹을 비교하고 충돌한 대상 목록을 받습니다.
        for robot in pygame.sprite.spritecollide(self.explorer, self.robots, False):
            if robot.state != 'walking':
                robot.kick_sound.play()
                robot.kill()
                self.score += 25
                self.crystals.add(Crystal(self.platforms, self.gates))
            elif self.explorer.hurt_remaining <= 0:
                self.explorer.health = max(0, self.explorer.health - 20)
                self.explorer.hit_sound.play()
                self.explorer.hurt_remaining = 1.0
                self.explorer.position.x = (self.explorer.position.x - 128 * robot.direction) % SCREEN_WIDTH
                self.explorer.rect.midbottom = self.explorer.position
                if self.explorer.health <= 0:
                    return
```

**편집 6.** **수정 위치:** running = True부터 파일 마지막 pygame.quit()까지의 실행 루프 전체. 아래 코드로 교체합니다. 클래스나 메서드 안에 넣지 않습니다.

**왜 이렇게 쓰나요 — 이 편집을 읽는 순서**

- **입력과 상태 변화, 그리기를 매 프레임 반복합니다.** 한 프레임은 게임을 한 번 갱신해서 표시하는 주기입니다. 준비 코드·그룹 생성은 while 위에서 한 번만 실행하고, 입력과 이동·그리기는 while 안에서 반복합니다. 물체를 매 프레임 새로 생성하면 위치가 초기화되거나 개수가 계속 늘어납니다. 반복문의 들여쓰기가 게임의 시간 구조를 정합니다.

- **지난 프레임 이후 쌓인 입력 이벤트를 처리합니다.** `event.get()`은 이번에 도착한 사건들을 꺼냅니다. KEYDOWN은 누르기 시작한 사건이고 `key.get_pressed()`는 지금 계속 누르고 있는 상태입니다. 점프·발사 한 번은 이벤트로, 연속 좌우 이동은 누름 상태로 처리하는 이유가 여기에 있습니다. 스튜디오 게임 화면을 클릭해야 입력이 게임으로 전달됩니다.

- **밀리초를 초로 바꾸고 지나치게 긴 프레임을 제한합니다.** `clock.tick(FPS)`는 최대 프레임 속도를 제한하고 경과 밀리초를 줍니다. 16밀리초는 16/1000=0.016초입니다. `min(..., 0.05)`는 긴 탭 전환 시간을 한 번의 큰 이동으로 적용하지 않기 위한 상한입니다. 따라서 오래 다른 탭에 머문 실제 시간과 게임 안 경과 시간이 항상 같지는 않습니다.

- **그룹의 image와 rect를 사용해 화면에 그립니다.** 그룹의 `update()`는 각 객체의 update를 호출하고, `draw(screen)`은 image를 rect 위치에 그립니다. update만 하면 값만 바뀌고, draw만 하면 같은 그림이 같은 위치에 남습니다. 배경 → 물체 → HUD/안내 순서로 그려야 뒤에 그린 배경이 물체를 덮지 않습니다. 마지막 display.update가 그린 화면을 표시합니다.

```python
running = True
# 입력과 상태 변화, 그리기를 매 프레임 반복합니다.
while running:
    # 밀리초를 초로 바꾸고 지나치게 긴 프레임을 제한합니다.
    seconds = min(clock.tick(FPS) / 1000, 0.05)
    # 지난 프레임 이후 쌓인 입력 이벤트를 처리합니다.
    for event in pygame.event.get():
        if event.type == pygame.QUIT:
            running = False
        elif event.type == pygame.KEYDOWN:
            if event.key == pygame.K_SPACE:
                explorer.jump()
            elif event.key == pygame.K_UP:
                explorer.fire()
            elif event.key == pygame.K_RETURN:
                robots.add(Robot(platforms, gates, 2, 7))
    if not running:
        break
    all_tiles.update(seconds)
    gates.update(seconds)
    explorers.update(seconds)
    pulses.update(seconds)
    robots.update(seconds)
    crystals.update(seconds)
    mission.update(seconds)
    screen.blit(background, (0, 0))
    # 그룹의 image와 rect를 사용해 화면에 그립니다.
    all_tiles.draw(screen)
    # 그룹의 image와 rect를 사용해 화면에 그립니다.
    gates.draw(screen)
    # 그룹의 image와 rect를 사용해 화면에 그립니다.
    explorers.draw(screen)
    # 그룹의 image와 rect를 사용해 화면에 그립니다.
    pulses.draw(screen)
    # 그룹의 image와 rect를 사용해 화면에 그립니다.
    robots.draw(screen)
    # 그룹의 image와 rect를 사용해 화면에 그립니다.
    crystals.draw(screen)
    mission.draw()
    pygame.display.update()

pygame.quit()
```
