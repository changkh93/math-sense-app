**편집 2.** `class Expedition` 안의 `draw` 메서드 전체를 아래 코드로 교체합니다. 다음 `def` 직전까지가 교체 범위입니다. `def` 앞 4칸, 본문 앞 8칸을 유지합니다.

**왜 이렇게 쓰나요 — 이 편집을 읽는 순서**

- **그림의 크기와 화면 위치를 담을 상자를 만듭니다.** `image`는 그림이고 `rect`는 그 그림을 놓을 사각형입니다. `get_rect(topleft=(x, y))`는 왼쪽 위, `midbottom=(x, y)`는 발 가운데를 해당 위치에 맞춥니다. 예를 들어 64×64 그림의 midbottom이 (100, 200)이면 왼쪽 위는 (68, 136)입니다. 같은 좌표라도 기준점이 다르면 표시 위치가 달라집니다. Group.draw는 각 객체의 image와 rect를 읽습니다.

- **숫자와 문자를 글자 그림으로 바꾸어 그립니다.** font.render의 첫 인수는 문자열입니다. f 문자열의 `{self.score}` 같은 부분은 그 시점의 값을 글자로 넣습니다. render 결과 역시 Surface이므로 get_rect로 정렬하고 blit으로 그립니다. 점수가 바뀐 뒤 다시 render해야 새 숫자가 보입니다. 파일 경로로 한글 폰트를 지정해 기본 폰트에 한글이 없는 문제를 피합니다.

- **딕셔너리의 항목을 위치 이름과 값으로 풀어 전달합니다.** `**{anchor: point}`는 예를 들어 anchor가 "topleft", point가 (16, 680)이면 `get_rect(topleft=(16, 680))`과 같은 호출입니다. 이름을 변수로 정해 왼쪽/오른쪽 정렬을 같은 반복문에서 처리하려고 사용합니다. 별표 두 개는 곱셈이 아니라 함수 인수 풀기 문법입니다.

```python
    # 현재 값을 읽어 화면과 안내를 그립니다.
    def draw(self):
        pygame.draw.rect(screen, (13, 24, 40), (0, SCREEN_HEIGHT - 58, SCREEN_WIDTH, 58))
        rows = [
            (f'점수 {self.score}', (16, SCREEN_HEIGHT - 56), 'topleft'),
            (f'에너지 {100}', (16, SCREEN_HEIGHT - 29), 'topleft'),
            (f'탐사 {self.round_number}', (SCREEN_WIDTH - 16, SCREEN_HEIGHT - 56), 'topright'),
            (f'신호 복구까지 {self.remaining}초', (SCREEN_WIDTH - 16, SCREEN_HEIGHT - 29), 'topright'),
        ]
        for text, point, anchor in rows:
            # 숫자와 문자를 글자 그림으로 바꾸어 그립니다.
            surface = self.hud_font.render(text, True, (237, 244, 252))
            # 그림의 크기와 화면 위치를 담을 상자를 만듭니다.
            rect = surface.get_rect(**{anchor: point})
            screen.blit(surface, rect)
        # 숫자와 문자를 글자 그림으로 바꾸어 그립니다.
        title = self.title_font.render('화성 탐사대', True, (101, 229, 217))
        # 그림의 크기와 화면 위치를 담을 상자를 만듭니다.
        screen.blit(title, title.get_rect(center=(SCREEN_WIDTH // 2, SCREEN_HEIGHT - 29)))
```

**왜 이렇게 쓰나요 — 이 편집을 읽는 순서**

- **같이 갱신하거나 검사할 객체들을 담을 그룹을 만듭니다.** Group은 Sprite들을 묶는 관리 목록입니다. 변수마다 `Group()`을 호출하면 별개의 빈 그룹을 만듭니다. 화성의 tiles/all_tiles는 그릴 타일 전체, platforms는 착지 대상, hazards는 위험 접촉 대상입니다. 우주 방어대의 양쪽 탄환 그룹도 분리해야 아군과 적의 탄환을 다른 규칙으로 검사할 수 있습니다. 그룹을 준비하는 것과 실제 객체를 넣는 것은 별개입니다.

- **각 행을 따로 만들어 칸 변경이 다른 행에 번지지 않게 합니다.** 지도는 행을 담은 바깥 리스트와 각 행의 칸을 담은 안쪽 리스트입니다. 안쪽 반복이 한 행을 만들고 바깥 반복이 새 행을 여러 번 만듭니다. `level_map[2][3]`은 세 번째 행, 네 번째 열입니다. `[[0] * 30] * 20`은 같은 행을 공유하므로 한 칸 수정이 다른 행에도 나타날 수 있습니다. 이 수업의 중첩 리스트 생성식을 그대로 구분해 읽으세요.

- **지도 숫자는 이미지가 아니라 칸의 종류를 나타내는 약속입니다.** `[2] * 10`은 숫자 2를 열 번 담은 리스트이고 `+`는 리스트들을 이어 붙입니다. `[4:12]`는 4열부터 11열까지 8칸이며 끝값 12는 포함하지 않습니다. 같은 길이의 리스트로 교체해야 행의 열 수가 바뀌지 않습니다. 숫자와 실제 그림의 연결은 아래 지도 해석 반복문에서 이루어집니다.

- **행 번호와 그 행의 칸 목록을 하나씩 꺼냅니다.** `enumerate(level_map)`은 (행 번호, 그 행의 리스트)를 차례로 줍니다. `row, cells`는 두 값을 나누어 받습니다. 안쪽 `enumerate(cells)`는 (열 번호, 칸 숫자)를 줍니다. 안쪽 반복을 끝까지 마친 뒤 다음 행으로 이동합니다. 이름만 바꾸어 외우기보다 현재 row와 column이 각각 어디를 가리키는지 손으로 표시해 보세요.

- **열은 x좌표, 행은 y좌표로 바꿉니다.** 32픽셀 타일에서 3행 4열은 x=4×32=128, y=3×32=96입니다. row와 column은 칸 번호이고 x와 y는 픽셀 위치입니다. 둘을 바꾸면 지도가 가로세로 뒤바뀝니다. 숫자 0은 어떤 생성 분기에도 들어가지 않아 빈칸으로 남고, 다른 숫자는 해당 분기에서 객체로 바뀝니다.

- **2·3·4·5를 모두 발판 종류로 처리합니다.** `2 <= kind <= 5`는 kind가 2 이상이면서 5 이하인지 검사합니다. 2·3·4·5는 그림 모양은 달라도 같은 발판 충돌 그룹에 들어갑니다. if/elif는 처음 참인 분기 하나만 실행하므로 한 칸에서 같은 타일을 여러 번 만들지 않습니다.

- **아직 구현하지 않은 자리이며 호출해도 아무 일도 하지 않습니다.** Python은 def/class/if 뒤에 빈 본문을 허용하지 않으므로 pass를 넣습니다. pass는 앞으로 완성할 빈 자리이지 기능 구현이 아닙니다. 설계도 작성 단계에서 화면 변화가 없는 것은 정상입니다. 실제 객체를 생성하고 그리기 전에 image/rect 등 필요한 부분을 채우는 순서를 지키세요.

- **발판 구간의 시작 열과 끝 열을 나누어 받습니다.** spans에는 (시작, 끝) 쌍들이 들어 있습니다. 예를 들어 (0,15)는 0열부터 14열까지를 뜻합니다. 한 행에 여러 구간을 넣으면 사이에 빈틈이 생깁니다. 두 값 받기와 바깥 row 반복을 구분하고, 오른쪽 끝 그림은 end 자체가 아닌 end-1열에 놓는 이유를 확인하세요.

```python
# 화면에 그릴 지형 전체입니다.
all_tiles = pygame.sprite.Group()
# 착지 검사에 사용할 발판만 담습니다.
platforms = pygame.sprite.Group()
# 탐사원을 갱신하고 그릴 그룹입니다.
explorers = pygame.sprite.Group()
# 화면에 남아 있는 펄스들을 담습니다.
pulses = pygame.sprite.Group()
# 현재 로봇을 갱신하고 충돌 검사할 그룹입니다.
robots = pygame.sprite.Group()
# 서로 연결할 이동문들을 담습니다.
gates = pygame.sprite.Group()
# 아직 회수되지 않은 신호 결정들을 담습니다.
crystals = pygame.sprite.Group()

# 0 빈칸 / 1 흙 / 2-5 발판 / 6 신호원 / 7-8 게이트 / 9 탐사원
# 각 행을 따로 만들어 칸 변경이 다른 행에 번지지 않게 합니다.
level_map = [[0 for column in range(40)] for row in range(23)]
for row, spans in [(3, [(0, 15), (25, 40)]), (8, [(11, 29)]),
                   (10, [(0, 6), (34, 40)]), (15, [(0, 16), (24, 40)]), (18, [(18, 22)])]:
    # 발판 구간의 시작 열과 끝 열을 나누어 받습니다.
    for start, end in spans:
        # 지도 숫자는 이미지가 아니라 칸의 종류를 나타내는 약속입니다.
        level_map[row][start:end] = [3] + [4] * (end - start - 2) + [5]
# 지도 숫자는 이미지가 아니라 칸의 종류를 나타내는 약속입니다.
level_map[21] = [2] * 40
# 지도 숫자는 이미지가 아니라 칸의 종류를 나타내는 약속입니다.
level_map[22] = [1] * 40
level_map[3][20] = 6
level_map[2][1], level_map[2][38] = 7, 8
level_map[20][1], level_map[20][38] = 8, 7
level_map[17][20] = 9

# 행 번호와 그 행의 칸 목록을 하나씩 꺼냅니다.
for row, cells in enumerate(level_map):
    for column, kind in enumerate(cells):
        # 열은 x좌표, 행은 y좌표로 바꿉니다.
        x, y = column * TILE_SIZE, row * TILE_SIZE
        if kind == 1:
            Terrain(x, y, kind, all_tiles)
        # 2·3·4·5를 모두 발판 종류로 처리합니다.
        elif 2 <= kind <= 5:
            Terrain(x, y, kind, all_tiles, platforms)
        elif kind == 6:
            SignalSource(x, y, all_tiles)
        elif kind in (7, 8):
            Gate(x + TILE_SIZE // 2, y + TILE_SIZE, 'teal' if kind == 7 else 'violet', gates)
        elif kind == 9:
            # 아직 구현하지 않은 자리이며 호출해도 아무 일도 하지 않습니다.
            pass

background = load_image('assets/background.png', (SCREEN_WIDTH, SCREEN_HEIGHT))
mission = Expedition(None, robots, platforms, gates, pulses, crystals)
```

**왜 이렇게 쓰나요 — 이 편집을 읽는 순서**

- **입력과 상태 변화, 그리기를 매 프레임 반복합니다.** 한 프레임은 게임을 한 번 갱신해서 표시하는 주기입니다. 준비 코드·그룹 생성은 while 위에서 한 번만 실행하고, 입력과 이동·그리기는 while 안에서 반복합니다. 물체를 매 프레임 새로 생성하면 위치가 초기화되거나 개수가 계속 늘어납니다. 반복문의 들여쓰기가 게임의 시간 구조를 정합니다.

- **지난 프레임 이후 쌓인 입력 이벤트를 처리합니다.** `event.get()`은 이번에 도착한 사건들을 꺼냅니다. KEYDOWN은 누르기 시작한 사건이고 `key.get_pressed()`는 지금 계속 누르고 있는 상태입니다. 점프·발사 한 번은 이벤트로, 연속 좌우 이동은 누름 상태로 처리하는 이유가 여기에 있습니다. 스튜디오 게임 화면을 클릭해야 입력이 게임으로 전달됩니다.

- **밀리초를 초로 바꾸고 지나치게 긴 프레임을 제한합니다.** `clock.tick(FPS)`는 최대 프레임 속도를 제한하고 경과 밀리초를 줍니다. 16밀리초는 16/1000=0.016초입니다. `min(..., 0.05)`는 긴 탭 전환 시간을 한 번의 큰 이동으로 적용하지 않기 위한 상한입니다. 따라서 오래 다른 탭에 머문 실제 시간과 게임 안 경과 시간이 항상 같지는 않습니다.

- **그룹의 image와 rect를 사용해 화면에 그립니다.** 그룹의 `update()`는 각 객체의 update를 호출하고, `draw(screen)`은 image를 rect 위치에 그립니다. update만 하면 값만 바뀌고, draw만 하면 같은 그림이 같은 위치에 남습니다. 배경 → 물체 → HUD/안내 순서로 그려야 뒤에 그린 배경이 물체를 덮지 않습니다. 마지막 display.update가 그린 화면을 표시합니다.

```python
running = True
# 입력과 상태 변화, 그리기를 매 프레임 반복합니다.
while running:
    # 밀리초를 초로 바꾸고 지나치게 긴 프레임을 제한합니다.
    seconds = min(clock.tick(FPS) / 1000, 0.05)
    # 지난 프레임 이후 쌓인 입력 이벤트를 처리합니다.
    for event in pygame.event.get():
        if event.type == pygame.QUIT:
            running = False
    if not running:
        break
    all_tiles.update(seconds)
    gates.update(seconds)
    screen.blit(background, (0, 0))
    # 그룹의 image와 rect를 사용해 화면에 그립니다.
    all_tiles.draw(screen)
    # 그룹의 image와 rect를 사용해 화면에 그립니다.
    gates.draw(screen)
    mission.draw()
    pygame.display.update()

pygame.quit()
```


### 코드가 하는 일

HUD는 점수0,에너지100,탐사1,남은시간30으로 시작합니다. 탐사원이 아직 없어서 에너지는 임시 숫자100입니다. render는 글자를 Surface로 바꾸고 get_rect의 anchor로 왼쪽·오른쪽 끝을 정렬합니다. 제공 도현체를 명시하여 기기마다 한글 폰트가 달라지는 문제를 줄입니다.

## 17-B - 1초씩 줄어드는 탐사 시간

게임 관리자 update를 루프에 연결합니다.

**이 단계의 연결:** 출발 코드는 **17-A**의 누적 코드입니다. 아래 편집은 위에서부터 모두 적용합니다. 이미 완성한 나머지 메서드는 지정된 교체 범위 밖이면 그대로 둡니다.


### 입력 전에 결과를 예상해 보세요

elapsed=2.7이면 30초 탐사의 남은 표시는 얼마인가요?

먼저 답을 한 문장으로 적고 아래 해설과 비교하세요.

**생각 확인:** int로 지난 정수초 2를 얻어 28초입니다. 표시 숫자와 더 정밀하게 누적되는 elapsed는 다른 값입니다.

### 수정 위치와 입력할 코드

**편집 1.** `class Expedition` 안의 `update` 메서드 전체를 아래 코드로 교체합니다. 다음 `def` 직전까지가 교체 범위입니다. `def` 앞 4칸, 본문 앞 8칸을 유지합니다.

**왜 이렇게 쓰나요 — 이 편집을 읽는 순서**

- **실수 누적 시간에서 화면에 표시할 정수초를 계산합니다.** elapsed가 2.7초, round_duration이 30이면 int(2.7)=2이므로 남은 표시는 28초입니다. max(0, ...)는 0보다 작은 표시를 막습니다. 프레임마다 1씩 빼면 60FPS에서 30초가 아니라 약 0.5초 만에 끝나므로 실제 초 단위 누적을 사용합니다.

```python
    # 그룹에서 호출하는 한 프레임의 처리 순서입니다.
    def update(self, seconds):
        self.elapsed += seconds
        # 실수 누적 시간에서 화면에 표시할 정수초를 계산합니다.
        self.remaining = max(0, self.round_duration - int(self.elapsed + 1e-9))
```

**편집 2.** **수정 위치:** running = True부터 파일 마지막 pygame.quit()까지의 실행 루프 전체. 아래 코드로 교체합니다. 클래스나 메서드 안에 넣지 않습니다.

**왜 이렇게 쓰나요 — 이 편집을 읽는 순서**

- **입력과 상태 변화, 그리기를 매 프레임 반복합니다.** 한 프레임은 게임을 한 번 갱신해서 표시하는 주기입니다. 준비 코드·그룹 생성은 while 위에서 한 번만 실행하고, 입력과 이동·그리기는 while 안에서 반복합니다. 물체를 매 프레임 새로 생성하면 위치가 초기화되거나 개수가 계속 늘어납니다. 반복문의 들여쓰기가 게임의 시간 구조를 정합니다.

- **지난 프레임 이후 쌓인 입력 이벤트를 처리합니다.** `event.get()`은 이번에 도착한 사건들을 꺼냅니다. KEYDOWN은 누르기 시작한 사건이고 `key.get_pressed()`는 지금 계속 누르고 있는 상태입니다. 점프·발사 한 번은 이벤트로, 연속 좌우 이동은 누름 상태로 처리하는 이유가 여기에 있습니다. 스튜디오 게임 화면을 클릭해야 입력이 게임으로 전달됩니다.

- **밀리초를 초로 바꾸고 지나치게 긴 프레임을 제한합니다.** `clock.tick(FPS)`는 최대 프레임 속도를 제한하고 경과 밀리초를 줍니다. 16밀리초는 16/1000=0.016초입니다. `min(..., 0.05)`는 긴 탭 전환 시간을 한 번의 큰 이동으로 적용하지 않기 위한 상한입니다. 따라서 오래 다른 탭에 머문 실제 시간과 게임 안 경과 시간이 항상 같지는 않습니다.

- **그룹의 image와 rect를 사용해 화면에 그립니다.** 그룹의 `update()`는 각 객체의 update를 호출하고, `draw(screen)`은 image를 rect 위치에 그립니다. update만 하면 값만 바뀌고, draw만 하면 같은 그림이 같은 위치에 남습니다. 배경 → 물체 → HUD/안내 순서로 그려야 뒤에 그린 배경이 물체를 덮지 않습니다. 마지막 display.update가 그린 화면을 표시합니다.

```python
running = True
# 입력과 상태 변화, 그리기를 매 프레임 반복합니다.
while running:
    # 밀리초를 초로 바꾸고 지나치게 긴 프레임을 제한합니다.
    seconds = min(clock.tick(FPS) / 1000, 0.05)
    # 지난 프레임 이후 쌓인 입력 이벤트를 처리합니다.
    for event in pygame.event.get():
        if event.type == pygame.QUIT:
            running = False
    if not running:
        break
    all_tiles.update(seconds)
    gates.update(seconds)
    mission.update(seconds)
    screen.blit(background, (0, 0))
    # 그룹의 image와 rect를 사용해 화면에 그립니다.
    all_tiles.draw(screen)
    # 그룹의 image와 rect를 사용해 화면에 그립니다.
    gates.draw(screen)
    mission.draw()
    pygame.display.update()

pygame.quit()
```


### 코드가 하는 일

elapsed에 초 단위 시간을 누적하고 int로 지난 정수초를 구합니다. max(0,...)는 음수 표시를 막습니다. 1e-9는 1초 근처의 실수 오차 때문에30이 한 프레임 더 남는 것을 완화합니다. 프레임 번호를60으로 나누는 대신 실제 프레임 간격을 쓰지만 긴 멈춤은0.05초로 제한합니다.
