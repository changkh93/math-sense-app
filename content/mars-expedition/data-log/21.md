### 수정 위치와 입력할 코드

**편집 1.** `class Explorer` 안의 `animate` 메서드 전체를 아래 코드로 교체합니다. 다음 `def` 직전까지가 교체 범위입니다. `def` 앞 4칸, 본문 앞 8칸을 유지합니다.

**왜 이렇게 쓰나요 — 이 편집을 읽는 순서**

- **시간에 따라 그림 번호를 늘리고 끝에서 처음으로 순환합니다.** frame은 실수여도 리스트 인덱스는 정수여야 하므로 int(frame)을 씁니다. 네 장을 초당 8장 속도로 재생하면 한 바퀴는 4/8=0.5초입니다. frame=3.9에서 0.2를 더하면 4.1이고 %4의 결과 0.1로 돌아갑니다. 움직이는 좌표와 바뀌는 그림 번호는 별도의 값입니다.

```python
    # 표시할 애니메이션 프레임을 선택합니다.
    def animate(self, frames, seconds, speed):
        # 시간에 따라 그림 번호를 늘리고 끝에서 처음으로 순환합니다.
        self.frame = (self.frame + seconds * speed) % len(frames)
        self.image = frames[int(self.frame)]
```

**편집 2.** `class Explorer` 안의 `check_animations` 메서드 전체를 아래 코드로 교체합니다. 다음 `def` 직전까지가 교체 범위입니다. `def` 앞 4칸, 본문 앞 8칸을 유지합니다.

```python
    # 현재 행동이나 상태에 맞는 그림 묶음을 고릅니다.
    def check_animations(self, seconds):
        if self.fire_remaining > 0:
            action = 'fire'
        elif not self.grounded:
            action = 'jump'
        elif abs(self.acceleration.x + self.velocity.x * self.friction) > 0.1:
            action = 'run'
        else:
            action = 'idle'
        if action != self.action:
            self.frame = 0.0
            self.action = action
        self.animate(self.frames[(action, self.facing)], seconds, 8 if action != 'idle' else 4)
```

먼저 발사 중인지, 다음으로 공중인지, 그다음 이동 입력이 있는지 검사합니다. 먼저 참이 된 상태가 우선합니다. action이 바뀔 때만 frame을0으로 돌립니다. 방향은 facing에 따로 저장하므로 키를 놓고 속도가0이 되어도 마지막으로 바라본 쪽을 유지합니다. 초당8프레임의 달리기·점프와4프레임의 대기를 비교합니다.

## 21-B - 펄스 생성과 이동 연결

이번 편집의 목표는 **펄스 생성과 이동 연결**입니다. 아래 수정 위치를 모두 반영한 다음 실행 결과를 확인합니다.

**이 단계의 연결:** 출발 코드는 **21-A**의 누적 코드입니다. 아래 편집은 위에서부터 모두 적용합니다. 이미 완성한 나머지 메서드는 지정된 교체 범위 밖이면 그대로 둡니다.


### 입력 전에 결과를 예상해 보세요

왼쪽 펄스의 x 변화가 음수여도 같은 500픽셀 사거리를 쓰려면 무엇이 필요한가요?

먼저 답을 한 문장으로 적고 아래 해설과 비교하세요.

**생각 확인:** 시작점과 현재점 차이의 절댓값 abs를 사용합니다. 부호가 있는 차이를 그대로 500과 비교하면 왼쪽 발사가 제거되지 않을 수 있습니다.

### 수정 위치와 입력할 코드

**편집 1.** `class Pulse` 안의 `__init__` 메서드 전체를 아래 코드로 교체합니다. 다음 `def` 직전까지가 교체 범위입니다. `def` 앞 4칸, 본문 앞 8칸을 유지합니다.

**왜 이렇게 쓰나요 — 이 편집을 읽는 순서**

- **부모 Sprite의 내부 준비를 먼저 실행합니다.** `super().__init__()`은 상속받은 Sprite 내부를 준비합니다. 괄호 안에 그룹이 있으면 그 그룹에 이 객체를 바로 등록합니다. `super().__init__(tiles)`는 tiles에 자동 등록하지만 인수가 없는 `super().__init__()`은 자동 등록하지 않으므로 나중에 `그룹.add(객체)`가 필요합니다. 이 차이를 확인하고 중복 생성하지 마세요.

- **그림의 크기와 화면 위치를 담을 상자를 만듭니다.** `image`는 그림이고 `rect`는 그 그림을 놓을 사각형입니다. `get_rect(topleft=(x, y))`는 왼쪽 위, `midbottom=(x, y)`는 발 가운데를 해당 위치에 맞춥니다. 예를 들어 64×64 그림의 midbottom이 (100, 200)이면 왼쪽 위는 (68, 136)입니다. 같은 좌표라도 기준점이 다르면 표시 위치가 달라집니다. Group.draw는 각 객체의 image와 rect를 읽습니다.

- **호출 결과를 이 객체의 그림 속성에 보관합니다.** 대입은 오른쪽을 먼저 계산하고 그 결과를 왼쪽 이름에 저장합니다. self.image는 이번 객체가 사용할 그림입니다. load_image가 그림을 반환해야 그다음 get_rect를 호출할 수 있습니다. self.x처럼 self가 붙은 값은 메서드가 끝나도 객체에 남아 다른 메서드에서 사용할 수 있습니다.

- **같은 그림을 좌우로 뒤집어 반대 방향 프레임을 준비합니다.** flip(image, True, False)는 가로 방향만 뒤집습니다. 원래 그림을 지우는 것이 아니라 변환된 Surface를 반환합니다. 리스트 안의 각 프레임에 적용하면 같은 동작의 왼쪽 목록을 만들 수 있습니다. 방향 -1과 1은 인덱스가 아니라 선택용 키로 사용합니다.

```python
    # 객체를 생성할 때 필요한 초기 값과 참조를 준비합니다.
    def __init__(self, x, y, pulses, direction):
        # 부모 Sprite의 내부 준비를 먼저 실행합니다.
        super().__init__(pulses)
        self.speed = 20 * direction
        self.range = 500
        # 호출 결과를 이 객체의 그림 속성에 보관합니다.
        self.image = load_image('assets/pulse.png', (32, 24))
        if direction < 0:
            # 같은 그림을 좌우로 뒤집어 반대 방향 프레임을 준비합니다.
            self.image = pygame.transform.flip(self.image, True, False)
        # 그림의 크기와 화면 위치를 담을 상자를 만듭니다.
        self.rect = self.image.get_rect(center=(x, y))
        self.x = float(x)
        self.start_x = x
```

**편집 2.** `class Pulse` 안의 `update` 메서드 전체를 아래 코드로 교체합니다. 다음 `def` 직전까지가 교체 범위입니다. `def` 앞 4칸, 본문 앞 8칸을 유지합니다.

**왜 이렇게 쓰나요 — 이 편집을 읽는 순서**

- **이 객체를 소속 그룹에서 제거해 갱신과 그리기를 끝냅니다.** kill은 모든 소속 Group에서 Sprite를 제거합니다. 이후 그룹 update/draw와 개수 검사에서 빠집니다. Python 변수까지 모두 지우거나 즉시 메모리를 없애라는 명령은 아닙니다. 화면 이탈·회수·격추 뒤 같은 객체가 다음 프레임에 다시 처리되지 않게 하는 데 사용합니다.

```python
    # 그룹에서 호출하는 한 프레임의 처리 순서입니다.
    def update(self, seconds=1 / FPS):
        self.x += self.speed * min(seconds * FPS, 3)
        self.rect.centerx = round(self.x)
        if abs(self.x - self.start_x) >= self.range:
            # 이 객체를 소속 그룹에서 제거해 갱신과 그리기를 끝냅니다.
            self.kill()
```

**편집 3.** `class Explorer` 안의 `fire` 메서드 전체를 아래 코드로 교체합니다. 다음 `def` 직전까지가 교체 범위입니다. `def` 앞 4칸, 본문 앞 8칸을 유지합니다.

```python
    # 발사 조건을 확인하고 발사체를 생성합니다.
    def fire(self):
        if self.fire_remaining <= 0:
            self.fire_sound.play()
            Pulse(self.rect.centerx, self.rect.centery, self.pulses, self.facing)
            self.fire_remaining = 0.35
            self.frame = 0.0
```

**편집 4.** **수정 위치:** running = True부터 파일 마지막 pygame.quit()까지의 실행 루프 전체. 아래 코드로 교체합니다. 클래스나 메서드 안에 넣지 않습니다.

**왜 이렇게 쓰나요 — 이 편집을 읽는 순서**

- **입력과 상태 변화, 그리기를 매 프레임 반복합니다.** 한 프레임은 게임을 한 번 갱신해서 표시하는 주기입니다. 준비 코드·그룹 생성은 while 위에서 한 번만 실행하고, 입력과 이동·그리기는 while 안에서 반복합니다. 물체를 매 프레임 새로 생성하면 위치가 초기화되거나 개수가 계속 늘어납니다. 반복문의 들여쓰기가 게임의 시간 구조를 정합니다.

- **지난 프레임 이후 쌓인 입력 이벤트를 처리합니다.** `event.get()`은 이번에 도착한 사건들을 꺼냅니다. KEYDOWN은 누르기 시작한 사건이고 `key.get_pressed()`는 지금 계속 누르고 있는 상태입니다. 점프·발사 한 번은 이벤트로, 연속 좌우 이동은 누름 상태로 처리하는 이유가 여기에 있습니다. 스튜디오 게임 화면을 클릭해야 입력이 게임으로 전달됩니다.

- **밀리초를 초로 바꾸고 지나치게 긴 프레임을 제한합니다.** `clock.tick(FPS)`는 최대 프레임 속도를 제한하고 경과 밀리초를 줍니다. 16밀리초는 16/1000=0.016초입니다. `min(..., 0.05)`는 긴 탭 전환 시간을 한 번의 큰 이동으로 적용하지 않기 위한 상한입니다. 따라서 오래 다른 탭에 머문 실제 시간과 게임 안 경과 시간이 항상 같지는 않습니다.

- **그룹의 image와 rect를 사용해 화면에 그립니다.** 그룹의 `update()`는 각 객체의 update를 호출하고, `draw(screen)`은 image를 rect 위치에 그립니다. update만 하면 값만 바뀌고, draw만 하면 같은 그림이 같은 위치에 남습니다. 배경 → 물체 → HUD/안내 순서로 그려야 뒤에 그린 배경이 물체를 덮지 않습니다. 마지막 display.update가 그린 화면을 표시합니다.

```python
running = True
# 입력과 상태 변화, 그리기를 매 프레임 반복합니다.
while running:
    # 밀리초를 초로 바꾸고 지나치게 긴 프레임을 제한합니다.
    seconds = min(clock.tick(FPS) / 1000, 0.05)
    # 지난 프레임 이후 쌓인 입력 이벤트를 처리합니다.
    for event in pygame.event.get():
        if event.type == pygame.QUIT:
            running = False
        elif event.type == pygame.KEYDOWN:
            if event.key == pygame.K_SPACE:
                explorer.jump()
            elif event.key == pygame.K_UP:
                explorer.fire()
    if not running:
        break
    all_tiles.update(seconds)
    gates.update(seconds)
    explorers.update(seconds)
    pulses.update(seconds)
    mission.update(seconds)
    screen.blit(background, (0, 0))
    # 그룹의 image와 rect를 사용해 화면에 그립니다.
    all_tiles.draw(screen)
    # 그룹의 image와 rect를 사용해 화면에 그립니다.
    gates.draw(screen)
    # 그룹의 image와 rect를 사용해 화면에 그립니다.
    explorers.draw(screen)
    # 그룹의 image와 rect를 사용해 화면에 그립니다.
    pulses.draw(screen)
    mission.draw()
    pygame.display.update()

pygame.quit()
```


### 코드가 하는 일

`Pulse` 생성자는 `pulses` 그룹에 직접 등록합니다. `direction`이 -1이면 속도가 -20이고 그림도 뒤집습니다. 시작 x와 현재 x의 차이에 `abs`를 써서 왼쪽 발사에도 같은 사거리를 적용합니다. `kill`은 등록된 그룹에서 자신을 제거합니다. `fire_remaining = 0.35`는 연속 입력을 제한하고 발사 그림을 보여주는 시간입니다. `KEYDOWN`으로 연결했으므로 한 번 누를 때 한 번 발사를 시도합니다.

### 여기서 실행하세요

오른쪽을 보고 위쪽키, 왼쪽을 보고 위쪽키를 누릅니다. 펄스가 양방향으로 날아가다가 사라지고, 발사 자세와 소리가 나와야 합니다. 빠르게 반복해도 0.35초보다 촘촘하게 나오지 않습니다.

**이 시점의 정상 상태:** 아직 맞을 로봇이 없어 펄스는 공간을 그대로 통과합니다.

**예상과 다를 때:** 화면에 계속 남으면 update와 range 조건을 확인합니다. 왼쪽 발사가 사라지지 않으면 abs가 필요합니다.
