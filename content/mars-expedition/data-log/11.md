기초 실험과 에셋 점검을 마쳤으므로 본 게임 main.py의 골격을 새로 시작합니다.

**이 단계의 연결:** 10-A의 에셋 확인 코드를 준비 구간/실행 루프로 교체하며 본 게임을 시작합니다. 아래 편집은 위에서부터 모두 적용합니다. 이미 완성한 나머지 메서드는 지정된 교체 범위 밖이면 그대로 둡니다.


### 입력 전에 결과를 예상해 보세요

1280×736 화면과 32픽셀 타일이면 가로·세로 칸 수는 얼마인가요?

### 수정 위치와 입력할 코드

**편집 1.** **수정 위치:** 파일 맨 위에서 준비 함수 또는 첫 class가 나오기 전까지의 준비 구간(별도 함수·클래스가 없으면 running = True 바로 위까지). 아래 코드로 교체합니다. 클래스나 메서드 안에 넣지 않습니다.

**왜 이렇게 쓰나요 — 이 편집을 읽는 순서**

- **게임 화면·입력·소리를 다루는 도구를 불러옵니다.** pygame은 게임용 기능을 모아 둔 모듈입니다. `import`는 도구를 쓸 수 있게 하는 준비이고, 화면을 만드는 명령 자체는 아닙니다. 따라서 import만 실행해도 우주선이나 창이 생기지 않습니다.

- **화면과 소리 모듈을 사용하기 전에 초기화합니다.** `pygame.init()`은 여러 Pygame 모듈의 준비를 수행합니다. 함수를 쓰려면 이름 뒤에 `()`를 붙여 호출해야 합니다. 함수 이름만 적으면 그 기능을 실행한 것이 아닙니다.

- **화면은 한 번 만들고, 반복문 안에서 내용을 갱신합니다.** `set_mode((가로, 세로))`는 그림을 그릴 Surface를 반환합니다. `screen = ...`은 그 결과를 screen에 보관한다는 뜻입니다. 좌표의 원점은 왼쪽 위이며 x는 오른쪽, y는 아래쪽으로 커집니다. 화면 크기의 튜플과 개별 물체의 위치 튜플을 구별하세요.

```python
import random
# 게임 화면·입력·소리를 다루는 도구를 불러옵니다.
import pygame

# 화면과 소리 모듈을 사용하기 전에 초기화합니다.
pygame.init()
Vector = pygame.math.Vector2
SCREEN_WIDTH, SCREEN_HEIGHT = 1280, 736
TILE_SIZE = 32
FPS = 60
# 화면은 한 번 만들고, 반복문 안에서 내용을 갱신합니다.
screen = pygame.display.set_mode((SCREEN_WIDTH, SCREEN_HEIGHT))
pygame.display.set_caption('화성 탐사대: 신호 복구')
clock = pygame.time.Clock()
```

**편집 3.** 기존 클래스 정의 구간 전체를 삭제합니다. 새 빈 프로젝트여서 해당 구간이 없으면 추가하지 않고 넘어갑니다. 이 단계에서는 빈 구간으로 남깁니다.

**편집 4.** 기존 그룹·지도·객체 준비 구간 전체를 삭제합니다. 새 빈 프로젝트여서 해당 구간이 없으면 추가하지 않고 넘어갑니다. 이 단계에서는 빈 구간으로 남깁니다.

**편집 5.** **수정 위치:** running = True부터 파일 마지막 pygame.quit()까지의 실행 루프 전체. 아래 코드로 교체합니다. 클래스나 메서드 안에 넣지 않습니다.

**왜 이렇게 쓰나요 — 이 편집을 읽는 순서**

- **입력과 상태 변화, 그리기를 매 프레임 반복합니다.** 한 프레임은 게임을 한 번 갱신해서 표시하는 주기입니다. 준비 코드·그룹 생성은 while 위에서 한 번만 실행하고, 입력과 이동·그리기는 while 안에서 반복합니다. 물체를 매 프레임 새로 생성하면 위치가 초기화되거나 개수가 계속 늘어납니다. 반복문의 들여쓰기가 게임의 시간 구조를 정합니다.

- **지난 프레임 이후 쌓인 입력 이벤트를 처리합니다.** `event.get()`은 이번에 도착한 사건들을 꺼냅니다. KEYDOWN은 누르기 시작한 사건이고 `key.get_pressed()`는 지금 계속 누르고 있는 상태입니다. 점프·발사 한 번은 이벤트로, 연속 좌우 이동은 누름 상태로 처리하는 이유가 여기에 있습니다. 스튜디오 게임 화면을 클릭해야 입력이 게임으로 전달됩니다.

- **밀리초를 초로 바꾸고 지나치게 긴 프레임을 제한합니다.** `clock.tick(FPS)`는 최대 프레임 속도를 제한하고 경과 밀리초를 줍니다. 16밀리초는 16/1000=0.016초입니다. `min(..., 0.05)`는 긴 탭 전환 시간을 한 번의 큰 이동으로 적용하지 않기 위한 상한입니다. 따라서 오래 다른 탭에 머문 실제 시간과 게임 안 경과 시간이 항상 같지는 않습니다.

```python
running = True
# 입력과 상태 변화, 그리기를 매 프레임 반복합니다.
while running:
    # 밀리초를 초로 바꾸고 지나치게 긴 프레임을 제한합니다.
    seconds = min(clock.tick(FPS) / 1000, 0.05)
    # 지난 프레임 이후 쌓인 입력 이벤트를 처리합니다.
    for event in pygame.event.get():
        if event.type == pygame.QUIT:
            running = False
    if not running:
        break
    screen.fill((15, 25, 42))
    pygame.display.update()

pygame.quit()
```

## 11-B - 배경을 맞추고 두 설계도 선언하기

배경을 화면 크기로 맞춘 다음 게임 관리자와 타일의 이름을 먼저 정합니다.

**이 단계의 연결:** 출발 코드는 **11-A**의 누적 코드입니다. 아래 편집은 위에서부터 모두 적용합니다. 이미 완성한 나머지 메서드는 지정된 교체 범위 밖이면 그대로 둡니다.


### 입력 전에 결과를 예상해 보세요

빈 Expedition과 Terrain을 선언해도 배경이 정상 표시되는 이유는 무엇인가요?

먼저 답을 한 문장으로 적고 아래 해설과 비교하세요.

**생각 확인:** 클래스 선언이 배경 그리기와 독립적이고 아직 빈 생성자로 객체를 만들어 그리지 않기 때문입니다. 배경 표시 성공과 객체 구현 완료를 구분합니다.

### 수정 위치와 입력할 코드

**편집 1.** **수정 위치:** clock 아래에서 첫 class 위까지의 그림·소리 준비 함수 구간. 아래 코드로 추가합니다. 클래스나 메서드 안에 넣지 않습니다.

**왜 이렇게 쓰나요 — 이 편집을 읽는 순서**

- **파일 경로와 요청 크기를 묶어 캐시의 열쇠로 씁니다.** 캐시는 이미 준비한 결과를 다시 쓰는 보관함입니다. `image_cache = {}`는 빈 딕셔너리이고, `(path, size)`는 경로와 크기를 묶은 튜플입니다. 같은 파일도 32×32와 64×64로 요청하면 서로 다른 결과가 필요하므로 두 값을 함께 열쇠로 씁니다. 첫 호출에는 저장하고, 다음 같은 요청에는 저장한 그림을 돌려줍니다. 캐시는 그림만 공유하며 각 타일의 위치는 별도 rect에 저장합니다.

- **처음 요청한 그림만 읽고 크기를 맞춥니다.** `key not in image_cache`는 그 열쇠로 저장한 결과가 아직 없는지 묻습니다. 처음에는 참이어서 if 안을 실행하고, 같은 요청의 두 번째 호출에는 거짓이어서 건너뜁니다. 아래 `return image_cache[key]`는 if 바깥이므로 처음 요청과 재요청 모두 그림을 받습니다. return을 if 안에 넣으면 두 번째 호출은 그림 대신 None을 돌려주는 오류가 생깁니다.

- **PNG의 투명한 여백을 유지합니다.** `image.load`로 읽은 Surface를 `convert_alpha()`로 투명도를 유지하는 표시 형식으로 바꿉니다. 투명한 여백까지 배경색 사각형으로 그리지 않기 위한 준비입니다. `smoothscale(그림, (가로, 세로))`은 그다음 표시 크기를 맞춥니다. 여러 함수가 한 줄에 겹쳐 있으면 가장 안쪽 호출부터 읽으세요.

- **매개변수로 요청을 받고 return으로 결과를 돌려주는 함수입니다.** def는 함수 정의입니다. load_image에 넘긴 첫 값은 path, 두 번째 값은 size가 됩니다. 예를 들어 load_image("assets/tiles/2.png", (32,32))를 호출하면 해당 경로와 크기로 함수 본문이 실행되고 return한 그림이 호출한 자리의 결과가 됩니다. 정의 자체는 본문을 바로 실행하지 않습니다. 함수 안의 key는 이 호출에서 만드는 지역 이름이고 image_cache는 함수 밖에서 준비한 공용 딕셔너리입니다.

- **문자열 안에 현재 종류나 번호를 넣어 에셋 경로를 만듭니다.** 문자열 앞 f는 중괄호 안의 값을 글자로 끼워 넣습니다. kind가 2이면 f'assets/tiles/{kind}.png'는 assets/tiles/2.png가 됩니다. 파일명을 직접 여섯 번 쓰는 대신 같은 생성자를 다른 kind로 호출할 수 있습니다. 중괄호 안의 변수는 이 호출에서 먼저 값을 받아야 합니다.

- **소리 파일을 준비하는 일과 재생하는 일을 구분합니다.** Sound 또는 load_sound는 소리를 사용할 준비입니다. .play()를 호출하는 순간 재생을 시도합니다. 생성자에서 준비하고 실제 발사·충돌 사건에서 재생해야 매 프레임 파일을 읽거나 준비만 했는데 소리가 날 것으로 기대하지 않습니다.

```python
# 같은 그림과 소리는 한 번만 읽고, 위치와 게임 상태는 객체마다 보관합니다.
image_cache = {}
sound_cache = {}


# 그림을 준비하고 같은 요청에는 저장한 그림을 재사용합니다.
def load_image(path, size):
    # 파일 경로와 요청 크기를 묶어 캐시의 열쇠로 씁니다.
    key = (path, size)
    # 처음 요청한 그림만 읽고 크기를 맞춥니다.
    if key not in image_cache:
        # PNG의 투명한 여백을 유지합니다.
        original = pygame.image.load(path).convert_alpha()
        image_cache[key] = pygame.transform.smoothscale(original, size)
    return image_cache[key]


# 번호순 이미지들을 애니메이션 목록으로 준비합니다.
def load_frames(folder, size=(64, 64)):
    # 문자열 안에 현재 종류나 번호를 넣어 에셋 경로를 만듭니다.
    return [load_image(f'assets/{folder}/{index}.png', size) for index in range(4)]


# 효과음을 준비하고 재사용합니다.
def load_sound(name):
    if name not in sound_cache:
        # 문자열 안에 현재 종류나 번호를 넣어 에셋 경로를 만듭니다.
        sound_cache[name] = pygame.mixer.Sound(f'assets/sounds/{name}.ogg')
    return sound_cache[name]
```

**편집 2.** 준비 함수 아래, 그룹과 지도 코드 위의 **클래스 정의 구간 전체**를 아래로 추가합니다.

- **역할이 같은 객체를 만드는 설계도입니다.** `class`는 설계도이고 `Terrain(...)`이나 `Scout(...)` 같은 호출이 실제 객체를 만드는 순간입니다. 클래스 정의만으로 화면에 나타나지 않습니다. `__init__`은 생성할 때 초기 값을 준비하고, `self`는 지금 준비 중인 바로 그 객체를 뜻합니다. 서로 다른 두 객체는 같은 메서드를 사용하지만 위치·속도 같은 값은 각각 가질 수 있습니다.

**왜 이렇게 쓰나요 — 이 편집을 읽는 순서**

- **입력과 상태 변화, 그리기를 매 프레임 반복합니다.** 한 프레임은 게임을 한 번 갱신해서 표시하는 주기입니다. 준비 코드·그룹 생성은 while 위에서 한 번만 실행하고, 입력과 이동·그리기는 while 안에서 반복합니다. 물체를 매 프레임 새로 생성하면 위치가 초기화되거나 개수가 계속 늘어납니다. 반복문의 들여쓰기가 게임의 시간 구조를 정합니다.

- **지난 프레임 이후 쌓인 입력 이벤트를 처리합니다.** `event.get()`은 이번에 도착한 사건들을 꺼냅니다. KEYDOWN은 누르기 시작한 사건이고 `key.get_pressed()`는 지금 계속 누르고 있는 상태입니다. 점프·발사 한 번은 이벤트로, 연속 좌우 이동은 누름 상태로 처리하는 이유가 여기에 있습니다. 스튜디오 게임 화면을 클릭해야 입력이 게임으로 전달됩니다.

- **밀리초를 초로 바꾸고 지나치게 긴 프레임을 제한합니다.** `clock.tick(FPS)`는 최대 프레임 속도를 제한하고 경과 밀리초를 줍니다. 16밀리초는 16/1000=0.016초입니다. `min(..., 0.05)`는 긴 탭 전환 시간을 한 번의 큰 이동으로 적용하지 않기 위한 상한입니다. 따라서 오래 다른 탭에 머문 실제 시간과 게임 안 경과 시간이 항상 같지는 않습니다.

```python
running = True
# 입력과 상태 변화, 그리기를 매 프레임 반복합니다.
while running:
    # 밀리초를 초로 바꾸고 지나치게 긴 프레임을 제한합니다.
    seconds = min(clock.tick(FPS) / 1000, 0.05)
    # 지난 프레임 이후 쌓인 입력 이벤트를 처리합니다.
    for event in pygame.event.get():
        if event.type == pygame.QUIT:
            running = False
    if not running:
        break
    screen.blit(background, (0, 0))
    pygame.display.update()

pygame.quit()
```
