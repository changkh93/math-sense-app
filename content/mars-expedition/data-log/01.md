## 코드를 읽고 작성하는 방법

코드 안의 `#` 뒤 문장은 **이해를 돕는 설명용 주석**입니다. 주석은 따라 적지 않아도 게임이 똑같이 실행됩니다. 먼저 주석을 읽고 그 아래 코드의 목적을 이해한 뒤, 실행되는 코드와 들여쓰기를 작성하세요. 따옴표 안의 글자, 변수 이름, 괄호와 콜론은 주석이 아니므로 생략하면 안 됩니다. 누적 코드에는 길 찾기에 필요한 핵심 주석만 남겼습니다.

각 편집의 ‘왜 이렇게 쓰나요’를 읽고, 입력하기 전에 결과를 예상해 보세요. 이번 단계의 편집을 모두 마친 다음 실행합니다. 중간에 아직 정의하지 않은 이름을 참조할 수 있으므로 편집 하나마다 실행하지 않습니다. 실행 후에는 화면이 맞는지만 보지 말고, **어떤 값이 바뀌어 그 결과가 생겼는지** 한 문장으로 설명해 보세요. 누적 코드는 먼저 직접 시도한 뒤 비교·복구할 때 사용합니다.

## 01-A - 화면을 먼저 열기

지도를 입력하기 전에 실행과 정지가 되는 빈 화면을 만듭니다.

**이 단계의 연결:** 빈 main.py에서 시작합니다. 아래 편집은 위에서부터 모두 적용합니다. 이미 완성한 나머지 메서드는 지정된 교체 범위 밖이면 그대로 둡니다.


### 입력 전에 결과를 예상해 보세요

게임 시간 seconds를 1000으로 나누는 이유를 20밀리초로 설명하세요.

먼저 답을 한 문장으로 적고 아래 해설과 비교하세요.

**생각 확인:** 20밀리초는 0.02초입니다. 밀리초 값을 그대로 초 단위 계산에 쓰면 이동과 시간이 1000배 어긋납니다. 지금은 값을 준비만 하고 이후 움직임에서 사용합니다.

### 수정 위치와 입력할 코드

**편집 1.** **수정 위치:** 파일 맨 위에서 준비 함수 또는 첫 class가 나오기 전까지의 준비 구간(별도 함수·클래스가 없으면 running = True 바로 위까지). 아래 코드로 추가합니다. 클래스나 메서드 안에 넣지 않습니다.

**왜 이렇게 쓰나요 — 이 편집을 읽는 순서**

- **게임 화면·입력·소리를 다루는 도구를 불러옵니다.** pygame은 게임용 기능을 모아 둔 모듈입니다. `import`는 도구를 쓸 수 있게 하는 준비이고, 화면을 만드는 명령 자체는 아닙니다. 따라서 import만 실행해도 우주선이나 창이 생기지 않습니다.

- **화면과 소리 모듈을 사용하기 전에 초기화합니다.** `pygame.init()`은 여러 Pygame 모듈의 준비를 수행합니다. 함수를 쓰려면 이름 뒤에 `()`를 붙여 호출해야 합니다. 함수 이름만 적으면 그 기능을 실행한 것이 아닙니다.

- **화면은 한 번 만들고, 반복문 안에서 내용을 갱신합니다.** `set_mode((가로, 세로))`는 그림을 그릴 Surface를 반환합니다. `screen = ...`은 그 결과를 screen에 보관한다는 뜻입니다. 좌표의 원점은 왼쪽 위이며 x는 오른쪽, y는 아래쪽으로 커집니다. 화면 크기의 튜플과 개별 물체의 위치 튜플을 구별하세요.

```python
# 게임 화면·입력·소리를 다루는 도구를 불러옵니다.
import pygame

# 화면과 소리 모듈을 사용하기 전에 초기화합니다.
pygame.init()
SCREEN_WIDTH, SCREEN_HEIGHT = 960, 640
TILE_SIZE = 32
FPS = 60
# 화면은 한 번 만들고, 반복문 안에서 내용을 갱신합니다.
screen = pygame.display.set_mode((SCREEN_WIDTH, SCREEN_HEIGHT))
pygame.display.set_caption('화성 탐사대 - 기초 실험')
clock = pygame.time.Clock()
```

**편집 2.** **수정 위치:** running = True부터 파일 마지막 pygame.quit()까지의 실행 루프 전체. 아래 코드로 추가합니다. 클래스나 메서드 안에 넣지 않습니다.

**왜 이렇게 쓰나요 — 이 편집을 읽는 순서**

- **입력과 상태 변화, 그리기를 매 프레임 반복합니다.** 한 프레임은 게임을 한 번 갱신해서 표시하는 주기입니다. 준비 코드·그룹 생성은 while 위에서 한 번만 실행하고, 입력과 이동·그리기는 while 안에서 반복합니다. 물체를 매 프레임 새로 생성하면 위치가 초기화되거나 개수가 계속 늘어납니다. 반복문의 들여쓰기가 게임의 시간 구조를 정합니다.

- **지난 프레임 이후 쌓인 입력 이벤트를 처리합니다.** `event.get()`은 이번에 도착한 사건들을 꺼냅니다. KEYDOWN은 누르기 시작한 사건이고 `key.get_pressed()`는 지금 계속 누르고 있는 상태입니다. 점프·발사 한 번은 이벤트로, 연속 좌우 이동은 누름 상태로 처리하는 이유가 여기에 있습니다. 스튜디오 게임 화면을 클릭해야 입력이 게임으로 전달됩니다.

- **밀리초를 초로 바꾸고 지나치게 긴 프레임을 제한합니다.** `clock.tick(FPS)`는 최대 프레임 속도를 제한하고 경과 밀리초를 줍니다. 16밀리초는 16/1000=0.016초입니다. `min(..., 0.05)`는 긴 탭 전환 시간을 한 번의 큰 이동으로 적용하지 않기 위한 상한입니다. 따라서 오래 다른 탭에 머문 실제 시간과 게임 안 경과 시간이 항상 같지는 않습니다.

```python
running = True
# 입력과 상태 변화, 그리기를 매 프레임 반복합니다.
while running:
    # 밀리초를 초로 바꾸고 지나치게 긴 프레임을 제한합니다.
    seconds = min(clock.tick(FPS) / 1000, 0.05)
    # 지난 프레임 이후 쌓인 입력 이벤트를 처리합니다.
    for event in pygame.event.get():
        if event.type == pygame.QUIT:
            running = False
    if not running:
        break
    screen.fill((15, 25, 42))
    pygame.display.update()

pygame.quit()
```


### 코드가 하는 일

set_mode는 (가로, 세로) 튜플을 받습니다. 왼쪽 위가 (0,0)이고 아래로 y가 증가합니다. QUIT은 종료 요청이며 running=False 뒤 break로 더 그리지 않습니다. tick(60)은 최대60FPS로 제한하고 경과 밀리초를 반환합니다. 1000으로 나눈 seconds는 초 단위이며 지금은 보관만 합니다. min(...,0.05)는 탭 전환 뒤 한 프레임의 시간이 지나치게 커지는 것을 막습니다.

### 여기서 실행하세요

실행하면 960×640의 남색 화면이 유지됩니다. 스튜디오 정지 버튼으로 종료한 뒤 다시 실행해 보세요.

**이 시점의 정상 상태:** 탐사원, 발판, 배경 그림, 소리가 없어도 정상입니다.

**예상과 다를 때:** while 안에는 4칸, for 안에는 8칸, if 본문에는 12칸입니다. pygame.quit()을 while 안으로 들여쓰지 않습니다.

## 01-B - 20행 30열의 빈 지도

960÷32=30, 640÷32=20입니다. 가로 개수와 세로 개수를 구별합니다.

**이 단계의 연결:** 출발 코드는 **01-A**의 누적 코드입니다. 아래 편집은 위에서부터 모두 적용합니다. 이미 완성한 나머지 메서드는 지정된 교체 범위 밖이면 그대로 둡니다.


### 입력 전에 결과를 예상해 보세요

level_map[2][3]은 몇 번째 행과 열인가요?

먼저 답을 한 문장으로 적고 아래 해설과 비교하세요.

**생각 확인:** 인덱스가 0부터이므로 세 번째 행, 네 번째 열입니다. 바깥 리스트가 행, 안쪽 리스트가 열입니다. 아직 지도 숫자를 그리는 코드가 없어 화면 변화는 없습니다.

### 수정 위치와 입력할 코드

**편집 1.** **수정 위치:** 마지막 클래스 아래에서 running = True 위까지의 그룹·지도·객체 준비 구간. 아래 코드로 추가합니다. 클래스나 메서드 안에 넣지 않습니다.

**왜 이렇게 쓰나요 — 이 편집을 읽는 순서**

- **각 행을 따로 만들어 칸 변경이 다른 행에 번지지 않게 합니다.** 지도는 행을 담은 바깥 리스트와 각 행의 칸을 담은 안쪽 리스트입니다. 안쪽 반복이 한 행을 만들고 바깥 반복이 새 행을 여러 번 만듭니다. `level_map[2][3]`은 세 번째 행, 네 번째 열입니다. `[[0] * 30] * 20`은 같은 행을 공유하므로 한 칸 수정이 다른 행에도 나타날 수 있습니다. 이 수업의 중첩 리스트 생성식을 그대로 구분해 읽으세요.

```python
# 각 행을 따로 만들어 칸 변경이 다른 행에 번지지 않게 합니다.
level_map = [[0 for column in range(30)] for row in range(20)]
```


### 코드가 하는 일

바깥 리스트의 원소 하나가 한 행입니다. 안쪽 range(30)은 열30개, 바깥 range(20)은 서로 다른 행20개를 만듭니다. 0은 빈칸이라는 약속입니다. [[0]*30]*20은 같은 행을20번 참조하므로 한 칸 변경이 여러 행에 번질 수 있어 쓰지 않습니다.

### 여기서 실행하세요

실행 화면이 그대로인지 확인합니다. 아직 숫자를 그림으로 바꾸는 코드가 없습니다.

**이 시점의 정상 상태:** 변수가 만들어져도 자동으로 화면에 그려지지는 않습니다.

**예상과 다를 때:** 대괄호 두 겹과 for 순서를 확인합니다. 행20개 안에 각 열30개가 있어야 합니다.

## 01-C - 흙과 발판, 위험 구역 배치

아래 두 줄을 땅으로 채우고 높이가 다른 세 발판을 만듭니다.

**이 단계의 연결:** 출발 코드는 **01-B**의 누적 코드입니다. 아래 편집은 위에서부터 모두 적용합니다. 이미 완성한 나머지 메서드는 지정된 교체 범위 밖이면 그대로 둡니다.


### 입력 전에 결과를 예상해 보세요

[4:12]에 [3]+[4]*6+[5]를 넣을 때 양쪽 길이는 같은가요?

먼저 답을 한 문장으로 적고 아래 해설과 비교하세요.

**생각 확인:** 12-4=8칸이며 1+6+1=8개이므로 같습니다. 길이가 다르면 그 행의 열 수가 바뀌어 이후 배치가 밀릴 수 있습니다.

### 수정 위치와 입력할 코드

**편집 1.** **수정 위치:** 마지막 클래스 아래에서 running = True 위까지의 그룹·지도·객체 준비 구간. 아래 코드로 교체합니다. 클래스나 메서드 안에 넣지 않습니다.

**왜 이렇게 쓰나요 — 이 편집을 읽는 순서**

- **각 행을 따로 만들어 칸 변경이 다른 행에 번지지 않게 합니다.** 지도는 행을 담은 바깥 리스트와 각 행의 칸을 담은 안쪽 리스트입니다. 안쪽 반복이 한 행을 만들고 바깥 반복이 새 행을 여러 번 만듭니다. `level_map[2][3]`은 세 번째 행, 네 번째 열입니다. `[[0] * 30] * 20`은 같은 행을 공유하므로 한 칸 수정이 다른 행에도 나타날 수 있습니다. 이 수업의 중첩 리스트 생성식을 그대로 구분해 읽으세요.

- **지도 숫자는 이미지가 아니라 칸의 종류를 나타내는 약속입니다.** `[2] * 10`은 숫자 2를 열 번 담은 리스트이고 `+`는 리스트들을 이어 붙입니다. `[4:12]`는 4열부터 11열까지 8칸이며 끝값 12는 포함하지 않습니다. 같은 길이의 리스트로 교체해야 행의 열 수가 바뀌지 않습니다. 숫자와 실제 그림의 연결은 아래 지도 해석 반복문에서 이루어집니다.

```python
# 각 행을 따로 만들어 칸 변경이 다른 행에 번지지 않게 합니다.
level_map = [[0 for column in range(30)] for row in range(20)]
# 지도 숫자는 이미지가 아니라 칸의 종류를 나타내는 약속입니다.
level_map[19] = [1] * 30
# 지도 숫자는 이미지가 아니라 칸의 종류를 나타내는 약속입니다.
level_map[18] = [2] * 10 + [6] * 10 + [2] * 10
# 지도 숫자는 이미지가 아니라 칸의 종류를 나타내는 약속입니다.
level_map[14][4:12] = [3] + [4] * 6 + [5]
# 지도 숫자는 이미지가 아니라 칸의 종류를 나타내는 약속입니다.
level_map[10][14:22] = [3] + [4] * 6 + [5]
# 지도 숫자는 이미지가 아니라 칸의 종류를 나타내는 약속입니다.
level_map[6][5:13] = [3] + [4] * 6 + [5]
```


### 코드가 하는 일

1은 흙,2~5는 발판,6은 지열 위험 구역입니다. [2]*10은 2를 10번 반복합니다. [4:12]는4~11열, 총8칸입니다. 왼쪽 끝3, 가운데4, 오른쪽 끝5를 넣습니다. [19]는20번째 행입니다. 기초 실험에서 위험 구역을 넣어 복귀 동작을 배우고, 본 게임에서는 바닥을 모두 연결합니다.

### 여기서 실행하세요

실행 화면은 여전히 남색입니다. 숫자를 읽어 만든 타일은 다음 단원에서 나타납니다.

**이 시점의 정상 상태:** 지도 입력이 끝나도 그림이 없는 것이 이번 단원의 정확한 완료 상태입니다.

**예상과 다를 때:** 슬라이스에 넣는 원소 수가 범위와 다르면 행 길이가 달라집니다. [3]+[4]*6+[5]는8개인지 계산하세요.
