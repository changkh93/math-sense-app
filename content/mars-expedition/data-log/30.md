**편집 2.** `class Expedition` 안의 `update` 메서드 전체를 아래 코드로 교체합니다. 다음 `def` 직전까지가 교체 범위입니다. `def` 앞 4칸, 본문 앞 8칸을 유지합니다.

**왜 이렇게 쓰나요 — 이 편집을 읽는 순서**

- **실수 누적 시간에서 화면에 표시할 정수초를 계산합니다.** elapsed가 2.7초, round_duration이 30이면 int(2.7)=2이므로 남은 표시는 28초입니다. max(0, ...)는 0보다 작은 표시를 막습니다. 프레임마다 1씩 빼면 60FPS에서 30초가 아니라 약 0.5초 만에 끝나므로 실제 초 단위 누적을 사용합니다.

- **대기나 종료 상태이면 게임 규칙 갱신을 멈춥니다.** 상태는 지금 허용되는 동작을 정하는 문자열입니다. playing에서만 이동·충돌·시간을 진행하고, 대기 중에도 이벤트와 그리기는 유지합니다. 처리 도중 피격으로 상태가 바뀔 수 있어 다음 처리 전에 다시 검사합니다. return은 현재 메서드만 끝내며 게임 전체를 종료하지 않습니다.

```python
    # 그룹에서 호출하는 한 프레임의 처리 순서입니다.
    def update(self, seconds):
        # 대기나 종료 상태이면 게임 규칙 갱신을 멈춥니다.
        if self.state != 'playing':
            return
        self.check_collisions()
        self.check_game_over()
        # 대기나 종료 상태이면 게임 규칙 갱신을 멈춥니다.
        if self.state != 'playing':
            return
        self.elapsed += seconds
        # 실수 누적 시간에서 화면에 표시할 정수초를 계산합니다.
        self.remaining = max(0, self.round_duration - int(self.elapsed + 1e-9))
        self.check_round_completion()
        # 대기나 종료 상태이면 게임 규칙 갱신을 멈춥니다.
        if self.state != 'playing':
            return
        self.add_robot(seconds)
```

**편집 4.** `class Expedition` 안의 `reset_game` 메서드 전체를 아래 코드로 교체합니다. 다음 `def` 직전까지가 교체 범위입니다. `def` 앞 4칸, 본문 앞 8칸을 유지합니다.

**왜 이렇게 쓰나요 — 이 편집을 읽는 순서**

- **이 그룹의 현재 객체들을 정리합니다.** empty는 해당 Group의 구성원을 모두 빼는 동작입니다. 점수나 생명 같은 별도 변수까지 초기화하지 않습니다. 다음 라운드와 새 게임에서 무엇을 유지하고 무엇을 지울지 각각 결정해야 합니다. 함수 이름이 reset이라고 해서 모든 값이 자동 복구되는 것은 아닙니다.

```python
    # 종료 또는 재시작에 필요한 게임 상태를 처리합니다.
    def reset_game(self):
        self.score = 0
        self.round_number = 1
        self.remaining = self.round_duration
        self.spawn_interval = self.initial_spawn_interval
        self.elapsed = 0.0
        self.spawn_elapsed = 0.0
        self.explorer.health = self.explorer.starting_health
        self.explorer.reset()
        # 이 그룹의 현재 객체들을 정리합니다.
        self.robots.empty()
        # 이 그룹의 현재 객체들을 정리합니다.
        self.pulses.empty()
        # 이 그룹의 현재 객체들을 정리합니다.
        self.crystals.empty()
        self.state = 'playing'
        pygame.mixer.music.play(-1)
```

**편집 5.** **수정 위치:** running = True부터 파일 마지막 pygame.quit()까지의 실행 루프 전체. 아래 코드로 교체합니다. 클래스나 메서드 안에 넣지 않습니다.

**왜 이렇게 쓰나요 — 이 편집을 읽는 순서**

- **입력과 상태 변화, 그리기를 매 프레임 반복합니다.** 한 프레임은 게임을 한 번 갱신해서 표시하는 주기입니다. 준비 코드·그룹 생성은 while 위에서 한 번만 실행하고, 입력과 이동·그리기는 while 안에서 반복합니다. 물체를 매 프레임 새로 생성하면 위치가 초기화되거나 개수가 계속 늘어납니다. 반복문의 들여쓰기가 게임의 시간 구조를 정합니다.

- **지난 프레임 이후 쌓인 입력 이벤트를 처리합니다.** `event.get()`은 이번에 도착한 사건들을 꺼냅니다. KEYDOWN은 누르기 시작한 사건이고 `key.get_pressed()`는 지금 계속 누르고 있는 상태입니다. 점프·발사 한 번은 이벤트로, 연속 좌우 이동은 누름 상태로 처리하는 이유가 여기에 있습니다. 스튜디오 게임 화면을 클릭해야 입력이 게임으로 전달됩니다.

- **밀리초를 초로 바꾸고 지나치게 긴 프레임을 제한합니다.** `clock.tick(FPS)`는 최대 프레임 속도를 제한하고 경과 밀리초를 줍니다. 16밀리초는 16/1000=0.016초입니다. `min(..., 0.05)`는 긴 탭 전환 시간을 한 번의 큰 이동으로 적용하지 않기 위한 상한입니다. 따라서 오래 다른 탭에 머문 실제 시간과 게임 안 경과 시간이 항상 같지는 않습니다.

- **그룹의 image와 rect를 사용해 화면에 그립니다.** 그룹의 `update()`는 각 객체의 update를 호출하고, `draw(screen)`은 image를 rect 위치에 그립니다. update만 하면 값만 바뀌고, draw만 하면 같은 그림이 같은 위치에 남습니다. 배경 → 물체 → HUD/안내 순서로 그려야 뒤에 그린 배경이 물체를 덮지 않습니다. 마지막 display.update가 그린 화면을 표시합니다.

```python
running = True
# 입력과 상태 변화, 그리기를 매 프레임 반복합니다.
while running:
    # 밀리초를 초로 바꾸고 지나치게 긴 프레임을 제한합니다.
    seconds = min(clock.tick(FPS) / 1000, 0.05)
    # 지난 프레임 이후 쌓인 입력 이벤트를 처리합니다.
    for event in pygame.event.get():
        if event.type == pygame.QUIT:
            running = False
        elif event.type == pygame.KEYDOWN:
            if event.key == pygame.K_RETURN:
                if mission.state == 'title':
                    mission.state = 'playing'
                    pygame.mixer.music.play(-1)
                elif mission.state == 'round_clear':
                    mission.start_new_round()
                elif mission.state == 'game_over':
                    mission.reset_game()
                elif mission.state == 'playing':
                    robots.add(Robot(platforms, gates, 2, 7))
            elif mission.state == 'playing':
                if event.key == pygame.K_SPACE:
                    explorer.jump()
                elif event.key == pygame.K_UP:
                    explorer.fire()
    if not running:
        break
    if mission.state == 'playing':
        all_tiles.update(seconds)
        gates.update(seconds)
        explorers.update(seconds)
        pulses.update(seconds)
        robots.update(seconds)
        crystals.update(seconds)
        mission.update(seconds)
    screen.blit(background, (0, 0))
    # 그룹의 image와 rect를 사용해 화면에 그립니다.
    all_tiles.draw(screen)
    # 그룹의 image와 rect를 사용해 화면에 그립니다.
    gates.draw(screen)
    # 그룹의 image와 rect를 사용해 화면에 그립니다.
    explorers.draw(screen)
    # 그룹의 image와 rect를 사용해 화면에 그립니다.
    pulses.draw(screen)
    # 그룹의 image와 rect를 사용해 화면에 그립니다.
    robots.draw(screen)
    # 그룹의 image와 rect를 사용해 화면에 그립니다.
    crystals.draw(screen)
    mission.draw()
    pygame.display.update()

pygame.quit()
```


### 코드가 하는 일

충돌 후 먼저 `check_game_over`를 호출하고, state가 바뀌면 즉시 반환합니다. 시간 0과 에너지 0이 같은 프레임이면 종료가 우선입니다. `reset_game`은 점수 0, 탐사 1, 시간 30, 생성 간격 5, 에너지 100과 빈 그룹을 복구합니다. `Explorer.reset`은 위치뿐 아니라 속도·가속도·재사용 대기시간·그림을 함께 되돌립니다. 원강의 후반의 ‘리셋 후 속도가 남는 버그’는 이 수업의 공통 reset에서 예방합니다.

- **현재 그림의 불투명한 부분을 충돌용 마스크로 만듭니다.** Rect는 투명 여백까지 포함하는 상자이고 Mask는 불투명 픽셀의 모양입니다. 그림 프레임을 바꾼 뒤 마스크도 갱신해야 보이는 모양과 충돌 모양이 어긋나지 않습니다. 다만 발판 지지는 팔 자세에 흔들리지 않게 별도의 발 폭/면 통과 판정을 사용합니다. 모든 충돌에 마스크를 쓰는 것이 항상 더 좋은 것은 아닙니다.

    # 표시할 애니메이션 프레임을 선택합니다.
    def animate(self, seconds):
        self.frame = (self.frame + seconds * 6) % len(self.frames)
        self.image = self.frames[int(self.frame)]
        # 현재 그림의 불투명한 부분을 충돌용 마스크로 만듭니다.
        self.mask = pygame.mask.from_surface(self.image)

**편집 10.** `class Expedition` 안의 `check_collisions` 메서드 전체를 아래 코드로 교체합니다. 다음 `def` 직전까지가 교체 범위입니다. `def` 앞 4칸, 본문 앞 8칸을 유지합니다.

**왜 이렇게 쓰나요 — 이 편집을 읽는 순서**

- **상자가 겹치는 것만으로 끝내지 않고 픽셀 모양까지 비교합니다.** `collide_mask`는 충돌 함수에 전달하는 판정 함수입니다. 여기서는 괄호를 붙여 즉시 실행하지 않고 함수 자체를 넘깁니다. Pygame이 비교할 두 객체를 넣어 호출합니다. 두 객체의 mask와 rect 위치를 함께 사용하므로 그림만 바꾸거나 좌표 한쪽만 고치면 판정이 틀어집니다.

- **두 그룹의 충돌 결과를 받아 맞힌 대상 수를 셉니다.** `groupcollide(A, B, 지울A, 지울B)`는 A의 객체를 열쇠로, 그 객체가 맞힌 B 목록을 값으로 돌려줍니다. 두 True/False는 각각 어느 쪽을 그룹에서 제거할지 정합니다. 우주 방어대는 양쪽 제거, 화성의 로봇 피격은 펄스만 제거하고 로봇을 남겨 상태를 바꿉니다. values()로 얻는 것은 객체 하나가 아니라 대상 목록이라는 점에 주의하세요.

- **객체 하나와 그룹을 비교하고 충돌한 대상 목록을 받습니다.** `spritecollide(객체, 그룹, 제거여부)`는 겹친 대상들의 리스트를 반환합니다. 빈 리스트는 if에서 거짓, 한 개 이상은 참입니다. if 본문을 한 번 실행하는 규칙과 len(목록)만큼 보상을 계산하는 규칙은 다릅니다. 여러 탄환 피격은 생명 한 번 차감, 결정 여러 개 회수는 개수별 보상이라는 해당 단계의 의도를 읽으세요.

- **검사를 시작할 때의 로봇 목록만 순회합니다.** 결정을 빼앗기면 검사 중 로봇이 새로 추가됩니다. list로 검사 시작 시점의 목록을 따로 만들면 새로 추가된 로봇까지 같은 반복에서 계속 검사하는 일을 피합니다. 객체의 복제본을 만드는 것이 아니라 목록만 복사합니다.

- **이번 대상의 나머지 검사를 건너뛰고 다음 대상으로 갑니다.** continue는 가장 가까운 반복문의 다음 반복으로 이동합니다. 발판과 가로 범위가 겹치지 않으면 그 발판의 세로 착지 검사를 생략합니다. break는 반복문 전체를 끝내고 return은 메서드를 끝냅니다. 세 명령이 어느 범위를 빠져나가는지 들여쓰기를 따라 확인하세요.

```python
    # 접촉 대상을 검사하고 이 단계의 충돌 규칙을 적용합니다.
    def check_collisions(self):
        # 상자가 겹치는 것만으로 끝내지 않고 픽셀 모양까지 비교합니다.
        collisions = pygame.sprite.groupcollide(self.pulses, self.robots, True, False, pygame.sprite.collide_mask)
        for targets in collisions.values():
            for robot in targets:
                if robot.state == 'walking':
                    robot.hit_sound.play()
                    robot.state = 'falling'
                    robot.frame = 0.0
                    robot.down_elapsed = 0.0
        # 상자가 겹치는 것만으로 끝내지 않고 픽셀 모양까지 비교합니다.
        for robot in pygame.sprite.spritecollide(self.explorer, self.robots, False, pygame.sprite.collide_mask):
            if robot.state != 'walking':
                robot.kick_sound.play()
                robot.kill()
                self.score += 25
                self.crystals.add(Crystal(self.platforms, self.gates))
            elif self.explorer.hurt_remaining <= 0:
                self.explorer.health = max(0, self.explorer.health - 20)
                self.explorer.hit_sound.play()
                self.explorer.hurt_remaining = 1.0
                self.explorer.position.x = (self.explorer.position.x - 128 * robot.direction) % SCREEN_WIDTH
                self.explorer.rect.midbottom = self.explorer.position
                if self.explorer.health <= 0:
                    return
        # 상자가 겹치는 것만으로 끝내지 않고 픽셀 모양까지 비교합니다.
        collected = pygame.sprite.spritecollide(self.explorer, self.crystals, True, pygame.sprite.collide_mask)
        if collected:
            self.pickup_sound.play()
            self.score += 100 * len(collected)
            self.explorer.health = min(self.explorer.starting_health, self.explorer.health + 10 * len(collected))
        # 검사를 시작할 때의 로봇 목록만 순회합니다.
        for robot in list(self.robots):
            if robot.state != 'walking':
                # 이번 대상의 나머지 검사를 건너뛰고 다음 대상으로 갑니다.
                continue
            # 상자가 겹치는 것만으로 끝내지 않고 픽셀 모양까지 비교합니다.
            lost = pygame.sprite.spritecollide(robot, self.crystals, True, pygame.sprite.collide_mask)
            if lost:
                self.lost_sound.play()
                for _ in lost:
                    self.robots.add(Robot(self.platforms, self.gates, self.round_number, self.round_number + 5))
```


### 코드가 하는 일

정적인 이미지는 생성할 때, 애니메이션은 image를 바꾼 직후 mask를 만듭니다. `groupcollide`와 `spritecollide`의 마지막 인수에 `collide_mask`를 전달합니다. 발판은 팔 자세에 따라 흔들리지 않도록 기존 발 지지 판정을 유지하고, 공격·적·회수물에 픽셀 판정을 적용합니다. 원강의의 타일·플레이어 선택 마스크와 고정 +5 보정은 새 그림에 그대로 옮기지 않았습니다. 마스크의 용도와 갱신 시점을 배우면서 안정적인 착지를 유지하기 위한 조정입니다.
