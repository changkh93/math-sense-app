## 04-A - 아군 탄환을 만들고 발사 연결하기

탄환을 생성해 그룹에 등록하고 위로 움직입니다. 발사 함수와 키 입력은 서로 어떻게 연결될까요?

**이 단계의 연결:** 출발 코드는 **03-C**의 누적 코드입니다. 아래 편집은 위에서부터 모두 적용합니다. 이미 완성한 나머지 메서드는 지정된 교체 범위 밖이면 그대로 둡니다.


### 입력 전에 결과를 예상해 보세요

탐사선 top에서 시작한 탄환의 y가 650이고 속도가 10이면 한 update 뒤 y는 얼마인가요?

먼저 답을 한 문장으로 적고 아래 해설과 비교하세요.

**생각 확인:** 640입니다. 화면 위쪽으로 가려면 y를 빼야 합니다. 그룹에 등록되어 있어야 다음 프레임에도 update와 draw의 대상이 됩니다.

### main.py 수정 위치와 입력 코드

**편집 1.** `class ScoutPulse` 안의 `def __init__`부터 그 메서드 본문 끝까지 **전체 교체**합니다. 다음 def나 다음 class는 지우지 않습니다. def 앞4칸, 본문 앞8칸을 유지합니다.

**왜 이렇게 쓰나요 — 이 편집을 읽는 순서**

- **부모 Sprite의 내부 준비를 먼저 실행합니다.** `super().__init__()`은 상속받은 Sprite 내부를 준비합니다. 괄호 안에 그룹이 있으면 그 그룹에 이 객체를 바로 등록합니다. `super().__init__(tiles)`는 tiles에 자동 등록하지만 인수가 없는 `super().__init__()`은 자동 등록하지 않으므로 나중에 `그룹.add(객체)`가 필요합니다. 이 차이를 확인하고 중복 생성하지 마세요.

- **그림의 크기와 화면 위치를 담을 상자를 만듭니다.** `image`는 그림이고 `rect`는 그 그림을 놓을 사각형입니다. `get_rect(topleft=(x, y))`는 왼쪽 위, `midbottom=(x, y)`는 발 가운데를 해당 위치에 맞춥니다. 예를 들어 64×64 그림의 midbottom이 (100, 200)이면 왼쪽 위는 (68, 136)입니다. 같은 좌표라도 기준점이 다르면 표시 위치가 달라집니다. Group.draw는 각 객체의 image와 rect를 읽습니다.

```python
    # 객체를 생성할 때 필요한 초기 값과 참조를 준비합니다.
    def __init__(self, x, y, pulse_group):
        # 부모 Sprite의 내부 준비를 먼저 실행합니다.
        super().__init__()
        self.image = pygame.Surface((4, 16), pygame.SRCALPHA)
        self.image.fill((78, 240, 255))
        # 그림의 크기와 화면 위치를 담을 상자를 만듭니다.
        self.rect = self.image.get_rect()
        self.rect.centerx = x
        self.rect.centery = y
        self.velocity = 10
        pulse_group.add(self)
```


**편집 2.** `class ScoutPulse` 안의 `def update`부터 그 메서드 본문 끝까지 **전체 교체**합니다. 다음 def나 다음 class는 지우지 않습니다. def 앞4칸, 본문 앞8칸을 유지합니다.

```python
    # 그룹에서 호출하는 한 프레임의 처리 순서입니다.
    def update(self):
        self.rect.y -= self.velocity
```


**편집 3.** `class Scout` 안의 `def fire`부터 그 메서드 본문 끝까지 **전체 교체**합니다. 다음 def나 다음 class는 지우지 않습니다. def 앞4칸, 본문 앞8칸을 유지합니다.

```python
    # 발사 조건을 확인하고 발사체를 생성합니다.
    def fire(self):
        self.shoot_sound.play()
        ScoutPulse(self.rect.centerx, self.rect.top, self.pulses)
```


**편집 4.** `running = True`부터 파일 마지막 `pygame.quit()`까지의 메인 루프 전체를 **교체**합니다. 아래 코드를 다른 함수나 클래스 안에 넣지 않습니다.

**왜 이렇게 쓰나요 — 이 편집을 읽는 순서**

- **입력과 상태 변화, 그리기를 매 프레임 반복합니다.** 한 프레임은 게임을 한 번 갱신해서 표시하는 주기입니다. 준비 코드·그룹 생성은 while 위에서 한 번만 실행하고, 입력과 이동·그리기는 while 안에서 반복합니다. 물체를 매 프레임 새로 생성하면 위치가 초기화되거나 개수가 계속 늘어납니다. 반복문의 들여쓰기가 게임의 시간 구조를 정합니다.

- **지난 프레임 이후 쌓인 입력 이벤트를 처리합니다.** `event.get()`은 이번에 도착한 사건들을 꺼냅니다. KEYDOWN은 누르기 시작한 사건이고 `key.get_pressed()`는 지금 계속 누르고 있는 상태입니다. 점프·발사 한 번은 이벤트로, 연속 좌우 이동은 누름 상태로 처리하는 이유가 여기에 있습니다. 스튜디오 게임 화면을 클릭해야 입력이 게임으로 전달됩니다.

- **그룹의 image와 rect를 사용해 화면에 그립니다.** 그룹의 `update()`는 각 객체의 update를 호출하고, `draw(screen)`은 image를 rect 위치에 그립니다. update만 하면 값만 바뀌고, draw만 하면 같은 그림이 같은 위치에 남습니다. 배경 → 물체 → HUD/안내 순서로 그려야 뒤에 그린 배경이 물체를 덮지 않습니다. 마지막 display.update가 그린 화면을 표시합니다.

```python
running = True
# 입력과 상태 변화, 그리기를 매 프레임 반복합니다.
while running:
    # 지난 프레임 이후 쌓인 입력 이벤트를 처리합니다.
    for event in pygame.event.get():
        if event.type == pygame.QUIT:
            running = False
        if event.type == pygame.KEYDOWN:
            if event.key == pygame.K_SPACE:
                scout.fire()

    if not running:
        break

    screen.fill((9, 17, 37))
    scouts.update()
    raiders.update()
    scout_pulses.update()
    raider_pulses.update()
    mission.update()

    # 그룹의 image와 rect를 사용해 화면에 그립니다.
    scouts.draw(screen)
    # 그룹의 image와 rect를 사용해 화면에 그립니다.
    raiders.draw(screen)
    # 그룹의 image와 rect를 사용해 화면에 그립니다.
    scout_pulses.draw(screen)
    # 그룹의 image와 rect를 사용해 화면에 그립니다.
    raider_pulses.draw(screen)
    mission.draw()

    pygame.display.update()
    clock.tick(FPS)

pygame.quit()
```


### 코드가 하는 일

Surface((4,16),SRCALPHA)는 투명도를 지원하는 작은 표면입니다. fill의 청록색으로 탄환을 칠합니다. centerx/centery는 전달한 포구 좌표, velocity10은 이동거리입니다. pulse_group.add(self)가 생성된 탄환을 그룹에 넣습니다. y를 빼면 위로 이동합니다. KEYDOWN의 SPACE에서 scout.fire를 한 번 호출합니다. fire는 소리를 재생하고 ScoutPulse를 만듭니다.03에서 연결한 그룹 update/draw가 새 탄환에도 적용됩니다.

## 04-B - 두 발 제한의 빈틈 관찰하기

화면에 보이는 탄환 수와 그룹에 남은 탄환 수는 같을까요? 일부러 정리를 연결하기 전에 차이를 확인합니다.

**이 단계의 연결:** 출발 코드는 **04-A**의 누적 코드입니다. 아래 편집은 위에서부터 모두 적용합니다. 이미 완성한 나머지 메서드는 지정된 교체 범위 밖이면 그대로 둡니다.


### 입력 전에 결과를 예상해 보세요

탄환 두 개가 화면 밖에 나갔는데도 세 번째가 안 나오는 이유를 그룹 관점에서 설명하세요.

먼저 답을 한 문장으로 적고 아래 해설과 비교하세요.

**생각 확인:** 화면 밖으로 나간 것과 그룹에서 제거된 것은 다릅니다. 그룹 길이가 여전히 2여서 조건이 거짓입니다. 이 단계의 막힘은 다음 단계에서 제거 기능의 필요성을 확인하는 의도된 상태입니다.

### main.py 수정 위치와 입력 코드

**편집 1.** `class Scout` 안의 `def fire`부터 그 메서드 본문 끝까지 **전체 교체**합니다. 다음 def나 다음 class는 지우지 않습니다. def 앞4칸, 본문 앞8칸을 유지합니다.

**왜 이렇게 쓰나요 — 이 편집을 읽는 순서**

- **보이지 않는 탄환도 그룹에 남아 있으면 개수에 포함됩니다.** len은 발사한 누적 횟수가 아니라 지금 그룹에 들어 있는 객체 수를 셉니다. 화면 밖 탄환을 제거하지 않으면 제한에 도달한 뒤 영원히 발사할 수 없습니다. 따라서 발사 제한과 이탈 제거는 서로 연결된 기능입니다. 소리도 허용 조건 안에 두어 발사되지 않았는데 소리만 나는 일을 막습니다.

```python
    # 발사 조건을 확인하고 발사체를 생성합니다.
    def fire(self):
        # 보이지 않는 탄환도 그룹에 남아 있으면 개수에 포함됩니다.
        if len(self.pulses) < 2:
            self.shoot_sound.play()
            ScoutPulse(self.rect.centerx, self.rect.top, self.pulses)
```


### 코드가 하는 일

len(self.pulses)는 이 그룹의 객체 수입니다.2보다 작을 때만 소리와 생성을 모두 실행합니다. 화면 밖으로 이동한 객체도 그룹에서 제거하지 않았다면 계속 셉니다.

## 04-C - 화면 밖 탄환을 그룹에서 제거하기

탄환 전체가 화면 위로 나갔는지 판정합니다. top과 bottom 중 어느 값으로 검사해야 끝부분까지 나간 것을 알 수 있을까요?

**이 단계의 연결:** 출발 코드는 **04-B**의 누적 코드입니다. 아래 편집은 위에서부터 모두 적용합니다. 이미 완성한 나머지 메서드는 지정된 교체 범위 밖이면 그대로 둡니다.


### 입력 전에 결과를 예상해 보세요

탄환 top=-1, 높이=16이면 바로 제거해야 할까요?

먼저 답을 한 문장으로 적고 아래 해설과 비교하세요.

**생각 확인:** bottom은 15이므로 아직 일부가 화면 안에 있습니다. bottom<0이면 전체가 위로 빠져나간 상태입니다. 제거 뒤 len이 줄어 발사 공간이 생깁니다.

### main.py 수정 위치와 입력 코드

**편집 1.** `class ScoutPulse` 안의 `def update`부터 그 메서드 본문 끝까지 **전체 교체**합니다. 다음 def나 다음 class는 지우지 않습니다. def 앞4칸, 본문 앞8칸을 유지합니다.

**왜 이렇게 쓰나요 — 이 편집을 읽는 순서**

- **이 객체를 소속 그룹에서 제거해 갱신과 그리기를 끝냅니다.** kill은 모든 소속 Group에서 Sprite를 제거합니다. 이후 그룹 update/draw와 개수 검사에서 빠집니다. Python 변수까지 모두 지우거나 즉시 메모리를 없애라는 명령은 아닙니다. 화면 이탈·회수·격추 뒤 같은 객체가 다음 프레임에 다시 처리되지 않게 하는 데 사용합니다.

```python
    # 그룹에서 호출하는 한 프레임의 처리 순서입니다.
    def update(self):
        self.rect.y -= self.velocity
        if self.rect.bottom < 0:
            # 이 객체를 소속 그룹에서 제거해 갱신과 그리기를 끝냅니다.
            self.kill()
```


### 코드가 하는 일

bottom<0이면 탄환의 맨 아래까지 화면 위에 있습니다. kill은 이 Sprite를 모든 소속 그룹에서 제거합니다. 객체를 참조하는 모든 변수를 지우거나 메모리를 무조건 즉시 해제한다는 뜻은 아닙니다. 그룹 수가 줄어 발사 조건이 다시 참이 됩니다.

### 여기서 실행하세요

정지 → 위 코드 수정 → 실행 → 게임 화면 클릭 순서로 진행합니다.

두 발 발사→화면 위로 소멸→다시 두 발 발사를 반복할 수 있습니다.

**이 시점의 정상 상태:** 두 발이 아직 화면 안에 있으면 세 번째 입력은 무시됩니다.

**예상과 다를 때:** 계속 막히면 kill의 괄호와 bottom<0을 확인합니다. 발사하자마자 사라지면 bottom>0으로 쓰지 않았는지 확인합니다.

[이 단계 누적 코드 04-C.py](/space-invaders/checkpoints/04-C.py)와 비교할 수 있습니다.
