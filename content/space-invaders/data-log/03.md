### main.py 수정 위치와 입력 코드

**편집 1.** 다섯 클래스가 끝난 뒤부터 `running = True` 직전까지의 그룹·객체 준비 구간를 **추가**합니다. 아래 코드를 다른 함수나 클래스 안에 넣지 않습니다.

**왜 이렇게 쓰나요 — 이 편집을 읽는 순서**

- **같이 갱신하거나 검사할 객체들을 담을 그룹을 만듭니다.** Group은 Sprite들을 묶는 관리 목록입니다. 변수마다 `Group()`을 호출하면 별개의 빈 그룹을 만듭니다. 화성의 tiles/all_tiles는 그릴 타일 전체, platforms는 착지 대상, hazards는 위험 접촉 대상입니다. 우주 방어대의 양쪽 탄환 그룹도 분리해야 아군과 적의 탄환을 다른 규칙으로 검사할 수 있습니다. 그룹을 준비하는 것과 실제 객체를 넣는 것은 별개입니다.

```python
# --- 스프라이트 그룹 및 객체 생성 ---
# 현재 아군 탄환을 담아 이동·충돌·개수를 관리합니다.
scout_pulses = pygame.sprite.Group()
# 현재 적 탄환을 담아 이동·충돌·개수를 관리합니다.
raider_pulses = pygame.sprite.Group()

# 아군 탐사선을 담습니다.
scouts = pygame.sprite.Group()
scout = Scout(scout_pulses)
scouts.add(scout)

# 현재 편대의 적들을 담습니다.
raiders = pygame.sprite.Group()

mission = Mission(scout, raiders, scout_pulses, raider_pulses)
```


**편집 2.** `running = True`부터 파일 마지막 `pygame.quit()`까지의 메인 루프 전체를 **교체**합니다. 아래 코드를 다른 함수나 클래스 안에 넣지 않습니다.

**왜 이렇게 쓰나요 — 이 편집을 읽는 순서**

- **입력과 상태 변화, 그리기를 매 프레임 반복합니다.** 한 프레임은 게임을 한 번 갱신해서 표시하는 주기입니다. 준비 코드·그룹 생성은 while 위에서 한 번만 실행하고, 입력과 이동·그리기는 while 안에서 반복합니다. 물체를 매 프레임 새로 생성하면 위치가 초기화되거나 개수가 계속 늘어납니다. 반복문의 들여쓰기가 게임의 시간 구조를 정합니다.

- **지난 프레임 이후 쌓인 입력 이벤트를 처리합니다.** `event.get()`은 이번에 도착한 사건들을 꺼냅니다. KEYDOWN은 누르기 시작한 사건이고 `key.get_pressed()`는 지금 계속 누르고 있는 상태입니다. 점프·발사 한 번은 이벤트로, 연속 좌우 이동은 누름 상태로 처리하는 이유가 여기에 있습니다. 스튜디오 게임 화면을 클릭해야 입력이 게임으로 전달됩니다.

- **그룹의 image와 rect를 사용해 화면에 그립니다.** 그룹의 `update()`는 각 객체의 update를 호출하고, `draw(screen)`은 image를 rect 위치에 그립니다. update만 하면 값만 바뀌고, draw만 하면 같은 그림이 같은 위치에 남습니다. 배경 → 물체 → HUD/안내 순서로 그려야 뒤에 그린 배경이 물체를 덮지 않습니다. 마지막 display.update가 그린 화면을 표시합니다.

```python
running = True
# 입력과 상태 변화, 그리기를 매 프레임 반복합니다.
while running:
    # 지난 프레임 이후 쌓인 입력 이벤트를 처리합니다.
    for event in pygame.event.get():
        if event.type == pygame.QUIT:
            running = False

    if not running:
        break

    screen.fill((9, 17, 37))
    scouts.update()
    raiders.update()
    scout_pulses.update()
    raider_pulses.update()
    mission.update()

    # 그룹의 image와 rect를 사용해 화면에 그립니다.
    scouts.draw(screen)
    # 그룹의 image와 rect를 사용해 화면에 그립니다.
    raiders.draw(screen)
    # 그룹의 image와 rect를 사용해 화면에 그립니다.
    scout_pulses.draw(screen)
    # 그룹의 image와 rect를 사용해 화면에 그립니다.
    raider_pulses.draw(screen)
    mission.draw()

    pygame.display.update()
    clock.tick(FPS)

pygame.quit()
```


**편집 3.** `class Scout` 안의 `def __init__`부터 그 메서드 본문 끝까지 **전체 교체**합니다. 다음 def나 다음 class는 지우지 않습니다. def 앞4칸, 본문 앞8칸을 유지합니다.

**왜 이렇게 쓰나요 — 이 편집을 읽는 순서**

- **PNG의 투명한 여백을 유지합니다.** `image.load`로 읽은 Surface를 `convert_alpha()`로 투명도를 유지하는 표시 형식으로 바꿉니다. 투명한 여백까지 배경색 사각형으로 그리지 않기 위한 준비입니다. `smoothscale(그림, (가로, 세로))`은 그다음 표시 크기를 맞춥니다. 여러 함수가 한 줄에 겹쳐 있으면 가장 안쪽 호출부터 읽으세요.

- **부모 Sprite의 내부 준비를 먼저 실행합니다.** `super().__init__()`은 상속받은 Sprite 내부를 준비합니다. 괄호 안에 그룹이 있으면 그 그룹에 이 객체를 바로 등록합니다. `super().__init__(tiles)`는 tiles에 자동 등록하지만 인수가 없는 `super().__init__()`은 자동 등록하지 않으므로 나중에 `그룹.add(객체)`가 필요합니다. 이 차이를 확인하고 중복 생성하지 마세요.

- **그림의 크기와 화면 위치를 담을 상자를 만듭니다.** `image`는 그림이고 `rect`는 그 그림을 놓을 사각형입니다. `get_rect(topleft=(x, y))`는 왼쪽 위, `midbottom=(x, y)`는 발 가운데를 해당 위치에 맞춥니다. 예를 들어 64×64 그림의 midbottom이 (100, 200)이면 왼쪽 위는 (68, 136)입니다. 같은 좌표라도 기준점이 다르면 표시 위치가 달라집니다. Group.draw는 각 객체의 image와 rect를 읽습니다.

- **소리 파일을 준비하는 일과 재생하는 일을 구분합니다.** Sound 또는 load_sound는 소리를 사용할 준비입니다. .play()를 호출하는 순간 재생을 시도합니다. 생성자에서 준비하고 실제 발사·충돌 사건에서 재생해야 매 프레임 파일을 읽거나 준비만 했는데 소리가 날 것으로 기대하지 않습니다.

```python
    # 객체를 생성할 때 필요한 초기 값과 참조를 준비합니다.
    def __init__(self, pulses):
        # 부모 Sprite의 내부 준비를 먼저 실행합니다.
        super().__init__()
        self.image = pygame.transform.smoothscale(
            pygame.image.load('assets/scout.png').convert_alpha(), (64, 64)
        )
        # 그림의 크기와 화면 위치를 담을 상자를 만듭니다.
        self.rect = self.image.get_rect()
        self.rect.centerx = SCREEN_WIDTH // 2
        self.rect.bottom = SCREEN_HEIGHT
        self.lives = 5
        self.velocity = 8
        self.pulses = pulses
        # 소리 파일을 준비하는 일과 재생하는 일을 구분합니다.
        self.shoot_sound = pygame.mixer.Sound('assets/scout_pulse.ogg')
```


### 코드가 하는 일

Group은 여러 Sprite를 담습니다. Scout(scout_pulses)는 탄환을 넣을 같은 그룹을 전달합니다. 먼저 그룹과 update/draw 연결을 쓰고, 마지막으로 Scout 생성자를 채워 실제 실행이 가능하게 만듭니다. super().__init__은 Sprite 내부를 준비합니다. image.load로 원본을 읽고 convert_alpha로 투명을 유지합니다. smoothscale은64×64로 줄입니다. get_rect는 이미지 크기의 위치 상자입니다. centerx=600, bottom=700이면 아래 중앙입니다. lives5, velocity8은 생명과 프레임당 이동거리입니다. self.pulses는 전달한 그룹의 참조입니다. 소리는 지금 로드하지만 발사는04에서 연결합니다. 빈 적/탄환 그룹의 update·draw는 표시할 것이 없어도 호출할 수 있습니다.

### 입력 전에 결과를 예상해 보세요

left=1, velocity=8에서 왼쪽 이동 후 경계 보정 전후의 left는 얼마인가요?

### main.py 수정 위치와 입력 코드

**편집 1.** `class Scout` 안의 `def update`부터 그 메서드 본문 끝까지 **전체 교체**합니다. 다음 def나 다음 class는 지우지 않습니다. def 앞4칸, 본문 앞8칸을 유지합니다.

**왜 이렇게 쓰나요 — 이 편집을 읽는 순서**

- **이번 프레임에 계속 눌린 방향키를 읽습니다.** `keys[pygame.K_LEFT]`는 왼쪽 키가 눌렸는지 알려주는 값입니다. if의 본문은 참일 때만 실행됩니다. 두 독립 if는 둘 다 실행될 수 있고 if/elif는 첫 참 분기만 실행됩니다. 양쪽 키를 동시에 누른 경우를 떠올리면 차이가 드러납니다.

```python
    # 그룹에서 호출하는 한 프레임의 처리 순서입니다.
    def update(self):
        # 이번 프레임에 계속 눌린 방향키를 읽습니다.
        keys = pygame.key.get_pressed()
        if keys[pygame.K_LEFT] and self.rect.left > 0:
            self.rect.x -= self.velocity
        if keys[pygame.K_RIGHT] and self.rect.right < SCREEN_WIDTH:
            self.rect.x += self.velocity

        if self.rect.left < 0:
            self.rect.left = 0
        if self.rect.right > SCREEN_WIDTH:
            self.rect.right = SCREEN_WIDTH
```


### 코드가 하는 일

get_pressed는 현재 누른 키를 알려줍니다. 왼쪽은 x에서8을 빼고 오른쪽은8을 더합니다. 이동 전 조건만 검사하면 x=1에서8을 뺐을 때-7이 됩니다. 마지막 두 if가 left를0 이상, right를1200 이하로 되돌립니다. 각 if 본문은12칸입니다. 상수와 키 이름은 대문자입니다.

## 03-C - reset으로 중앙 복귀 확인하기

피격됐을 때 새 객체를 만드는 대신 위치만 복원하려고 합니다. 좌우로만 움직이는 기체는 어떤 좌표만 되돌리면 될까요?

**이 단계의 연결:** 출발 코드는 **03-B**의 누적 코드입니다. 아래 편집은 위에서부터 모두 적용합니다. 이미 완성한 나머지 메서드는 지정된 교체 범위 밖이면 그대로 둡니다.


### 입력 전에 결과를 예상해 보세요

reset을 정의했는데 평소 실행에서 자동으로 중앙으로 돌아오지 않는 이유는 무엇인가요?

먼저 답을 한 문장으로 적고 아래 해설과 비교하세요.

**생각 확인:** 정의는 호출과 다릅니다. reset 호출이 있어야 본문이 실행됩니다. 임시 시험에서 호출하고, 이후 피격/라운드 처리에서 정식으로 호출합니다.

### main.py 수정 위치와 입력 코드

**편집 1.** `class Scout` 안의 `def reset`부터 그 메서드 본문 끝까지 **전체 교체**합니다. 다음 def나 다음 class는 지우지 않습니다. def 앞4칸, 본문 앞8칸을 유지합니다.

```python
    # 정해 둔 시작 상태로 이 객체를 복귀시킵니다.
    def reset(self):
        self.rect.centerx = SCREEN_WIDTH // 2
```


### 코드가 하는 일

centerx를 화면 폭의 절반으로 돌립니다. bottom은 이동 코드에서 바뀌지 않아 그대로700입니다. reset을 정의한 것과 실제 호출한 것은 다릅니다. 아래 임시 호출로 결과를 확인합니다.

### 여기서 실행하세요

정지 → 위 코드 수정 → 실행 → 게임 화면 클릭 순서로 진행합니다.

일반 실행에서는 기존 이동이 유지됩니다. 아래 시험에서는 콘솔600과 중앙에 놓인 기체를 확인합니다.

**이 시점의 정상 상태:** 피격 시 자동 reset은09에서 연결합니다.

**예상과 다를 때:** 시험 후100이 나오면 reset() 호출의 괄호와 들여쓰기를 확인합니다. reset을 클래스 밖 함수로 쓰지 않습니다.
