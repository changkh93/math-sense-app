## 09-A - 상태 확인: 탄환 정리와 위치 복원부터

**이 단계의 연결:** 출발 코드는 **08-B**의 누적 코드입니다. 아래 편집은 위에서부터 모두 적용합니다. 이미 완성한 나머지 메서드는 지정된 교체 범위 밖이면 그대로 둡니다.

### main.py 수정 위치와 입력 코드

**편집 1.** `class Mission` 안의 `def check_game_status`부터 그 메서드 본문 끝까지 **전체 교체**합니다. 다음 def나 다음 class는 지우지 않습니다. def 앞4칸, 본문 앞8칸을 유지합니다.

**왜 이렇게 쓰나요 — 이 편집을 읽는 순서**

- **이 그룹의 현재 객체들을 정리합니다.** empty는 해당 Group의 구성원을 모두 빼는 동작입니다. 점수나 생명 같은 별도 변수까지 초기화하지 않습니다. 다음 라운드와 새 게임에서 무엇을 유지하고 무엇을 지울지 각각 결정해야 합니다. 함수 이름이 reset이라고 해서 모든 값이 자동 복구되는 것은 아닙니다.

```python
    # 전장을 정리하고 남은 생명에 따라 다음 상태를 정합니다.
    def check_game_status(self, main_text, sub_text):
        # 이 그룹의 현재 객체들을 정리합니다.
        self.scout_pulses.empty()
        # 이 그룹의 현재 객체들을 정리합니다.
        self.raider_pulses.empty()
        self.scout.reset()
        for raider in self.raiders:
            raider.reset()

        if self.scout.lives <= 0:
            self.reset_game()
        else:
            self.pause_game(main_text, sub_text)
```


### 코드가 하는 일

양쪽 그룹 empty로 잔여 탄환을 비웁니다. Scout.reset은 중앙, 남은 Raider.reset은 각자의 시작좌표와 오른쪽 방향을 복원합니다. 생명 차감은 이미 침범 처리에 있으므로 이 함수에서 또 빼지 않습니다. lives<=0이면 reset_game, 아니면 pause_game을 호출합니다. 둘 다 아직 pass입니다.

### 입력 전에 결과를 예상해 보세요

### main.py 수정 위치와 입력 코드

**편집 1.** `class Mission` 안의 `def __init__`부터 그 메서드 본문 끝까지 **전체 교체**합니다. 다음 def나 다음 class는 지우지 않습니다. def 앞4칸, 본문 앞8칸을 유지합니다.

**왜 이렇게 쓰나요 — 이 편집을 읽는 순서**

- **소리 파일을 준비하는 일과 재생하는 일을 구분합니다.** Sound 또는 load_sound는 소리를 사용할 준비입니다. .play()를 호출하는 순간 재생을 시도합니다. 생성자에서 준비하고 실제 발사·충돌 사건에서 재생해야 매 프레임 파일을 읽거나 준비만 했는데 소리가 날 것으로 기대하지 않습니다.

```python
    # 객체를 생성할 때 필요한 초기 값과 참조를 준비합니다.
    def __init__(self, scout, raiders, scout_pulses, raider_pulses):
        self.round_number = 1
        self.score = 0
        self.scout = scout
        self.raiders = raiders
        self.scout_pulses = scout_pulses
        self.raider_pulses = raider_pulses

        self.state = 'playing'
        self.pause_main_text = ''
        self.pause_sub_text = ''

        # 소리 파일을 준비하는 일과 재생하는 일을 구분합니다.
        self.new_round_sound = pygame.mixer.Sound('assets/wave_ready.ogg')
        # 소리 파일을 준비하는 일과 재생하는 일을 구분합니다.
        self.breach_sound = pygame.mixer.Sound('assets/line_alert.ogg')
        # 소리 파일을 준비하는 일과 재생하는 일을 구분합니다.
        self.raider_break_sound = pygame.mixer.Sound('assets/raider_break.ogg')
        # 소리 파일을 준비하는 일과 재생하는 일을 구분합니다.
        self.shield_hit_sound = pygame.mixer.Sound('assets/shield_hit.ogg')

        self.font = pygame.font.Font('assets/DoHyeon-Regular.ttf', 28)
```


**편집 2.** `class Mission` 안의 `def pause_game`부터 그 메서드 본문 끝까지 **전체 교체**합니다. 다음 def나 다음 class는 지우지 않습니다. def 앞4칸, 본문 앞8칸을 유지합니다.

```python
    # 안내 문구와 대기 상태를 저장합니다.
    def pause_game(self, main_text, sub_text):
        self.state = 'paused'
        self.pause_main_text = main_text
        self.pause_sub_text = sub_text
```


**편집 3.** `class Mission` 안의 `def update`부터 그 메서드 본문 끝까지 **전체 교체**합니다. 다음 def나 다음 class는 지우지 않습니다. def 앞4칸, 본문 앞8칸을 유지합니다.

**왜 이렇게 쓰나요 — 이 편집을 읽는 순서**

- **대기나 종료 상태이면 게임 규칙 갱신을 멈춥니다.** 상태는 지금 허용되는 동작을 정하는 문자열입니다. playing에서만 이동·충돌·시간을 진행하고, 대기 중에도 이벤트와 그리기는 유지합니다. 처리 도중 피격으로 상태가 바뀔 수 있어 다음 처리 전에 다시 검사합니다. return은 현재 메서드만 끝내며 게임 전체를 종료하지 않습니다.

```python
    # 그룹에서 호출하는 한 프레임의 처리 순서입니다.
    def update(self):
        # 대기나 종료 상태이면 게임 규칙 갱신을 멈춥니다.
        if self.state != 'playing':
            return
        self.shift_raiders()
        # 대기나 종료 상태이면 게임 규칙 갱신을 멈춥니다.
        if self.state != 'playing':
            return
        self.check_collisions()
        # 대기나 종료 상태이면 게임 규칙 갱신을 멈춥니다.
        if self.state != 'playing':
            return
        self.check_round_completion()
```


**편집 4.** `running = True`부터 파일 마지막 `pygame.quit()`까지의 메인 루프 전체를 **교체**합니다. 아래 코드를 다른 함수나 클래스 안에 넣지 않습니다.

**왜 이렇게 쓰나요 — 이 편집을 읽는 순서**

- **입력과 상태 변화, 그리기를 매 프레임 반복합니다.** 한 프레임은 게임을 한 번 갱신해서 표시하는 주기입니다. 준비 코드·그룹 생성은 while 위에서 한 번만 실행하고, 입력과 이동·그리기는 while 안에서 반복합니다. 물체를 매 프레임 새로 생성하면 위치가 초기화되거나 개수가 계속 늘어납니다. 반복문의 들여쓰기가 게임의 시간 구조를 정합니다.

- **지난 프레임 이후 쌓인 입력 이벤트를 처리합니다.** `event.get()`은 이번에 도착한 사건들을 꺼냅니다. KEYDOWN은 누르기 시작한 사건이고 `key.get_pressed()`는 지금 계속 누르고 있는 상태입니다. 점프·발사 한 번은 이벤트로, 연속 좌우 이동은 누름 상태로 처리하는 이유가 여기에 있습니다. 스튜디오 게임 화면을 클릭해야 입력이 게임으로 전달됩니다.

- **그룹의 image와 rect를 사용해 화면에 그립니다.** 그룹의 `update()`는 각 객체의 update를 호출하고, `draw(screen)`은 image를 rect 위치에 그립니다. update만 하면 값만 바뀌고, draw만 하면 같은 그림이 같은 위치에 남습니다. 배경 → 물체 → HUD/안내 순서로 그려야 뒤에 그린 배경이 물체를 덮지 않습니다. 마지막 display.update가 그린 화면을 표시합니다.

```python
running = True
# 입력과 상태 변화, 그리기를 매 프레임 반복합니다.
while running:
    # 지난 프레임 이후 쌓인 입력 이벤트를 처리합니다.
    for event in pygame.event.get():
        if event.type == pygame.QUIT:
            running = False
        if event.type == pygame.KEYDOWN:
            if event.key == pygame.K_SPACE and mission.state == 'playing':
                scout.fire()
            if event.key == pygame.K_RETURN:
                if mission.state == 'paused':
                    mission.state = 'playing'

    if not running:
        break

    screen.fill((9, 17, 37))

    if mission.state == 'playing':
        scouts.update()
        raiders.update()
        scout_pulses.update()
        raider_pulses.update()
        mission.update()

    # 그룹의 image와 rect를 사용해 화면에 그립니다.
    scouts.draw(screen)
    # 그룹의 image와 rect를 사용해 화면에 그립니다.
    raiders.draw(screen)
    # 그룹의 image와 rect를 사용해 화면에 그립니다.
    scout_pulses.draw(screen)
    # 그룹의 image와 rect를 사용해 화면에 그립니다.
    raider_pulses.draw(screen)
    mission.draw()

    pygame.display.update()
    clock.tick(FPS)

pygame.quit()
```


### 코드가 하는 일

state는 playing/paused를 나타냅니다. pause_game은 문구와 상태를 저장하고 즉시 반환합니다. 최상위 루프에서 playing일 때만 그룹 update와 Mission.update를 실행합니다. Space도 playing만 허용하고 Enter는 paused를 해제합니다. Mission.update는 처리 중 상태가 바뀌면 return해서 같은 프레임의 다음 처리를 중단합니다. draw와 이벤트 처리는 대기 중에도 계속합니다.

**생각 확인:** 나중에 그린 물체가 막 위로 또렷하게 덮입니다. 전장과 HUD를 먼저 그리고 마지막에 반투명 막과 안내문을 그려야 대기 화면처럼 보입니다.

### main.py 수정 위치와 입력 코드

**편집 1.** `class Mission` 안의 `def draw`부터 그 메서드 본문 끝까지 **전체 교체**합니다. 다음 def나 다음 class는 지우지 않습니다. def 앞4칸, 본문 앞8칸을 유지합니다.

**왜 이렇게 쓰나요 — 이 편집을 읽는 순서**

- **그림의 크기와 화면 위치를 담을 상자를 만듭니다.** `image`는 그림이고 `rect`는 그 그림을 놓을 사각형입니다. `get_rect(topleft=(x, y))`는 왼쪽 위, `midbottom=(x, y)`는 발 가운데를 해당 위치에 맞춥니다. 예를 들어 64×64 그림의 midbottom이 (100, 200)이면 왼쪽 위는 (68, 136)입니다. 같은 좌표라도 기준점이 다르면 표시 위치가 달라집니다. Group.draw는 각 객체의 image와 rect를 읽습니다.

- **숫자와 문자를 글자 그림으로 바꾸어 그립니다.** font.render의 첫 인수는 문자열입니다. f 문자열의 `{self.score}` 같은 부분은 그 시점의 값을 글자로 넣습니다. render 결과 역시 Surface이므로 get_rect로 정렬하고 blit으로 그립니다. 점수가 바뀐 뒤 다시 render해야 새 숫자가 보입니다. 파일 경로로 한글 폰트를 지정해 기본 폰트에 한글이 없는 문제를 피합니다.

```python
    # 현재 값을 읽어 화면과 안내를 그립니다.
    def draw(self):
        # 숫자와 문자를 글자 그림으로 바꾸어 그립니다.
        score_text = self.font.render(f'점수: {self.score}', True, (240, 246, 255))
        # 그림의 크기와 화면 위치를 담을 상자를 만듭니다.
        score_rect = score_text.get_rect(centerx=SCREEN_WIDTH // 2, top=10)

        # 숫자와 문자를 글자 그림으로 바꾸어 그립니다.
        round_text = self.font.render(f'라운드: {self.round_number}', True, (240, 246, 255))
        # 그림의 크기와 화면 위치를 담을 상자를 만듭니다.
        round_rect = round_text.get_rect(topleft=(20, 10))

        # 숫자와 문자를 글자 그림으로 바꾸어 그립니다.
        lives_text = self.font.render(f'남은 기체: {self.scout.lives}', True, (240, 246, 255))
        # 그림의 크기와 화면 위치를 담을 상자를 만듭니다.
        lives_rect = lives_text.get_rect(topright=(SCREEN_WIDTH - 20, 10))

        screen.blit(score_text, score_rect)
        screen.blit(round_text, round_rect)
        screen.blit(lives_text, lives_rect)

        pygame.draw.line(screen, (70, 90, 130), (0, 50), (SCREEN_WIDTH, 50), 3)
        pygame.draw.line(screen, (220, 70, 90), (0, SCREEN_HEIGHT - 100), (SCREEN_WIDTH, SCREEN_HEIGHT - 100), 3)

        if self.state in ('paused', 'game_over'):
            overlay = pygame.Surface((SCREEN_WIDTH, SCREEN_HEIGHT), pygame.SRCALPHA)
            overlay.fill((0, 0, 0, 180))
            screen.blit(overlay, (0, 0))

            # 숫자와 문자를 글자 그림으로 바꾸어 그립니다.
            title = self.font.render(self.pause_main_text, True, (255, 255, 255))
            # 그림의 크기와 화면 위치를 담을 상자를 만듭니다.
            t_rect = title.get_rect(center=(SCREEN_WIDTH // 2, SCREEN_HEIGHT // 2 - 20))
            # 숫자와 문자를 글자 그림으로 바꾸어 그립니다.
            sub = self.font.render(self.pause_sub_text, True, (200, 220, 240))
            # 그림의 크기와 화면 위치를 담을 상자를 만듭니다.
            s_rect = sub.get_rect(center=(SCREEN_WIDTH // 2, SCREEN_HEIGHT // 2 + 30))

            screen.blit(title, t_rect)
            screen.blit(sub, s_rect)
```


### 코드가 하는 일

overlay는 화면 크기의 투명 표면입니다. (0,0,0,180)의 마지막 값은 불투명도이며255보다 작아 뒤 화면이 비칩니다. 전장과 HUD를 그린 다음 검은 막과 문구를 그립니다. title은 가운데보다20픽셀 위, 보조문구는30픽셀 아래입니다. game_over라는 상태의 표시도 준비하되 실제 전환은10에서 구현합니다.
