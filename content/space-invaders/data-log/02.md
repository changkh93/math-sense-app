**이 단계의 연결:** 출발 코드는 **01-A**의 누적 코드입니다. 아래 편집은 위에서부터 모두 적용합니다. 이미 완성한 나머지 메서드는 지정된 교체 범위 밖이면 그대로 둡니다.

먼저 답을 한 문장으로 적고 아래 해설과 비교하세요.

### main.py 수정 위치와 입력 코드

**편집 1.** 파일 맨 위의 기존 준비 코드 전체(이전 print 두 줄 포함)를 **교체**합니다. 아래 코드를 다른 함수나 클래스 안에 넣지 않습니다.

**왜 이렇게 쓰나요 — 이 편집을 읽는 순서**

- **게임 화면·입력·소리를 다루는 도구를 불러옵니다.** pygame은 게임용 기능을 모아 둔 모듈입니다. `import`는 도구를 쓸 수 있게 하는 준비이고, 화면을 만드는 명령 자체는 아닙니다. 따라서 import만 실행해도 우주선이나 창이 생기지 않습니다.

- **화면과 소리 모듈을 사용하기 전에 초기화합니다.** `pygame.init()`은 여러 Pygame 모듈의 준비를 수행합니다. 함수를 쓰려면 이름 뒤에 `()`를 붙여 호출해야 합니다. 함수 이름만 적으면 그 기능을 실행한 것이 아닙니다.

- **화면은 한 번 만들고, 반복문 안에서 내용을 갱신합니다.** `set_mode((가로, 세로))`는 그림을 그릴 Surface를 반환합니다. `screen = ...`은 그 결과를 screen에 보관한다는 뜻입니다. 좌표의 원점은 왼쪽 위이며 x는 오른쪽, y는 아래쪽으로 커집니다. 화면 크기의 튜플과 개별 물체의 위치 튜플을 구별하세요.

```python
# 게임 화면·입력·소리를 다루는 도구를 불러옵니다.
import pygame
import random

# 화면과 소리 모듈을 사용하기 전에 초기화합니다.
pygame.init()

SCREEN_WIDTH = 1200
SCREEN_HEIGHT = 700
# 화면은 한 번 만들고, 반복문 안에서 내용을 갱신합니다.
screen = pygame.display.set_mode((SCREEN_WIDTH, SCREEN_HEIGHT))
pygame.display.set_caption('우주 방어대')

FPS = 60
clock = pygame.time.Clock()
```


**편집 2.** `running = True`부터 파일 마지막 `pygame.quit()`까지의 메인 루프 전체를 **추가**합니다. 아래 코드를 다른 함수나 클래스 안에 넣지 않습니다.

**왜 이렇게 쓰나요 — 이 편집을 읽는 순서**

- **입력과 상태 변화, 그리기를 매 프레임 반복합니다.** 한 프레임은 게임을 한 번 갱신해서 표시하는 주기입니다. 준비 코드·그룹 생성은 while 위에서 한 번만 실행하고, 입력과 이동·그리기는 while 안에서 반복합니다. 물체를 매 프레임 새로 생성하면 위치가 초기화되거나 개수가 계속 늘어납니다. 반복문의 들여쓰기가 게임의 시간 구조를 정합니다.

- **지난 프레임 이후 쌓인 입력 이벤트를 처리합니다.** `event.get()`은 이번에 도착한 사건들을 꺼냅니다. KEYDOWN은 누르기 시작한 사건이고 `key.get_pressed()`는 지금 계속 누르고 있는 상태입니다. 점프·발사 한 번은 이벤트로, 연속 좌우 이동은 누름 상태로 처리하는 이유가 여기에 있습니다. 스튜디오 게임 화면을 클릭해야 입력이 게임으로 전달됩니다.

```python
running = True
# 입력과 상태 변화, 그리기를 매 프레임 반복합니다.
while running:
    # 지난 프레임 이후 쌓인 입력 이벤트를 처리합니다.
    for event in pygame.event.get():
        if event.type == pygame.QUIT:
            running = False

    if not running:
        break

    screen.fill((9, 17, 37))
    pygame.display.update()
    clock.tick(FPS)

pygame.quit()
```


### 코드가 하는 일

set_mode는 (가로, 세로) 튜플을 받습니다. 화면 왼쪽 위가 (0,0), 오른쪽으로 x, 아래로 y가 증가합니다. running은 반복 여부입니다. event.get()은 모인 입력을 꺼냅니다. QUIT을 받으면 False로 바꾸고 break로 반복을 빠져나옵니다. fill은 이전 프레임을 남색으로 덮고 display.update는 그린 내용을 표시합니다. tick(60)은 초당 최대60회로 제한합니다. 실제 처리 속도가 느리면60보다 낮아질 수 있습니다. pygame.quit()은 while 밖에 둡니다.

### main.py 수정 위치와 입력 코드

**편집 1.** `running = True`부터 파일 마지막 `pygame.quit()`까지의 메인 루프 전체를 **교체**합니다. 아래 코드를 다른 함수나 클래스 안에 넣지 않습니다.

```python
while running:
```

**편집 2.** `clock = pygame.time.Clock()` 바로 아래, `running = True` 바로 위에 아래 설계도를 **추가**합니다.

**왜 이렇게 쓰나요 — 이 편집을 읽는 순서**

- **역할이 같은 객체를 만드는 설계도입니다.** `class`는 설계도이고 `Terrain(...)`이나 `Scout(...)` 같은 호출이 실제 객체를 만드는 순간입니다. 클래스 정의만으로 화면에 나타나지 않습니다. `__init__`은 생성할 때 초기 값을 준비하고, `self`는 지금 준비 중인 바로 그 객체를 뜻합니다. 서로 다른 두 객체는 같은 메서드를 사용하지만 위치·속도 같은 값은 각각 가질 수 있습니다.

- **아직 구현하지 않은 자리이며 호출해도 아무 일도 하지 않습니다.** Python은 def/class/if 뒤에 빈 본문을 허용하지 않으므로 pass를 넣습니다. pass는 앞으로 완성할 빈 자리이지 기능 구현이 아닙니다. 설계도 작성 단계에서 화면 변화가 없는 것은 정상입니다. 실제 객체를 생성하고 그리기 전에 image/rect 등 필요한 부분을 채우는 순서를 지키세요.


### 코드가 하는 일

Mission은 전체 규칙, Scout는 아군, Raider는 적, 두 Pulse는 탄환입니다. __init__은 생성 준비, update는 움직임, draw는 HUD 표시, fire는 발사, reset은 위치 복원입니다. self는 그 객체 자신입니다. 메서드 아래 pass는 아직 아무 일도 하지 않는다는 뜻입니다. 빈 본문 대신 pass를 넣어 문법을 지킵니다. Sprite를 상속한 네 클래스는 Pygame Group에 담아 update와 draw를 함께 처리할 수 있습니다. 이때 모든 기능을 외울 필요는 없고 실제 구현할 단원에서 다시 설명합니다.
