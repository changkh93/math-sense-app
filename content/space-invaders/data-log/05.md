코드 안의 `#` 뒤 문장은 **이해를 돕는 설명용 주석**입니다. 주석은 따라 적지 않아도 게임이 똑같이 실행됩니다. 먼저 주석을 읽고 그 아래 코드의 목적을 이해한 뒤, 실행되는 코드와 들여쓰기를 작성하세요. 따옴표 안의 글자, 변수 이름, 괄호와 콜론은 주석이 아니므로 생략하면 안 됩니다. 누적 코드에는 길 찾기에 필요한 핵심 주석만 남겼습니다.

각 편집의 ‘왜 이렇게 쓰나요’를 읽고, 입력하기 전에 결과를 예상해 보세요. 이번 단계의 편집을 모두 마친 다음 실행합니다. 중간에 아직 정의하지 않은 이름을 참조할 수 있으므로 편집 하나마다 실행하지 않습니다. 실행 후에는 화면이 맞는지만 보지 말고, **어떤 값이 바뀌어 그 결과가 생겼는지** 한 문장으로 설명해 보세요. 누적 코드는 먼저 직접 시도한 뒤 비교·복구할 때 사용합니다.


## 05-A - 적의 생성·이동·복원 설계도 작성하기

적도 Sprite이지만 각자 시작 위치와 방향을 기억해야 합니다. 실제 편대 생성은 다음 단원입니다. 이번에는 설계도를 작은 메서드 세 개로 채웁니다.

**이 단계의 연결:** 출발 코드는 **04-C**의 누적 코드입니다. 아래 편집은 위에서부터 모두 적용합니다. 이미 완성한 나머지 메서드는 지정된 교체 범위 밖이면 그대로 둡니다.

### main.py 수정 위치와 입력 코드

**편집 1.** `class Raider` 안의 `def __init__`부터 그 메서드 본문 끝까지 **전체 교체**합니다. 다음 def나 다음 class는 지우지 않습니다. def 앞4칸, 본문 앞8칸을 유지합니다.

**왜 이렇게 쓰나요 — 이 편집을 읽는 순서**

- **PNG의 투명한 여백을 유지합니다.** `image.load`로 읽은 Surface를 `convert_alpha()`로 투명도를 유지하는 표시 형식으로 바꿉니다. 투명한 여백까지 배경색 사각형으로 그리지 않기 위한 준비입니다. `smoothscale(그림, (가로, 세로))`은 그다음 표시 크기를 맞춥니다. 여러 함수가 한 줄에 겹쳐 있으면 가장 안쪽 호출부터 읽으세요.

- **부모 Sprite의 내부 준비를 먼저 실행합니다.** `super().__init__()`은 상속받은 Sprite 내부를 준비합니다. 괄호 안에 그룹이 있으면 그 그룹에 이 객체를 바로 등록합니다. `super().__init__(tiles)`는 tiles에 자동 등록하지만 인수가 없는 `super().__init__()`은 자동 등록하지 않으므로 나중에 `그룹.add(객체)`가 필요합니다. 이 차이를 확인하고 중복 생성하지 마세요.

- **그림의 크기와 화면 위치를 담을 상자를 만듭니다.** `image`는 그림이고 `rect`는 그 그림을 놓을 사각형입니다. `get_rect(topleft=(x, y))`는 왼쪽 위, `midbottom=(x, y)`는 발 가운데를 해당 위치에 맞춥니다. 예를 들어 64×64 그림의 midbottom이 (100, 200)이면 왼쪽 위는 (68, 136)입니다. 같은 좌표라도 기준점이 다르면 표시 위치가 달라집니다. Group.draw는 각 객체의 image와 rect를 읽습니다.

- **첫 적이 공용 자료를 준비했는지 검사합니다.** hasattr(클래스, 이름)은 해당 속성이 있는지 확인합니다. 첫 생성 시 이미지와 소리를 클래스 속성에 저장하면 이후 적은 이 조건을 건너뜁니다. self.rect는 각 적에서 따로 생성해야 위치가 공유되지 않습니다. 자료 재사용과 게임 상태 공유를 혼동하지 마세요.

- **소리 파일을 준비하는 일과 재생하는 일을 구분합니다.** Sound 또는 load_sound는 소리를 사용할 준비입니다. .play()를 호출하는 순간 재생을 시도합니다. 생성자에서 준비하고 실제 발사·충돌 사건에서 재생해야 매 프레임 파일을 읽거나 준비만 했는데 소리가 날 것으로 기대하지 않습니다.

```python
    # 객체를 생성할 때 필요한 초기 값과 참조를 준비합니다.
    def __init__(self, x, y, velocity, pulse_group):
        # 부모 Sprite의 내부 준비를 먼저 실행합니다.
        super().__init__()
        # 첫 적이 공용 자료를 준비했는지 검사합니다.
        if not hasattr(Raider, 'shared_image'):
            Raider.shared_image = pygame.transform.smoothscale(
                pygame.image.load('assets/raider.png').convert_alpha(), (56, 48)
            )
            # 소리 파일을 준비하는 일과 재생하는 일을 구분합니다.
            Raider.shared_shoot_sound = pygame.mixer.Sound('assets/raider_pulse.ogg')
        self.image = Raider.shared_image
        # 그림의 크기와 화면 위치를 담을 상자를 만듭니다.
        self.rect = self.image.get_rect()
        self.rect.topleft = (x, y)
        self.starting_x = x
        self.starting_y = y
        self.direction = 1
        self.velocity = velocity
        self.pulses = pulse_group
        self.shoot_sound = Raider.shared_shoot_sound
```


**편집 2.** `class Raider` 안의 `def update`부터 그 메서드 본문 끝까지 **전체 교체**합니다. 다음 def나 다음 class는 지우지 않습니다. def 앞4칸, 본문 앞8칸을 유지합니다.

**왜 이렇게 쓰나요 — 이 편집을 읽는 순서**

- **각 적이 매 프레임 확률에 따라 발사를 시도합니다.** `randint(0,1000)`은 양끝을 포함해 1001개 정수 중 하나를 고릅니다. `>999`에 해당하는 수는 1000 하나입니다. 1000프레임마다 반드시 발사한다는 뜻이 아니며 연속 성공이나 긴 실패도 가능합니다. 여기에 공유 탄환 그룹의 개수 조건이 함께 참이어야 실제 발사가 이루어집니다.

- **보이지 않는 탄환도 그룹에 남아 있으면 개수에 포함됩니다.** len은 발사한 누적 횟수가 아니라 지금 그룹에 들어 있는 객체 수를 셉니다. 화면 밖 탄환을 제거하지 않으면 제한에 도달한 뒤 영원히 발사할 수 없습니다. 따라서 발사 제한과 이탈 제거는 서로 연결된 기능입니다. 소리도 허용 조건 안에 두어 발사되지 않았는데 소리만 나는 일을 막습니다.

```python
    # 그룹에서 호출하는 한 프레임의 처리 순서입니다.
    def update(self):
        self.rect.x += self.direction * self.velocity
        # 각 적이 매 프레임 확률에 따라 발사를 시도합니다.
        if random.randint(0, 1000) > 999 and len(self.pulses) < 3:
            self.shoot_sound.play()
            self.fire()
```


**편집 3.** `class Raider` 안의 `def reset`부터 그 메서드 본문 끝까지 **전체 교체**합니다. 다음 def나 다음 class는 지우지 않습니다. def 앞4칸, 본문 앞8칸을 유지합니다.

```python
    # 정해 둔 시작 상태로 이 객체를 복귀시킵니다.
    def reset(self):
        self.rect.topleft = (self.starting_x, self.starting_y)
        self.direction = 1
```


### 코드가 하는 일

x/y는 전달받은 시작 좌표, velocity는 이동거리입니다. hasattr(Raider, "shared_image")는 클래스에 공용 그림이 준비됐는지 검사합니다. 첫 적만 그림·소리를 로드해 Raider.shared_image/shared_shoot_sound에 저장하고 이후 적은 같은 자료를 참조합니다.55기마다 고해상도 그림을 다시 읽고 축소하지 않아 새 편대 준비를 줄입니다. 각 적의 rect는 따로 만들어 위치는 공유하지 않습니다. 이미지56×48의 rect.topleft에 좌표를 넣고 starting_x/y에도 별도로 기억합니다. direction=1은 오른쪽, -1은 왼쪽입니다. direction*velocity로 두 방향을 같은 식으로 처리합니다. randint(0,1000)은 양끝 포함1001가지이고 >999는1000 하나만 선택하므로 확률1/1001입니다. 한 적·60FPS·탄환 제한이 없다는 가정에서 평균 대기시간은 약16.7초이며 고정 주기가 아닙니다. 모든 적이 같은 pulses 그룹을 참조해 총3발을 제한합니다. fire는 아직 pass라 소리 호출 외 탄환 생성은06에서 완성합니다. reset은 시작좌표와 오른쪽 방향을 복원합니다.
