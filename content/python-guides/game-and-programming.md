“게임을 좋아하니까 코딩도 좋아하지 않을까요?” 관심을 여는 출발점은 될 수 있습니다. 하지만 게임을 플레이하는 일과 만드는 일은 다른 시간을 요구합니다. 만들 때는 재미있는 장면 사이에 숫자를 조정하고, 오류를 읽고, 다시 실행하는 시간이 끼어듭니다.

## 게임 하나에는 여러 작은 규칙이 있습니다

캐릭터가 오른쪽으로 가려면 위치 값이 변해야 합니다. 벽을 통과하지 않으려면 이동 가능한 범위를 확인해야 합니다. 점수를 보여주려면 값을 저장하고 화면에 그려야 합니다. 게임이라는 결과물 아래에 좌표·조건·반복·함수가 자리 잡고 있습니다.

한 번에 완성 게임을 요구하기보다 “오른쪽 끝에서 더 나가지 않게 만들기”처럼 규칙 하나를 맡겨 보세요. 제대로 작동했는지 확인하는 기준도 선명해집니다.

## 변수는 체력, 조건문은 게임의 약속

```python
health = 3
hit = True
if hit:
    health = health - 1
print(health)
```

위 코드는 충돌 장면을 그리지는 않습니다. 충돌했다고 정한 경우 체력을 한 칸 줄이는 규칙만 확인합니다. 출력값은 2입니다. 그림을 붙이기 전에 규칙을 작은 코드로 확인하면 화면 문제와 계산 문제를 구분하기 쉽습니다.

## 부모가 물어볼 것은 점수보다 규칙입니다

“몇 점 땄어?” 대신 “점수가 언제 올라가게 만들었어?”를 물어보세요. 아이가 직접 정한 규칙이 있는지 확인할 수 있습니다. 코드 전체를 설명하지 못하더라도, 바꾼 부분과 달라진 결과를 연결하면 대화가 됩니다.

## 게임 제작만으로 끝나지 않으려면

체력을 관리하던 변수는 다른 프로젝트에서 재고 수량이나 횟수를 담을 수 있습니다. 충돌 여부를 판단하던 조건은 점수 구간을 나누는 데도 쓰입니다. 같은 개념을 다른 상황에 옮겨보는 활동이 필요합니다. 메타센스는 그림·게임에 이어 수학과 데이터 등 서로 다른 프로젝트를 소개합니다. 게임을 완성했다는 사실만으로 모든 기초를 이해했다고 판단하지는 않습니다.
