## 코드를 읽고 작성하는 방법

코드 안의 `#` 뒤 문장은 **이해를 돕는 설명용 주석**입니다. 주석은 따라 적지 않아도 게임이 똑같이 실행됩니다. 먼저 주석을 읽고 그 아래 코드의 목적을 이해한 뒤, 실행되는 코드와 들여쓰기를 작성하세요. 따옴표 안의 글자, 변수 이름, 괄호와 콜론은 주석이 아니므로 생략하면 안 됩니다. 누적 코드에는 길 찾기에 필요한 핵심 주석만 남겼습니다.

### 수정 위치와 입력할 코드

**편집 1.** `class Explorer` 안의 `__init__` 메서드 전체를 아래 코드로 교체합니다. 다음 `def` 직전까지가 교체 범위입니다. `def` 앞 4칸, 본문 앞 8칸을 유지합니다.

**왜 이렇게 쓰나요 — 이 편집을 읽는 순서**

- **부모 Sprite의 내부 준비를 먼저 실행합니다.** `super().__init__()`은 상속받은 Sprite 내부를 준비합니다. 괄호 안에 그룹이 있으면 그 그룹에 이 객체를 바로 등록합니다. `super().__init__(tiles)`는 tiles에 자동 등록하지만 인수가 없는 `super().__init__()`은 자동 등록하지 않으므로 나중에 `그룹.add(객체)`가 필요합니다. 이 차이를 확인하고 중복 생성하지 마세요.

- **그림의 크기와 화면 위치를 담을 상자를 만듭니다.** `image`는 그림이고 `rect`는 그 그림을 놓을 사각형입니다. `get_rect(topleft=(x, y))`는 왼쪽 위, `midbottom=(x, y)`는 발 가운데를 해당 위치에 맞춥니다. 예를 들어 64×64 그림의 midbottom이 (100, 200)이면 왼쪽 위는 (68, 136)입니다. 같은 좌표라도 기준점이 다르면 표시 위치가 달라집니다. Group.draw는 각 객체의 image와 rect를 읽습니다.

- **이동하기 전 위치를 별도로 기억합니다.** 현재 rect를 바로 대입하면 같은 상자를 가리킬 수 있으므로 `.copy()`로 별도 상자를 만듭니다. 이전 발 높이 90, 현재 발 높이 110, 발판 윗면 100이라면 중간에 발판을 통과했다는 것을 알 수 있습니다. 현재 위치만 검사할 때 놓칠 수 있는 빠른 낙하를 이 두 시점으로 잡습니다.

- **위치·속도·가속도를 구별하고 이번 프레임 힘을 준비합니다.** position은 어디 있는지, velocity는 한 기준 프레임 동안 얼마나 움직이는지, acceleration은 속도가 얼마나 변하는지입니다. Vector2는 x와 y를 묶어 두 방향을 함께 계산합니다. 이동 시작마다 가속도를 다시 정해야 이전 프레임의 입력·마찰이 계속 누적되지 않습니다. 중력이 있는 단계에서는 y 가속도에 gravity를 넣습니다.

- **호출 결과를 이 객체의 그림 속성에 보관합니다.** 대입은 오른쪽을 먼저 계산하고 그 결과를 왼쪽 이름에 저장합니다. self.image는 이번 객체가 사용할 그림입니다. load_image가 그림을 반환해야 그다음 get_rect를 호출할 수 있습니다. self.x처럼 self가 붙은 값은 메서드가 끝나도 객체에 남아 다른 메서드에서 사용할 수 있습니다.

```python
    # 객체를 생성할 때 필요한 초기 값과 참조를 준비합니다.
    def __init__(self, x, y, platforms, hazards):
        # 부모 Sprite의 내부 준비를 먼저 실행합니다.
        super().__init__()
        # 호출 결과를 이 객체의 그림 속성에 보관합니다.
        self.image = load_image('assets/explorer/idle/0.png', (64, 64))
        # 그림의 크기와 화면 위치를 담을 상자를 만듭니다.
        self.rect = self.image.get_rect(midbottom=(x, y))
        self.position = Vector(x, y)
        self.velocity = Vector(0, 0)
        # 위치·속도·가속도를 구별하고 이번 프레임 힘을 준비합니다.
        self.acceleration = Vector(0, 0)
        self.horizontal_acceleration = 2
        self.friction = 0.15
        self.gravity = 0.5
        self.platforms = platforms
        self.hazards = hazards
        self.start = Vector(x, y)
        # 이동하기 전 위치를 별도로 기억합니다.
        self.previous_rect = self.rect.copy()
        self.grounded = False
        self.jump_speed = 15
```

**편집 2.** `class Explorer` 안에서 기존 메서드 뒤에 새 `jump` 메서드를 추가합니다. 다른 class가 시작되기 전에 넣고 def 앞 4칸을 유지합니다.

**왜 이렇게 쓰나요 — 이 편집을 읽는 순서**

- **발판에 서 있을 때만 점프를 허용합니다.** 화면 좌표는 아래가 양수이므로 위로 점프하려면 y속도가 음수여야 합니다. 점프 순간 grounded를 False로 바꾸지 않으면 다음 착지 전에 또 점프할 수 있습니다. grounded는 그림이 바닥 가까이 보이는지가 아니라 충돌 코드가 계산한 지지 상태입니다.

```python
    # 점프가 가능한 상태인지 확인하고 상승 속도를 줍니다.
    def jump(self):
        # 발판에 서 있을 때만 점프를 허용합니다.
        if self.grounded:
            self.velocity.y = -self.jump_speed
            self.grounded = False
```

**편집 3.** **수정 위치:** running = True부터 파일 마지막 pygame.quit()까지의 실행 루프 전체. 아래 코드로 교체합니다. 클래스나 메서드 안에 넣지 않습니다.

**왜 이렇게 쓰나요 — 이 편집을 읽는 순서**

- **입력과 상태 변화, 그리기를 매 프레임 반복합니다.** 한 프레임은 게임을 한 번 갱신해서 표시하는 주기입니다. 준비 코드·그룹 생성은 while 위에서 한 번만 실행하고, 입력과 이동·그리기는 while 안에서 반복합니다. 물체를 매 프레임 새로 생성하면 위치가 초기화되거나 개수가 계속 늘어납니다. 반복문의 들여쓰기가 게임의 시간 구조를 정합니다.

- **지난 프레임 이후 쌓인 입력 이벤트를 처리합니다.** `event.get()`은 이번에 도착한 사건들을 꺼냅니다. KEYDOWN은 누르기 시작한 사건이고 `key.get_pressed()`는 지금 계속 누르고 있는 상태입니다. 점프·발사 한 번은 이벤트로, 연속 좌우 이동은 누름 상태로 처리하는 이유가 여기에 있습니다. 스튜디오 게임 화면을 클릭해야 입력이 게임으로 전달됩니다.

- **밀리초를 초로 바꾸고 지나치게 긴 프레임을 제한합니다.** `clock.tick(FPS)`는 최대 프레임 속도를 제한하고 경과 밀리초를 줍니다. 16밀리초는 16/1000=0.016초입니다. `min(..., 0.05)`는 긴 탭 전환 시간을 한 번의 큰 이동으로 적용하지 않기 위한 상한입니다. 따라서 오래 다른 탭에 머문 실제 시간과 게임 안 경과 시간이 항상 같지는 않습니다.

- **그룹의 image와 rect를 사용해 화면에 그립니다.** 그룹의 `update()`는 각 객체의 update를 호출하고, `draw(screen)`은 image를 rect 위치에 그립니다. update만 하면 값만 바뀌고, draw만 하면 같은 그림이 같은 위치에 남습니다. 배경 → 물체 → HUD/안내 순서로 그려야 뒤에 그린 배경이 물체를 덮지 않습니다. 마지막 display.update가 그린 화면을 표시합니다.

```python
running = True
# 입력과 상태 변화, 그리기를 매 프레임 반복합니다.
while running:
    # 밀리초를 초로 바꾸고 지나치게 긴 프레임을 제한합니다.
    seconds = min(clock.tick(FPS) / 1000, 0.05)
    # 지난 프레임 이후 쌓인 입력 이벤트를 처리합니다.
    for event in pygame.event.get():
        if event.type == pygame.QUIT:
            running = False
        elif event.type == pygame.KEYDOWN and event.key == pygame.K_SPACE:
            explorer.jump()
    if not running:
        break
    explorers.update(seconds)
    screen.blit(background, (0, 0))
    # 그룹의 image와 rect를 사용해 화면에 그립니다.
    tiles.draw(screen)
    # 그룹의 image와 rect를 사용해 화면에 그립니다.
    explorers.draw(screen)
    pygame.display.update()

pygame.quit()
```

**왜 이렇게 쓰나요 — 이 편집을 읽는 순서**

- **이번 프레임에 계속 눌린 방향키를 읽습니다.** `keys[pygame.K_LEFT]`는 왼쪽 키가 눌렸는지 알려주는 값입니다. if의 본문은 참일 때만 실행됩니다. 두 독립 if는 둘 다 실행될 수 있고 if/elif는 첫 참 분기만 실행됩니다. 양쪽 키를 동시에 누른 경우를 떠올리면 차이가 드러납니다.

- **이동하기 전 위치를 별도로 기억합니다.** 현재 rect를 바로 대입하면 같은 상자를 가리킬 수 있으므로 `.copy()`로 별도 상자를 만듭니다. 이전 발 높이 90, 현재 발 높이 110, 발판 윗면 100이라면 중간에 발판을 통과했다는 것을 알 수 있습니다. 현재 위치만 검사할 때 놓칠 수 있는 빠른 낙하를 이 두 시점으로 잡습니다.

- **위치·속도·가속도를 구별하고 이번 프레임 힘을 준비합니다.** position은 어디 있는지, velocity는 한 기준 프레임 동안 얼마나 움직이는지, acceleration은 속도가 얼마나 변하는지입니다. Vector2는 x와 y를 묶어 두 방향을 함께 계산합니다. 이동 시작마다 가속도를 다시 정해야 이전 프레임의 입력·마찰이 계속 누적되지 않습니다. 중력이 있는 단계에서는 y 가속도에 gravity를 넣습니다.

- **현재 이동 방향의 반대로 마찰을 적용합니다.** 속도 10, 마찰 0.15라면 x 가속도에서 1.5를 뺍니다. 속도 -10이면 -1.5를 빼므로 오른쪽으로 1.5를 더하는 효과입니다. 두 경우 모두 속력이 줄어드는 방향입니다. 키를 놓으면 입력 가속도는 사라져도 마찰은 남으므로 즉시 정지하지 않고 서서히 멈춥니다.

- **이전 속도로 위치를 계산한 뒤 다음 줄에서 속도를 갱신합니다.** `scale=seconds*FPS`는 기준 60FPS 한 프레임에 대한 시간 비율입니다. scale=1, 이전 속도 4, 가속도 2이면 위치 변화는 4+0.5×2=5, 다음 속도는 6입니다. 속도를 먼저 6으로 바꾼 뒤 같은 위치 식을 쓰면 7이 되어 가속도를 중복 반영합니다. position은 소수를 보존하고 rect는 화면 표시용 정수 위치를 받습니다.

- **낙하 경로가 발판 윗면을 지나갔는지 검사합니다.** 가로 지지 범위가 발판과 겹치는지 먼저 확인한 뒤 세로 통과를 검사합니다. 착지하면 위치를 발판 윗면으로 맞추고 y속도를 0으로 바꿉니다. rect만 고치면 다음 이동에서 position의 옛 값이 되살아나므로 둘 다 맞춰야 합니다. 위쪽 발판부터 검사하고 첫 착지에서 break하는 순서도 필요합니다.

- **객체 하나와 그룹을 비교하고 충돌한 대상 목록을 받습니다.** `spritecollide(객체, 그룹, 제거여부)`는 겹친 대상들의 리스트를 반환합니다. 빈 리스트는 if에서 거짓, 한 개 이상은 참입니다. if 본문을 한 번 실행하는 규칙과 len(목록)만큼 보상을 계산하는 규칙은 다릅니다. 여러 탄환 피격은 생명 한 번 차감, 결정 여러 개 회수는 개수별 보상이라는 해당 단계의 의도를 읽으세요.

- **높은 발판부터 검사하도록 비교 기준을 지정합니다.** sorted는 원래 그룹을 바꾸지 않고 정렬된 목록을 줍니다. lambda tile: tile.rect.top은 타일 하나를 받아 윗면 높이를 반환하는 짧은 함수입니다. 화면의 작은 y가 위쪽이므로 작은 top부터 검사합니다. 한 프레임에 여러 발판 높이를 통과했을 때 먼저 만난 윗면에 착지시키려는 순서입니다.

- **이번 대상의 나머지 검사를 건너뛰고 다음 대상으로 갑니다.** continue는 가장 가까운 반복문의 다음 반복으로 이동합니다. 발판과 가로 범위가 겹치지 않으면 그 발판의 세로 착지 검사를 생략합니다. break는 반복문 전체를 끝내고 return은 메서드를 끝냅니다. 세 명령이 어느 범위를 빠져나가는지 들여쓰기를 따라 확인하세요.

```python
    # 그룹에서 호출하는 한 프레임의 처리 순서입니다.
    def update(self, seconds=1 / FPS):
        # 이동하기 전 위치를 별도로 기억합니다.
        self.previous_rect = self.rect.copy()
        # 위치·속도·가속도를 구별하고 이번 프레임 힘을 준비합니다.
        self.acceleration = Vector(0, self.gravity)
        # 이번 프레임에 계속 눌린 방향키를 읽습니다.
        keys = pygame.key.get_pressed()
        if keys[pygame.K_LEFT]:
            self.acceleration.x = -self.horizontal_acceleration
        elif keys[pygame.K_RIGHT]:
            self.acceleration.x = self.horizontal_acceleration
        # 현재 이동 방향의 반대로 마찰을 적용합니다.
        self.acceleration.x -= self.velocity.x * self.friction
        scale = min(seconds * FPS, 3)
        # 이전 속도로 위치를 계산한 뒤 다음 줄에서 속도를 갱신합니다.
        self.position += self.velocity * scale + 0.5 * self.acceleration * scale * scale
        self.velocity += self.acceleration * scale
        self.rect.midbottom = self.position
        self.grounded = False
        # 높은 발판부터 검사하도록 비교 기준을 지정합니다.
        for tile in sorted(self.platforms, key=lambda tile: tile.rect.top):
            if self.rect.right <= tile.rect.left or self.rect.left >= tile.rect.right:
                # 이번 대상의 나머지 검사를 건너뛰고 다음 대상으로 갑니다.
                continue
            # 낙하 경로가 발판 윗면을 지나갔는지 검사합니다.
            if self.velocity.y >= 0 and self.previous_rect.bottom <= tile.rect.top + 1 <= self.rect.bottom + 1:
                self.position.y = tile.rect.top
                self.velocity.y = 0
                self.rect.midbottom = self.position
                self.grounded = True
                break
        # 객체 하나와 그룹을 비교하고 충돌한 대상 목록을 받습니다.
        if pygame.sprite.spritecollide(self, self.hazards, False):
            print('지열 위험 구역에 닿았습니다')
```

- **낙하 경로가 발판 윗면을 지나갔는지 검사합니다.** 가로 지지 범위가 발판과 겹치는지 먼저 확인한 뒤 세로 통과를 검사합니다. 착지하면 위치를 발판 윗면으로 맞추고 y속도를 0으로 바꿉니다. rect만 고치면 다음 이동에서 position의 옛 값이 되살아나므로 둘 다 맞춰야 합니다. 위쪽 발판부터 검사하고 첫 착지에서 break하는 순서도 필요합니다.

```python
    # 그룹에서 호출하는 한 프레임의 처리 순서입니다.
    def update(self, seconds=1 / FPS):
        # 이동하기 전 위치를 별도로 기억합니다.
        self.previous_rect = self.rect.copy()
        # 위치·속도·가속도를 구별하고 이번 프레임 힘을 준비합니다.
        self.acceleration = Vector(0, self.gravity)
        # 이번 프레임에 계속 눌린 방향키를 읽습니다.
        keys = pygame.key.get_pressed()
        if keys[pygame.K_LEFT]:
            self.acceleration.x = -self.horizontal_acceleration
        elif keys[pygame.K_RIGHT]:
            self.acceleration.x = self.horizontal_acceleration
        # 현재 이동 방향의 반대로 마찰을 적용합니다.
        self.acceleration.x -= self.velocity.x * self.friction
        scale = min(seconds * FPS, 3)
        # 이전 속도로 위치를 계산한 뒤 다음 줄에서 속도를 갱신합니다.
        self.position += self.velocity * scale + 0.5 * self.acceleration * scale * scale
        self.velocity += self.acceleration * scale
        # 화면의 한쪽 끝을 반대쪽 끝으로 이어 줍니다.
        self.position.x %= SCREEN_WIDTH
        self.rect.midbottom = self.position
        self.grounded = False
        # 높은 발판부터 검사하도록 비교 기준을 지정합니다.
        for tile in sorted(self.platforms, key=lambda tile: tile.rect.top):
            if self.rect.right <= tile.rect.left or self.rect.left >= tile.rect.right:
                # 이번 대상의 나머지 검사를 건너뛰고 다음 대상으로 갑니다.
                continue
            # 낙하 경로가 발판 윗면을 지나갔는지 검사합니다.
            if self.velocity.y >= 0 and self.previous_rect.bottom <= tile.rect.top + 1 <= self.rect.bottom + 1:
                self.position.y = tile.rect.top
                self.velocity.y = 0
                self.rect.midbottom = self.position
                self.grounded = True
                break
        # 객체 하나와 그룹을 비교하고 충돌한 대상 목록을 받습니다.
        if pygame.sprite.spritecollide(self, self.hazards, False):
            # 시작 위치 자체가 바뀌지 않도록 복사해서 복귀합니다.
            self.position = self.start.copy()
            self.velocity = Vector(0, 0)
            self.rect.midbottom = self.position
            self.grounded = False
```

- **위치·속도·가속도를 구별하고 이번 프레임 힘을 준비합니다.** position은 어디 있는지, velocity는 한 기준 프레임 동안 얼마나 움직이는지, acceleration은 속도가 얼마나 변하는지입니다. Vector2는 x와 y를 묶어 두 방향을 함께 계산합니다. 이동 시작마다 가속도를 다시 정해야 이전 프레임의 입력·마찰이 계속 누적되지 않습니다. 중력이 있는 단계에서는 y 가속도에 gravity를 넣습니다.

- **현재 이동 방향의 반대로 마찰을 적용합니다.** 속도 10, 마찰 0.15라면 x 가속도에서 1.5를 뺍니다. 속도 -10이면 -1.5를 빼므로 오른쪽으로 1.5를 더하는 효과입니다. 두 경우 모두 속력이 줄어드는 방향입니다. 키를 놓으면 입력 가속도는 사라져도 마찰은 남으므로 즉시 정지하지 않고 서서히 멈춥니다.

- **이전 속도로 위치를 계산한 뒤 다음 줄에서 속도를 갱신합니다.** `scale=seconds*FPS`는 기준 60FPS 한 프레임에 대한 시간 비율입니다. scale=1, 이전 속도 4, 가속도 2이면 위치 변화는 4+0.5×2=5, 다음 속도는 6입니다. 속도를 먼저 6으로 바꾼 뒤 같은 위치 식을 쓰면 7이 되어 가속도를 중복 반영합니다. position은 소수를 보존하고 rect는 화면 표시용 정수 위치를 받습니다.

- **화면의 한쪽 끝을 반대쪽 끝으로 이어 줍니다.** 나머지 연산은 x를 0 이상 화면 폭 미만으로 돌려놓습니다. 폭이 960이면 -5 % 960은 955, 965 % 960은 5입니다. 벽에서 멈추는 방식과 다른 규칙입니다. 고친 position을 rect에 반영해야 화면에서도 이동이 보입니다.

```python
    # 입력 또는 정해진 속도로 위치를 갱신합니다.
    def move(self, seconds):
        # 이동하기 전 위치를 별도로 기억합니다.
        self.previous_rect = self.rect.copy()
        # 위치·속도·가속도를 구별하고 이번 프레임 힘을 준비합니다.
        self.acceleration = Vector(0, self.gravity)
        # 이번 프레임에 계속 눌린 방향키를 읽습니다.
        keys = pygame.key.get_pressed()
        if keys[pygame.K_LEFT]:
            self.acceleration.x = -self.horizontal_acceleration
        elif keys[pygame.K_RIGHT]:
            self.acceleration.x = self.horizontal_acceleration
        # 현재 이동 방향의 반대로 마찰을 적용합니다.
        self.acceleration.x -= self.velocity.x * self.friction
        scale = min(seconds * FPS, 3)
        # 이전 속도로 위치를 계산한 뒤 다음 줄에서 속도를 갱신합니다.
        self.position += self.velocity * scale + 0.5 * self.acceleration * scale * scale
        self.velocity += self.acceleration * scale
        # 화면의 한쪽 끝을 반대쪽 끝으로 이어 줍니다.
        self.position.x %= SCREEN_WIDTH
        self.rect.midbottom = self.position
```

**왜 이렇게 쓰나요 — 이 편집을 읽는 순서**

- **낙하 경로가 발판 윗면을 지나갔는지 검사합니다.** 가로 지지 범위가 발판과 겹치는지 먼저 확인한 뒤 세로 통과를 검사합니다. 착지하면 위치를 발판 윗면으로 맞추고 y속도를 0으로 바꿉니다. rect만 고치면 다음 이동에서 position의 옛 값이 되살아나므로 둘 다 맞춰야 합니다. 위쪽 발판부터 검사하고 첫 착지에서 break하는 순서도 필요합니다.

- **시작 위치 자체가 바뀌지 않도록 복사해서 복귀합니다.** `self.start`는 복귀 기준, `self.position`은 지금 움직이는 위치입니다. 같은 벡터를 공유하면 이동하면서 시작점도 변하므로 copy를 씁니다. 위치만 복원하고 속도를 남기면 복귀 직후 다시 빠르게 날아갈 수 있습니다. reset에서 어떤 값을 함께 되돌리는지 확인하세요.

- **객체 하나와 그룹을 비교하고 충돌한 대상 목록을 받습니다.** `spritecollide(객체, 그룹, 제거여부)`는 겹친 대상들의 리스트를 반환합니다. 빈 리스트는 if에서 거짓, 한 개 이상은 참입니다. if 본문을 한 번 실행하는 규칙과 len(목록)만큼 보상을 계산하는 규칙은 다릅니다. 여러 탄환 피격은 생명 한 번 차감, 결정 여러 개 회수는 개수별 보상이라는 해당 단계의 의도를 읽으세요.

- **높은 발판부터 검사하도록 비교 기준을 지정합니다.** sorted는 원래 그룹을 바꾸지 않고 정렬된 목록을 줍니다. lambda tile: tile.rect.top은 타일 하나를 받아 윗면 높이를 반환하는 짧은 함수입니다. 화면의 작은 y가 위쪽이므로 작은 top부터 검사합니다. 한 프레임에 여러 발판 높이를 통과했을 때 먼저 만난 윗면에 착지시키려는 순서입니다.

- **이번 대상의 나머지 검사를 건너뛰고 다음 대상으로 갑니다.** continue는 가장 가까운 반복문의 다음 반복으로 이동합니다. 발판과 가로 범위가 겹치지 않으면 그 발판의 세로 착지 검사를 생략합니다. break는 반복문 전체를 끝내고 return은 메서드를 끝냅니다. 세 명령이 어느 범위를 빠져나가는지 들여쓰기를 따라 확인하세요.

```python
    # 접촉 대상을 검사하고 이 단계의 충돌 규칙을 적용합니다.
    def check_collisions(self):
        self.grounded = False
        # 높은 발판부터 검사하도록 비교 기준을 지정합니다.
        for tile in sorted(self.platforms, key=lambda tile: tile.rect.top):
            if self.rect.right <= tile.rect.left or self.rect.left >= tile.rect.right:
                # 이번 대상의 나머지 검사를 건너뛰고 다음 대상으로 갑니다.
                continue
            # 낙하 경로가 발판 윗면을 지나갔는지 검사합니다.
            if self.velocity.y >= 0 and self.previous_rect.bottom <= tile.rect.top + 1 <= self.rect.bottom + 1:
                self.position.y = tile.rect.top
                self.velocity.y = 0
                self.rect.midbottom = self.position
                self.grounded = True
                break
        # 객체 하나와 그룹을 비교하고 충돌한 대상 목록을 받습니다.
        if pygame.sprite.spritecollide(self, self.hazards, False):
            # 시작 위치 자체가 바뀌지 않도록 복사해서 복귀합니다.
            self.position = self.start.copy()
            self.velocity = Vector(0, 0)
            self.rect.midbottom = self.position
            self.grounded = False
```
