## 07-A - 달리기 프레임 준비와 첫 이미지

여러 프레임을 리스트에 넣고 첫 프레임을 현재 image로 선택합니다.

**이 단계의 연결:** 출발 코드는 **06-C**의 누적 코드입니다. 아래 편집은 위에서부터 모두 적용합니다. 이미 완성한 나머지 메서드는 지정된 교체 범위 밖이면 그대로 둡니다.


### 입력 전에 결과를 예상해 보세요

이미지 네 장을 읽어 리스트에 넣으면 저절로 애니메이션이 되나요?

먼저 답을 한 문장으로 적고 아래 해설과 비교하세요.

**생각 확인:** 아닙니다. 현재 image를 시간에 따라 다른 장으로 바꾸어야 합니다. 이번 단계는 자료 준비, 다음 단계는 프레임 선택입니다.

### 수정 위치와 입력할 코드

**편집 1.** `class Explorer` 안의 `__init__` 메서드 전체를 아래 코드로 교체합니다. 다음 `def` 직전까지가 교체 범위입니다. `def` 앞 4칸, 본문 앞 8칸을 유지합니다.

**왜 이렇게 쓰나요 — 이 편집을 읽는 순서**

- **부모 Sprite의 내부 준비를 먼저 실행합니다.** `super().__init__()`은 상속받은 Sprite 내부를 준비합니다. 괄호 안에 그룹이 있으면 그 그룹에 이 객체를 바로 등록합니다. `super().__init__(tiles)`는 tiles에 자동 등록하지만 인수가 없는 `super().__init__()`은 자동 등록하지 않으므로 나중에 `그룹.add(객체)`가 필요합니다. 이 차이를 확인하고 중복 생성하지 마세요.

- **그림의 크기와 화면 위치를 담을 상자를 만듭니다.** `image`는 그림이고 `rect`는 그 그림을 놓을 사각형입니다. `get_rect(topleft=(x, y))`는 왼쪽 위, `midbottom=(x, y)`는 발 가운데를 해당 위치에 맞춥니다. 예를 들어 64×64 그림의 midbottom이 (100, 200)이면 왼쪽 위는 (68, 136)입니다. 같은 좌표라도 기준점이 다르면 표시 위치가 달라집니다. Group.draw는 각 객체의 image와 rect를 읽습니다.

- **이동하기 전 위치를 별도로 기억합니다.** 현재 rect를 바로 대입하면 같은 상자를 가리킬 수 있으므로 `.copy()`로 별도 상자를 만듭니다. 이전 발 높이 90, 현재 발 높이 110, 발판 윗면 100이라면 중간에 발판을 통과했다는 것을 알 수 있습니다. 현재 위치만 검사할 때 놓칠 수 있는 빠른 낙하를 이 두 시점으로 잡습니다.

- **위치·속도·가속도를 구별하고 이번 프레임 힘을 준비합니다.** position은 어디 있는지, velocity는 한 기준 프레임 동안 얼마나 움직이는지, acceleration은 속도가 얼마나 변하는지입니다. Vector2는 x와 y를 묶어 두 방향을 함께 계산합니다. 이동 시작마다 가속도를 다시 정해야 이전 프레임의 입력·마찰이 계속 누적되지 않습니다. 중력이 있는 단계에서는 y 가속도에 gravity를 넣습니다.

- **문자열 안에 현재 종류나 번호를 넣어 에셋 경로를 만듭니다.** 문자열 앞 f는 중괄호 안의 값을 글자로 끼워 넣습니다. kind가 2이면 f'assets/tiles/{kind}.png'는 assets/tiles/2.png가 됩니다. 파일명을 직접 여섯 번 쓰는 대신 같은 생성자를 다른 kind로 호출할 수 있습니다. 중괄호 안의 변수는 이 호출에서 먼저 값을 받아야 합니다.

- **같은 그림을 좌우로 뒤집어 반대 방향 프레임을 준비합니다.** flip(image, True, False)는 가로 방향만 뒤집습니다. 원래 그림을 지우는 것이 아니라 변환된 Surface를 반환합니다. 리스트 안의 각 프레임에 적용하면 같은 동작의 왼쪽 목록을 만들 수 있습니다. 방향 -1과 1은 인덱스가 아니라 선택용 키로 사용합니다.

```python
    # 객체를 생성할 때 필요한 초기 값과 참조를 준비합니다.
    def __init__(self, x, y, platforms, hazards):
        # 부모 Sprite의 내부 준비를 먼저 실행합니다.
        super().__init__()
        self.frames = {}
        for action in ['run']:
            # 문자열 안에 현재 종류나 번호를 넣어 에셋 경로를 만듭니다.
            right = [load_image(f'assets/explorer/{action}/{index}.png', (64, 64)) for index in range(4)]
            self.frames[(action, 1)] = right
            # 같은 그림을 좌우로 뒤집어 반대 방향 프레임을 준비합니다.
            self.frames[(action, -1)] = [pygame.transform.flip(frame, True, False) for frame in right]
        self.facing = 1
        self.action = 'run'
        self.frame = 0.0
        self.image = self.frames[('run', 1)][0]
        # 그림의 크기와 화면 위치를 담을 상자를 만듭니다.
        self.rect = self.image.get_rect(midbottom=(x, y))
        self.start = Vector(x, y)
        self.position = Vector(x, y)
        self.velocity = Vector(0, 0)
        # 위치·속도·가속도를 구별하고 이번 프레임 힘을 준비합니다.
        self.acceleration = Vector(0, 0)
        self.horizontal_acceleration = 2
        self.friction = 0.15
        self.gravity = 0.5
        self.jump_speed = 15
        self.platforms = platforms
        self.hazards = hazards
        # 이동하기 전 위치를 별도로 기억합니다.
        self.previous_rect = self.rect.copy()
        self.grounded = False
```


### 코드가 하는 일

새 그림은 동작별0.png~3.png 네 프레임으로 제공됩니다. 원강의의8장 대신 네 장을 쓰지만 리스트와 순환 원리는 같습니다. 오른쪽 프레임을 읽고 flip(frame,True,False)로 왼쪽 프레임을 준비합니다. 같은 캐릭터라도 rect는 하나를 유지해 위치가 바뀌지 않습니다. 현재 프레임을 바꾸지 않으면 첫 그림만 보입니다.

### 여기서 실행하세요

달리기 자세의 탐사원이 표시됩니다. 움직여도 아직 같은 자세인지 확인합니다.

**예상과 다를 때:** 파일 이름은1부터가 아니라0부터입니다. range(4)는0,1,2,3을 만듭니다.

## 07-B - 달리기 프레임을 순환시키기

소수 프레임 번호를 시간에 따라 늘려 네 장을 반복합니다.

**이 단계의 연결:** 출발 코드는 **07-A**의 누적 코드입니다. 아래 편집은 위에서부터 모두 적용합니다. 이미 완성한 나머지 메서드는 지정된 교체 범위 밖이면 그대로 둡니다.


### 입력 전에 결과를 예상해 보세요

네 장을 초당 8장으로 재생할 때 한 바퀴 시간은 얼마인가요?

먼저 답을 한 문장으로 적고 아래 해설과 비교하세요.

**생각 확인:** 0.5초입니다. 게임 업데이트 60FPS와 이미지 교체 8장/초는 다른 속도입니다. 같은 장이 여러 게임 프레임 동안 표시될 수 있습니다.

### 수정 위치와 입력할 코드

**편집 1.** `class Explorer` 안에서 기존 메서드 뒤에 새 `animate` 메서드를 추가합니다. 다른 class가 시작되기 전에 넣고 def 앞 4칸을 유지합니다.

**왜 이렇게 쓰나요 — 이 편집을 읽는 순서**

- **시간에 따라 그림 번호를 늘리고 끝에서 처음으로 순환합니다.** frame은 실수여도 리스트 인덱스는 정수여야 하므로 int(frame)을 씁니다. 네 장을 초당 8장 속도로 재생하면 한 바퀴는 4/8=0.5초입니다. frame=3.9에서 0.2를 더하면 4.1이고 %4의 결과 0.1로 돌아갑니다. 움직이는 좌표와 바뀌는 그림 번호는 별도의 값입니다.

```python
    # 표시할 애니메이션 프레임을 선택합니다.
    def animate(self, frames, seconds, speed):
        # 시간에 따라 그림 번호를 늘리고 끝에서 처음으로 순환합니다.
        self.frame = (self.frame + seconds * speed) % len(frames)
        self.image = frames[int(self.frame)]
```

**편집 2.** `class Explorer` 안의 `update` 메서드 전체를 아래 코드로 교체합니다. 다음 `def` 직전까지가 교체 범위입니다. `def` 앞 4칸, 본문 앞 8칸을 유지합니다.

```python
    # 그룹에서 호출하는 한 프레임의 처리 순서입니다.
    def update(self, seconds=1 / FPS):
        self.move(seconds)
        self.check_collisions()
        self.animate(self.frames[('run', 1)], seconds, 8)
```


### 코드가 하는 일

frame은 실수, 리스트에 넣는 int(frame)은 정수입니다. 초당8프레임이면 네 장을0.5초에 한 바퀴 돕니다. %len(frames)가 끝에서0으로 돌아오게 합니다. 모든 프레임이 같은 시간 동안 표시되며 마지막 프레임도 생략되지 않습니다.

서 있어도 다리가 움직입니다. 이는 현재 항상 달리기 리스트를 재생하기 때문입니다.

**이 시점의 정상 상태:** 왼쪽 이동과 대기 자세는 다음 편집에서 선택합니다.

**예상과 다를 때:** 리스트 인덱스 오류이면 int 변환과 나머지 연산을 확인합니다. 매번 frame=0을 쓰면 첫 자세에서 멈춥니다.

- **같은 그림을 좌우로 뒤집어 반대 방향 프레임을 준비합니다.** flip(image, True, False)는 가로 방향만 뒤집습니다. 원래 그림을 지우는 것이 아니라 변환된 Surface를 반환합니다. 리스트 안의 각 프레임에 적용하면 같은 동작의 왼쪽 목록을 만들 수 있습니다. 방향 -1과 1은 인덱스가 아니라 선택용 키로 사용합니다.

```python
    # 객체를 생성할 때 필요한 초기 값과 참조를 준비합니다.
    def __init__(self, x, y, platforms, hazards):
        # 부모 Sprite의 내부 준비를 먼저 실행합니다.
        super().__init__()
        self.frames = {}
        for action in ['run', 'idle']:
            # 문자열 안에 현재 종류나 번호를 넣어 에셋 경로를 만듭니다.
            right = [load_image(f'assets/explorer/{action}/{index}.png', (64, 64)) for index in range(4)]
            self.frames[(action, 1)] = right
            # 같은 그림을 좌우로 뒤집어 반대 방향 프레임을 준비합니다.
            self.frames[(action, -1)] = [pygame.transform.flip(frame, True, False) for frame in right]
        self.facing = 1
        self.action = 'idle'
        self.frame = 0.0
        self.image = self.frames[('idle', 1)][0]
        # 그림의 크기와 화면 위치를 담을 상자를 만듭니다.
        self.rect = self.image.get_rect(midbottom=(x, y))
        self.start = Vector(x, y)
        self.position = Vector(x, y)
        self.velocity = Vector(0, 0)
        # 위치·속도·가속도를 구별하고 이번 프레임 힘을 준비합니다.
        self.acceleration = Vector(0, 0)
        self.horizontal_acceleration = 2
        self.friction = 0.15
        self.gravity = 0.5
        self.jump_speed = 15
        self.platforms = platforms
        self.hazards = hazards
        # 이동하기 전 위치를 별도로 기억합니다.
        self.previous_rect = self.rect.copy()
        self.grounded = False
```

**왜 이렇게 쓰나요 — 이 편집을 읽는 순서**

- **이번 프레임에 계속 눌린 방향키를 읽습니다.** `keys[pygame.K_LEFT]`는 왼쪽 키가 눌렸는지 알려주는 값입니다. if의 본문은 참일 때만 실행됩니다. 두 독립 if는 둘 다 실행될 수 있고 if/elif는 첫 참 분기만 실행됩니다. 양쪽 키를 동시에 누른 경우를 떠올리면 차이가 드러납니다.

- **이동하기 전 위치를 별도로 기억합니다.** 현재 rect를 바로 대입하면 같은 상자를 가리킬 수 있으므로 `.copy()`로 별도 상자를 만듭니다. 이전 발 높이 90, 현재 발 높이 110, 발판 윗면 100이라면 중간에 발판을 통과했다는 것을 알 수 있습니다. 현재 위치만 검사할 때 놓칠 수 있는 빠른 낙하를 이 두 시점으로 잡습니다.

- **위치·속도·가속도를 구별하고 이번 프레임 힘을 준비합니다.** position은 어디 있는지, velocity는 한 기준 프레임 동안 얼마나 움직이는지, acceleration은 속도가 얼마나 변하는지입니다. Vector2는 x와 y를 묶어 두 방향을 함께 계산합니다. 이동 시작마다 가속도를 다시 정해야 이전 프레임의 입력·마찰이 계속 누적되지 않습니다. 중력이 있는 단계에서는 y 가속도에 gravity를 넣습니다.

- **현재 이동 방향의 반대로 마찰을 적용합니다.** 속도 10, 마찰 0.15라면 x 가속도에서 1.5를 뺍니다. 속도 -10이면 -1.5를 빼므로 오른쪽으로 1.5를 더하는 효과입니다. 두 경우 모두 속력이 줄어드는 방향입니다. 키를 놓으면 입력 가속도는 사라져도 마찰은 남으므로 즉시 정지하지 않고 서서히 멈춥니다.

- **이전 속도로 위치를 계산한 뒤 다음 줄에서 속도를 갱신합니다.** `scale=seconds*FPS`는 기준 60FPS 한 프레임에 대한 시간 비율입니다. scale=1, 이전 속도 4, 가속도 2이면 위치 변화는 4+0.5×2=5, 다음 속도는 6입니다. 속도를 먼저 6으로 바꾼 뒤 같은 위치 식을 쓰면 7이 되어 가속도를 중복 반영합니다. position은 소수를 보존하고 rect는 화면 표시용 정수 위치를 받습니다.

- **화면의 한쪽 끝을 반대쪽 끝으로 이어 줍니다.** 나머지 연산은 x를 0 이상 화면 폭 미만으로 돌려놓습니다. 폭이 960이면 -5 % 960은 955, 965 % 960은 5입니다. 벽에서 멈추는 방식과 다른 규칙입니다. 고친 position을 rect에 반영해야 화면에서도 이동이 보입니다.

```python
    # 입력 또는 정해진 속도로 위치를 갱신합니다.
    def move(self, seconds):
        scale = min(seconds * FPS, 3)
        # 이동하기 전 위치를 별도로 기억합니다.
        self.previous_rect = self.rect.copy()
        # 위치·속도·가속도를 구별하고 이번 프레임 힘을 준비합니다.
        self.acceleration = Vector(0, self.gravity)
        # 이번 프레임에 계속 눌린 방향키를 읽습니다.
        keys = pygame.key.get_pressed()
        if keys[pygame.K_LEFT]:
            self.acceleration.x = -self.horizontal_acceleration
            self.facing = -1
        elif keys[pygame.K_RIGHT]:
            self.acceleration.x = self.horizontal_acceleration
            self.facing = 1
        # 현재 이동 방향의 반대로 마찰을 적용합니다.
        self.acceleration.x -= self.velocity.x * self.friction
        # 이전 속도로 위치를 계산한 뒤 다음 줄에서 속도를 갱신합니다.
        self.position += self.velocity * scale + 0.5 * self.acceleration * scale * scale
        self.velocity += self.acceleration * scale
        self.velocity.y = min(25, self.velocity.y)
        # 화면의 한쪽 끝을 반대쪽 끝으로 이어 줍니다.
        self.position.x %= SCREEN_WIDTH
        self.rect.midbottom = self.position
```

**왜 이렇게 쓰나요 — 이 편집을 읽는 순서**

- **이번 프레임에 계속 눌린 방향키를 읽습니다.** `keys[pygame.K_LEFT]`는 왼쪽 키가 눌렸는지 알려주는 값입니다. if의 본문은 참일 때만 실행됩니다. 두 독립 if는 둘 다 실행될 수 있고 if/elif는 첫 참 분기만 실행됩니다. 양쪽 키를 동시에 누른 경우를 떠올리면 차이가 드러납니다.

```python
    # 그룹에서 호출하는 한 프레임의 처리 순서입니다.
    def update(self, seconds=1 / FPS):
        self.move(seconds)
        self.check_collisions()
        # 이번 프레임에 계속 눌린 방향키를 읽습니다.
        action = 'run' if pygame.key.get_pressed()[pygame.K_LEFT] or pygame.key.get_pressed()[pygame.K_RIGHT] else 'idle'
        if action != self.action:
            self.action = action
            self.frame = 0.0
        self.animate(self.frames[(action, self.facing)], seconds, 8 if action == 'run' else 4)
```
