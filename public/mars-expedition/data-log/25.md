## 25-A - 정지한 로봇의 재부팅

이번 편집의 목표는 **정지한 로봇의 재부팅**입니다. 아래 수정 위치를 모두 반영한 다음 실행 결과를 확인합니다.

**이 단계의 연결:** 출발 코드는 **24-B**의 누적 코드입니다. 아래 편집은 위에서부터 모두 적용합니다. 이미 완성한 나머지 메서드는 지정된 교체 범위 밖이면 그대로 둡니다.


### 입력 전에 결과를 예상해 보세요

두 번째 피격 때 down_elapsed를 0으로 안 돌리면 무엇이 달라지나요?

먼저 답을 한 문장으로 적고 아래 해설과 비교하세요.

**생각 확인:** 이전 대기 시간이 남아 즉시 재부팅하거나 대기 시간이 짧아질 수 있습니다. 상태 진입마다 해당 시간과 프레임을 초기화해야 반복 플레이가 첫 플레이와 같습니다.

### 수정 위치와 입력할 코드

**편집 1.** `class Robot` 안의 `check_animations` 메서드 전체를 아래 코드로 교체합니다. 다음 `def` 직전까지가 교체 범위입니다. `def` 앞 4칸, 본문 앞 8칸을 유지합니다.

```python
    # 현재 행동이나 상태에 맞는 그림 묶음을 고릅니다.
    def check_animations(self, seconds):
        if self.state == 'walking':
            self.animate(self.walk_frames, seconds, 8, True)
        elif self.state == 'falling':
            if self.animate(self.down_frames, seconds, 6, False):
                self.state = 'down'
                self.down_elapsed = 0.0
        elif self.state == 'down':
            self.down_elapsed += seconds
            if self.down_elapsed >= self.rise_delay:
                self.state = 'rising'
                self.frame = 0.0
        elif self.state == 'rising':
            if self.animate(self.rise_frames, seconds, 6, False):
                self.state = 'walking'
                self.frame = 0.0
```


### 코드가 하는 일

`down` 상태에서만 `down_elapsed`를 늘립니다. 2초 뒤 `rising`으로 바꾸고 frame을 0으로 되돌립니다. 역순 애니메이션이 끝나면 `walking`으로 돌아갑니다. 이 수업은 쓰러지는 동작이 완료된 시점부터 2초를 재어 회수 기회를 명확히 줍니다. 원강의는 피격 시점부터 시간을 재므로 대기 기준이 다릅니다. 다음 피격을 위해 시간과 프레임을 매번 초기화합니다.

### 여기서 실행하세요

로봇을 맞힌 뒤 가까이 다가가지 말고 기다립니다. 쓰러짐 → 2초 정지 → 일어남 → 걷기 순서가 보이는지 확인합니다. 두 번 연속 맞혀도 같은 순서여야 합니다.

## 25-B - 쓰러진 로봇 회수와 살아 있는 로봇 피해

이번 편집의 목표는 **쓰러진 로봇 회수와 살아 있는 로봇 피해**입니다. 아래 수정 위치를 모두 반영한 다음 실행 결과를 확인합니다.

**이 단계의 연결:** 출발 코드는 **25-A**의 누적 코드입니다. 아래 편집은 위에서부터 모두 적용합니다. 이미 완성한 나머지 메서드는 지정된 교체 범위 밖이면 그대로 둡니다.


### 입력 전에 결과를 예상해 보세요

걷는 로봇과 0.2초 동안 겹쳐도 피해를 매 프레임 주면 안 되는 이유는 무엇인가요?

먼저 답을 한 문장으로 적고 아래 해설과 비교하세요.

**생각 확인:** 프레임 속도에 따라 피해량이 달라지고 너무 빨리 에너지가 소진됩니다. 1초 피해 대기시간으로 사건의 간격을 정합니다. 쓰러진 로봇 접촉은 피해가 아닌 회수입니다.

### 수정 위치와 입력할 코드

**편집 1.** `class Expedition` 안의 `check_collisions` 메서드 전체를 아래 코드로 교체합니다. 다음 `def` 직전까지가 교체 범위입니다. `def` 앞 4칸, 본문 앞 8칸을 유지합니다.

**왜 이렇게 쓰나요 — 이 편집을 읽는 순서**

- **두 그룹의 충돌 결과를 받아 맞힌 대상 수를 셉니다.** `groupcollide(A, B, 지울A, 지울B)`는 A의 객체를 열쇠로, 그 객체가 맞힌 B 목록을 값으로 돌려줍니다. 두 True/False는 각각 어느 쪽을 그룹에서 제거할지 정합니다. 우주 방어대는 양쪽 제거, 화성의 로봇 피격은 펄스만 제거하고 로봇을 남겨 상태를 바꿉니다. values()로 얻는 것은 객체 하나가 아니라 대상 목록이라는 점에 주의하세요.

- **객체 하나와 그룹을 비교하고 충돌한 대상 목록을 받습니다.** `spritecollide(객체, 그룹, 제거여부)`는 겹친 대상들의 리스트를 반환합니다. 빈 리스트는 if에서 거짓, 한 개 이상은 참입니다. if 본문을 한 번 실행하는 규칙과 len(목록)만큼 보상을 계산하는 규칙은 다릅니다. 여러 탄환 피격은 생명 한 번 차감, 결정 여러 개 회수는 개수별 보상이라는 해당 단계의 의도를 읽으세요.

```python
    # 접촉 대상을 검사하고 이 단계의 충돌 규칙을 적용합니다.
    def check_collisions(self):
        # 두 그룹의 충돌 결과를 받아 맞힌 대상 수를 셉니다.
        collisions = pygame.sprite.groupcollide(self.pulses, self.robots, True, False)
        for targets in collisions.values():
            for robot in targets:
                if robot.state == 'walking':
                    robot.hit_sound.play()
                    robot.state = 'falling'
                    robot.frame = 0.0
                    robot.down_elapsed = 0.0
        # 객체 하나와 그룹을 비교하고 충돌한 대상 목록을 받습니다.
        for robot in pygame.sprite.spritecollide(self.explorer, self.robots, False):
            if robot.state != 'walking':
                robot.kick_sound.play()
                robot.kill()
                self.score += 25
            elif self.explorer.hurt_remaining <= 0:
                self.explorer.health = max(0, self.explorer.health - 20)
                self.explorer.hit_sound.play()
                self.explorer.hurt_remaining = 1.0
                self.explorer.position.x = (self.explorer.position.x - 128 * robot.direction) % SCREEN_WIDTH
                self.explorer.rect.midbottom = self.explorer.position
                if self.explorer.health <= 0:
                    return
```

**편집 2.** `class Expedition` 안의 `draw` 메서드 전체를 아래 코드로 교체합니다. 다음 `def` 직전까지가 교체 범위입니다. `def` 앞 4칸, 본문 앞 8칸을 유지합니다.

**왜 이렇게 쓰나요 — 이 편집을 읽는 순서**

- **그림의 크기와 화면 위치를 담을 상자를 만듭니다.** `image`는 그림이고 `rect`는 그 그림을 놓을 사각형입니다. `get_rect(topleft=(x, y))`는 왼쪽 위, `midbottom=(x, y)`는 발 가운데를 해당 위치에 맞춥니다. 예를 들어 64×64 그림의 midbottom이 (100, 200)이면 왼쪽 위는 (68, 136)입니다. 같은 좌표라도 기준점이 다르면 표시 위치가 달라집니다. Group.draw는 각 객체의 image와 rect를 읽습니다.

- **숫자와 문자를 글자 그림으로 바꾸어 그립니다.** font.render의 첫 인수는 문자열입니다. f 문자열의 `{self.score}` 같은 부분은 그 시점의 값을 글자로 넣습니다. render 결과 역시 Surface이므로 get_rect로 정렬하고 blit으로 그립니다. 점수가 바뀐 뒤 다시 render해야 새 숫자가 보입니다. 파일 경로로 한글 폰트를 지정해 기본 폰트에 한글이 없는 문제를 피합니다.

- **딕셔너리의 항목을 위치 이름과 값으로 풀어 전달합니다.** `**{anchor: point}`는 예를 들어 anchor가 "topleft", point가 (16, 680)이면 `get_rect(topleft=(16, 680))`과 같은 호출입니다. 이름을 변수로 정해 왼쪽/오른쪽 정렬을 같은 반복문에서 처리하려고 사용합니다. 별표 두 개는 곱셈이 아니라 함수 인수 풀기 문법입니다.

```python
    # 현재 값을 읽어 화면과 안내를 그립니다.
    def draw(self):
        pygame.draw.rect(screen, (13, 24, 40), (0, SCREEN_HEIGHT - 58, SCREEN_WIDTH, 58))
        rows = [
            (f'점수 {self.score}', (16, SCREEN_HEIGHT - 56), 'topleft'),
            (f'에너지 {self.explorer.health}', (16, SCREEN_HEIGHT - 29), 'topleft'),
            (f'탐사 {self.round_number}', (SCREEN_WIDTH - 16, SCREEN_HEIGHT - 56), 'topright'),
            (f'신호 복구까지 {self.remaining}초', (SCREEN_WIDTH - 16, SCREEN_HEIGHT - 29), 'topright'),
        ]
        for text, point, anchor in rows:
            # 숫자와 문자를 글자 그림으로 바꾸어 그립니다.
            surface = self.hud_font.render(text, True, (237, 244, 252))
            # 그림의 크기와 화면 위치를 담을 상자를 만듭니다.
            rect = surface.get_rect(**{anchor: point})
            screen.blit(surface, rect)
        # 숫자와 문자를 글자 그림으로 바꾸어 그립니다.
        title = self.title_font.render('화성 탐사대', True, (101, 229, 217))
        # 그림의 크기와 화면 위치를 담을 상자를 만듭니다.
        screen.blit(title, title.get_rect(center=(SCREEN_WIDTH // 2, SCREEN_HEIGHT - 29)))
```


### 코드가 하는 일

`walking`이 아닌 로봇에 접촉하면 제거하고 25점을 얻습니다. 걷는 로봇은 에너지 20을 줄이고 반대쪽 128픽셀로 밀어냅니다. `hurt_remaining`을 1초로 설정해 한 번 겹쳤다고 매 프레임 피해를 받지 않게 합니다. 에너지는 `max`로 0 아래로 내려가지 않게 합니다. HUD의 임시 100을 현재 `health`로 교체합니다. 에너지가 0이면 충돌 처리를 즉시 끝내 같은 프레임의 회복으로 종료가 취소되지 않게 합니다.

### 여기서 실행하세요

쓰러진 로봇에 닿아 25점만 증가하는지 확인합니다. 걷는 로봇에 닿으면 에너지 100 → 80과 밀림이 한 번 일어나야 합니다. 연속 접촉해도 한 프레임에 0이 되지 않아야 합니다.

**이 시점의 정상 상태:** 에너지가 0이 되어도 종료 화면은 아직 없습니다. 30단원에서 연결합니다.
