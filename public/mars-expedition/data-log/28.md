## 코드를 읽고 작성하는 방법

코드 안의 `#` 뒤 문장은 **이해를 돕는 설명용 주석**입니다. 주석은 따라 적지 않아도 게임이 똑같이 실행됩니다. 먼저 주석을 읽고 그 아래 코드의 목적을 이해한 뒤, 실행되는 코드와 들여쓰기를 작성하세요. 따옴표 안의 글자, 변수 이름, 괄호와 콜론은 주석이 아니므로 생략하면 안 됩니다. 누적 코드에는 길 찾기에 필요한 핵심 주석만 남겼습니다.

각 편집의 ‘왜 이렇게 쓰나요’를 읽고, 입력하기 전에 결과를 예상해 보세요. 이번 단계의 편집을 모두 마친 다음 실행합니다. 중간에 아직 정의하지 않은 이름을 참조할 수 있으므로 편집 하나마다 실행하지 않습니다. 실행 후에는 화면이 맞는지만 보지 말고, **어떤 값이 바뀌어 그 결과가 생겼는지** 한 문장으로 설명해 보세요. 누적 코드는 먼저 직접 시도한 뒤 비교·복구할 때 사용합니다.

## 28-A - 탐사원의 결정 회수와 회복

이번 편집의 목표는 **탐사원의 결정 회수와 회복**입니다. 아래 수정 위치를 모두 반영한 다음 실행 결과를 확인합니다.

**이 단계의 연결:** 출발 코드는 **27-B**의 누적 코드입니다. 아래 편집은 위에서부터 모두 적용합니다. 이미 완성한 나머지 메서드는 지정된 교체 범위 밖이면 그대로 둡니다.


### 입력 전에 결과를 예상해 보세요

에너지 95에서 결정 두 개를 같은 프레임에 회수하면 점수와 에너지는 어떻게 바뀌나요?

먼저 답을 한 문장으로 적고 아래 해설과 비교하세요.

### 수정 위치와 입력할 코드

**편집 1.** `class Expedition` 안의 `__init__` 메서드 전체를 아래 코드로 교체합니다. 다음 `def` 직전까지가 교체 범위입니다. `def` 앞 4칸, 본문 앞 8칸을 유지합니다.

**왜 이렇게 쓰나요 — 이 편집을 읽는 순서**

- **소리 파일을 준비하는 일과 재생하는 일을 구분합니다.** Sound 또는 load_sound는 소리를 사용할 준비입니다. .play()를 호출하는 순간 재생을 시도합니다. 생성자에서 준비하고 실제 발사·충돌 사건에서 재생해야 매 프레임 파일을 읽거나 준비만 했는데 소리가 날 것으로 기대하지 않습니다.

```python
    # 객체를 생성할 때 필요한 초기 값과 참조를 준비합니다.
    def __init__(self, explorer, robots, platforms, gates, pulses, crystals):
        self.round_duration = 30
        self.score = 0
        self.round_number = 1
        self.remaining = self.round_duration
        self.elapsed = 0.0
        self.title_font = pygame.font.Font('assets/fonts/DoHyeon-Regular.ttf', 42)
```

**편집 2.** `class Expedition` 안의 `check_collisions` 메서드 전체를 아래 코드로 교체합니다. 다음 `def` 직전까지가 교체 범위입니다. `def` 앞 4칸, 본문 앞 8칸을 유지합니다.

**왜 이렇게 쓰나요 — 이 편집을 읽는 순서**

- **두 그룹의 충돌 결과를 받아 맞힌 대상 수를 셉니다.** `groupcollide(A, B, 지울A, 지울B)`는 A의 객체를 열쇠로, 그 객체가 맞힌 B 목록을 값으로 돌려줍니다. 두 True/False는 각각 어느 쪽을 그룹에서 제거할지 정합니다. 우주 방어대는 양쪽 제거, 화성의 로봇 피격은 펄스만 제거하고 로봇을 남겨 상태를 바꿉니다. values()로 얻는 것은 객체 하나가 아니라 대상 목록이라는 점에 주의하세요.

- **객체 하나와 그룹을 비교하고 충돌한 대상 목록을 받습니다.** `spritecollide(객체, 그룹, 제거여부)`는 겹친 대상들의 리스트를 반환합니다. 빈 리스트는 if에서 거짓, 한 개 이상은 참입니다. if 본문을 한 번 실행하는 규칙과 len(목록)만큼 보상을 계산하는 규칙은 다릅니다. 여러 탄환 피격은 생명 한 번 차감, 결정 여러 개 회수는 개수별 보상이라는 해당 단계의 의도를 읽으세요.

```python
    # 접촉 대상을 검사하고 이 단계의 충돌 규칙을 적용합니다.
    def check_collisions(self):
        # 두 그룹의 충돌 결과를 받아 맞힌 대상 수를 셉니다.
        collisions = pygame.sprite.groupcollide(self.pulses, self.robots, True, False)
        for targets in collisions.values():
            for robot in targets:
                if robot.state == 'walking':
                    robot.hit_sound.play()
                    robot.state = 'falling'
                    robot.frame = 0.0
                    robot.down_elapsed = 0.0
        # 객체 하나와 그룹을 비교하고 충돌한 대상 목록을 받습니다.
        for robot in pygame.sprite.spritecollide(self.explorer, self.robots, False):
            if robot.state != 'walking':
                robot.kick_sound.play()
                robot.kill()
                self.score += 25
                self.crystals.add(Crystal(self.platforms, self.gates))
            elif self.explorer.hurt_remaining <= 0:
                self.explorer.health = max(0, self.explorer.health - 20)
                self.explorer.hit_sound.play()
                self.explorer.hurt_remaining = 1.0
                self.explorer.position.x = (self.explorer.position.x - 128 * robot.direction) % SCREEN_WIDTH
                self.explorer.rect.midbottom = self.explorer.position
                if self.explorer.health <= 0:
                    return
        # 객체 하나와 그룹을 비교하고 충돌한 대상 목록을 받습니다.
        collected = pygame.sprite.spritecollide(self.explorer, self.crystals, True)
        if collected:
            self.pickup_sound.play()
            self.score += 100 * len(collected)
            self.explorer.health = min(self.explorer.starting_health, self.explorer.health + 10 * len(collected))
```


### 코드가 하는 일

`spritecollide`의 True는 회수한 결정을 즉시 그룹에서 지웁니다. `len(collected)`로 같은 프레임에 두 개를 회수하면 200점과 에너지 20을 계산합니다. `min(starting_health, ...)`가 100 상한을 지킵니다. 음악은 여기서 파일만 읽고, 29단원의 시작 화면에서 재생합니다.

### 여기서 실행하세요

피해를 한 번 받아 에너지 80으로 만든 뒤 결정을 회수해 90이 되는지 확인합니다. 에너지 100에서 회수하면 점수만 오르고 100을 넘지 않아야 합니다.

**이 시점의 정상 상태:** 배경음악이 아직 들리지 않는 것이 정상입니다.

**예상과 다를 때:** 회수 점수가 계속 오르면 결정 삭제 인수가 True인지 확인합니다.

## 28-B - 로봇에게 결정을 빼앗긴 경우

이번 편집의 목표는 **로봇에게 결정을 빼앗긴 경우**입니다. 아래 수정 위치를 모두 반영한 다음 실행 결과를 확인합니다.

**이 단계의 연결:** 출발 코드는 **28-A**의 누적 코드입니다. 아래 편집은 위에서부터 모두 적용합니다. 이미 완성한 나머지 메서드는 지정된 교체 범위 밖이면 그대로 둡니다.


### 입력 전에 결과를 예상해 보세요

탐사원과 걷는 로봇이 같은 결정에 동시에 닿으면 누가 가져가나요?

먼저 답을 한 문장으로 적고 아래 해설과 비교하세요.

**생각 확인:** 탐사원 회수 검사를 먼저 하고 회수물을 제거하므로 탐사원입니다. 같은 프레임 내 함수/반복문의 순서가 우선권입니다.

### 수정 위치와 입력할 코드

**편집 1.** `class Expedition` 안의 `check_collisions` 메서드 전체를 아래 코드로 교체합니다. 다음 `def` 직전까지가 교체 범위입니다. `def` 앞 4칸, 본문 앞 8칸을 유지합니다.

**왜 이렇게 쓰나요 — 이 편집을 읽는 순서**

- **두 그룹의 충돌 결과를 받아 맞힌 대상 수를 셉니다.** `groupcollide(A, B, 지울A, 지울B)`는 A의 객체를 열쇠로, 그 객체가 맞힌 B 목록을 값으로 돌려줍니다. 두 True/False는 각각 어느 쪽을 그룹에서 제거할지 정합니다. 우주 방어대는 양쪽 제거, 화성의 로봇 피격은 펄스만 제거하고 로봇을 남겨 상태를 바꿉니다. values()로 얻는 것은 객체 하나가 아니라 대상 목록이라는 점에 주의하세요.

- **검사를 시작할 때의 로봇 목록만 순회합니다.** 결정을 빼앗기면 검사 중 로봇이 새로 추가됩니다. list로 검사 시작 시점의 목록을 따로 만들면 새로 추가된 로봇까지 같은 반복에서 계속 검사하는 일을 피합니다. 객체의 복제본을 만드는 것이 아니라 목록만 복사합니다.

- **이번 대상의 나머지 검사를 건너뛰고 다음 대상으로 갑니다.** continue는 가장 가까운 반복문의 다음 반복으로 이동합니다. 발판과 가로 범위가 겹치지 않으면 그 발판의 세로 착지 검사를 생략합니다. break는 반복문 전체를 끝내고 return은 메서드를 끝냅니다. 세 명령이 어느 범위를 빠져나가는지 들여쓰기를 따라 확인하세요.

```python
    # 접촉 대상을 검사하고 이 단계의 충돌 규칙을 적용합니다.
    def check_collisions(self):
        # 두 그룹의 충돌 결과를 받아 맞힌 대상 수를 셉니다.
        collisions = pygame.sprite.groupcollide(self.pulses, self.robots, True, False)
        for targets in collisions.values():
            for robot in targets:
                if robot.state == 'walking':
                    robot.hit_sound.play()
                    robot.state = 'falling'
                    robot.frame = 0.0
                    robot.down_elapsed = 0.0
        # 객체 하나와 그룹을 비교하고 충돌한 대상 목록을 받습니다.
        for robot in pygame.sprite.spritecollide(self.explorer, self.robots, False):
            if robot.state != 'walking':
                robot.kick_sound.play()
                robot.kill()
                self.score += 25
                self.crystals.add(Crystal(self.platforms, self.gates))
            elif self.explorer.hurt_remaining <= 0:
                self.explorer.health = max(0, self.explorer.health - 20)
                self.explorer.hit_sound.play()
                self.explorer.hurt_remaining = 1.0
                self.explorer.position.x = (self.explorer.position.x - 128 * robot.direction) % SCREEN_WIDTH
                self.explorer.rect.midbottom = self.explorer.position
                if self.explorer.health <= 0:
                    return
        # 객체 하나와 그룹을 비교하고 충돌한 대상 목록을 받습니다.
        collected = pygame.sprite.spritecollide(self.explorer, self.crystals, True)
        if collected:
            self.pickup_sound.play()
            self.score += 100 * len(collected)
            self.explorer.health = min(self.explorer.starting_health, self.explorer.health + 10 * len(collected))
        # 검사를 시작할 때의 로봇 목록만 순회합니다.
        for robot in list(self.robots):
            if robot.state != 'walking':
                # 이번 대상의 나머지 검사를 건너뛰고 다음 대상으로 갑니다.
                continue
            # 객체 하나와 그룹을 비교하고 충돌한 대상 목록을 받습니다.
            lost = pygame.sprite.spritecollide(robot, self.crystals, True)
            if lost:
                self.lost_sound.play()
                for _ in lost:
                    self.robots.add(Robot(self.platforms, self.gates, self.round_number, self.round_number + 5))
```


### 코드가 하는 일

쓰러졌거나 재부팅 중인 로봇은 `continue`로 건너뜁니다. 걷는 로봇만 신호를 가져갑니다. `list(self.robots)`는 검사 시작 목록을 복사하여 루프 중 새로 추가한 로봇을 이번 검사에 다시 넣지 않습니다. 결정 하나당 로봇 한 대입니다. 탐사원 회수 검사를 먼저 하므로 동시에 닿으면 탐사원이 먼저 회수합니다.

### 여기서 실행하세요

결정을 직접 회수하지 않고 로봇이 닿도록 기다립니다. 결정이 사라지고 위쪽에 새 로봇이 추가되어야 합니다. 쓰러진 로봇 위로 지나는 결정은 빼앗기지 않아야 합니다.

**이 시점의 정상 상태:** 탐사원 점수는 로봇이 회수한 결정으로 오르지 않습니다.
