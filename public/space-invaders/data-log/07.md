먼저 답을 한 문장으로 적고 아래 해설과 비교하세요.

### main.py 수정 위치와 입력 코드

**편집 1.** `class Mission` 안의 `def __init__`부터 그 메서드 본문 끝까지 **전체 교체**합니다. 다음 def나 다음 class는 지우지 않습니다. def 앞4칸, 본문 앞8칸을 유지합니다.

**왜 이렇게 쓰나요 — 이 편집을 읽는 순서**

```python

    def __init__(self, scout, raiders, scout_pulses, raider_pulses):
```

## 07-B - 한글 점수 한 줄부터 표시하기

폰트→글자 표면→위치 상자→화면 복사의 순서를 익힙니다.

**이 단계의 연결:** 출발 코드는 **07-A**의 누적 코드입니다. 아래 편집은 위에서부터 모두 적용합니다. 이미 완성한 나머지 메서드는 지정된 교체 범위 밖이면 그대로 둡니다.


### 입력 전에 결과를 예상해 보세요

score가 0에서 100으로 바뀌면 이미 만들어 둔 score_text도 저절로 바뀔까요?

먼저 답을 한 문장으로 적고 아래 해설과 비교하세요.

**생각 확인:** 아닙니다. 문자열로 만든 Surface는 그 시점의 결과입니다. draw 때 다시 render해서 현재 점수를 보여줍니다.

### main.py 수정 위치와 입력 코드

**편집 1.** `class Mission` 안의 `def draw`부터 그 메서드 본문 끝까지 **전체 교체**합니다. 다음 def나 다음 class는 지우지 않습니다. def 앞4칸, 본문 앞8칸을 유지합니다.

**왜 이렇게 쓰나요 — 이 편집을 읽는 순서**

- **그림의 크기와 화면 위치를 담을 상자를 만듭니다.** `image`는 그림이고 `rect`는 그 그림을 놓을 사각형입니다. `get_rect(topleft=(x, y))`는 왼쪽 위, `midbottom=(x, y)`는 발 가운데를 해당 위치에 맞춥니다. 예를 들어 64×64 그림의 midbottom이 (100, 200)이면 왼쪽 위는 (68, 136)입니다. 같은 좌표라도 기준점이 다르면 표시 위치가 달라집니다. Group.draw는 각 객체의 image와 rect를 읽습니다.

- **숫자와 문자를 글자 그림으로 바꾸어 그립니다.** font.render의 첫 인수는 문자열입니다. f 문자열의 `{self.score}` 같은 부분은 그 시점의 값을 글자로 넣습니다. render 결과 역시 Surface이므로 get_rect로 정렬하고 blit으로 그립니다. 점수가 바뀐 뒤 다시 render해야 새 숫자가 보입니다. 파일 경로로 한글 폰트를 지정해 기본 폰트에 한글이 없는 문제를 피합니다.

```python
    # 현재 값을 읽어 화면과 안내를 그립니다.
    def draw(self):
        # 숫자와 문자를 글자 그림으로 바꾸어 그립니다.
        score_text = self.font.render(f'점수: {self.score}', True, (240, 246, 255))
        # 그림의 크기와 화면 위치를 담을 상자를 만듭니다.
        score_rect = score_text.get_rect(centerx=SCREEN_WIDTH // 2, top=10)
        screen.blit(score_text, score_rect)
```


### 코드가 하는 일

font.render는 문자열을 이미지처럼 그릴 표면으로 만듭니다. f 문자열의 {self.score}에는 현재 값0이 들어갑니다. True는 글자 경계를 부드럽게 처리합니다. get_rect(centerx=600,top=10)으로 위 중앙에 배치하고 blit으로 화면에 복사합니다. 제공된 한글 폰트를 함께 로드하므로 운영체제 기본 폰트에 의존하지 않습니다.

**예상과 다를 때:** 네모가 보이면 기본 Font(None,...)로 바꾸지 않았는지 확인합니다. 폰트에 없는 특수문자 대신 한글과 ASCII 하이픈을 사용합니다.

## 07-C - 라운드·기체와 방어선 표시하기

### main.py 수정 위치와 입력 코드

**편집 1.** `class Mission` 안의 `def draw`부터 그 메서드 본문 끝까지 **전체 교체**합니다. 다음 def나 다음 class는 지우지 않습니다. def 앞4칸, 본문 앞8칸을 유지합니다.

**왜 이렇게 쓰나요 — 이 편집을 읽는 순서**

- **그림의 크기와 화면 위치를 담을 상자를 만듭니다.** `image`는 그림이고 `rect`는 그 그림을 놓을 사각형입니다. `get_rect(topleft=(x, y))`는 왼쪽 위, `midbottom=(x, y)`는 발 가운데를 해당 위치에 맞춥니다. 예를 들어 64×64 그림의 midbottom이 (100, 200)이면 왼쪽 위는 (68, 136)입니다. 같은 좌표라도 기준점이 다르면 표시 위치가 달라집니다. Group.draw는 각 객체의 image와 rect를 읽습니다.

- **숫자와 문자를 글자 그림으로 바꾸어 그립니다.** font.render의 첫 인수는 문자열입니다. f 문자열의 `{self.score}` 같은 부분은 그 시점의 값을 글자로 넣습니다. render 결과 역시 Surface이므로 get_rect로 정렬하고 blit으로 그립니다. 점수가 바뀐 뒤 다시 render해야 새 숫자가 보입니다. 파일 경로로 한글 폰트를 지정해 기본 폰트에 한글이 없는 문제를 피합니다.

```python
    # 현재 값을 읽어 화면과 안내를 그립니다.
    def draw(self):
        # 숫자와 문자를 글자 그림으로 바꾸어 그립니다.
        score_text = self.font.render(f'점수: {self.score}', True, (240, 246, 255))
        # 그림의 크기와 화면 위치를 담을 상자를 만듭니다.
        score_rect = score_text.get_rect(centerx=SCREEN_WIDTH // 2, top=10)

        # 숫자와 문자를 글자 그림으로 바꾸어 그립니다.
        round_text = self.font.render(f'라운드: {self.round_number}', True, (240, 246, 255))
        # 그림의 크기와 화면 위치를 담을 상자를 만듭니다.
        round_rect = round_text.get_rect(topleft=(20, 10))

        # 숫자와 문자를 글자 그림으로 바꾸어 그립니다.
        lives_text = self.font.render(f'남은 기체: {self.scout.lives}', True, (240, 246, 255))

        lives_rect = lives_text.get_rect(topright=(SCREEN_WIDTH - 20, 10))

        screen.blit(score_text, score_rect)
        screen.blit(round_text, round_rect)
        screen.blit(lives_text, lives_rect)

        pygame.draw.line(screen, (70, 90, 130), (0, 50), (SCREEN_WIDTH, 50), 3)
```

라운드는 topleft=(20,10), 기체는 top right가(1180,10)이 되도록 정렬합니다. 생명은 self.scout.lives를 읽습니다. draw.line의 앞 두 좌표가 시작점과 끝점, 마지막3이 두께입니다. 위 구분선은 y50, 붉은 방어선은 y600입니다.

## 07-D - 11열×5행 편대 생성 메서드 작성하기

한 줄 배치를 두 겹 반복문으로 확장합니다. i=2,j=1일 때 위치는 어디일까요?

**이 단계의 연결:** 출발 코드는 **07-C**의 누적 코드입니다. 아래 편집은 위에서부터 모두 적용합니다. 이미 완성한 나머지 메서드는 지정된 교체 범위 밖이면 그대로 둡니다.


### 입력 전에 결과를 예상해 보세요

i=2,j=1인 적의 좌표와 총 적 수를 계산하세요.

먼저 답을 한 문장으로 적고 아래 해설과 비교하세요.

**생각 확인:** x=64+2×64=192, y=64+1×64=128입니다. 11개 열 각각에서 5개 행을 만들므로 55기입니다. 두 반복문을 나란히 두면 55번 생성하는 중첩 구조가 되지 않습니다.

### main.py 수정 위치와 입력 코드

**편집 1.** `class Mission` 안의 `def start_new_round`부터 그 메서드 본문 끝까지 **전체 교체**합니다. 다음 def나 다음 class는 지우지 않습니다. def 앞4칸, 본문 앞8칸을 유지합니다.

```python
    # 다음 라운드의 객체와 진행 값을 준비합니다.
    def start_new_round(self):
        for i in range(11):
            for j in range(5):
                raider = Raider(64 + i * 64, 64 + j * 64, self.round_number, self.raider_pulses)
                self.raiders.add(raider)
        self.new_round_sound.play()
        self.pause_game(f'우주 방어대 - 라운드 {self.round_number}', 'Enter 키를 눌러 시작하세요')
```


### 코드가 하는 일

바깥 i는0~10, 안쪽 j는0~4로55번 생성합니다. 좌표는64+i*64,64+j*64이며 예시는(192,128)입니다. 가로64 간격에 폭56이므로 사이8픽셀이 남습니다. 속도에 round_number를 전달합니다. 생성 후 출격음을 재생하고 pause_game을 호출하지만 아직 pause는 pass입니다.

### 여기서 실행하세요

정지 → 위 코드 수정 → 실행 → 게임 화면 클릭 순서로 진행합니다.

현재는 메서드를 정의했을 뿐이라 임시10기가 그대로 보입니다. 다음 단계에서 초기화 구간을 교체해 정식 편대를 호출합니다.

**이 시점의 정상 상태:** 정식55기가 아직 나타나지 않는 것이 정상입니다.

**예상과 다를 때:** Raider 인수는 좌표 두 개, 속도, 탄환그룹 총4개입니다. add는 안쪽 for 안12칸입니다.

## 07-E - 임시 편대를 제거하고 정식 편대 호출하기

두 편대가 함께 생기지 않도록 준비 구간 전체를 확인합니다. Mission 객체도 한 번만 만듭니다.

**이 단계의 연결:** 출발 코드는 **07-D**의 누적 코드입니다. 아래 편집은 위에서부터 모두 적용합니다. 이미 완성한 나머지 메서드는 지정된 교체 범위 밖이면 그대로 둡니다.


### 입력 전에 결과를 예상해 보세요

임시 열 마리와 정식 55기를 모두 남기면 몇 기가 생길까요?

먼저 답을 한 문장으로 적고 아래 해설과 비교하세요.

**생각 확인:** 65기입니다. 메서드 구현만 보고 끝내지 말고 setup에서 임시 반복문이 제거되고 start_new_round가 한 번만 호출되는지 확인합니다.

### main.py 수정 위치와 입력 코드

**편집 1.** 다섯 클래스가 끝난 뒤부터 `running = True` 직전까지의 그룹·객체 준비 구간를 **교체**합니다. 아래 코드를 다른 함수나 클래스 안에 넣지 않습니다.

**왜 이렇게 쓰나요 — 이 편집을 읽는 순서**

- **같이 갱신하거나 검사할 객체들을 담을 그룹을 만듭니다.** Group은 Sprite들을 묶는 관리 목록입니다. 변수마다 `Group()`을 호출하면 별개의 빈 그룹을 만듭니다. 화성의 tiles/all_tiles는 그릴 타일 전체, platforms는 착지 대상, hazards는 위험 접촉 대상입니다. 우주 방어대의 양쪽 탄환 그룹도 분리해야 아군과 적의 탄환을 다른 규칙으로 검사할 수 있습니다. 그룹을 준비하는 것과 실제 객체를 넣는 것은 별개입니다.

```python
# --- 스프라이트 그룹 및 객체 생성 ---
# 현재 아군 탄환을 담아 이동·충돌·개수를 관리합니다.
scout_pulses = pygame.sprite.Group()
# 현재 적 탄환을 담아 이동·충돌·개수를 관리합니다.
raider_pulses = pygame.sprite.Group()

# 아군 탐사선을 담습니다.
scouts = pygame.sprite.Group()
scout = Scout(scout_pulses)
scouts.add(scout)

# 현재 편대의 적들을 담습니다.
raiders = pygame.sprite.Group()

mission = Mission(scout, raiders, scout_pulses, raider_pulses)
mission.start_new_round()
```


### 코드가 하는 일

setup 전체를 교체하므로 이전 for range(10)은 남기지 않습니다. 그룹과 아군 생성은 그대로이고 Mission 생성 바로 뒤에서 start_new_round를 한 번 호출합니다. 메서드는 이미 정의돼 있어 호출할 수 있습니다.

### 여기서 실행하세요

정지 → 위 코드 수정 → 실행 → 게임 화면 클릭 순서로 진행합니다.

출격음과 함께11열5행의55기가 보이고 오른쪽으로 이동합니다. 임시10기는 없습니다.

**이 시점의 정상 상태:** 아직 화면 끝을 넘어가며 일시정지하지 않습니다.

**예상과 다를 때:** 65기가 보이면 임시 루프가 남았는지,110기면 start_new_round를 두 번 호출했는지 확인합니다. 아래 시험에서55가 출력돼야 합니다.

### 잠깐 바꿔 보고 원래 상태로 복원하기

정지한 뒤 `running = True` 바로 위에 다음 시험 코드만 추가합니다. 들여쓰기 없이 시작하며 for 본문만4칸입니다. 클래스/메서드 안에 넣지 않습니다.
