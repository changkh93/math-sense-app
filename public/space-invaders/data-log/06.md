## 06-A - 임시 열 마리 편대부터 확인하기

적 탄환을 만들기 전에 적 객체가 실제로 생성되고 움직이는지 확인합니다. 한 줄의 좌표 간격을 먼저 예측합니다.

**이 단계의 연결:** 출발 코드는 **05-A**의 누적 코드입니다. 아래 편집은 위에서부터 모두 적용합니다. 이미 완성한 나머지 메서드는 지정된 교체 범위 밖이면 그대로 둡니다.


### 입력 전에 결과를 예상해 보세요

range(10)의 첫 번째와 마지막 i, 그리고 x를 계산해 보세요.

먼저 답을 한 문장으로 적고 아래 해설과 비교하세요.

**생각 확인:** i는 0과 9, x는 64과 640입니다. 열 개를 만든다고 마지막 i가 10인 것은 아닙니다. 임시 편대는 정식 55기 편대로 교체할 때 제거합니다.

### main.py 수정 위치와 입력 코드

**편집 1.** 다섯 클래스가 끝난 뒤부터 `running = True` 직전까지의 그룹·객체 준비 구간를 **교체**합니다. 아래 코드를 다른 함수나 클래스 안에 넣지 않습니다.

**왜 이렇게 쓰나요 — 이 편집을 읽는 순서**

- **같이 갱신하거나 검사할 객체들을 담을 그룹을 만듭니다.** Group은 Sprite들을 묶는 관리 목록입니다. 변수마다 `Group()`을 호출하면 별개의 빈 그룹을 만듭니다. 화성의 tiles/all_tiles는 그릴 타일 전체, platforms는 착지 대상, hazards는 위험 접촉 대상입니다. 우주 방어대의 양쪽 탄환 그룹도 분리해야 아군과 적의 탄환을 다른 규칙으로 검사할 수 있습니다. 그룹을 준비하는 것과 실제 객체를 넣는 것은 별개입니다.

```python
# --- 스프라이트 그룹 및 객체 생성 ---
# 현재 아군 탄환을 담아 이동·충돌·개수를 관리합니다.
scout_pulses = pygame.sprite.Group()
# 현재 적 탄환을 담아 이동·충돌·개수를 관리합니다.
raider_pulses = pygame.sprite.Group()

# 아군 탐사선을 담습니다.
scouts = pygame.sprite.Group()
scout = Scout(scout_pulses)
scouts.add(scout)

# 현재 편대의 적들을 담습니다.
raiders = pygame.sprite.Group()

for i in range(10):
    raiders.add(Raider(64 + i * 64, 100, 2, raider_pulses))

mission = Mission(scout, raiders, scout_pulses, raider_pulses)
```


### 코드가 하는 일

range(10)의 i는0~9입니다. x는64,128,...640이고 y는100입니다. 속도2를 전달합니다. 객체를 raiders에 넣으면 기존 update/draw 연결로 이동과 표시가 시작됩니다. Mission은 여전히 pass입니다.

**예상과 다를 때:** 적이 하나뿐이면 add가 for 안4칸인지 확인합니다. 생성 인수는 x,y,속도,탄환그룹의 네 개입니다.

## 06-B - 적 탄환의 하강과 발사 연결하기

아군과 반대로 아래로 움직이는 탄환을 만듭니다. 먼저 정리 없이 하강 자체를 확인합니다.

**이 단계의 연결:** 출발 코드는 **06-A**의 누적 코드입니다. 아래 편집은 위에서부터 모두 적용합니다. 이미 완성한 나머지 메서드는 지정된 교체 범위 밖이면 그대로 둡니다.


### 입력 전에 결과를 예상해 보세요

아군 탄환 코드에서 색만 바꾸면 적 탄환이 될까요?

먼저 답을 한 문장으로 적고 아래 해설과 비교하세요.

**생각 확인:** 아닙니다. 시작점은 적의 bottom, 이동은 y 증가, 소속은 적 탄환 그룹이어야 합니다. 아래 경계 제거는 이어지는 단계에서 의도적으로 잘못된 조건을 관찰한 뒤 고칩니다.

### main.py 수정 위치와 입력 코드

**편집 1.** `class RaiderPulse` 안의 `def __init__`부터 그 메서드 본문 끝까지 **전체 교체**합니다. 다음 def나 다음 class는 지우지 않습니다. def 앞4칸, 본문 앞8칸을 유지합니다.

**왜 이렇게 쓰나요 — 이 편집을 읽는 순서**

- **부모 Sprite의 내부 준비를 먼저 실행합니다.** `super().__init__()`은 상속받은 Sprite 내부를 준비합니다. 괄호 안에 그룹이 있으면 그 그룹에 이 객체를 바로 등록합니다. `super().__init__(tiles)`는 tiles에 자동 등록하지만 인수가 없는 `super().__init__()`은 자동 등록하지 않으므로 나중에 `그룹.add(객체)`가 필요합니다. 이 차이를 확인하고 중복 생성하지 마세요.

- **그림의 크기와 화면 위치를 담을 상자를 만듭니다.** `image`는 그림이고 `rect`는 그 그림을 놓을 사각형입니다. `get_rect(topleft=(x, y))`는 왼쪽 위, `midbottom=(x, y)`는 발 가운데를 해당 위치에 맞춥니다. 예를 들어 64×64 그림의 midbottom이 (100, 200)이면 왼쪽 위는 (68, 136)입니다. 같은 좌표라도 기준점이 다르면 표시 위치가 달라집니다. Group.draw는 각 객체의 image와 rect를 읽습니다.

```python
    # 객체를 생성할 때 필요한 초기 값과 참조를 준비합니다.
    def __init__(self, x, y, pulse_group):
        # 부모 Sprite의 내부 준비를 먼저 실행합니다.
        super().__init__()
        self.image = pygame.Surface((4, 16), pygame.SRCALPHA)
        self.image.fill((255, 92, 124))
        # 그림의 크기와 화면 위치를 담을 상자를 만듭니다.
        self.rect = self.image.get_rect()
        self.rect.centerx = x
        self.rect.centery = y
        self.velocity = 10
        pulse_group.add(self)
```


**편집 2.** `class RaiderPulse` 안의 `def update`부터 그 메서드 본문 끝까지 **전체 교체**합니다. 다음 def나 다음 class는 지우지 않습니다. def 앞4칸, 본문 앞8칸을 유지합니다.

```python
    # 그룹에서 호출하는 한 프레임의 처리 순서입니다.
    def update(self):
        self.rect.y += self.velocity
```


**편집 3.** `class Raider` 안의 `def fire`부터 그 메서드 본문 끝까지 **전체 교체**합니다. 다음 def나 다음 class는 지우지 않습니다. def 앞4칸, 본문 앞8칸을 유지합니다.

```python
    # 발사 조건을 확인하고 발사체를 생성합니다.
    def fire(self):
        RaiderPulse(self.rect.centerx, self.rect.bottom, self.pulses)
```


### 코드가 하는 일

적 탄환은 산호색(255,92,124)이고4×16입니다. y+=10이면 아래로 이동합니다. Raider.fire는 적의 centerx와 bottom에서 RaiderPulse를 만듭니다. 적의 공통 그룹에 추가되어 총3발 제한을 공유합니다.

잠시 관찰하면 산호색 탄환이 적 아래에서 아래쪽으로 내려갑니다. 스페이스를 누르면 아군 탄환은 반대로 올라갑니다.

**이 단계의 연결:** 출발 코드는 **06-B**의 누적 코드입니다. 아래 편집은 위에서부터 모두 적용합니다. 이미 완성한 나머지 메서드는 지정된 교체 범위 밖이면 그대로 둡니다.


### 입력 전에 결과를 예상해 보세요

top=120인 적 탄환에서 top<700이 참이면 어떤 일이 생기나요?

### main.py 수정 위치와 입력 코드

**편집 1.** `class RaiderPulse` 안의 `def update`부터 그 메서드 본문 끝까지 **전체 교체**합니다. 다음 def나 다음 class는 지우지 않습니다. def 앞4칸, 본문 앞8칸을 유지합니다.

**왜 이렇게 쓰나요 — 이 편집을 읽는 순서**

- **이 객체를 소속 그룹에서 제거해 갱신과 그리기를 끝냅니다.** kill은 모든 소속 Group에서 Sprite를 제거합니다. 이후 그룹 update/draw와 개수 검사에서 빠집니다. Python 변수까지 모두 지우거나 즉시 메모리를 없애라는 명령은 아닙니다. 화면 이탈·회수·격추 뒤 같은 객체가 다음 프레임에 다시 처리되지 않게 하는 데 사용합니다.

```python
    # 그룹에서 호출하는 한 프레임의 처리 순서입니다.
    def update(self):
        self.rect.y += self.velocity
        if self.rect.top < SCREEN_HEIGHT:
            # 이 객체를 소속 그룹에서 제거해 갱신과 그리기를 끝냅니다.
            self.kill()
```


### 코드가 하는 일

이번 코드는 진단용 오류입니다. 아직 화면 안에 있는 탄환의 top도700보다 작으므로 첫 update에서 제거됩니다. 소리가 나도 탄환이 안 보이는 원인을 좌표로 찾습니다.

### main.py 수정 위치와 입력 코드

**편집 1.** `class RaiderPulse` 안의 `def update`부터 그 메서드 본문 끝까지 **전체 교체**합니다. 다음 def나 다음 class는 지우지 않습니다. def 앞4칸, 본문 앞8칸을 유지합니다.

**왜 이렇게 쓰나요 — 이 편집을 읽는 순서**

- **이 객체를 소속 그룹에서 제거해 갱신과 그리기를 끝냅니다.** kill은 모든 소속 Group에서 Sprite를 제거합니다. 이후 그룹 update/draw와 개수 검사에서 빠집니다. Python 변수까지 모두 지우거나 즉시 메모리를 없애라는 명령은 아닙니다. 화면 이탈·회수·격추 뒤 같은 객체가 다음 프레임에 다시 처리되지 않게 하는 데 사용합니다.

```python
    # 그룹에서 호출하는 한 프레임의 처리 순서입니다.
    def update(self):
        self.rect.y += self.velocity
        if self.rect.top > SCREEN_HEIGHT:
            # 이 객체를 소속 그룹에서 제거해 갱신과 그리기를 끝냅니다.
            self.kill()
```

top>SCREEN_HEIGHT로 고칩니다. 아군은 bottom<0, 적은 top>700으로 전체 이탈을 검사합니다. 두 경우 모두 움직인 뒤 판정합니다.
