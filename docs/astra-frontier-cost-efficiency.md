# 아스트라 프론티어 비용 효율화

2026-09-06, 기준 커밋 51c755d. 로컬 변경이며 운영 배포 전이다. 청구 계정이나 운영 사용량은 조회하지 않았다.

## 과금으로 이어지는 경로

- Cloud Functions 호출과 그 안의 Firestore 조회·트랜잭션: 이용권 확인, 세션 체크포인트, 방 접근권 갱신, 구매·보상·건축·대화. 권한·광석·보상 검증은 비용을 이유로 클라이언트로 옮기지 않는다.
- Firestore 실시간 구독: 내 행성, 방문 행성, 지갑/장비, 최근 방문 이벤트. 변경 문서 읽기와 재구독이 비용에 영향을 준다. 방문 이벤트는 배지·시설 상태에도 쓰므로 메뉴를 닫았다고 무조건 중단하지 않는다.
- RTDB: 위치·장비·대화·접속 상태의 다운로드와 방 참여자에게 전달되는 트래픽. 쓰기 횟수만을 요금으로 환산하면 안 된다. 방 인원에 따라 동일 변경의 전달량이 증가한다.
- Hosting: JS·모델 코드·음원 등 정적 파일 전송. 기존 음원은 캐시와 재생 인스턴스 재사용이 있어 유지했다.
- 해양 생물·수초·물결·캐릭터 애니메이션은 로컬 CPU/GPU 계산이다. 개체마다 서버 호출하거나 유료 AI 모델을 호출하지 않는다. 기기 성능 부담과 클라우드 요금은 별개다.

공식 기준: [RTDB 과금](https://firebase.google.com/docs/database/usage/billing), [Firestore 실시간 구독 과금](https://firebase.google.com/docs/firestore/pricing#listening_to_query_results). 무료 제공량, 지역, 실제 접속 인원과 트래픽에 따라 청구액이 달라진다.

## 적용한 변경

1. **체크포인트 반복 호출 제거.** 응답이 session/clock을 바꾸면 callback identity가 달라지고, effect가 다시 즉시 호출하는 구조를 끊었다. Effect Event로 최신 상태를 읽고 30초 타이머는 유지한다. 탭 복귀/online 이벤트 폭주는 5초 최소 간격과 진행 중 요청 재사용으로 제한한다. 게스트 체크포인트·종료는 서버를 호출하지 않는다. 늦게 도착한 다른 계정/종료 세션의 응답도 무시한다.
2. **변경 항목만 위치 전송.** 120ms 간격, 좌표 정밀도, 이동 판정 임계값, 15초 접속 만료는 유지했다. 이동 없는 축·장비·크기는 재전송하지 않는다. 하나라도 실패한 delta가 있으면 다음 위치는 전체 전송하여 복구한다. 초기 접속 중 움직임도 실제로 보낸 위치와 비교한다.
3. **이동 중 중복 heartbeat 제거.** 최근 5초 안에 위치 전송이 있으면 그 갱신 시각을 사용한다. 정지 시에는 기존 5초 신호를 유지해 새 방문자에게 계속 보인다.
4. **구독 관리.** 비활성 presence의 serverTimeOffset 구독을 중단했다. 내 행성 구독은 방문 대상이 바뀌어도 다시 생성하지 않으며, 수신 시 최신 방문 대상을 확인한다. 자기 위치 이벤트의 불필요한 로컬 재렌더도 줄였다. 마지막 항목은 다운로드 자체를 차단하는 변경은 아니다.
5. **방 접근권 갱신 2분→3분.** 서버 5분 유효기간과 모든 권한 재검증은 그대로다. 숨김/오프라인 호출, 동시 요청과 이벤트 폭주를 억제하고, 화면 복귀 시 만료 임박 여부를 확인한다. 정상 지속 접속의 주기적 시도는 시간당 30회→20회이며 시작·복귀·실패 재시도는 별도다.
6. **해시 정적 파일 장기 캐시.** `/assets/**`에 1년 immutable 캐시를 추가했다. Vite의 콘텐츠 해시 이름이 바뀌면 새 버전을 받는다. HTML의 no-cache와 기존 `/sounds/**` 정책은 유지한다. 앞으로 해시 없는 파일을 public/assets에 넣으면 안 된다.

예시: x만 이동하는 JSON 본문은 117→37바이트로 약 68% 작아졌다. 프로토콜·암호화·다른 축의 변화·초기 스냅샷·청구 무료량을 제외한 **본문 비교**이며 전체 요금 68% 절감을 의미하지 않는다.

## 검증과 운영 반영

- `npm run test:frontier-cost`: 실제 React/StrictMode + jsdom에서 응답 재렌더, 30초 주기, 숨김/오프라인/복귀, 진행 중 중복, 게스트 종료, 늦은 다른 계정 응답을 검증한다. 실제 presence 훅과 메모리 RTDB 모형으로 delta 전송, 이동/정지 heartbeat, 이전 쓰기 실패 후 전체 복구와 모든 구독 해제를 검사한다. 운영 API는 호출하지 않는다.
- 이용시간 서버 정책, 탐험·해양, 오디오 테스트 및 변경 코드 ESLint, 프로덕션 빌드 검증. 오디오 테스트의 과거 강 수면 상수 0.05를 현재 공유 수면 상수로 교정했다. 오디오 동작 코드는 변경하지 않았다.
- 변경은 웹 번들과 Hosting 캐시 헤더를 배포해야 운영에 적용된다. 이번 최적화는 DB 규칙·서버 함수 변경을 요구하지 않는다. 이전 해양 확장의 미배포 규칙 변경이 있다면 그 규칙을 먼저 반영해야 한다.
- 배포 후 callable 요청률, Firestore 읽기량, RTDB sent bytes와 오류율, Hosting 전송량을 같은 플레이 시간·접속 인원 기준으로 비교한다. 실제 절감액은 그 자료 없이 단정할 수 없다.
- 운영 다중 사용자·불안정 네트워크의 장시간 실기기 검증은 미수행이다. 고빈도 구매/보상/건축 검증을 생략하거나 전역 DB 연결을 강제로 끊는 방식은 적용하지 않았다.
