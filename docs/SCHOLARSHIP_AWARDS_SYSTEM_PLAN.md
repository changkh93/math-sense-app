# 장학금, 상장 운영 제도 및 구현 계획

## 1. 목적

메타센스의 장학금 제도는 단순히 문제 점수나 광석 총량이 높은 학생을 자동 선발하는 제도가 아니다. 과제 제출, 출석, 학습기록, 피드백 반영 흐름을 종합적으로 보여주고, 운영자가 그 정보를 바탕으로 학생의 성실성과 성장 가능성을 판단하여 장학금을 수여하는 운영 제도다.

장학생은 매월 선발한다. 예를 들어 6월 한 달간의 과제, 출석, 학습기록, 보너스 광석 지표를 기준으로 `6월 장학생`을 선정하고, 7월 한 달간의 지표를 기준으로 `7월 장학생`을 선정한다. 장학금 기록과 장학증서에는 항상 `평가월`이 명확히 남아야 한다.

기존 운영툴의 `월간평가 상장` 메뉴는 `장학금, 상장`으로 확장한다. 내부에는 `장학금` 탭과 `월간평가 상장` 탭을 분리해서, 장학금 수여와 월간평가 상장 수여가 같은 메뉴 안에서 관리되지만 서로 다른 기준과 화면을 갖도록 한다.

## 2. 운영 원칙

### 2.1 자동 선발하지 않는다

시스템은 장학금 수여 대상자를 자동으로 확정하지 않는다. 대신 과목별, 월별 학생 데이터를 기준에 따라 정렬하고, 운영자가 지표와 이력 정보를 보고 최종 수여 여부를 판단한다.

따라서 장학금 화면의 핵심은 `후보 추천`이 아니라 `좋은 판단을 돕는 정렬과 근거 표시`다.

### 2.2 중복 수여를 시스템이 차단하지 않는다

한 학생이 같은 달 여러 과목에서 장학금을 받을 수 있는지, 최근에 받은 학생에게 다시 줄 수 있는지는 운영자가 판단한다. 시스템은 중복을 강제로 막지 않고, 최근 장학금 수여 이력과 누적 수여 횟수를 잘 보여준다.

운영자는 이 정보를 바탕으로 골고루 수여할지, 특정 학생의 뛰어난 성과를 반복 인정할지 결정할 수 있다.

### 2.3 장학금은 수강료 감면으로 지급한다

장학금은 현금 지급이 아니라 해당 과목 수강료의 20% 감면으로 적용한다.

- 기본 혜택: 해당 과목 수강료 20% 감면
- 적용 시점: 운영자가 확정한 다음 청구 또는 다음 수강료 반영 시점
- 학생 표시: `장학생 선정`, `수강료 20% 감면`
- 운영툴 표시: 기준 수강료, 감면율, 감면액, 적용 상태

### 2.4 평가월과 혜택 적용월을 분리한다

장학생 명칭은 지표가 집계된 월을 기준으로 한다.

- 6월 1일~6월 30일 지표 기준: `6월 장학생`
- 7월 1일~7월 31일 지표 기준: `7월 장학생`

혜택 적용월은 운영 정책에 따라 다음 청구월 또는 다음 수강월이 될 수 있다. 따라서 데이터와 화면에서는 `평가월`과 `혜택 적용월`을 분리해서 표시한다.

예시:

- 평가월: 2026년 6월
- 표시명: 2026년 6월 초등수학 장학생
- 혜택 적용월: 2026년 7월 수강료

## 3. 대상 과목

장학금 산정 대상 과목은 다음 3개다.

| 과목 | clusterId | 비고 |
| --- | --- | --- |
| 초등수학 | `cluster_elementary` | 기본 수학 과정 |
| 중등수학 | `middle-math` | 중등 수학 과정 |
| 파이썬 | `python` | 코딩 및 프로젝트 과정 |

운영툴에서는 과목 필터를 제공하고, 기본 화면은 전체 과목을 함께 보되 과목별 순위와 지표를 별도로 계산한다.

## 4. 장학금 판단 기준

### 4.1 핵심 기준

장학금 판단의 중심 지표는 과제 제출 후 운영자가 부여한 `bonusCrystals`다. 보너스 광석은 이미 과제 제출, 학습기록, 출석 흐름, 제출물 품질, 피드백 맥락을 종합적으로 반영하는 값이므로 장학금 기준의 중심으로 사용한다.

다만 단순 평균만 사용하면 과제 수가 적은 학생이나 특정 과제에서만 높은 점수를 받은 학생이 과도하게 유리할 수 있다. 따라서 운영툴에서는 여러 정렬 기준과 보조 지표를 함께 보여준다.

모든 지표는 선택한 평가월의 월초 00:00부터 월말 23:59까지를 기준으로 집계한다. 시간대 기준은 한국 시간 `Asia/Seoul`로 통일한다.

### 4.2 기본 장학 지수

운영툴의 기본 정렬값은 `장학 지수`로 둔다.

```txt
장학 지수 =
  0.45 * 보너스광석 평균 점수
+ 0.20 * 보너스광석 총량 점수
+ 0.15 * 과제 제출 충실도
+ 0.10 * 학습기록 연결도
+ 0.10 * 성장도
- 경고/불성실 감점
```

각 항목은 0~100점으로 정규화한 뒤 계산한다.

### 4.3 보너스광석 평균 점수

월별, 과목별 리뷰 완료 과제의 `bonusCrystals` 평균을 사용한다.

- 대상: `assignments.status == reviewed`
- 과목 기준: `assignments.clusterId`
- 기간 기준: 과제의 `date` 또는 `submittedAt`
- 값 기준: `bonusCrystals`

과제 수가 너무 적은 경우 평균이 왜곡될 수 있으므로, 화면에 `리뷰 완료 과제 수`를 반드시 함께 표시한다.

### 4.4 보너스광석 총량 점수

월별, 과목별 리뷰 완료 과제의 `bonusCrystals` 총합을 사용한다.

총량은 꾸준히 제출한 학생에게 유리한 지표다. 평균은 높지만 제출 수가 적은 학생과, 평균은 조금 낮아도 꾸준히 좋은 제출을 이어간 학생을 구분할 수 있게 해준다.

### 4.5 과제 제출 충실도

출석일 또는 과제 기대일 대비 실제 제출일 비율을 보여준다.

```txt
과제 제출 충실도 = 제출일 수 / 기대 제출일 수
```

기대 제출일 수는 초기 구현에서는 해당 월 과목별 출석 기록을 기준으로 계산한다.

- 출석 기록 있음 + 과제 제출 있음: 충실 제출
- 출석 기록 있음 + 과제 제출 없음: 미제출
- 출석 기록 없음 + 과제 제출 있음: 자율 제출 또는 보강 제출로 표시

운영툴에는 제출률뿐 아니라 `출석일`, `제출일`, `미제출일`을 함께 보여준다.

### 4.6 학습기록 연결도

과제 제출일에 같은 과목의 학습기록이 연결되어 있는지 본다.

인정 가능한 기록은 다음과 같다.

- 퀴즈 응시 기록
- 영상 학습 기록
- 데이터 로그 읽기 기록
- 파이썬 코드/노트북/프로젝트 제출 근거
- 다크매터 또는 오답 복습 관련 활동

```txt
학습기록 연결도 = 학습기록이 확인된 제출일 수 / 과제 제출일 수
```

파이썬 과정은 영상 시간보다 직접 코드 작성, 실행 결과, 오류 수정, 변경 설명을 더 중요하게 본다.

### 4.7 성장도

월 전반과 월 후반의 보너스 광석 흐름을 비교한다.

```txt
성장도 = 월 후반 평균 bonusCrystals - 월 전반 평균 bonusCrystals
```

운영툴에는 단순 점수뿐 아니라 추세를 표시한다.

- 상승
- 유지
- 하락
- 데이터 부족

성장도는 성적이 이미 높은 학생뿐 아니라 최근 태도가 좋아진 학생을 발견하기 위한 보조 지표다.

### 4.8 감점 정보

감점은 자동 탈락 용도가 아니라 운영자 판단을 돕는 경고 표시다.

표시할 감점 요인은 다음과 같다.

- 출석 후 과제 미제출
- 연속 미제출 경고
- 불성실 과제 제출 경고
- `needs_revision` 과제 수
- 리뷰 완료 전 제출 누락
- 피드백 반영이 거의 없는 반복 제출

운영툴에는 감점 총점보다 `무슨 이유로 감점되었는지`를 더 잘 보여준다.

## 5. 운영툴 화면 설계

### 5.1 메뉴 구조

기존 메뉴명:

```txt
월간평가 상장
```

변경 후:

```txt
장학금, 상장
```

내부 탭:

- `장학금`
- `월간평가 상장`

`월간평가 상장` 탭은 기존 기능을 유지한다. `장학금` 탭은 새로 만든다.

### 5.2 장학금 탭 상단 필터

필터는 다음을 제공한다.

- 연도
- 월
- 과목
- 학년
- 수강 상태
- 장학금 수여 상태
- 최근 수여 이력
- 검색어

기본값은 현재 연도와 현재 월, 전체 과목이다.

### 5.3 요약 카드

상단에는 월별 운영 상황을 요약한다.

- 전체 표시 학생 수
- 과목별 수강생 수
- 리뷰 완료 과제 수
- 장학금 수여 완료 수
- 미수여 학생 수
- 최근 3개월 수여 경험자 수

### 5.4 학생 테이블 컬럼

장학금 탭의 핵심 테이블에는 다음 컬럼을 둔다.

| 컬럼 | 설명 |
| --- | --- |
| 순위 | 현재 정렬 기준 내 순위 |
| 과목 | 초등수학, 중등수학, 파이썬 |
| 학생 | 이름, 이메일, 학년 |
| 평가월 | 6월 장학생, 7월 장학생 등 지표 기준 월 |
| 장학 지수 | 기본 정렬 점수 |
| 보너스 평균 | 리뷰 완료 과제의 평균 bonusCrystals |
| 보너스 총합 | 월간 bonusCrystals 총합 |
| 리뷰 과제 | 리뷰 완료 과제 수 |
| 제출률 | 출석/기대일 대비 제출률 |
| 학습 연결 | 제출일 중 학습기록 연결 비율 |
| 성장 | 상승, 유지, 하락, 데이터 부족 |
| 경고 | 미제출/불성실/재제출 정보 |
| 장학 이력 | 최근 수여월, 최근 3개월/누적 수여 수 |
| 혜택 | 수강료, 감면율, 감면액 |
| 관리 | 수여, 상세, 보류 메모 |

### 5.5 정렬 기준

운영자가 정렬 기준을 바꿀 수 있어야 한다.

- 장학 지수 높은 순
- 보너스 평균 높은 순
- 보너스 총합 높은 순
- 제출률 높은 순
- 학습 연결도 높은 순
- 성장도 높은 순
- 최근 미수상자 우선
- 최근 수상자 우선
- 경고 적은 순

기본 정렬은 `장학 지수 높은 순`이다.

### 5.6 상세 패널

학생 행을 클릭하면 우측 또는 모달로 상세 패널을 연다.

상세 패널에는 다음 정보를 보여준다.

- 학생 기본 정보
- 현재 과목 수강 상태
- 해당 월 과제 제출 캘린더
- 과제별 bonusCrystals, 피드백 요약, 제출 상태
- 출석 기록
- 제출일 학습기록 요약
- 경고 및 재제출 이력
- 최근 6개월 장학금 수여 이력
- 최근 6개월 월간평가 상장 이력
- 운영자 메모

장학금 수여는 상세 패널 또는 테이블 행 버튼에서 가능하다.

## 6. 장학금 수여 흐름

### 6.1 수여 전 확인

운영자가 `장학금 수여` 버튼을 누르면 확인 모달을 띄운다.

확인 모달에는 다음을 표시한다.

- 학생명
- 과목
- 대상 월
- 장학생 표시명
- 장학 지수
- 핵심 근거 3~5개
- 최근 장학금 수여 이력
- 감면율 20%
- 기준 수강료
- 감면액
- 적용 예정월

운영자는 필요하면 수여 사유 메모를 남길 수 있다.

### 6.2 수여 확정

확정 시 다음 작업을 한 번에 처리한다.

- `scholarshipAwards` 문서 생성
- 학생 알림 생성
- 학생 현황판에 표시될 장학증서 데이터 생성
- 운영자 수여 메모 저장

이미 같은 월/과목/학생에게 장학금이 수여된 경우에는 중복 문서 생성을 막는다. 이는 제도적 중복 제한이 아니라 동일 건 중복 클릭 방지를 위한 데이터 무결성 규칙이다.

### 6.3 수여 취소

운영 실수에 대비해 취소 기능도 필요하다.

취소 시에는 문서를 삭제하기보다 상태를 `revoked`로 바꾸고 취소 사유를 남긴다.

```txt
status: awarded | revoked
revokedAt
revokedBy
revokedReason
```

학생 화면에서는 `revoked` 상태의 장학증서를 숨긴다.

```js
  awardedBy: string,
  awardedAt: serverTimestamp,
  awardedDate: 'YYYY-MM-DD',
  createdAt: serverTimestamp,
  updatedAt: serverTimestamp
}
```

### 7.2 notifications

기존 `notifications` 컬렉션에 장학금 알림 타입을 추가한다.

```js
{
  recipientId: studentId,
  type: 'scholarship_award',
  message: '축하합니다! 2026년 6월 초등수학 장학생으로 선정되어 다음 수강료 20% 감면 혜택이 적용됩니다.',
  link: '/?view=dashboard&scholarship={awardId}',
  isRead: false,
  createdAt: serverTimestamp,
  metadata: {
    awardId,
    year,
    month,
    evaluationPeriodKey: '2026-06',
    courseClusterId,
    tuitionDiscountRate: 0.2
  }
}
```

### 7.3 Firestore Rules

관리자는 장학금 기록을 생성, 수정, 취소할 수 있다. 학생은 본인의 장학금 기록만 읽을 수 있다. 연결된 보호자 계정도 자녀의 장학금 기록을 읽을 수 있게 한다.

```txt
match /scholarshipAwards/{awardId} {
  allow read: if isAuth() && (
    isAdmin() ||
    resource.data.studentId == request.auth.uid ||
    isLinkedParentOf(resource.data.studentId)
  );
  allow create, update, delete: if isAdmin();
}
```

운영 실수 추적을 위해 실제 구현에서는 삭제보다 `status: revoked` 업데이트를 권장한다.

## 8. 학생 화면

### 8.1 상장 수여 현황판 확장

현재 학생 대시보드의 `상장 수여 현황판`은 월간평가 상장을 보여준다. 이 영역에 장학증서도 함께 표시한다.

표시 그룹:

- 월간평가 상장
- 장학증서

또는 월별 그룹 안에서 다음 배지로 구분한다.

- `최우수상`
- `장학증서`

### 8.2 장학증서 카드

장학증서 카드에는 다음을 표시한다.

- 장학증서 배지
- 평가월: `2026년 6월 장학생`
- 과목
- 수강료 20% 감면
- 수여일

클릭하면 장학증서 모달이 열린다.

### 8.3 장학증서 문구

장학증서 기본 문구:

```txt
장학 증서

위 학생은 {year}년 {month}월 {courseName} 과정에서
성실한 과제 제출과 꾸준한 학습 기록을 통해
뛰어난 자기주도 학습 태도를 보여주었기에
{month}월 메타센스 장학생으로 선정합니다.

혜택: 다음 수강료 20% 감면
```

운영자 메모가 있는 경우 학생에게 직접 노출하지 않고, 장학증서 문구는 일정한 형식을 유지한다.

### 8.4 장학증서 디자인 방향

기존 월간평가 상장은 종이 상장 느낌을 유지하고, 장학증서는 메타센스의 우주 탐사 테마에 맞춘 별도 디자인으로 만든다.

디자인 키워드:

- 딥 네이비 배경
- 시안 라인
- 골드 포인트
- 다이아몬드 광석 심볼
- 별자리 패턴
- 공식 증서 번호
- 직인 이미지

장학증서는 학생에게 특별한 보상으로 느껴져야 하지만, 월간평가 상장과 시각적으로 구분되어야 한다.

## 9. 알림 UX

장학금 수여 시 학생에게 알림을 보낸다.

알림 메시지:

```txt
축하합니다! {year}년 {month}월 {courseName} 장학생으로 선정되어 다음 수강료 20% 감면 혜택이 적용됩니다.
```

알림 클릭 시 해당 장학증서가 있는 대시보드로 이동한다.

추가로 학생이 해당 과목에 진입했을 때 미확인 장학금이 있으면 1회성 축하 모달을 표시할 수 있다.

모달 예시:

```txt
장학생 선정

{studentName} 학생, 축하합니다.
{courseName} 과정에서 성실한 학습 태도를 인정받아
이번 달 메타센스 장학생으로 선정되었습니다.

혜택: 다음 수강료 20% 감면
```

모달 확인 시 `acknowledgedAt`을 저장하면 반복 노출을 막을 수 있다.

## 11. 운영 시나리오

### 11.1 월말 장학금 수여

1. 운영자가 `장학금, 상장` 메뉴에 진입한다.
2. `장학금` 탭에서 평가 연도와 평가월을 선택한다.
3. 예를 들어 2026년 6월을 선택하면 화면의 모든 지표는 6월 1일~6월 30일 기록으로 집계된다.
4. 과목별로 `장학 지수 높은 순` 정렬을 확인한다.
5. 학생별 상세 패널에서 과제, 출석, 학습기록, 장학금 이력을 확인한다.
6. 운영자가 `6월 장학생`으로 수여할 학생을 결정한다.
7. `장학금 수여` 버튼을 눌러 확정한다.
8. 학생에게 알림이 발송되고, 학생 현황판에 `2026년 6월 {과목} 장학생` 장학증서가 표시된다.

### 11.2 최근 수상자 판단

1. 운영자가 장학금 테이블에서 `장학 이력` 컬럼을 확인한다.
2. 최근 3개월 수상자가 상위권에 있으면 상세 패널에서 이번 달 성과를 확인한다.
3. 운영자는 골고루 수여할지, 반복 수여할지 직접 판단한다.
4. 시스템은 판단을 제한하지 않고 기록과 근거만 제공한다.

### 11.3 다과목 수강생 판단

1. 한 학생이 초등수학과 파이썬을 모두 수강한다.
2. 각 과목 탭 또는 전체 화면에서 과목별 지표가 따로 표시된다.
3. 운영자는 두 과목의 성과와 기존 수여 이력을 비교한다.
4. 필요하면 같은 달 여러 과목 장학금을 수여할 수도 있고, 한 과목만 수여할 수도 있다.

## 12. 주의사항

- 장학 지수는 운영 판단을 돕는 정렬값이지, 자동 수여 기준이 아니다.
- 장학금 수여 이력은 운영툴에서 가장 잘 보여야 한다.
- 중복 수여는 정책적으로 막지 않는다.
- 단, 동일 월/동일 과목/동일 학생에 대한 중복 클릭은 데이터 무결성 차원에서 방지한다.
- 수강료 감면액은 수강료 정보가 없으면 `20% 감면`만 저장하고, 금액은 추후 운영자가 입력할 수 있게 한다.
- 학생에게는 과도한 순위 정보나 감점 정보가 노출되지 않게 한다.
- 보호자 화면에는 장학금 수여 사실과 혜택 중심으로 보여주는 것이 좋다.

- 장학금 월별 리포트 다운로드
- 수강료 청구 시스템과 감면액 자동 연동
- 장학금 수여 사유 템플릿
- 학생별 장학 성장 히스토리 차트
- 과목별 장학금 운영 통계
