# 과제 기록소 주간 성장 루프 개편 계획

- 문서 상태: 구현 전 제품 계획안 v1
- 작성일: 2026-08-24
- 대상: 과제 기록소(`AssignmentHub`, `AssignmentChronicle`)
- 연계 기술 문서: `docs/WEEKLY_GROWTH_LOOP_TECHNICAL_DESIGN.md`
- 임시 제품명: `이번 주 항로`

## 1. 결정 요약

과제 기록소에 일반적인 주간 플래너를 추가하지 않는다. 대신 기존 과제·학습 기록을 짧게 돌아보고, 다음 주에 바꿀 전략 하나와 실천 목표 최대 3개를 학생이 고르는 **주간 성장 루프**를 추가한다.

> 지난주 보기 → 돌아보기 → 하나 바꾸기 → 이번 주 목표 고르기 → 다음 주에 다시 보기

MVP의 핵심 결정은 다음과 같다.

1. 기능명은 `이번 주 항로`로 사용한다. 내부 도메인명은 `Weekly Growth Loop`로 통일한다.
2. 과제 기록소 헤더에서 학생이 명시적으로 열 때만 데이터를 읽는다. 자동 팝업과 실시간 구독은 사용하지 않는다.
3. 성찰은 자유 작문이 아니라 1~2개 선택, 다음 전략은 정확히 1개 선택으로 구성한다.
4. 이번 주 목표는 서로 다른 생활 영역을 포함한 고정 템플릿에서 최대 3개만 고른다.
5. 목표 달성은 자동 판정하지 않는다. 다음 주 돌아보기에서 학생이 `했어요 / 조금 했어요 / 아직이에요` 중 하나로 직접 돌아본다.
6. 학습 데이터는 학생을 평가하거나 계획을 자동 결정하는 데 쓰지 않고, 지난주를 보여주는 작은 `기록 거울`로만 사용한다.
7. 목표 성공에 보상하지 않는다. 도입 후 필요할 경우 주간 돌아보기 완료 자체에만 동일한 소량 보상을 검토한다.
8. 교사 대시보드, 월간 회고, AI 추천, 중장기 목표, 알림은 MVP에서 제외한다.

## 2. 현재 시스템 진단

### 2.1 활용할 수 있는 기존 기반

- `AssignmentHub`는 학생별·클러스터별 과제와 출석을 불러오고 날짜 탐색을 제공한다.
- `AssignmentChronicle`은 제출 내용, 교사 피드백, 해당 날짜의 학습 타임라인을 함께 보여준다.
- `learningSummaries/{uid}`에는 최근 일별 학습 활동이 서버 관리 요약으로 저장되어 있다.
- `users/{uid}/readingDayCredits/{dateKey}`는 유효 독서일을 하루 한 문서로 보존한다.
- 과제 초안은 이미 `localStorage`와 IndexedDB를 활용한다. 주간 계획 초안도 같은 원칙으로 서버 쓰기를 줄일 수 있다.
- 서버 명령·트랜잭션·광석 원장은 기존 멱등 처리 방식을 재사용할 수 있다.

### 2.2 그대로 확장하면 생기는 문제

| 접근 | 문제 |
|---|---|
| 일별 과제 문서에 주간 회고 필드 추가 | 일·주 개념이 섞이고, 과제 수정 권한과 회고 권한이 결합된다. |
| 과제 기록 페이지 사이에 주간 카드를 삽입 | 페이지 모델이 여러 타입으로 바뀌고 기존 일지 탐색·공유 기능이 복잡해진다. |
| 주간 화면을 열 때 원본 학습 이력을 전부 스캔 | 학습량이 많을수록 Firestore 읽기 비용이 증가한다. |
| 로그인 시 자동 팝업 | 학생의 통제감을 해치고 매주 추가 조회가 모든 사용자에게 발생한다. |
| 목표를 자동 완료 처리 | 외부 생활 목표를 판단할 수 없고 기록 누락을 실패로 오인한다. |
| AI가 목표를 자동 생성 | 비용·설명 가능성·학생 선택권 문제가 생긴다. |

따라서 주간 루프는 과제 문서와 분리된 **사용자별·주차별 단일 문서**로 관리하고, 화면도 과제 기록소에서 여는 별도 흐름으로 제공한다.

## 3. 제품 목표와 비목표

### 3.1 제품 목표

- 학생이 2~3분 안에 지난주를 돌아보고 이번 주 계획을 세울 수 있다.
- 잘했는지 평가하기보다 자신에게 맞는 전략을 한 가지씩 시험하게 한다.
- 지난 계획과 이번 결과가 다음 주에 자연스럽게 이어진다.
- 수학·Python 사용량을 늘리는 도구가 아니라 독서, 생활 습관, 도전, 관계까지 선택할 수 있게 한다.
- 기록이 쌓일수록 `나는 어떻게 배우는 사람인가`를 학생 스스로 발견하게 한다.

### 3.2 MVP 비목표

- 장기·중기·단기 계획표
- 일일 할 일 체크리스트와 캘린더 앱
- 목표 달성 자동 판정
- 성적 예측과 학생 간 비교
- 약점 단원 자동 진단
- 생성형 AI 코칭
- 교사의 주간 계획 배정
- 학부모 알림과 푸시 알림
- 공개 프로필·아고라 공유

## 4. 제안 아이디어 선별

| 제안 | 판단 | MVP 결정 | 이유 |
|---|---|---|---|

| 성찰 체크 1~2개 | 효과 매우 높음 | **채택** | 어린 학생에게 작문 부담 없이 메타인지를 훈련시킨다. |
| 자랑스러운 점 1개 | 효과 높음 | **채택, 선택 입력** | 실패 중심 회고를 막되 억지 긍정을 요구하지 않는다. |
| 다음 전략 1개 | 핵심 | **채택** | 계획–관찰–전략 수정의 연결점이다. |
| 목표 최대 3개 | 핵심 | **채택** | 과도한 계획을 제품 차원에서 막는다. |
| 학습 외 영역 | 효과 높음 | **채택** | 자기조절을 콘텐츠 소비량과 분리한다. |
| 다음 주 목표 결과 돌아보기 | 필수 연결 | **채택** | 계획만 쌓이고 닫히지 않는 문제를 막는다. |
| 자동 목표 추천 | 잠재 효과 | **후속** | 먼저 선택 데이터와 이용 패턴을 확보해야 한다. |
| 4주마다 월간 한 문장 | 유용 | **후속** | 주간 루프 정착 후 추가해야 부담을 판단할 수 있다. |
| 교사 최근 6주 보기 | 유용 | **Phase 2** | 학생용 가치 검증 후 상담 도구로 확장한다. |
| 완료 보상 | 주의 필요 | **MVP 제외** | 목표 성공을 보상하면 쉬운 목표 선택을 유도한다. |
| 돌아보기 완료 소량 보상 | 조건부 가능 | **실험 후 결정** | 참여율이 낮을 때만 전원 동일·주 1회로 검토한다. |
| AI 자동 분석·계획 | 비용·위험 큼 | **제외** | 학생 선택권, 비용, 오판 가능성 때문에 현재 불필요하다. |
| 중장기 목표 | 교육적 가치 있음 | **후속** | MVP에서 주간 루프가 자리 잡기 전에 넣으면 행정 양식이 된다. |

## 5. MVP 사용자 경험

### 5.1 진입점

과제 기록소 헤더의 `항해 일지 열기` 옆에 `이번 주 항로` 버튼을 둔다.

- 자동 팝업은 사용하지 않는다.
- 버튼을 눌렀을 때만 주간 문서와 요약을 읽는다.
- 완료 전에는 `이번 주 항로`, 완료 후에는 `항로 설정 완료`로 보인다.
- 첫 출시에서는 별도 홈 배너·푸시·이메일 알림을 만들지 않는다.

### 5.2 1단계 — 지난주 보기

화면 예시:

> 지난주 나는 이렇게 움직였어요  
> 8월 17일 ~ 23일

- MetaSense 학습 활동: 4일
- 제출한 과제: 3건
- 독서 기록: 2일
- 지난주 목표: 3개

지난 목표가 있으면 각 목표에 대해 학생이 하나를 고른다.

- `했어요`
- `조금 했어요`
- `아직이에요`

표시 원칙:

- 수치는 평가 점수나 순위로 변환하지 않는다.
- 데이터가 없는 영역은 `기록 없음`으로 표시하고 `하지 않았어요`라고 단정하지 않는다.
- 학습 기록이 일부 누락될 수 있음을 짧게 안내한다.
- 첫 주에는 지난 목표 평가를 생략하고 `첫 항로를 정해볼까요?`로 시작한다.

### 5.3 2단계 — 돌아보기

질문: `지난주 나는 어땠나요?`

1~2개 선택:

- 계획을 너무 많이 세웠어요
- 시작을 자꾸 미뤘어요
- 어려운 것을 피했어요
- 생각보다 꾸준히 했어요
- 공부할 때 집중이 잘 됐어요
- 모르는 것을 그냥 넘어갔어요
- 계획이 나에게 잘 맞았어요
- 다른 일이 생겨 계획대로 못 했어요
- 아직 잘 모르겠어요

선택 질문: `가장 마음에 드는 것은?`

- 꾸준히 한 것
- 포기하지 않은 것
- 어려운 것에 도전한 것
- 스스로 시작한 것
- 다시 해본 것
- 아직 잘 모르겠어요
- 이번에는 건너뛸래요

### 5.4 3단계 — 하나 바꾸기

질문: `다음 주에는 무엇을 하나 바꿔볼까요?`

정확히 1개 선택:

- 계획을 조금 줄일래요
- 매일 조금씩 할래요
- 어려운 것부터 할래요
- 틀린 것을 다시 해볼래요
- 시작 시간을 정할래요
- 공부할 때 다른 것을 치울래요
- 모르면 질문할래요
- 지난 계획 그대로 해볼래요

MetaSense는 하나를 미리 선택하지 않는다. 학생이 직접 결정해야 다음 단계로 갈 수 있다.

### 5.5 4단계 — 이번 주 목표 고르기

최대 3개 선택한다. 최소 1개를 권장하되 `이번 주는 목표 없이 돌아보기만 할래요`를 허용할지는 파일럿에서 결정한다. MVP 기본안은 1개 이상이다.

템플릿 영역:

**배우기**

- 수학 3번 하기
- 틀린 문제 다시 풀기
- Python 미션 2개 하기
- 책 3일 읽기
- 학교 공부 10분씩 3일 하기

**습관**

- 공부 시작 시간 정하기
- 자기 전에 내일 할 일 확인하기
- 공부할 때 다른 화면 치우기
- 준비물을 스스로 챙기기

**도전**

- 새로운 책 시작하기
- 작은 프로그램 하나 만들기
- 궁금한 것 하나 조사하기
- 배운 것을 가족에게 설명해 보기

**함께하기**

- 가족을 한 번 돕기
- 친구에게 배운 것을 설명해 주기
- 약속한 일을 지키기

자유 입력 목표는 MVP에서 제외한다. 실제 이용 중 템플릿 부족이 반복될 때 80자 이내 1개로 제한해 후속 검토한다.

### 5.6 5단계 — 확인 및 시작

한 화면에서 다음을 확인한다.

- 지난주 성찰 1~2개
- 다음 전략 1개
- 이번 주 목표 최대 3개

버튼: `이번 주 시작하기 🚀`

저장 후에는 계획을 읽기 전용으로 보여주고 `계획 수정`을 제공한다. 수정은 서버 자동 저장이 아니라 명시적 저장 버튼을 누를 때만 수행한다.

## 6. 주간 경계와 예외 처리

### 6.1 주차 기준

- 한국 시간 월요일 00:00부터 일요일 23:59:59까지를 한 주로 정의한다.
- 문서 키는 해당 주 월요일 날짜(`YYYY-MM-DD`)를 사용한다.
- 주간 화면에서 검토하는 기간은 바로 전 월요일~일요일이다.

### 6.2 첫 이용

- 이전 주 문서가 없으면 목표 결과 평가를 생략한다.
- 데이터 거울은 존재하는 기록만 보여준다.
- `지난 계획이 없어요`를 실패로 표현하지 않는다.

### 6.3 한 주 이상 건너뛴 경우

- 놓친 주를 소급 작성하도록 요구하지 않는다.
- 바로 전 주 데이터만 보여주고 현재 주 계획을 만든다.
- 가장 최근 계획은 참고 문구로만 보여줄 수 있지만 자동으로 복사하지 않는다.

### 6.4 기록이 없는 경우

> 지난주 MetaSense에 남은 기록이 많지 않아요. 그래도 지난주를 떠올리며 하나만 골라볼 수 있어요.

기록이 없다는 이유로 루프 작성을 막지 않는다.

## 7. 과제 기록소 통합 원칙

1. `AssignmentHub`에는 진입 버튼과 완료 상태만 추가한다.
2. `AssignmentChronicle`의 일별 페이지 모델에는 주간 문서를 섞지 않는다.
3. 주간 루프는 별도 모달 또는 전체 화면 드로어로 연다.
4. 현재 선택한 클러스터와 관계없이 사용자 전체의 주간 루프 한 건을 사용한다.
5. 과제 기록소 어느 클러스터에서 열어도 같은 주간 계획이 보인다.
6. 비공개 학습 기록으로 취급하며 아고라·공개 프로필에는 노출하지 않는다.

## 8. 보상 정책

MVP에서는 보상 없이 시작하는 것을 권장한다.

도입 후 완료율이 지나치게 낮아 보상 실험이 필요할 경우:

- 주간 루프를 처음 완료했을 때만 소량 광석을 지급한다.
- 목표 성공 수와 관계없이 같은 양을 지급한다.
- 한 주에 한 번만 지급하고 멱등 명령으로 중복 지급을 막는다.
- 교사·학생 문구는 `성공 보상`이 아니라 `돌아본 기록 보상`으로 표현한다.

목표 완료율, 목표 난이도, 연속 성공에는 보상·랭킹·배지를 연결하지 않는다.

## 9. 성공 지표와 방어 지표

### 9.1 제품 지표

- 과제 기록소 방문 학생 중 주간 루프 시작률
- 시작 대비 완료율
- 평균 완료 시간(목표 2~3분)
- 4주 중 2회 이상 반복한 학생 비율
- 목표 개수 분포와 전략 선택 분포
- 이전 목표 결과를 솔직하게 `조금/아직`으로 선택한 비율

### 9.2 품질 지표

- 자유 입력 없이도 완료 가능한 비율
- `아직 잘 모르겠어요` 선택률
- 중간 이탈이 가장 많은 단계
- 계획 수정률
- 학생·교사의 정성 피드백

### 9.3 비용·부하 지표

- 주간 화면 최초 열기당 Firestore 읽기 수
- 같은 주 재진입당 읽기 수
- 완료당 쓰기 수
- 주간 요약 생성 함수 p95 지연 시간
- 동일 주 중복 문서·중복 보상 건수
- `learningSummaries` 누락 또는 오래된 요약 비율

## 10. 단계별 출시 계획

### Phase 0 — 정책·문구 확정

- 제품명과 진입 위치 확정
- 선택지·목표 템플릿의 연령 적합성 검토
- 주차 기준과 첫 이용 정책 확정
- 학생 기록을 볼 수 있는 역할 범위 확정

### Phase 1 — 학생 MVP

- 주간 문서·Callable·규칙·인덱스
- 과제 기록소 진입 버튼
- 5단계 작성 흐름과 로컬 초안
- 지난주 기록 거울
- 이전 목표 결과 선택
- 단위·통합·규칙·비용 테스트

예상 규모: 1인 개발 6~9일, QA 2~3일.

### Phase 1.1 — 사용성 보정

- 선택지 순서·문구 조정
- 목표 템플릿 추가·정리
- 완료 화면에서 지난주와 이번 주의 작은 비교
- 필요 시 돌아보기 완료 소량 보상 A/B 실험

### Phase 2 — 교사 상담 보기

- 학생별 최근 6주를 지연 로드
- 성찰·전략의 변화만 간단히 표로 제공
- 점수·등급·학생 간 비교 금지
- 상담 메모와 학생 기록을 분리

### Phase 3 — 월간 방향과 규칙 기반 제안

- 4주 완료 시 선택형 월간 돌아보기
- 학생이 반복 선택한 전략을 보여주는 개인 추세
- 기존 요약 데이터 기반의 설명 가능한 목표 후보 제안
- `[넣을래요] [이번에는 안 할래요]`로 최종 선택권 보장

## 11. 중단·조정 기준

- 평균 완료 시간이 5분을 넘으면 단계나 선택지를 줄인다.
- 시작 대비 완료율이 50% 미만이면 목표 선택 단계를 축소한다.
- 목표 3개를 항상 채우는 비율이 지나치게 높고 실패율도 높으면 2개 권장을 실험한다.
- 기록 거울 때문에 화면 최초 진입이 2초를 넘으면 요약 항목을 줄이거나 비동기 표시한다.
- 최초 열기 비용이 설계 예산을 넘으면 원본 집계를 제거하고 서버 요약 문서만 사용한다.
- 학생이 평가·감시로 느낀다는 피드백이 반복되면 교사 보기 확대를 중단한다.

## 12. 최종 제품 원칙

> MetaSense는 학생 대신 계획하지 않는다.  
> 기록은 거울로 보여주고, 다음 행동은 학생이 고른다.

이 원칙을 훼손하는 자동 계획, 성공 보상, 비교 랭킹, 강제 알림은 이후 단계에서도 기본적으로 도입하지 않는다.
