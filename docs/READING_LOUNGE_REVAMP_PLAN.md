- 문서 상태: 제품 개편안 v1

- 대상: 스텔라 아고라 `독서 라운지`, 나의 책장

## 1. 결정 요약

현재 독서 라운지는 추천 글·반응·댓글·신고 기능이 이미 안정적으로 분리되어 있다. 따라서 화면을 전면 재구축하거나 별도의 책 커뮤니티를 새로 만들기보다 다음 핵심 흐름을 먼저 완성하는 것이 비용 대비 효과가 가장 높다.

> 추천 발견 → `읽고 싶어요` → 나의 책장에 저장 → `읽기 시작` → 생각과 대댓글 → 완독 → 다른 친구에게 추천

1차 개편에서 구현할 기능은 다음 네 가지다.

1. `읽고 싶어요`를 단순 반응에서 실제 책장 저장 행동으로 전환한다.
2. `저도 이 책 읽었어요`로 기존 책을 연결하거나 완독 책을 추가한다.
3. 댓글에 1단계 대댓글을 추가해 질문과 답변이 이어지게 한다.
4. 독서 라운지에서 Q&A 명예의 전당을 숨기고 독서 전용 안내·내 책장 요약으로 교체한다.

`지금 N명이 읽는 중`, 추천으로 시작된 독서 수 같은 집계는 위 흐름에서 생성되는 신뢰할 수 있는 데이터를 이용해 1차 후속 단계에서 제공한다. 개별 학생의 실시간 진행률, 책별 방, 전체 활동 티커는 개인정보·데이터 정규화·읽기 비용이 커서 이번 범위에서 제외한다.

## 2. 현행 진단

### 2.1 잘 되어 있는 기반

- 추천 글은 `readingShares` 공개 스냅샷으로 분리되어 원본 독서 기록을 노출하지 않는다.
- 최신순 피드, 상세 드로어, 스포일러, 반응, 댓글, 신고, 알림이 구현되어 있다.
- 나의 책장은 `readingBooks` 현재 상태와 `readingLogs` 이력을 분리한다.
- 모든 주요 쓰기는 Callable Function과 트랜잭션을 사용한다.
- 댓글은 상세 화면을 열 때만 읽어 피드 읽기 비용을 억제한다.

### 2.2 핵심 문제

| 문제 | 현재 결과 | 개편 방향 |
|---|---|---|
| 추천 이후 행동이 끊김 | `읽어보고 싶어요`가 반응 수만 바꿈 | 책장 저장과 즉시 연결 |
| 책장에 관심 상태가 없음 | 읽기 전 후보와 읽는 책이 섞임 | `읽고 싶어요` 상태 추가 |
| 댓글이 한 줄 목록 | 질문에 대한 직접 응답이 불명확 | 1단계 대댓글 제공 |
| 독서 탭에도 Q&A 경쟁 패널 노출 | 독서보다 도움 수·랭킹에 시선이 감 | 독서 전용 패널로 교체 |
| 동일 책의 사회적 활동 데이터가 부족 | 실제 독서 연결 수를 표시할 근거가 없음 | 추천 출처와 책장 연결을 먼저 기록 |

## 3. 제품 원칙

1. **버튼은 실제 상태를 바꾼다.** `읽고 싶어요`는 좋아요의 다른 표현이 아니라 나의 책장 저장이다.
2. **상태는 서로 다른 의미를 가진다.** `읽고 싶어요`, `읽고 있어요`, `완독했어요`, `읽기 중단`을 구분한다.
3. **완독은 실수로 기록되지 않게 한다.** `저도 이 책 읽었어요`는 확인 단계를 거친다.
4. **대화는 한 단계만 중첩한다.** 모바일 가독성, 알림, 삭제, 페이지네이션 복잡도를 제한한다.
5. **개인의 상세 진행도는 기본 비공개다.** 라운지에는 우선 익명 집계만 표시한다.
6. **독서를 경쟁 점수로 바꾸지 않는다.** 다독 순위와 보상은 도입하지 않는다.
7. **외부 도서 API 없이 시작한다.** 기존 제목·저자 스냅샷을 재사용하고 실제 사용 데이터가 쌓인 뒤 책 정규화를 검토한다.

## 4. 의견 선별 결과

비용은 현재 코드 기준 1인 개발 상대 규모다. `S`는 0.5~1일, `M`은 2~4일, `L`은 5~10일, `XL`은 10일 이상을 뜻한다.

| 제안 | 판단 | 효과 | 비용/위험 | 결정 |
|---|---|---:|---|---|
| `읽고 싶어요` 클릭 시 책장에 자동 추가 | 매우 높음 | 매우 높음 | M, 중복 책·멱등 처리 필요 | **1차 필수** |
| 책장에 `읽고 싶어요` 상태 추가 | 매우 높음 | 매우 높음 | M, 상태 사용처 전반 수정 | **1차 필수** |
| `저도 이 책 읽었어요` 연결 | 높음 | 높음 | M, 오입력 확인·기존 책 연결 필요 | **1차 필수** |
| 댓글 대댓글 | 높음 | 높음 | M, 알림·삭제·집계 필요 | **1차 필수** |
| 독서 탭에서 Q&A 명예의 전당 교체 | 높음 | 중간 | S, 기존 사이드바 조건 분기 | **1차 필수** |
| `N명이 읽고 싶어요/읽었어요` 집계 | 높음 | 높음 | S~M, 위 기능의 결과값 재사용 | **1차에 기반 저장, 후속 노출** |
| `내 추천으로 N명이 시작` 흔적 | 높음 | 높음 | M, 이후 상태 전환과 출처 연결 필요 | **1차 후속** |
| 익명 `N명이 읽는 중` 표시 | 중간 | 높음 | M, 상태 전환 집계 필요 | **1차 후속** |
| 독서 중 짧은 생각 카드 | 중간 | 중간~높음 | L, 공개 범위·신고·혼합 피드 설계 필요 | **2차 실험** |
| 카드 3종 혼합 피드 | 중간 | 중간 | L, 콘텐츠 종류가 먼저 필요 | **2차 이후** |
| 이번 주 함께 읽는 책 | 중간 | 중간 | L, 책 동일성·주간 집계 필요 | **데이터 축적 후** |
| 책 중심 Book Room | 장기적으로 높음 | 높음 | XL, ISBN/판본/동명이책 정규화 필요 | **장기 과제** |
| 실시간 활동 수치·티커 | 낮음~중간 | 중간 | L, 이벤트 원장·집계·추가 읽기 | **보류** |
| 개별 학생 이름·진행률·오늘 읽은 쪽 공개 | 낮음 | 불확실 | L, 아동 개인정보·비교 압력 | **제외** |
| 실제 책 표지 외부 API | 낮음 | 중간 | L, 저작권·API 비용·실패 처리 | **제외** |
| 책별 상징 아이콘 | 중간 | 낮음~중간 | S, 해시 기반 CSS/이모지 가능 | **선택 후속** |
| 독서 행동별 새로운 영예/배지 | 중간 | 중간 | L, 지표 악용·운영 기준 필요 | **관찰 후 검토** |

## 5. 1차 개편 범위

### 5.1 `읽고 싶어요`

다른 사용자의 추천 카드와 상세에 CTA를 제공한다.

1. 사용자가 `읽고 싶어요`를 누른다.
2. 서버가 동일 제목·저자의 활성 책을 찾는다.
3. 책이 없으면 `want_to_read` 상태로 나의 책장에 생성한다.
4. 책이 이미 있으면 중복 생성하지 않고 해당 책과 연결한다.
5. 이미 `reading`, `completed`, `paused`인 책은 `want_to_read`로 낮추지 않는다.
6. 성공 후 버튼은 `내 책장에 담김`으로 바뀌고 `책장 보기`를 제공한다.

책장에서는 `읽고 싶어요`를 별도 필터와 통계로 보여준다. 이 상태에서는 페이지 기록보다 `읽기 시작`을 주 행동으로 보여준다.

### 5.2 `저도 이 책 읽었어요`

1. 사용자가 버튼을 누른다.
2. `완독한 책으로 기록할까요?` 확인 창에서 제목·저자와 결과를 보여준다.
3. 같은 책이 있으면 그 책을 `completed`로 바꿀지 확인한다.
4. 같은 책이 없으면 완독 책으로 생성한다.
5. 완독 일자는 기본적으로 오늘이며 후속 수정이 가능하다.
6. 페이지·독서일 조건이 없는 완독 등록은 기존 독서 성취 보상을 자동 지급하지 않는다.

`읽고 싶어요`와 `읽었어요`는 상호 배타적인 독서 의도다. `읽었어요`로 전환하면 관심 상태는 종료되지만 `생각이 이어졌어요` 공감은 독립적으로 유지한다.

### 5.3 1단계 대댓글

- 각 최상위 댓글에 `답글` 버튼을 제공한다.
- 대댓글은 최대 240자다.
- 대댓글에 다시 답글을 누르면 같은 최상위 댓글 아래에 작성자를 지칭해 추가한다.
- 대댓글 목록은 기본 3개까지 보이고 나머지는 사용자가 펼칠 때 읽는다.
- 답글 대상자에게 알림을 보내되 자기 자신에게는 보내지 않는다.
- 최상위 댓글 작성자가 삭제되어도 대댓글은 유지하며 삭제된 자리 문구를 보여준다.
- 댓글 수는 최상위 댓글과 대댓글을 모두 포함한 전체 대화 수다.

### 5.4 독서 전용 사이드 패널

독서 라운지에서는 `AgoraMotivationPanel` 대신 다음을 보여준다.

- `내 책장 바로가기`
- 내 책장의 `읽고 싶어요`, `읽고 있어요`, `완독했어요` 수
- “추천을 발견하고 책장에 담아보세요” 같은 짧은 이용 안내
- 후속 단계에서 `내 추천으로 시작된 독서` 수

Q&A 명예의 전당과 도움 수 랭킹은 다른 아고라 탭에서 그대로 유지한다.

## 6. 화면 구조

### 6.1 1차 화면

1. 상단 도구 막대
   - 최근 추천
   - 내가 추천한 책
   - 추천 글 쓰기
2. 추천 카드
   - 책 제목·저자
   - 한 줄 평·추천 이유
   - `읽고 싶어요`
   - `저도 이 책 읽었어요`
   - `생각이 이어졌어요`
   - 댓글 수
3. 상세 드로어
   - 추천 전체 내용
   - 책장 연결 상태와 CTA
   - 생각 공감
   - 댓글과 1단계 대댓글
4. 독서 전용 사이드 패널

카드 CTA는 클릭 시 카드 상세 열기와 충돌하지 않도록 이벤트 전파를 막는다. 완독은 카드에서 눌러도 확인 창을 거친다.

### 6.2 책장 변화

- 필터 순서: `전체 → 읽고 싶어요 → 읽고 있어요 → 완독했어요 → 읽기 중단`
- 기본 정렬: `읽고 있어요 → 읽고 싶어요 → 완독했어요 → 읽기 중단`, 상태 안에서는 최근 변경순
- `읽고 싶어요` 책의 주 CTA: `읽기 시작`
- `읽고 싶어요` 책에는 페이지 기록과 추천 글 쓰기를 노출하지 않는다.
- 책 상세에 “○○님의 추천으로 발견”을 표시하되 공개 표시 이름만 사용한다.
- `읽고 싶어요` 목록은 개인 관심 정보로 보고 공개 프로필에는 기본 노출하지 않는다.

## 7. 단계별 출시 계획

### Phase 0 — 계약과 안전 기준 확정

- `want_to_read` 상태명과 표시 문구 확정
- 기존 `읽어보고 싶어요` 반응 데이터의 호환 정책 확정
- 완독 연결 확인 문구와 성취 보상 비대상 정책 확정
- 대댓글 알림·삭제 정책 확정

### Phase 1 — 1차 필수 기능

- 책 상태·책장 UI 확장
- 추천에서 책장으로 연결하는 서버 명령
- `읽고 싶어요`, `저도 이 책 읽었어요` CTA
- 1단계 대댓글
- 독서 전용 사이드 패널
- 단위·통합·규칙 테스트

예상 규모: 1인 개발 7~11일 + QA 2~3일.

### Phase 1.1 — 사회적 독서 집계

- `N명이 읽고 싶어해요`, `N명이 읽었어요`
- 관심 책이 `reading`으로 바뀔 때 추천 연결 수 갱신
- 추천자에게 일일 묶음 알림 또는 최초 1회 알림
- 카드에 익명 집계만 노출

예상 규모: 2~4일 + 데이터 검증.

### Phase 2 — 짧은 생각 실험

- 공개를 명시적으로 선택한 짧은 생각만 별도 피드 후보로 사용
- 추천 카드와 생각 카드를 제한된 비율로 혼합하는 A/B 실험
- 신고율과 댓글 품질을 확인한 뒤 확대 여부 결정

### 장기 — 책 중심 구조

ISBN·판본·동명이책을 구분할 수 있는 책 엔터티가 준비된 후 Book Room, 함께 읽기, 주간 인기 책을 검토한다.

## 8. 성공 지표와 중단 기준

### 8.1 핵심 지표

- 추천 상세 조회 대비 `읽고 싶어요` 책장 저장 전환율
- `읽고 싶어요` 저장 후 30일 이내 `읽고 있어요` 전환율
- 추천 상세 조회 대비 `저도 읽었어요` 연결률
- 댓글 중 답글이 1개 이상 달린 비율
- 추천 1건당 실제 책장 연결 수

### 8.2 품질·비용 방어 지표

- 동일 사용자·동일 제목·저자 중복 책 비율
- 완독 연결 후 24시간 내 상태 되돌림 비율
- 대댓글 신고·삭제율
- 상세 1회당 Firestore 평균 읽기 수
- CTA 1회당 함수 실패율과 재시도 중복 생성 건수
- 알림 생성량과 읽지 않은 알림 누적량

### 8.3 중단 또는 조정 기준

- 중복 책 비율이 2%를 넘으면 자동 생성 전에 선택 창을 강제한다.
- 완독 되돌림 비율이 5%를 넘으면 카드의 완독 버튼을 상세 화면으로 이동한다.
- 대댓글 신고율이 최상위 댓글보다 유의하게 높으면 빠른 질문 칩과 일일 한도를 조정한다.
- 추가 Firestore 읽기가 목표치를 넘으면 사이드 패널의 책장 통계를 지연 로드한다.

## 9. 이번 개편의 비범위

- 사용자별 실시간 진행률 공개
