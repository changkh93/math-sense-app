# SEO + AEO/GEO + SNS 운영 전략

최종 개편: 2026-09-20. 사용자 첨부 의견을 검토하여 적용. 과거 발행량 할당보다 이 문서와 [현행 일정](CALENDAR.md)을 우선한다. [이전 전략](reference/SEO-AEO-GEO-SNS-PLAN-before-20260920.md)은 이력이다.

## 목표: 원본에서 실제 학습과 구매까지

msense.me에 질문별 원본과 실제 학습 근거를 쌓는다. 검색·SNS에서 온 사람이 해당 질문의 답을 얻고, 필요에 따라 과정 체험 또는 교재 구매로 이동하게 한다. 콘텐츠 수·조회·AI 인용 자체를 신청 성과로 세지 않는다.

- 과정: 검색/SNS → 해당 학습 노트 → /python/ 또는 /math/ → 7일 무료체험 → 상담 → 학부모 회원가입 → 자녀 계정 생성 → 첫 학습 → 정규 수강.
- 교재: 검색/SNS → 해당 활용법 또는 /math/books/ → 정확한 스마트스토어 상품 → 실제 구매 → 활용 안내·선택적 후기.
- 구매 의도가 분명한 교재 광고·게시물은 바로 상품으로 연결할 수 있다. 모든 방문자에게 사이트를 거치게 하지 않는다.
- 무료체험 전에 회원가입을 필수로 추가하지 않는다. 공개 활동 실행·진도 저장은 실제 제공·검증된 기능만 안내한다.

## 첨부 의견에 대한 판단

| 제안 | 반영 방식과 이유 |
|---|---|
| 사이트 원본 + 채널별 재구성 | 채택. 공식 학습 노트가 원본이고 블로그·영상에도 독립적으로 유용한 답과 활동을 제공한다. 링크만 있는 티저를 양산하지 않는다. |
| 원본 하나를 여러 채널에 활용 | 채택. 글 1편 → 블로그 1편 + 공통 영상 1편(YouTube/릴스/클립 각각 검수) + 선별 카카오 소식. 5~10개 발행 의무는 없음. |
| 주제별 내부 연결 | 채택. 기존 /python/guides/·/math/guides/ 주소 유지. URL을 모두 옮기는 대신 입문→활동→막힘 해결→기록→체험을 연결한다. |
| 질문·답·사례·FAQ | 채택. 글에 맞는 형식만 사용. 모든 글을 같은 번호형 템플릿으로 채우지 않는다. FAQ는 본문에서 해결되지 않은 실제 질문에 답한다. |
| 매일 원본 1편, 먼저 500개 설계 | 현 단계에서는 보류. 기존 파이썬10편·수학10편을 먼저 활용하고 검색 의도 중복을 제거한다. 기본 주2편 신규·1편 개선, 장애/광고 점검 주간에는 감량. |
| 사이트 작업 60% | 고정 효율 법칙이 아닌 초기 작업시간 가설로 사용. 제작 시간의 약60%를 원본·근거·활동·전환 개선에 배정하고 4주 후 조정. 광고/문의/운영 필수 시간은 별도다. |
| 새 지식 사이트 분류 전체 도입 | 수학5과정과 파이썬부터. 현재 제공하지 않는 기하·중등 전과목을 제공 과정처럼 확대하지 않는다. 고전읽기는 기존 안내 유지, 이번 집중 제작 범위 밖. |
| AI 검색용 특별 장치 | 읽을 수 있는 HTML·정확한 정보·출처·내부 링크를 우선. 특별 파일/FAQ 마크업/콘텐츠 수가 인용을 보장하지 않는다. |
| 복붙 금지·대표 URL | 자사 원본의 대표 URL을 유지하고 채널 독자에 맞게 재편집한다. 네이버의 동일 URL 권고를 모든 교차 게시가 처벌된다는 주장으로 확대하지 않는다. |

Shorts → 관련 영상 → 채널 → 사이트를 모든 사용자에게 강제하지 않는다. 프로필에서 해당 과정으로 바로 이동 가능하면 더 짧은 경로를 쓴다. 새 원본이 준비되기 전에는 존재하지 않는 URL을 공유하지 않는다.

## 콘텐츠 구조와 제작 기준

[콘텐츠 대장](CONTENT-REGISTER.md)을 기준으로 ID·대표 URL·검색 의도·근거·관련 글·주 CTA·파생물·상태를 관리한다. 현재 카탈로그20편은 로컬 published 상태와 기존 공개 기록을 확인했으며, 오늘 모든 URL의 실운영·색인을 재검증한 것은 아니다.

원본 한 편의 완료 기준:
1. 질문 하나와 짧은 직접 답, 실제 장면 또는 실행한 코드, 독자가 해볼 활동, 막힐 때 확인할 점을 담는다. 필요한 길이로 쓰며 3,000~5,000자 할당은 두지 않는다.
2. 교재/도구/화면 설명을 사실과 대조한다. 파이썬은 실행 결과, 수학은 같은 전체·단위·표기 검수. 저자·운영 주체·자료 출처·실질 수정일 표시.
3. AI 초안을 사람이 쓴 경험담처럼 꾸미지 않는다. 일반론·슬로건 반복을 덜고 구체적인 코드 변화, 오답 이유, 부모 질문을 넣는다. 실제 학생·학부모 대화나 효과를 만들지 않는다.
4. 관련 글 2~3개와 상위 목록·과정/교재를 자연스럽게 연결. 중복 주제는 기존 URL을 개선하고 신규 발행으로 세지 않는다.
5. 200 응답, 비로그인 접근, JS 실행 전 본문·고유 title/description/H1·canonical, robots/noindex, sitemap, 모바일·새로고침·이미지/링크 확인. RSS는 실제 운영 여부를 확인한 뒤 제출하며 완료를 가정하지 않는다.
6. FAQ/Article 등 구조화 데이터는 보이는 내용과 일치. llms.txt는 보조 목차이며 수집/색인/AI 인용 보장이 아니다. 신청서·운영툴·학생 기록은 공개 검색 대상에서 제외한다.
7. 과정/상품 이동과 신청 완료를 따로 확인한다. 공개 URL·검증 결과·다음 관측일을 남겨야 공개 완료다.

확정 운영조건: 파이썬 초3부터·자율·월15만 원·7일 체험·신청 후1일 이내 연락·자동결제 없음. 초등수학은 곱셈/나눗셈/분수/소수/비와비례식, 수학감각 기반, 영상·도구·퀴즈·워크북·기록·성장면담·7일 체험. 수학의 미확정 가격/연락 조건을 파이썬에서 복사하지 않는다. 수세기·덧뺄셈은 교재이며 현재 온라인 과정 목록에 추가하지 않는다. 곱셈/나눗셈/소수 교재는 절판 후 PDF 판매, 나머지 종이책/세트 구성은 상품별 확인한다.

학생 자료는 이름·닉네임 마스킹만으로 공개 가능하다고 판단하지 않는다. 최종 공개물의 식별 단서와 창작물 이용 권한을 확인하고 교사 소유 코드·자료·개인정보 없는 실제 도구 화면을 우선한다. 실제 캡처에 ‘시연용 예시’를 일괄 붙이지 않으며 재구성을 실제 기록으로 소개하지 않는다.

## 매일 및 주간 운영

매일 우선순위는 **신청/문의·광고 한도·오류 → 검색과 전환의 막힘 → 당일 원본/재활용 → 기록**이다. 밀린 발행량을 한꺼번에 따라잡지 않는다. 자세한 기준은 [운영 절차](OPERATING.md)·[일지 양식](DAILY-TEMPLATE.md).

| 요일 | 핵심 작업 | 완료 기준 |
|---|---|---|

| 화 | 원본A 제작 또는 기존 원본 실질 보강 | 설명·실행·정적HTML·모바일·링크 검증 |

| 목 | 원본B 제작 또는 기존 원본 보강 | A와 다른 질문, 실제 근거·FAQ·관련 글·CTA 검수 |

| 토 | 기존 글1편·신청/구매 동선 개선 | 변경 전후·선택 이유·다음 관측일 기록 |
| 일 | 문의·광고 종료/한도·이월 정리 | 실제 결과만 기록, 다음 주 질문 후보 |

**9/21~27은 광고 시작 주간이므로 신규1편(파이썬 반복문) + 기존2편(분수·수세기) 개선**으로 줄인다. 신규2편에 개선2편을 더하는 일정이 아니다. 원본1편에서 블로그1편·영상1편을 우선 파생하고 카드뉴스/롱폼은 성과가 확인된 질문에만 추가한다.

## 측정과 개선 판단

- 검색: URL별 Google/Naver 수집·색인·검색 노출·클릭·검색어를 분리. 요청 접수는 색인 완료가 아니다. 저량 표본의 하루 CTR로 성패 단정 금지.
- 단계: 콘텐츠 방문 → 과정/상품 이동 → 폼 시작 → 실제 저장 완료 → 상담/첫학습/정규 전환 또는 교재 주문. 비율은 분자/분모·기간을 함께 적는다. 분모0이면 계산 불가.
- GA4 성공 이벤트 연결은 완료, 파이썬 테스트1건 수신 확인·실제 신청0건. 수학 실제 수신과 Ads 유료 클릭 귀속은 미검증. [Google 기록](daily/2026-09-20/GOOGLE-ADS-TEST.md).
- 외부 링크 UTM은 현행 허용값 사용: source naver/google/instagram/youtube/kakao/clip, medium organic/social/video/cpc, campaign python_trial/math_trial. 원본ID는 우선 대장에 보관. utm_content나 새 캠페인명을 썼다는 이유로 수집된다고 가정하지 않는다.
- **측정 이월:** 원본→과정 이동 때 유입 정보 유지 여부, 원본별 과정 이동 이벤트와 상품 클릭 수집 여부 확인. 현재 코드가 모든 콘텐츠의 기여를 추적한다고 기록하지 않는다. 내부 링크에 새 UTM을 덧붙여 최초 유입원을 덮지 않는다.
- AI 인용은 주1회 대표 질문 소수만 서비스·질문·날짜·인용URL로 기록. Google AI 유입이 Search Console 웹 검색에 포함되므로 별도 전용 지표로 분리됐다고 쓰지 않는다.
- 주간 비교: 검색 노출 없음→수집/의도/내부링크, 노출 있지만 클릭 적음→제목·의도, 방문 있지만 과정 이동 없음→내용/CTA, 폼 시작 후 완료 없음→오류/조건, 접수 후 첫학습 없음→상담·가입 안내 순으로 가설을 세운다. 한 번에 주요 변수 하나를 바꾼다.
- 게시7일 후 수집/이동,28일 후 검색어/실제전환을 평가한다. 검색 효과가 나타나는 보장 기간은 아니다. 조회·저장만 늘고 전환이 없으면 무조건 제작량을 늘리지 않는다.

## 확장: 20편에서 100편 이상으로

첫4주는 기존20편의 중복·연결·근거를 보강하고 광고 검색어/부모 질문에서 다음 주제를 고른다. 이후 월별 수학·파이썬 각 핵심 질문을 늘리되 실제 제공범위 안에서 단계적으로 확장한다. 100/500편은 수용 구조의 목표이며 발행 기한이나 성과 약속이 아니다. 주2편을26주 유지해도 신규52편이므로 기존20편과 합쳐 약72편이다. 6개월500편 목표를 채택하지 않는다.

카탈로그에 고유 slug/status/관련글을 유지하고 발행 전 중복·끊긴 링크·목록 페이지·사이트맵 자동 검사를 수행한다. 대장으로 원본과 파생물을 묶어 같은 글을 중복 제작하지 않는다. 분류가 충분히 쌓이면 목록을 보강하되 빈 분류 페이지를 대량 공개하지 않는다.
