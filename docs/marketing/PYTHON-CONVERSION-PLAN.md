## 이번 개선

- 초3·자율 학습·월15만 원·7일 체험을 첫 화면에 표시. 신청 후1일 이내 연락과 절차 명시.
- 실제 입문 영상8초 무음 미리보기(끄기 가능, 움직임 줄이기 설정 존중), 입문/기초 이후 게임/수학 결과물 구분.
- 원래6편의 영상 유지. 시연 예제를 실제 학생 작품이나 기간 보장으로 과장하지 않음.
- 결과물 뒤·학습 설명 뒤·모바일 고정·첫 화면 CTA. CTA는 양식에 직접 이동.
- 학생 이름은 현재 서버 필수이므로4개 필수 항목 유지. 연락시간·경험은 선택 펼침, 개인정보 동의 유지. 성공은 서버 success 확인 후에만 표시.
- /python 빌드 시 실제 React 페이지 HTML 미리 생성. title/description/canonical/OG·robots·sitemap 준비. 본문과 메타는 검색 색인/상위 노출 보장이 아님.

## 측정 상태 — 완료와 준비 구분

python_view → python_cta → python_form_start → python_submit → python_success, 오류 및 영상 선택을 dataLayer에 기록하는 코드 준비. 고정된 이벤트/라벨만 허용하며 폼 이름·연락처·자유 입력·추천 토큰을 이벤트로 보내지 않음. 허용된 UTM 값은 신청 메모에 저장돼 관리자가 유입 출처를 볼 수 있음.
**통계 수집 완료 아님:** 현재 사이트에서 GA/GTM 수집 태그 연결을 확인하지 못했다. dataLayer만으로 보고서가 생성되지는 않는다. 기존 측정 속성의 관리자 접근·설정과 실제 수신 검증을 완료한 뒤 방문→클릭→접수 전환율을 계산한다. 유료 등록은 관리자의 실제 등록 기록으로 별도 확인. 기존 신청0의 원인은 여전히 미확정.

## 다음7일 우선순위

1. 배포 HTML·신청 경로 검증, 검색 콘솔/서치어드바이저 소유 확인 및 sitemap 제출 상태 확인. 기존 등록이 있으면 중복 생성하지 않음.
2. GA/GTM 실제 이벤트 수신과 개인정보 설정 검증. 접수 알림은 별도 외부 연동 확인, 자동 알림 완료를 주장하지 않음.
3. 검색 질문 글1: ‘초등3학년 파이썬, 코딩이 처음이라면 어디서 시작할까요?’ 실제 입문 화면과7일 체험 흐름으로 작성.
4. 검색 질문 글2: ‘스크래치 다음 파이썬, 문법보다 먼저 확인할 경험’ 수준별 시작과 실제 코드를 보여주기.
5. 기존 영상 재활용: ‘게임을 만들기 전, 숫자 하나를 바꿔 보세요.’ 입문→게임 순서, 공통 /python CTA.
6. 접수 후1일 이내 연락·체험 시작 여부를 실무 기록. 실제 질문으로 FAQ 수정.
7. 방문·클릭·입력 시작·접수의 병목 평가. 방문 부족이면 타깃 유입, 클릭 부족이면 제안/근거, 제출 실패면 폼/기술을 우선.

유료 광고·추천 보상·학생 작품 수집 연락은 이번에 집행하지 않음. 광고는 추적과 접수 흐름 확인 뒤 키워드·예산·중단 기준을 구체화해 사용자 결정. 사례는 공개 동의를 확보한 자료만 사용한다. 제작량 확대보다 한 경로의 측정 가능한 개선을 우선한다.
