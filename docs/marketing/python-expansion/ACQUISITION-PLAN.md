# 400편 보강 이후의 유입·전환 운영안

작성 2026-09-22. 사용자 최신 요청이 기존 ‘파이썬 10편, 주 신규 2편’ 계획보다 우선한다. 아래 발행량은 최적값으로 입증된 수치가 아니라 **4주간 검증할 운영 가설**이다. 과거 게시·주문을 이번 실행 성과로 합산하지 않는다.

## 지금의 판단

기존 주 신규2편/개선1편만으로는 5개 채널에서 어떤 주제와 형식이 반응하는지 비교할 기회가 적다. 따라서 원본 확보와 유통량을 함께 확대한다. 다만 사이트 글 수 증가만으로 유입·매출·체험신청이 늘어난다고 판단하지 않는다.

사용자는 채널 유입·스마트스토어 매출이 거의 없고 체험신청은 0이라고 보고했다. 최근 검색 도구 확인에는 보고 지연이 있다. 9/22 확인한 Google 보고서(9/18 기준)는 색인1·미색인14, Naver 보고서(9/20 기준)는 색인1이었다. 네이버 개별 검사에서는 /math/ 수집·색인 성공을 확인했다. 보고서 수치만으로 모든 신규 URL이 미색인이라고 단정하지 않는다. **발행 → 발견/수집 → 노출 → 클릭 → 과정/상품 이동 → 신청/구매** 중 어디가 막혔는지를 구분해야 한다.

이번 운영에서 광고·유입 측정 구현·네이버 담당자 문의 재점검은 사용자가 미룬 범위를 유지한다. 새 광고비, 일괄 메시지, 구매 유도 댓글, 허위 후기나 조회수 구매를 계획의 실행 수단으로 삼지 않는다.

## 낮은 유입을 개선할 실험 순서

### 1주: 발견되는 입구와 정확한 약속

- 과정별 허브를 상위 목록과 연결하고 대표12개 원본의 내부 링크·canonical·모바일·본문 접근을 확인한다.
- Google/Naver에는 실제 사이트맵과 대표 허브를 기준으로 수집 상태를 기록한다. 요청 접수와 색인을 구분한다. 매일 같은 URL을 반복 요청해 성과로 세지 않는다.
- 제목은 부모 질문 또는 수행할 작업을 먼저 말한다. ‘창의력 향상’ 같은 추상적 효익보다 한 장면의 학습을 보여준다.
- 무료체험 CTA에는 상담 후 시작·7일·자동결제 없음 등 확인된 조건을 유지한다. 수학·중등수학의 가격에 파이썬 가격을 복사하지 않는다.

### 2주: 클릭할 이유

- 7일 관측에서 노출이 있는데 클릭이 적은 주제는 제목/첫 장면 한 가지만 바꾼다.
- 블로그의 첫 문단에서 질문에 바로 답하고 활동의 실제 결과를 보여준다. 링크를 클릭해야만 답을 알 수 있게 만들지 않는다.
- 상품형 콘텐츠는 정확한 상품과 제공 형태(종이책/PDF/세트), 필요한 대상, 활용 장면을 연결한다. 여러 상품을 한 링크에 무조건 몰지 않는다.

### 3주: 방문 뒤의 선택

- 반응이 생긴 상위3개 주제에 부모 FAQ, 실행 시연, 오류 해결을 추가한다.
- 교재 관심 방문자에게는 상품 선택, 함께 공부할 도움이 필요한 방문자에게는 과정 체험을 주 행동으로 둔다.
- 전환이 없으면 먼저 과정·상품 설명과 신청 절차의 오해를 확인한다. 검증 없이 할인·가격변경·광고 증액을 하지 않는다.

### 4주: 다음 발행량 결정

‘노출당 클릭’, ‘콘텐츠 방문당 과정/상품 이동’, ‘폼 시작당 실제 신청’을 각각 분자/분모와 함께 기록한다. 기존 측정이 불완전하면 미확인으로 남기고, 출처를 특정할 수 없는 주문을 콘텐츠 성과로 귀속하지 않는다.

- 모든 채널의 노출이 거의 없으면 글을 추가하는 것보다 검색 수집·제목·채널 배포 방식부터 보완한다.
- 노출은 늘고 클릭이 없으면 첫 장면과 독자 질문을 수정한다.
- 클릭은 있지만 신청/구매가 없으면 상품·과정 일치와 설명, 동선을 점검한다.
- 두 주 이상 반복해서 반응하는 주제가 있고 검수 시간을 유지할 수 있을 때만 해당 채널을 주1개 추가한다. 단일 게시물의 우연한 반응을 승자로 확정하지 않는다.
- 소표본으로 CTR·전환율의 통계적 우열을 주장하지 않는다. 전환0은 전환율을 개선했다는 증거가 아니다.

## 매일 체크할 것

1. 오늘 원본ID·독자 질문·근거·주 CTA를 선택한다.
2. 코드/교재/이미지를 대조한다. 실제 화면과 관계없는 이미지는 사용하지 않는다.
3. 채널별 첫 장면·설명·활동·CTA를 다르게 작성한다.
4. 공개 전 모바일·맞춤법·출처·링크·기존 중복 게시를 확인한다.
5. 공개 후 실제 URL과 시간을 기록하고 7일·28일 관측일을 남긴다.
6. 미실행은 이월, 성과는 확인된 값만 기록한다. 예약 작업은 기존 로컬 초안·기록 범위를 유지한다.

## Jev의 역할과 한계

일반적인 편집 원칙만 외부에 전달했다. 원본 코드·내부 운영 수치·학생 정보는 보내지 않았다. [요청](JEV-EDITORIAL-REQUEST.json)과 [응답](JEV-EDITORIAL-RESPONSE.json)을 보존했다.

Jev는 출처/실행 검수(choice confidence0.99), 채널별 재구성(0.95), 기간을 정한 발행량 시험(0.95)을 선택했다. 이 값은 선택지 사이의 모델 확신이지 실제 마케팅 성공 확률이 아니다. 주11개,4주,대표12개 주제는 Codex의 운영 제안이며 Jev가 생성한 마케팅 전략으로 표시하지 않는다.

## 공식 자료와 해석

- [Google 사용자 중심 콘텐츠](https://developers.google.com/search/docs/fundamentals/creating-helpful-content): 독자에게 실제 도움이 되는 경험과 충분한 답을 우선한다. **해석:** 실제 코드·관찰·오류 설명을 콘텐츠 수보다 우선하는 검수 기준으로 사용한다.
- [Google 스팸 정책](https://developers.google.com/search/docs/essentials/spam-policies): 사용자 가치 없이 검색 순위 조작을 목적으로 대량 생성하는 콘텐츠를 경계한다. **해석:** 400이라는 수량만으로 품질 또는 위반을 단정하지 않고 개별 자료의 유용성과 중복을 검수한다.
- [네이버 사이트 제작 안내](https://searchadvisor.naver.com/guide/seo-basic-create): 검색이 읽을 수 있는 사이트 구조를 기본으로 한다. **해석:** 사이트맵·내부 연결·본문 접근은 확보하되 색인이나 순위를 보장한다고 표현하지 않는다.
