# 프론티어 비행·해양 탐험 구현 기록

2026-09-06. 로컬 구현 및 검증 완료. 운영 배포 전.

## 이용 방법

- 탐험 화면 왼쪽의 **장비**에서 산책 / 호버팩 / 잠수복을 선택한다. 산책은 무료이고 호버팩과 잠수복은 각각 1,000광석에 한 번 구매하면 계속 사용할 수 있다.
- 호버팩: 이륙 버튼 또는 H. Space로 상승, C로 하강. 입력을 놓으면 정지 비행한다. 다시 H를 누르면 현재 위치에서 완만하게 내려온다.
- 조감: 조감 버튼 또는 B. 드래그 회전, 휠 줌, 다시 B로 캐릭터 시점 복귀. 조감은 캐릭터 이동·보상 획득과 독립적이다.
- 물에서는 장비 없이 수면 수영한다. 잠수복은 오리발·탱크 외형과 더 빠른 수중 이동, 상승·하강 기능을 제공한다.
- 섬 둘레의 산호 숲에는 물고기·거북·해파리가 자연스럽게 유영한다. 별도 도감이나 관찰 버튼 없이 자유롭게 발견한다.
- 안전 귀환은 마지막으로 확인된 지상 위치로 돌아간다. 일반 착륙과 구분한다. 장비 해제는 공중에서는 완만한 착륙, 물속에서는 수면 수영으로 전환한다.
- 모바일은 조이스틱과 상승/하강 누름 버튼을 사용한다. 포인터 취소·포커스 상실·일시정지 시 입력을 해제한다.

## 구현 범위

기존 지상 점프·계단 로직을 유지하면서 비행 / 착륙 / 수영 / 잠수의 수직 이동 해결기를 분리했다. 4cm 이하 수직 소단계 충돌로 얇은 천장 통과를 방지한다. 수평 이동은 기존 소단계와 벽 미끄러짐을 사용하되 비행 높이를 보존한다. 시설·자연물 충돌은 높이를 고려하고, 물 진입을 막던 강의 보행 장벽은 수영 상태로 대체했다.

비행 상한은 18이다. 해저는 해안 약 -0.8에서 외해의 최대 -36까지 깊어지고, 탐험 반경은 섬 반경+60(최대 92)이다. 기본 섬에서는 반경 80, 확장 섬에서는 약 88.28까지 이동한다. RTDB의 x/z 검증과 송수신 정규화는 ±96, y는 -40~24로 맞춘다. 수면은 강 하구와 가까운 -0.09를 유지하며 양면 반투명이다. 아래에서 본 수면은 거리에 따른 산란으로 원경에 섞인다.

물고기는 체형·색·속도가 다른 네 종류의 공통 지오메트리와 InstancedMesh 네 개를 사용한다. 48개 서식지의 무리 행동과 꼬리 변형은 로컬 계산이며 생물 위치는 서버에 전송하지 않는다. 기존 캐릭터 위치 전송 간격과 변화 임계값을 유지한다.

원격 캐릭터에도 장비 외형을 표시한다. 기존 rules 파일은 y/scale을 허용하지 않는 상태였으므로 범위를 명시하고 장비·이동 상태는 허용 목록으로 검증했다. 구형 클라이언트의 해당 필드 생략도 지원한다. 근접 상호작용·픽업 및 서버 대화 거리에 높이를 반영했다.

- 로컬 RTDB 에뮬레이터에서 정상 비행/착륙/잠수 저장, 구형 필드 생략, 잘못된 좌표·장비·상태·타인 쓰기 거절을 확인했다. 의도적 거절 테스트의 permission_denied 로그는 정상 결과다.

## 로컬 QA

`npm run dev -- --host 127.0.0.1` 실행 후 `/dev/frontier-exploration`에서 같은 GalaxyWorld3D를 테스트한다. 산호 위치 이동과 1초 상승/하강 입력 버튼은 개발 모드에서만 활성화되며 운영 라우트에는 포함되지 않는다.

권한 테스트는 로컬 RTDB 에뮬레이터를 실행하고 다음 명령을 사용한다.

```sh
FIREBASE_DATABASE_EMULATOR_HOST=127.0.0.1:9009 node scripts/test-frontier-presence-rules.mjs
```

테스트는 demo-frontier 네임스페이스만 사용하고 127.0.0.1 이외의 호스트를 거절한다. 최신 firebase CLI는 Java 21을 요구하지만 이 환경은 Java 17이므로 이미 설치된 RTDB emulator v4.11.2 JAR를 직접 실행해 검증했다.

## 운영 반영 순서와 후속 범위

1. `database.rules.json`을 먼저 반영한다. 새 좌표 범위와 장비/상태 필드를 허용하지 않는 구형 규칙이 남으면 외해 이동이나 깊은 잠수 중 위치 갱신이 거절된다.
2. `sendGalaxyWorldSpeech` 서버 함수의 높이 기반 거리 검증을 반영한다.
3. 웹 번들을 반영하고 방문자 간 위치·장비 표시와 저장 오류를 관찰한다.

이번 구현은 계획서의 비행·조감·수영·잠수·해양 생태계에 해당한다. 설계도 공유·대칭/영역 건축 도구, 수족관 가구, 해저 동굴, 공유 물고기 포획, 운영 비용 대시보드는 아직 구현하지 않았다. 산책의 무료 제공은 유지하며, 호버팩·잠수복 소유권은 사용자 프로필에 영구 저장한다.


## 예기치 않은 수동 종료 수정

마우스 잠금 해제를 Escape에 의한 종료 의사로 추정하던 Astronaut의 이벤트 처리 때문에 UI 조작이나 브라우저 상태 변화가 `manual_exit`으로 이어질 수 있었다. 잠금 이벤트에서 세션 종료 콜백으로 이어지는 경로를 제거했다. 이제 잠금 해제는 카메라/이동 입력만 초기화한다. Esc는 열린 장비 패널을 닫거나 커서를 해제하며, 수동 세션 종료는 명시적인 귀환 버튼으로만 실행한다. 시간·유휴·연결 만료 정책은 변경하지 않았다.

`npm run test:frontier-pointer-lock`은 정상/비정상 잠금 해제, 포커스 상실, 이벤트 재등록/해제, 입력 초기화 및 종료 경로의 분리를 검증한다. 브라우저에서는 장비 패널 열기→Esc로 패널 닫기→추가 Esc 이후에도 탐험이 유지됨을 확인했다.

## 수영·비행 동작과 환경 확장 (2026-09-06)

- 걷기와 수영·비행 포즈를 `frontierCharacterMotion.js`로 분리했다. 수영은 수평 자세, 팔 젓기, 교차 발차기, 발에 붙은 오리발을 사용한다. 호버링은 접힌 다리, 균형 잡는 팔, 측면 이동 시 기울기와 추진기 맥동을 사용한다. 포즈 전환은 보간하며 일시정지는 동작 시간도 멈춘다. 원격 아바타도 같은 포즈 함수를 사용한다.
- 섬 둘레 24개 서식지에 물고기 144마리, 거북·해파리 12마리, 산호와 흔들리는 해초를 배치했다. 해저 기포와 탐사자 주변 기포를 합쳐 최대 160개로 재사용한다. 물고기는 가까이 접근하면 간격을 벌리며, 별도 위치 안내 없이 탐색한다.
- 하늘 고도 7/11/15에 구름 정원·바람의 문·별빛 쉼터를 추가했다. 구름, 빛 입자, 날개를 움직이는 하늘 생물과 통과할 수 있는 고리가 있다. 접근 후 풍경을 기록하면 다음 장소를 안내하며 브라우저에 저장한다.
- 잠수 중 3인칭 카메라가 섬의 단단한 측면 안으로 들어가지 않도록 보정했다.
- 환경 효과는 인스턴싱과 고정된 수의 객체를 사용하며 서버 쓰기를 추가하지 않는다. 실제 저사양 기기의 GPU 성능은 별도 검증 대상이다.
- 동작/포즈 전환/정지/서식지 분포/하늘 좌표 테스트와 탐험, 포인터 잠금, 지형, 이동, 건축 회귀 테스트가 통과했다. 브라우저에서 수중 포즈·기포, 비행과 하늘 고리, 풍경 기록 0→1 및 다음 장소 안내를 확인했다. 다중 사용자 실기기 동작은 아직 검증하지 않았다.

## 유료 탐험 장비 (2026-09-06)

- 호버팩과 잠수복은 각각 1,000광석의 직접 구매 장비다. 산책과 수면 수영은 무료로 유지한다.
- 서버 `purchaseStoreItem` 트랜잭션이 최신 잔액 확인, 광석 차감, `ownedExplorationKits` 소유권 저장과 `frontier_equipment_purchase` 거래 원장 기록을 함께 수행한다. 이미 보유한 장비의 중복 구매와 선물 경로 우회는 거절한다.
- 클라이언트는 보유 광석·가격·부족분·보유 상태를 장비 카드에 표시한다. 구매 성공 시 즉시 장착하고, 사용자 프로필 실시간 구독으로 광석과 영구 소유권을 동기화한다.
- 호버팩의 좌우 비행 롤은 실제 이동 방향으로 기울도록 로컬 좌표 부호를 맞췄다. 추진 불꽃은 빨강·주황·연노랑의 가산 혼합 3중 불꽃과 짧은 비주기 점멸을 사용하며, 꺼졌을 때는 표시하지 않는다.
- 개발용 탐험 화면과 460px 폭 브라우저에서 장비 패널 배치를 확인했다. 운영 Firebase 함수 배포 및 실계정 광석 차감은 별도 운영 반영 대상이다.

## 첫 1인칭 전환 지연 수정 (2026-09-06)

- 첫 V 입력에서 다음 렌더 프레임을 기다리지 않고, 화면을 그리기 전에 카메라를 캐릭터 눈 위치와 현재 시선 방향으로 즉시 배치한다.
- 1인칭 동안 비활성화되는 OrbitControls에는 기존 3인칭 거리·각도 범위를 유지해, 최초 전환 시 내부 궤도 상태가 불필요하게 축소되지 않도록 했다.
- 3인칭으로 돌아갈 때도 위치와 함께 near/fov를 같은 전환 단계에서 복원한다. 이후 V 재전환 동작은 기존과 동일하다.

## 해양 환경 전면 개선 (2026-09-06)

- 바다 도감, 관찰 기록 버튼, 산호 숲 방향 안내와 관련 로컬 저장을 제거했다. 해양 생물은 점수나 체크리스트 없이 자유롭게 발견한다.
- 수면을 -0.24에서 -0.09로 올려 강 하구와 해안의 높이 차를 줄였다. 섬 측면은 안쪽으로 꺾이는 검은 벽 대신 바깥쪽 얕은 대륙붕으로 이어진다.
- 단일 평면 해저를 해안 경사·넓은 능선·잔굴곡·산호 둔덕이 있는 메시로 교체했다. 같은 높이 함수를 렌더링, 잠수 바닥 충돌, 카메라와 QA 이동에 함께 사용한다.
- 물고기는 몸통·주둥이·등지느러미·가슴지느러미·눈·움직이는 꼬리를 갖고 줄무늬와 크기 차이를 표현한다. 거북은 등딱지·배갑·머리·눈·네 지느러미·꼬리로 분리하고 앞지느러미를 움직인다.
- 산호는 결정 모양 오브젝트 대신 가지형과 판형 군락을 섞고, 바위·해초·기포와 함께 배치했다. 반복 객체는 인스턴싱을 유지한다.

## 해양 재구성 및 외해 확장 — 후속 개선 (2026-09-06)

- 이전 개선으로 부족했던 생물의 비례를 다시 구성했다. 물고기는 연속 단면의 몸체·꼬리자루·얇은 지느러미·작은 눈을 사용하며, 네 체형의 무리가 이웃과 방향을 맞추고 캐릭터를 피한다. 꼬리와 수초는 GPU에서 변형한다.
- 산호는 여러 단계로 갈라지는 가지·부채·판·뇌산호·속이 빈 관 형태로 나눈다. 바위와 넓은 산호 밑면은 해저 경사에 맞춰 배치한다. 거북은 곡면을 따르는 등갑 무늬, 배갑, 머리, 네 개의 움직이는 지느러미로 구성한다.
- 해안에서 외해로 이어지는 굴곡과 골짜기, 모래 결·잔물결·암반 얼룩·움직이는 빛 무늬를 추가했다. 가까운 수초와 기포 크기를 줄였고, 수중에서는 별과 원경 행성이 비치지 않는다. 수면 아래쪽의 직선 경계와 모래 무늬의 원거리 깨짐도 수정했다.
- 기본 섬의 탐험 반경은 26→80, 확장 섬은 31→약 88.28로 넓혔다. 최대 수심은 약 36이며, 송수신 위치와 RTDB 범위도 함께 확장했다. 도감 UI는 다시 도입하지 않았다.
