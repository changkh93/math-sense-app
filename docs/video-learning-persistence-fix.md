# 기술 문서: 영상 학습 데이터 보존 및 UI/UX 성능 최적화 (2026-03-28)

## 1. 개요
영상 학습 과정에서의 고질적인 데이터 유실 문제를 해결(03-27)한 데 이어, 대규모 리렌더링으로 인한 시청 방해(깜빡임) 및 운영 효율성을 개선한 기술적 내역을 기록합니다.

---

## 2. 03-27 개선 사항: 데이터 보존 (Data Persistence)

### ✅ 통합된 상태 복원 (Consolidated Restoration)
- `useEffect`를 통해 Firestore의 `stampedSeconds`, `totalTimeSpent`, `completed` 플래그를 로컬 캐시와 병합하여 복원합니다.

### ✅ 비동기 저장 강화 (Auto-save & Unload-save)
- **10초 주기 자동 저장**: 학습 중 예기치 않은 종료에 대비해 주기적으로 Firestore와 동기화합니다.
- **Beacon API 도입**: 브라우저 탭을 닫거나 이동할 때 `navigator.sendBeacon`을 사용하여 서버에 최종 상태를 안정적으로 전송합니다.

## 3. 03-28 개선 사항: UI/UX 및 성능 최적화 (UX & Performance)

### ✅ 영상 깜빡임 해결 (Flicker-Free Optimization)
1. **플레이어 메모이제이션**: `YoutubePlayer` 컴포넌트를 `React.memo`로 래핑하여, 자동 저장 시 발생하는 부모 컴포넌트(`MissionHub`)의 상태 변화(저장 완료 상태 등)가 영상 재생에 영향을 주지 않도록 차단했습니다.
2. **이펙트 분리**: '초기 복원(Restoration)'과 '주기적 동기화(Sync)' 로직을 분리했습니다. 이전에는 동기화가 일어날 때마다 초기 복원 로직이 다시 실행되면서 영상 플레이어의 `key`가 변하고, 이로 인해 플레이어가 새로고침(Re-mount)되는 현상이 있었습니다. 현재는 `prevTxIdRef`를 사용하여 초기 위치 설정이 한 번만 수행되도록 고정했습니다.
3. **상태 안정화**: `onComplete`, `onTimeUpdate` 등 플레이어에 전달되는 콜백 함수들을 `useCallback`으로 감싸 프롭스(Props) 변화로 인한 리렌더링을 방지했습니다.

### ✅ 학습 콘텐츠(마크다운) 편의성 강화
- **체크박스(Task List) 지원**: `* [ ]` 및 `* [x]` 문법을 정식 지원하며, 완료된 항목은 시각적으로 구분되도록 커스텀 UI를 적용했습니다.
- **하단 닫기 기능**: 문서가 길어질 경우 상단까지 스크롤하지 않고 즉시 나갈 수 있도록 하단에 "본부로 돌아가기 (CLOSE)" 버튼을 추가했습니다.
- **스타일 최적화**: Gemini Canvas 스타일의 촘촘한 간격과 블록 수식($$) 중앙 정렬을 지원합니다.

### ✅ 어드민 운영 편의성 개선
- **세션 상태 유지**: `ContentManager`에서 탐색하던 지역/챕터 목록 확장 상태를 `sessionStorage`에 저장합니다. 이제 편집기에서 돌아왔을 때 이전 작업 위치가 그대로 유지됩니다.

## 4. 03-30 개선 사항: 브라우저 백그라운드 스로틀링 극복 (Tab Throttling Fix)

### ✅ 영상 학습 시간 정지 현상 해결 (Time Freeze Bug Fix)
- **문제 원인**: 브라우저는 비활성 탭(백그라운드 탭)에 대해 `setInterval` 호출 주기를 극단적으로 늦춥니다(최소 1초~수십 초). 기존 코드에서는 타이머 갱신 간격(`gap`)이 5초를 초과하면 사용자가 영상을 **건너뛰기(Scrubbing)** 한 것으로 간주하여 초당 스탬프를 1초만 부여했습니다. 이로 인해 백그라운드에서 오랜 시간 영상을 시청해도 학습 시간이 늘어나지 않고 멈춰있는 현상이 발생했습니다.
- **해결 로직**: `lastPollTimeRef`를 도입하여 실제 현실 시간(Real-world Clock Time)을 측정합니다. 브라우저 지연으로 인해 타이머가 15초 뒤에 동작하더라도, 타이머 지연 간격(15초)과 영상 진행 간격(15초)이 일치한다면 이는 임의 조작(건너뛰기)이 아닌 정상 재생임을 판단하여 15초 분량의 스탬프를 모두 정상적으로 지급하도록 수정했습니다.

### ✅ 시청 위치(이어보기) 북마크 오류 해결 (Position Sticking Bug Fix)
- **문제 원인**: 
  1. 기존에는 시청 위치(초)를 브라우저 `localStorage`에 저장할 때, "새로운 학습 시간(Stamp)이 인정되었을 때"에만 기록하도록 조건문(`if (newStampsAdded)`)에 묶여 있었습니다. 이로 인해 학생이 영상을 **이전 구간으로 되감기하여 다시 시청**할 경우, 이미 학습이 인정된 구간이므로 `localStorage` 위치 기록이 아예 갱신되지 않는 버그가 있었습니다.
  2. 게다가 다음 번 영상을 틀 때 `Math.max(serverPos, localPos)` 로직을 적용하여 서버 기록과 로컬 기록 중 *무조건 가장 큰(미래의) 타임라인*을 억지로 채택하고 있었습니다. 결과적으로 사용자가 의도적으로 0분 0초부터 3분까지 다시 보고 '오늘은 여기까지'를 눌러도, 이전에 묻혀있던 9분 9초 기록이 `Math.max`에 의해 승리하면서 위치가 계속 9분 9초로 롤백되는 현상이 발생했습니다.
- **해결 로직**:
  1. `localStorage` 갱신 로직을 0.2초마다 실행되는 빈번한 이벤트에서 빼내고, 10초 주기 `Auto-save` 루프에 일괄 편입시켜 성능 간섭(마이크로 스터터링)을 제거했습니다. (되감기/재시청 시에도 항상 현재의 물리적 위치가 저장됩니다)
  2. 복원 로직에서 `Math.max`를 폐기하고, **`updatedAt` (최종 수정 시간)**을 비교하여 서버 또는 로컬 캐시 중 **시간상 가장 최근에 저장된** 위치 북마크를 신뢰하도록 완전히 구조를 변경했습니다.

## 5. 향후 주의사항 및 가이드라인
1. **Component Stability**: 영상 플레이어처럼 무거운 외부 API를 사용하는 컴포넌트는 반드시 메모이제이션하고, 부모로부터 전달받는 `key`나 `start` 지점이 시청 중에 변하지 않도록 관리해야 합니다.
2. **Effect Dependencies**: 주기적으로 상태를 업데이트하는 이펙트와 초기 로딩 시 한 번만 실행되어야 하는 이펙트를 엄격히 분리하여, 리렌더링 사이클이 무한 루프나 깜빡임을 유발하지 않도록 주의합니다.
3. **Timer Accuracy**: 영상 학습량과 같이 시간에 의존하는 상태(State)를 구현할 때는 브라우저의 내부 타이머 불확실성(CPU 부하, 백그라운드 탭 제약)을 항상 고려하여 절대 시간(`Date.now()`) 기반 검증을 추가해야 합니다.
4. **Tx ID Consistency**: 영상 식별자(`txId`) 처리는 전 시스템에서 일관된 포맷을 유지해야 합니다.

## 6. 05-07 운영 규칙 명확화: 인정 학습과 집중 광석

### ✅ 인정 학습 시간과 영상 위치의 분리
- `lastPosition`은 이어보기용 영상 위치입니다. 학생이 마지막으로 머문 YouTube 타임라인 위치를 저장합니다.
- `stampedSeconds`는 완료율 산정용 인정 학습 구간입니다. 영상 타임라인에서 실제로 재생된 초 단위 구간만 누적합니다.
- 되감기 재시청은 복습으로 인정하지만, 이미 인정된 구간이므로 완료율은 새로 증가하지 않습니다.
- 앞으로 넘겨 건너뛴 구간은 인정 학습에 포함하지 않습니다. 이동 후 실제로 재생된 구간부터 다시 인정합니다.
- UI 표기는 `학습 시간` 대신 `인정 학습`과 `완료율 / 기준`으로 표시합니다.

### ✅ 완료 기준
- 일반 영상은 인정 구간이 전체 길이의 95% 이상이면 완료입니다.
- 40분 초과 장시간 영상은 인정 구간이 전체 길이의 85% 이상이면 완료입니다.
- 영상 끝까지 도달했더라도 기준에 부족하면 수동 완료는 가능하지만 완료 보너스는 지급하지 않습니다.

### ✅ 집중 광석 랜덤성 보정
- 집중 광석(Time Attack)은 계속 랜덤성을 유지합니다.
- 단, 예약 기준을 영상 타임라인 위치가 아니라 실제 재생 중인 시간으로 둡니다.
- 따라서 되감기나 구간 반복 때문에 영상 위치가 뒤로 이동해도 집중 광석 기회가 과도하게 밀리지 않습니다.
- 일시정지 중에는 집중 광석 예약 시간과 `totalTimeSpent`가 증가하지 않습니다.
