# LUMI Protocol 제품·학습 명세

## 1. 제품 정의

LUMI Protocol은 Python 문법 문제를 우주 게임 화면에서 푸는 기능이 아니다.

> 학생이 실제 Python 코드를 발견하고 실행하면서 고장 난 탐사 로봇 LUMI의 명령·기억·센서·판단·자동화·데이터·함수 능력을 복원하는 프로그래밍 어드벤처다.

학생의 역할은 `Protocol Engineer`다. 학생이 배우는 Python 개념과 루미가 되찾는 능력은 항상 대응해야 한다.

## 2. 대상과 선수 지식

- 주요 대상: Turtle로 이동, 회전, 간단한 반복을 일부 경험한 초등 고학년~중학생
- 가정할 수 있는 것: 코드를 실행하면 화면이 변한다는 경험
- 가정하면 안 되는 것: import, 객체, 속성, 변수, 메서드, 자료형 용어, `for/range`, 들여쓰기 블록의 정확한 이해
- 첫 진입에서 API 문서나 IDE 사용 경험을 요구하지 않는다.

## 3. 핵심 학습 목표

과정을 마친 학생은 다음을 할 수 있어야 한다.

1. Python 코드가 위에서 아래로 실행되는 과정을 설명한다.
2. 값, 변수, 자료형과 상태 변화를 구분한다.
3. 외부 입력과 월드 센서 값을 받아 프로그램에서 사용한다.
4. Boolean, 비교와 조건문으로 행동을 선택한다.
5. `for`와 `while`을 목적에 맞게 구분한다.
6. 리스트, 딕셔너리, tuple과 문자열 변환을 실제 데이터에 적용한다.
7. `split()`으로 신호를 해독하고 `join()`으로 결과를 조합한다.
8. 함수의 매개변수와 반환값을 이용해 재사용 가능한 능력을 만든다.
9. 미지의 값이나 맵에서도 동작하도록 코드를 일반화한다.
10. 오류 메시지, 실행 줄, 변수 변화와 월드 결과를 근거로 코드를 수정한다.

## 4. 학습 설계 원칙

### LP-01. 상황이 문법보다 먼저다

학생은 문법 정의를 읽은 뒤 사용하는 것이 아니라, 먼저 월드에서 해결할 문제를 경험한다.

```text
상황 발견 → 결과 예상 → 실행 관찰 → 의미 이해 → 변경 → 전이
```

### LP-02. 하나의 새로운 핵심 사고 개념

한 미션에는 새로운 핵심 사고 개념을 하나만 둔다. `lumi.move(3)`에 객체·메서드·괄호·인자·정수가 함께 있어도 첫 미션의 핵심은 “명령을 실행하면 루미가 행동한다” 하나다. 용어는 필요해질 때 공개한다.

### LP-03. API는 체험 후 명명한다

새 API의 도입 순서는 다음과 같다.

1. 월드에서 현상이나 값이 보인다.
2. 완성 코드가 그 현상에 영향을 주는 것을 본다.
3. 학생이 값 하나를 바꾼다.
4. API 이름과 역할을 짧게 설명한다.
5. 다른 상황에서 API를 다시 사용한다.

### LP-04. 편집 자유도를 점진적으로 넓힌다

```text
관찰 전용 → RUN만 → 한 토큰 변경 → 빈칸 → 블록 조립 → 부분 작성 → 자유 작성
```

### LP-05. UI도 커리큘럼이다

- 시작: World + Code + RUN
- 순차 실행 후: STEP/Replay 해제
- 변수 후: Memory Core 해제
- 센서 후: Sensor Overlay 해제
- 반복 후: Timeline/속도 해제
- 자료구조 후: Inventory/Data View 해제

잠긴 기능은 장애물이 아니라 루미의 복구 대상처럼 표현한다.

### LP-06. 실패 비용은 0이다

Run, Reset, Replay에는 학습 재화나 별 페널티가 없다. 오류는 월드 증거, 실행 증거, 한국어 설명, 다음 행동의 네 층으로 설명한다.

### LP-07. 전이가 완료의 일부다

공개 맵에서만 성공한 것은 숙련이 아니다. 값, 입력 또는 위치가 바뀐 transfer variant에서 다시 작동해야 Mastered로 기록한다.

## 5. 서사 계약

### 5.1 시즌 1: 사라진 빛의 항로

신호 폭풍으로 LUMI의 프로토콜 코어와 행성 중계망이 손상되었다. 학생은 Python 명령으로 루미를 복구하고 흩어진 구조·탐사 신호를 되찾는다.

각 Act는 능력 복구와 연결한다.

```text
명령 → 기억 → 센서 → 판단 → 자동화 → 지속 행동 → 데이터 → 함수 → 자율 탐사
```

### 5.2 서사 분량

- 목표 비율: 코딩 70%, 월드 상호작용 20%, 서사 10%
- 일반 미션 시작 연출: 5~15초
- 일반 성공 연출: 5~10초
- Act 시작·종료 컷신: 최대 30~45초, 건너뛰기 가능
- 긴 대화문을 읽어야 RUN할 수 있는 미션을 만들지 않는다.
- 대화는 학생이 지금 해야 하는 행동 또는 월드 변화와 직접 관련되어야 한다.

## 6. 한 미션의 표준 루프

모든 미션이 여덟 단계를 모두 길게 노출할 필요는 없지만 내부 설계는 다음 순서를 따른다.

| 단계 | 목적 | 일반 분량 |
| --- | --- | ---: |
| Story | 왜 지금 필요한가 | 5~15초 |
| Observe | 월드 상태 확인 | 5~15초 |
| Predict | 실행 결과 예상 | 5~15초 |
| Code | 작성 또는 수정 | 1~5분 |
| Run | event tape 생성 | 수초 |
| Trace | 코드·메모리·월드 동기 재생 | 수초~1분 |
| Modify | 값·코드 수정 후 재실행 | 1~3분 |
| Transfer | 다른 값·맵에서 검증 | 1~3분 |

핵심 반복은 `Code → Run → Trace → Modify`다.

## 7. 성취와 진단

### 7.1 학생에게 보이는 성취

- ★ `CORE RESTORED`: 월드 목표 달성
- ★★ `SIGNAL UNDERSTOOD`: 목표 개념 사용 및 짧은 이해 확인
- ★★★ `FIELD VERIFIED`: transfer variant 성공

별은 속도, 코드 길이, 힌트 사용 여부로 깎지 않는다.

### 7.2 내부 진단

보상과 진단을 분리한다.

```js
{
  mastery: {
    worldGoalPassed: true,
    conceptPassed: true,
    transferPassed: true,
    stars: 3
  },
  assistance: {
    maxLevel: 2,
    hintsViewed: ["context", "concept"],
    rescueUsed: false,
    starterResetCount: 1
  }
}
```

교사용 진단은 “완료했는가”뿐 아니라 어떤 도움으로 회복했는지를 보여준다. 학생 화면에서는 도움 사용을 낙인화하지 않는다.

## 8. 화면 계약

### UX-01. 첫 진입 화면

처음에는 API 목록, raw JSON, 모든 탭을 노출하지 않는다. 화면 중심은 가까이 보이는 루미와 한두 줄 코드다.

### UX-02. 월드 가독성

- 루미와 목표물은 기본 뷰에서 즉시 식별 가능해야 한다.
- 카메라는 행동 구간을 자동 프레이밍하되 멀미를 유발하는 이동을 피한다.
- 이동 경로, 충돌, 스캔, 수집, 충전, 선택한 분기가 시각적으로 구분되어야 한다.
- 좌표나 방향 HUD는 해당 개념을 배우기 전에는 숨길 수 있다.

### UX-03. Trace 가독성

raw JSON 대신 의미 단위로 표시한다.

```text
반복 2/3
step: 0 → 1
위치: (2, 2) → (3, 2)
에너지: 99 → 98
```

### UX-04. 접근성

- 색 외에 모양·아이콘·텍스트를 함께 사용한다.
- 애니메이션 감소, 효과음·음악 분리, 0.5×/1×/2×를 지원한다.
- 키보드만으로 Run, Reset, Replay, Step, Hint 접근이 가능해야 한다.
- 한글 IME 조합 중 자동완성이나 포맷이 입력을 훼손하지 않아야 한다.
- 태블릿에서 들여쓰기, 괄호, 콜론을 쉽게 입력할 수 있는 키 바를 고려한다.

## 9. 힌트 계약

| 단계 | 학생에게 주는 도움 |
| --- | --- |
| 1. Context | 월드에서 무엇을 관찰할지 질문 |
| 2. Concept | 사용할 개념이나 명령을 제안 |
| 3. Structure | 빈칸이 있는 코드 골격 제공 |
| 4. Rescue | 완성 코드와 단계별 실행 설명 제공 |

- Hint 1부터 정답 코드를 노출하지 않는다.
- Rescue 뒤에도 transfer 문제를 통해 스스로 다시 적용할 기회를 준다.
- Assistance Level은 최대 공개 단계로 기록한다.

## 10. 비목표

이번 재설계의 목표는 다음이 아니다.

- 교재의 모든 세부 목차를 게임으로 옮기기
- 이야기 감상을 코딩보다 크게 만들기
- 가장 짧고 빠른 코드를 경쟁시키기
- MetaSense 전용 API만 잘 쓰는 학생 만들기
- 3D 그래픽을 학습 엔진보다 먼저 완성하기
- 학생 코드 실행 결과만 믿고 경제 보상을 지급하기

졸업 기준은 학생이 MetaSense API에서 일반 Python 문제와 프로젝트로 이동할 수 있는가다.
