# Data Log 시범 원고 — 02. 우리의 우주 창 열기 (앞부분)

이 문서는 02유닛 첫 실행 부분의 집필 품질 기준입니다. 완성된 전체 커리큘럼이나 02유닛 전체가 아닙니다. 뒤이어 클래스 뼈대 만들기를 같은 밀도로 작성해야 합니다.

## 시작하기 전에

오늘은 우주선이 움직일 무대를 만듭니다. 아직 우주선과 적이 나타나지 않아도 괜찮습니다. 이번 확인 지점의 목표는 **게임 화면에 짙은 남색 배경이 계속 보이고, 정지했다가 다시 실행할 수 있는 것**입니다.

메타센스의 파이썬 화면에서 게임 스튜디오를 열어 주세요. 위쪽 **내 프로젝트 → 우주 방어대 수업 준비**를 선택합니다. 왼쪽에 `assets` 폴더, `main.py`, `asset_credits.py`가 보이면 준비되었습니다. `main.py`를 누르세요. 이 파일은 처음에 비어 있습니다. 그림·소리·폰트는 이미 준비되어 있으므로 지금은 업로드하지 않습니다.

게임 스튜디오는 파일을 이 기기의 브라우저에 저장합니다. 수업을 마칠 때는 상단의 프로젝트 다운로드로 별도 백업도 남기세요.

## 1. 게임 화면을 준비하기

빈 `main.py`의 첫 줄부터 다음 코드를 입력하세요. 이전 코드가 없는 첫 단계입니다.

```python
import pygame
import random

pygame.init()

SCREEN_WIDTH = 1200
SCREEN_HEIGHT = 700
screen = pygame.display.set_mode((SCREEN_WIDTH, SCREEN_HEIGHT))
pygame.display.set_caption('우주 방어대')

FPS = 60
clock = pygame.time.Clock()
```

`pygame`은 창을 만들고 그림·입력·소리를 다루는 도구입니다. `random`은 나중에 적이 예상하지 못한 시점에 발사하도록 사용할 도구입니다. 지금은 가져오기만 하므로 눈에 보이는 변화가 없습니다.

`pygame.init()`은 Pygame의 기능들을 사용할 준비를 합니다. 화면을 만들기 **전에** 놓습니다. `SCREEN_WIDTH`와 `SCREEN_HEIGHT`는 게임 안 좌표의 가로·세로 크기입니다. 스튜디오의 게임 영역이 좁으면 실제 표시가 축소되지만, 코드에서 사용하는 크기는 계속 1200×700입니다.

`set_mode()`의 괄호가 두 겹인 이유를 살펴보세요. 안쪽 `(SCREEN_WIDTH, SCREEN_HEIGHT)`는 가로·세로를 하나로 묶은 튜플이고, 바깥쪽 괄호는 함수를 호출합니다. 반환된 화면을 `screen`이라는 이름으로 보관합니다. 앞으로 이 화면에 그림을 그립니다.

`FPS = 60`은 초당 최대 60번 갱신하는 목표이고, `clock`은 한 번 갱신할 때마다 속도를 조절할 시계입니다. 실제 기기가 느리면 항상 60번을 보장하는 값은 아닙니다.

**아직 실행하지 마세요.** 지금 파일에는 화면을 유지할 반복문이 없습니다. 끝까지 읽으면 바로 실행이 끝나므로, 다음 블록까지 작성한 뒤 첫 실행을 합니다. 제목은 Pygame에 설정되지만 스튜디오 바깥에 독립된 운영체제 창이 생기지는 않습니다.

## 2. 화면이 계속 살아 있도록 반복하기

방금 입력한 `clock = pygame.time.Clock()` 아래에 빈 줄 하나를 만든 뒤 다음 블록을 **추가**하세요. 앞의 코드는 그대로 둡니다.

```python
running = True
while running:
    for event in pygame.event.get():
        if event.type == pygame.QUIT:
            running = False

    screen.fill((9, 17, 37))
    pygame.display.update()
    clock.tick(FPS)

pygame.quit()
```

컴퓨터는 `while running:` 안을 반복합니다. 한 번 돌 때 할 일은 **입력 확인 → 배경 칠하기 → 화면에 보여 주기 → 속도 조절**입니다.

`pygame.event.get()`은 그동안 도착한 입력 사건을 모읍니다. `for`는 그 사건을 하나씩 확인합니다. `QUIT` 사건이라면 `running`을 `False`로 바꿔 다음 반복을 멈춥니다. 스튜디오에서는 실제 작업 중단에 위쪽 정지 버튼을 사용합니다.

들여쓰기를 손가락으로 따라가 보세요. `for`, `screen.fill`, `pygame.display.update`, `clock.tick`은 모두 `while` 안에 있으므로 앞에 공백 **4칸**입니다. `if`는 `for` 안이므로 **8칸**, `running = False`는 `if` 안이므로 **12칸**입니다. 맨 마지막 `pygame.quit()`은 반복이 끝난 뒤 한 번 실행해야 하므로 맨 왼쪽에서 시작합니다.

`screen.fill((9, 17, 37))`은 빨강·초록·파랑의 밝기를 순서대로 정합니다. 값이 모두 작고 파랑이 상대적으로 커서 짙은 남색이 됩니다. `fill`은 화면에 그릴 내용을 바꾸고, `display.update()`는 그 결과를 실제로 보여 줍니다.

### 여기서 실행하세요 — 확인 02-A

1. 위쪽 **실행**을 누릅니다. 최초에는 엔진 준비가 필요할 수 있습니다.
2. 게임 영역에 짙은 남색 화면이 보이는지 확인합니다. 상태가 실행 중으로 표시되어야 합니다.
3. 3초 정도 기다립니다. 게임 화면이 그대로 유지되는지 확인합니다.
4. 위쪽 **정지**를 누릅니다. 정지됨을 확인한 뒤 다시 **실행**을 누릅니다.

**정상 결과:** 남색 화면이 다시 열립니다. 우주선·적·점수·글자·소리는 아직 없습니다. 이번 코드는 배경만 그렸으므로 모두 정상입니다. 방향키를 눌러도 아무것도 움직이지 않습니다.

**예상과 다를 때:**

- 오류 영역에 `SyntaxError`가 보이면 오류가 가리키는 줄에서 콜론 `:`과 괄호 짝을 먼저 확인합니다. `while running:`과 `if event.type == pygame.QUIT:` 끝에는 콜론이 있습니다.
- `IndentationError`가 보이면 위의 4칸/8칸/12칸을 대조합니다. 공백 몇 개를 더 붙여 가며 추측하기보다, 같은 깊이의 줄을 서로 맞춥니다.
- 화면이 바로 끝나면 `running = True`인지, `pygame.quit()`이 `while` 안으로 들어가 있지 않은지 확인합니다.
- 색이 갱신되지 않으면 `screen.fill(...)`과 `pygame.display.update()`가 `for event` 안이 아니라 `while` 바로 안에 있는지 확인합니다. 사건이 들어왔을 때만 배경을 칠하는 코드가 되면 안 됩니다.
- 아무 반응 없이 엔진 준비 중이라면 먼저 준비 완료를 기다립니다. 코드 오류 메시지와 엔진 준비 상태는 서로 다릅니다.
