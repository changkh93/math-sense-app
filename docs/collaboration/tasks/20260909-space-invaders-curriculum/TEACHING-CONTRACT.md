# 우주 방어대: 제작·검수 계약

## 가장 중요한 사용자 요구

학생은 영상을 보지 않고 Data Log만 읽고 메타센스 게임 스튜디오에서 코드를 작성한다. 개념 요약이나 완성 코드 해설이 아니라, 교사가 화면 옆에서 천천히 제작 과정을 안내하는 교재가 필요하다. 첫 실행부터 마지막 게임 완성까지 생략된 코드를 학생이 추측하지 않도록 한다.

각 작은 단계는 아래 여덟 요소를 갖춘다.

1. 현재 화면과 이번에 해결할 작은 목표.
2. 이 기능이 필요한 이유와 학생의 예측 질문.
3. main.py의 정확한 수정 위치. 기존 코드의 고유한 앞뒤 기준 줄, 클래스/메서드 이름, 추가인지 전체 교체인지, 들여쓰기 깊이를 명시한다. ‘적당한 위치’ 금지.
4. 실제 입력할 완전한 코드. 실행 블록에서 `...` 생략 금지. `pass`는 아직 구현하지 않은 뼈대임을 설명한 경우만 허용.
5. 중요한 줄의 값과 동작 설명. 등장한 이름은 한 가지 표기로 끝까지 통일.
6. **여기서 실행하세요**: 정지 → 수정 → 실행 → 게임 화면 포커스 → 구체적 조작을 제시.
7. 기대 결과: 위치·색·개수·방향·숫자 변화 등 관찰 가능한 것. 아직 없는 기능을 ‘이 단계에서는 정상’으로 구별.
8. 흔한 실패 증상 → 확인할 위치 → 고치는 방법, 짧은 직접 바꿔보기와 원래 값 복원.

각 실행 지점에는 완전한 누적 main.py 체크포인트가 대응한다. 해당 단계 Data Log의 수정들을 순서대로 적용한 결과가 이 파일과 같아야 한다. 완성본에서 함수 순서대로 잘라 만든 수업은 불합격이다. 초반에 최종 코드 전체를 입력시키고 줄마다 해설하는 것도 불합격이다.

## 스튜디오 동선 (로컬 구현 확인)

파이썬 → 게임 스튜디오 → 내 프로젝트 → 우주 방어대 수업 준비.

빈 main.py, assets 폴더의 9개 에셋, asset_credits.py가 새 프로젝트로 열린다. 기존 초안은 교체하지 않는다. 같은 기기/브라우저에 자동 저장하며 프로젝트 다운로드로 백업한다. 학생에게 VS Code, pip, 터미널, 로컬 Python 설치, async 변환 명령을 요구하지 않는다. 스튜디오에서는 모듈 최상위 게임 루프를 지원한다. 메서드 안에 새 동기 무한 대기 루프를 만들면 안 된다.

경로·표시 크기:

- assets/scout.png — 투명 원본 PNG. 플레이어 화면 크기 64×64, 필요하면 pygame.transform.smoothscale로 조정.
- assets/raider.png — 투명 원본 PNG. 적 화면 크기 56×48.
- assets/DoHyeon-Regular.ttf — 도현체. pygame.font.Font(경로, 크기)로 로딩. pygame 기본 폰트로 한글 지원을 가정하지 않는다.
- assets/scout_pulse.ogg / raider_pulse.ogg — 플레이어/적 발사.
- assets/raider_break.ogg / shield_hit.ogg — 적 격추/플레이어 피격.
- assets/line_alert.ogg / wave_ready.ogg — 침범/새 라운드.
- 탄환은 작은 투명 pygame.Surface + draw.rect 등으로 제작. 초급자가 색·크기를 변경할 수 있게 설명. 원본 green_laser/red_laser를 요구하지 않는다.
- 폰트 라이선스는 asset_credits.py 및 다운로드 패키지에 동봉. 이미지·소리 새 생성 경위는 public/space-invaders/ASSETS.md.

## 이름과 코드 품질

원본의 Game/Player/Alien/PlayerBullet/AlienBullet는 각각 Mission/Scout/Raider/ScoutPulse/RaiderPulse로 개선한다. 메인 객체는 mission/scout, 그룹은 scouts/raiders/scout_pulses/raider_pulses. 화면은 screen, 상수 SCREEN_WIDTH=1200, SCREEN_HEIGHT=700, FPS=60. 숫자 5(기체), 8(기체 속도), 10(탄환 속도), 2(플레이어 탄환 제한), 3(적 탄환 제한), 11×5(편대), 64(격자 간격), 100(격추점수), 1000×현재 라운드(보너스)는 출발 기준으로 유지해 원강의와 대조 가능하게 한다.

한글 게임명/점수/라운드/남은 기체/계속/최종 점수 안내를 사용한다. 명확한 이름과 주석, 화면 경계 clamp, 동시 격추 수만큼 정확한 점수, 재시작 초기화, 정지 후 입력 금지 등 개선은 관련 기능을 배우는 시점에 이유와 함께 소개한다. 고급 추상화나 여러 파일 엔진에 핵심 학습 코드를 숨기지 않는다. 적 이미지 55번을 매 프레임 로딩하지 않는다. 학습에 필요한 캐시는 최소한으로 설명한다.

도현체의 가운데점 `·`은 실제 pygame 렌더에서 네모로 표시됨을 확인했다. 게임 내 구분 기호는 ASCII `-` 등 지원되는 문자로 쓰고, 이모지/특수문자 지원을 가정하지 않는다. `우주 방어대 - 한글 표시 확인`, `점수 1200   라운드 3   남은 기체 5`는 스튜디오 화면에서 확인했다.

일시정지는 `mission.state`와 안내 문구를 설정하는 방식으로 만들고, 최상위 기존 게임 루프가 대기/플레이/게임오버를 나누어 처리한다. 9단원에서 이 차이와 이유를 직접 가르친다. 그 이전에는 일시정지 구현을 선행시키지 않는다. 일시정지 중 이동/발사 금지, Enter 재개, 게임오버 Enter 초기화, 정지·닫기 종료를 구별한다. QUIT을 다시 running=True로 덮어쓰는 원본 문제는 재현하지 않는다.

## 콘텐츠 산출물

10개 유닛. 원강의 51 Preview를 01 게임 규칙/스튜디오 준비로, 52–60을 02–10으로 대응. 각 코딩 유닛에 최소 3개, 복잡한 유닛에 5–8개 정도의 의미 있는 중간 실행을 설계한다. 글자 수 채우기가 아니라 실제 기능이 작게 완성되는 지점이어야 한다.

- Data Log: 독립적인 한국어 markdown. SOURCE-MAP.md의 실제 강의 순서 준수.
- Code Trace: 유닛당 2–5개, 핵심 패턴 2–8줄. `answerLines` 배열·title·level·category·concepts·prompt·hints·commonMistakes. 정답은 완성된 올바른 Python, 의도적 오류는 해설에만. `__init__` 등의 밑줄 훼손 금지. 01은 출력을 관찰하는 짧은 print 실습을 먼저 Data Log에서 소개한 뒤 연습.
- Field Test: 유닛당 객관식 10문항, 선택지 4개·정답 하나·근거 해설·오답 이유. 실행 결과 예측, 오류 진단, 조건 변경, 순서 이해를 균형 있게 배치. 단순 변수명 암기 문제로 채우지 않는다. 텍스트만으로 독립 풀이 가능하고 아직 안 배운 개념으로 판정하지 않는다.
- Quiz Battle: 현재 앱은 `quizzes`에서 유닛 또는 누적 범위를 뽑는다. 별도 저장소/별도 평가·보상 시스템을 만들지 않는다. 동일한 10문항이 Battle에서도 명확하게 보이도록 질문 길이와 선택지를 설계하고 battle 안내를 Data Log 끝에 작성한다. 라이브 두 계정 대전 검증은 Codex 통합 단계에 남긴다.
- 실행 체크포인트: 코딩 중간 실행마다 누적 소스 파일 + 마지막 main.py. manifest에 유닛/단계/직전 파일/기대 화면/조작/정상 미구현/실패 진단을 연결한다.
- 검증은 실제로 수행한 것과 검토만 한 것을 구별한다. 문법검사 통과가 화면/교육 검증 완료는 아니다.
