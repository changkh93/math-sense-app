# 우주 방어대 교재 01차 검수 — NEEDS_REVISION

Codex가 실제 반환 파일을 독립 검토한 결과다. 기존 원본은 `01-draft-reviewed.zip`과 `01-draft-sha256.json`으로 보존했다. 아래 수정은 코드·Data Log·manifest·Code Trace·퀴즈·REVIEW에 함께 적용한다. 코드만 고치거나 보고서의 표현만 바꾸면 완료가 아니다.

## 확인된 사실과 검증 범위

- 실제 산출물: Data Log 10개, 중간 실행 23개 + final-main.py, Code Trace 29개, 퀴즈 100개.
- Python 24개 AST 파싱, 퀴즈 100개 선택지 4개/정답 1개 구조 검사는 통과했다.
- Code Trace 4개는 2–8줄 계약을 위반한다. 03 위치 reset/06 fire는 1줄, 09 status/10 충돌은 9줄이다.
- `verify-gameplay.py`로 실제 로컬 Pygame 2.4.0/SDL dummy 환경에서 검증했다. 7개 테스트 중 2개 통과, 5개 실패(경계 양쪽 subtest로 실패 기록 6개). 로그는 `01-gameplay-results.txt`다. 웹 브라우저 실행 검증이 아니다.
- 통과: 아군 탄환 2발 제한과 화면 밖 정리, 동시 2기 격추 시 200점.
- 실패: 최종 점수 보존, 마지막 적/마지막 생명 동시 충돌, 좌우 경계, 다음 라운드 탄환 정리, 상태 전환 후 같은 프레임의 후속 검사 중단.
- 앱 소스 통합 및 운영 DB 등록은 아직 하지 않았다. 이전 보고서의 ‘100% 순서/누적 적용 일치/완전 해결’ 주장은 이 검수에서 인정하지 않는다.

## 1. 실행 오류를 먼저 수정하되, 수업 도입 시점은 유지

### R1. 게임오버 화면이 즉시 덮인다 (10-A 이후 모두)

현재 reset_game은 최종 점수 문구/state='game_over'를 설정한 직후 start_new_round를 호출한다. 이 함수가 pause_game으로 state='paused' 및 ‘라운드 1’ 문구를 다시 설정하므로 최종 점수가 그려질 프레임이 없다. 700점/생명0에서 check_game_status 호출 시 실제 state는 paused다.

수정 계약:
- reset_game은 최종 점수 안내와 game_over 상태를 유지하고 반환한다. 이 시점에 새 편대를 시작하지 않는다.
- 게임오버에서 Enter를 누르는 별도 분기에서 점수0/라운드1/기체5/탄환 및 적 그룹/기체 위치를 초기화하고 새 55기 편대를 만든다. 필요하면 명확한 restart_game 메서드를 10단원에서 추가하고 설명한다.
- paused의 Enter 재개와 game_over의 Enter 새 게임을 구별한다. Enter 한 번에 새 게임을 시작하도록 상태 흐름을 명시한다. 최종 점수는 Enter 전까지 보여야 한다.
- 일시정지/게임오버 중 이동·발사 금지, QUIT/스튜디오 정지 가능을 유지한다.
- 10-A의 Data Log와 Code Trace도 반드시 함께 수정한다. 10-A에서 아직 충돌 없이도 게임오버를 빠르게 재현하는 임시 시험 코드를 정확히 제시하고 제거한다.

### R2. 같은 프레임에서 상태가 바뀌어도 후속 처리가 계속된다 (09에서 상태 도입, 10에서 완성)

Mission.update가 shift_raiders → check_collisions → check_round_completion을 무조건 실행한다. 침범으로 paused가 됐거나 피격으로 game_over가 됐으면 그 프레임의 후속 게임 진행을 멈춰야 한다. 각 처리 뒤 state를 확인하고 return하는 간단한 흐름을 설명한다. 시작부터 playing이 아닌 경우도 진행하지 않는다.

마지막 적 격추와 마지막 생명 피격이 같은 프레임이면 피격/게임오버가 우선이다. 격추점수100은 최종점수에 남고 다음 라운드/보너스로 게임오버를 덮지 않는다. 잔여 생명이 있으면 피격 안내를 먼저 보여주고 Enter 후 라운드 완료를 진행할 수 있다. 관련 예측 문제 1개로 순서를 확인한다.

### R3. 새로운 라운드로 이전 탄환이 넘어간다 (10의 라운드 완료 단계)

현재 raiders.empty() 후 완료 판정을 호출하면 새 55기는 만들어지지만 기존 양쪽 탄환이 남는다. 새 라운드 준비 시 양쪽 탄환을 비우고 기체를 중앙으로 되돌린다. 보너스는 증가 전 현재 라운드 기준이다. 점수100/라운드2에서 완료하면 2100점/라운드3/적55/양쪽탄환0, 시작 대기여야 한다.

### R4. 경계를 검사하고 8픽셀 이동하면 경계를 넘을 수 있다 (03 이후 모두)

현재 rect.left=1에서 왼쪽 이동하면 -7, rect.right=1199에서 오른쪽 이동하면1207이 된다. 이동 후 rect.clamp_ip(screen.get_rect()) 또는 명확한 min/max 보정을 추가하고 가르친다. 초기 위치에서는 우연히 잘 맞아도 속도·위치를 바꾸면 드러난다. 속도7 등의 짧은 바꿔보기 → 양쪽 확인 → 속도8 복원 절차를 준다. 기존 퀴즈03-5와 이동 Code Trace도 수정한다.

## 2. 실제 강의 순서에 맞춰 단계 재구성

SOURCE-MAP.md를 기준으로 단계 ID를 새로 정해도 된다. 관련 문서/manifest/이전 파일 링크를 모두 동기화한다.

- 02: 화면/루프를 먼저 실행한 뒤 다섯 클래스와 **메서드 pass 뼈대**를 작성한다. 현재 클래스에 pass 한 줄만 있어 후속 연결의 출발점이 부족하다. 후속 시그니처를 바꿀 때도 정확한 교체를 안내한다.
- 03: **양쪽 탄환 그룹 → 플레이어 그룹/객체/탄환 전달 → 빈 적 그룹/게임 객체 → update/draw 연결 → Scout 초기화/이미지 → 이동/경계 → reset**이다. 현재 Data Log는 Scout 초기화부터 시작한다. 그룹 연결을 먼저 작성하되 필요한 최소 뼈대를 명시하고, image/rect가 없는 미완성 객체를 draw해서 실패하는 중간 실행을 정상이라고 요구하지 않는다. 먼저 편집 후 첫 실행 가능 지점까지 안내할 수 있다. 추가 기능을 앞당겨 숨기지 않는다.
- 04: 탄환/발사 연결 → 실행 → 2발 제한 → 두 발 뒤 더 못 쏘는 현상 직접 관찰 → kill로 해결 순서를 유지한다.
- 05: 편대는 생성하지 않는다. 방향·속도·무작위 조건·reset을 작은 편집 블록으로 설명한다. 실행 개수를 늘리려고 미래 편대를 만들지 않는다. 화면이 그대로인 이유와 아직 호출하지 않는 메서드를 구별한다.
- 06: 임시10기 먼저 → 적 탄환/하강/화면 밖 정리/fire → 잘못된 비교 진단 → 해결. 원강의의 오류는 `self.rect.top < SCREEN_HEIGHT`다. 이미 올바른 코드만 준 뒤 다른 오류를 설명한 현재 원고를 고쳐, 임시 오류를 실제로 관찰하고 올바른 `>`로 복원하는 실행 지점을 만든다. 오류 단계는 명확히 ‘진단용’ 표시, 최종 답안에는 남기지 않는다.
- 07: 참조/상태/소리/폰트 → update의 미구현 메서드 호출 → HUD/선 → 정식 편대/임시 편대 삭제 → 새 라운드 호출. 75줄 Mission을 한꺼번에 입력시키지 말고 5개 안팎 의미 있는 실행으로 분리한다.
- 08: 경계 검사 → 일괄 하강/반전/보정 → 침범/생명 감소 → 높은 라운드로 빠른 시험 → 복원. 최소3개 의미 있는 실행. 기본 라운드에서 오랫동안 기다리라고만 하지 않는다.
- 09: **check_game_status의 탄환 정리/위치 복원/생명 분기가 먼저**, 그다음 pause/안내/Enter/QUIT/호출부다. 현재는 반대다. 상태 방식 개선은 이 단원에서 도입하며, status를 먼저 구현할 때 pause/reset은 여전히 pass임을 안내한다. 5개 안팎 실행으로 비상 정돈, 대기 상태, 오버레이, Enter/입력 차단, 침범 후 재개를 확인한다.
- 10: **전체 reset/재시작 먼저 → 충돌 다음 → 라운드 완료 마지막**을 유지한다. 게임오버 안내 유지, Enter 초기화, 적 격추, 기체 피격, 전멸/보너스, 동시 사건 등을 5–8개 실행 지점으로 나눈다. 문서에서 실험을 위해 주입한 임시 코드는 정식 checkpoint에 남기지 않는다.

## 3. Data Log만 보고 입력할 수 있도록 편집 지시와 관찰 보강

각 실행 지점은 TEACHING-CONTRACT의 8요소를 모두 갖춘다. 단원 초반만 자세히 쓰고 후반의 목표·이유·줄 설명·실패 진단을 생략하지 않는다. 실행 절차에는 정지 → 수정 → 실행 → 게임 화면 포커스 → 실제 조작 → 관찰 → 임시 값 복원을 적는다.

구체적으로 확인된 누적 편집 오류:
- 07-B: 기존 임시 편대 3줄만 삭제하고 그 자리에 mission 생성+start_new_round를 넣으라고 한다. 07-A에는 기존 mission 생성 줄이 이미 뒤에 있어 그대로 따라 치면 Mission 객체가 두 번 만들어진다. `raiders = pygame.sprite.Group()`부터 `running = True` 직전까지 등 고유한 구간 전체의 전/후 코드를 보여 한 번만 생성되게 한다.
- 09-A: 이전 루프의 update/draw가 섞여 있는데 ‘update를 if로 감싸라’만으로 이동/중복 삭제를 정확히 알 수 없다. 상태 도입 시 `running = True`부터 마지막 `pygame.quit()`까지 전체 루프를 교체하는 정확한 코드를 제공하고 draw는 매 프레임, update는 playing만 실행한다고 설명한다.
- 08/10: 기다리기 어려운 침범·게임오버·라운드 완료는 임시 설정의 정확한 위치, 조작, 기대 숫자, 되돌릴 줄을 제시한다. 모든 적55기를 수동 격추해야만 시험할 수 있게 하지 않는다. 아직 안 배운 충돌로 10-A reset을 시험하지 않는다.
- 03 reset은 호출되지 않으므로 실행만 하고 ‘검증 완료’라고 하지 않는다. 임시 초기 위치 변경+reset 호출/출력 등 학생이 결과를 확인할 방법을 주고 제거한다.
- 모든 Data Log의 코드 블록을 이전 체크포인트에 실제 적용하여 다음 코드와 대조한다. 적용 순서·앵커·교체 전/후를 `draft/edits.json`에 기록하면 Codex가 재검증할 수 있다. 권장 구조: steps 배열, stepId, previous, target, edits 배열의 before/after(고유한 문자열, 정확히1회 일치), 전체 교체는 mode=replaceAll. 임시 실험과 복원은 별도 experiment 항목으로 구분한다. 단계 본문에 없는 변경을 edits에 몰래 추가하면 안 된다.
- 교재는 학생의 직접 입력이 기본이다. 전체 체크포인트는 막혔을 때 비교/복구용이며 앞 단계부터 완성 코드를 여는 흐름으로 바꾸지 않는다.

사실과 표현 수정:
- 01의 ‘아래로10픽셀’은 1라운드 기준이며 이후10×라운드다. 방어선 침범1회는 생명1 감소이고, 생명0 이하일 때 게임오버다. ‘방어선이 무너지면 종료’로 별도 즉시 종료 규칙처럼 쓰지 않는다.
- 프로젝트 다운로드는 실제 `.mspygame.json`이다. ZIP으로도 내려받는 버튼처럼 쓰지 않는다. 별도 제공 ZIP 시작 묶음은 압축해제 후 폴더 가져오기이며 두 동선을 구별한다.
- 브라우저의 정지 버튼과 데스크톱 창의 닫기(X)를 구별한다. 스튜디오에서 존재하지 않는 독립 게임창 X를 누르라고 하지 않는다.
- `random.randint(0,1000)`은 양끝 포함1001개, 조건 확률1/1001이다. 약16.7초는60FPS·한 적·탄환제한에 걸리지 않는 경우의 평균일 뿐 정해진 발사 주기가 아니다.
- `kill()`은 모든 소속 그룹에서 제거한다. 객체의 모든 참조/메모리를 즉시 삭제한다는 설명은 피한다.
- 동기 중첩 루프는 이 런타임의 최상위 양보 처리를 우회해 응답을 막을 수 있다. ‘항상 탭 강제 종료’ 및 ‘상태 방식이면 절대 버벅이지 않음’은 사실이 아니다.
- 실제 효과는 적 스프라이트 제거+효과음이다. 파편 애니메이션을 구현하지 않았다면 산산조각이 보인다고 약속하지 않는다.
- 학생 확인란은 `[ ]`로 시작한다. 미검증인 ‘100% 완성/메모리 안정/절대 정지 없음’은 삭제한다. 마법/안락사/완벽한 군무 등 설명에 도움 되지 않는 표현보다 좌표·개수·관찰을 쓴다.

## 4. 평가 문제도 수정된 학습 범위와 일치

- 각 유닛2–5 Code Trace, 정답2–8줄. 1줄 항목에는 함수 선언 등 실제 맥락을 포함하고, 9줄은 둘로 나누거나 핵심 패턴을 선택한다. 빈 줄로 분량만 채우지 않는다.
- 03 경계 Code Trace/퀴즈, 06 비교 오류, 09 상태·제어권 퀴즈, 10 reset Code Trace를 고친다. Code Trace의 문맥(어느 메서드 내부인지/제공 변수)을 prompt에 명시한다.
- 09 비상 정돈과10 충돌은 길어서 작은 독립 패턴으로 나누는 편이 적합하다.
- 05 확률 정답/해설에1001개 및 평균/제한 조건을 반영한다.
- 07 ‘모든 OS/브라우저에서 깨짐 없음’ 대신 제공 한글 폰트를 함께 로딩하는 이유를 묻는다. 지원하지 않는 모든 글리프까지 보장하지 않는다.
- 08 임시 시험값 복원 문제는 Data Log에서 먼저 직접 해본 내용에 연결한다.
- 10 마지막 문항의 ‘이 수업은 완전한 게임을 만들었다’ 같은 자기평가를 코드 결과 예측(상태 전환·동시 사건 등)으로 교체한다.
- 각 단원 정확히10문항/선택지4개/정답1개, 정답·오답 근거를 코드 및 원고에 대조한다. 구조 검사는 정답 검증과 별개다.
- 실제 앱은 최상위 `codeExercises`/`quizzes` 컬렉션을 unitId로 연결한다. `unit.codeExercises`/`unit.quizzes`에 바로 넣으면 호환된다는 REVIEW 설명을 고친다. DB 변경은 하지 않는다.
- `commonMistakes` 문자열 배열은 현재 전달 형식으로 유지해도 Codex가 `{message: ...}`로 매핑한다. 이를 ‘앱과100% 직접 호환’이라고 하지 않는다. answerLines → answerCode 등 통합도 Codex 담당이다.

## 완료 조건과 제출

1. 원고10개 전체와 모든 누적 checkpoint/final-main/manifest/assessments/REVIEW를 함께 수정한다. 일부 예시만 제출하지 않는다.
2. final-main.py가 이 폴더의 읽기 전용 `verify-gameplay.py` 7개 테스트를 통과해야 한다. 테스트를 삭제/약화/수정하지 않는다. 실행 명령과 실제 출력은 draft/verification/에 보존한다. 이 검사는 로컬 Pygame 의미 검증이며 웹 실행의 증거로 주장하지 않는다.
3. 추가로 Enter 재시작, paused 입력 차단, 정지/재실행, 정상55기 및 중복 없음 등 검증한 방법/결과를 기록한다. 실행하지 못한 항목은 따로 남긴다.
4. 수정 블록의 누적 적용 증거 `draft/edits.json` 및 검증 결과를 제공한다. 원고·manifest에 모든 실행 지점이 일치해야 한다. totalCheckpoints에서 단계수와final포함 파일수를 구분한다.
5. 자동 검증용 생성기/검사기를 사용했다면 draft/tools/에 저장해 재현 가능하게 한다. 개인 scratch 폴더에만 두고 검증완료라고 주장하지 않는다. 학생 안내에는 터미널 명령을 넣지 않는다.
6. 원고에 쓰이지 않는 미래 기능/임시 진단 코드는 최종본에서 제거한다. 원래 에셋/경로/스튜디오 준비 방식은 유지한다.
7. REVIEW에는 실제 실패→수정→재검증과 미검증을 구분한다. 보고서 표현만 바꾸는 것으로 오류를 해결하지 않는다.

외부 수정 범위는 기존 `draft/` 및 `02-antigravity-report.md`뿐이다. 이 검수문서, verifier, 01기록/백업/STATE/INDEX/앱 소스/public/scripts/운영 DB는 읽기 전용이다. Codex는 결과가 돌아오면 독립 검수 후 게임 프로젝트 통합을 계속한다.
