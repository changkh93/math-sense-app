# 지속 개선형 코드 도움: 구현과 운영

2026-09-16. 로컬 구현. 실운영 배포·학생 수집 활성화는 하지 않았다. 기존 구조 변환형 AI 도움 작업 위에 연결했으며, OpenAI 준비 조건과 ZDR 상태는 변경하지 않았다.

## 현재 구현된 개선 루프

1. 오류 아래에서 뜻·위치·예시·재발·설명 불일치·도움 여부를 선택한다. 질문 버튼은 로컬 설명을 펼친다. 추가 AI 요청은 기존 명시적 요청 경로만 사용한다.
2. 참여한 탭에서 다음 실행을 관찰한다. 오류/실행 ID·소스 비교는 브라우저 메모리에만 존재한다. 한 도움을 한 이벤트로 합쳐 보낸다.
3. 관리자 `/admin/studio-coach`의 **코드 도움 개선**에서 최근 14일의 반복·이해 어려움·오진 제보·AI 요청을 본다. 오진 제보가 있는 그룹을 우선하고, 그 안에서는 단순 가중치로 정렬한다. 제보를 오진 확정으로 간주하지 않는다.
4. 이미 받은 변환된 AI 답변이 있다면 문구·확인 질문을 초안으로 가져와 편집한다. 예제는 합성 코드로 작성한다. 추가 분석 API는 호출하지 않는다.
5. 새 버전 초안 → 진단기 검사 → 교사 검토 → 비노출 관찰 → 약 10%의 탭 세션 적용 → 전체 적용 또는 회수.
6. 버전별 관찰과 실제 토큰 표본을 보고 유지·개선·회수를 판단한다. 새로운 진단 조건은 별도의 코드 변경과 양성/반례 검증을 거친다.

이 시스템은 모델을 자동 학습시키거나 답변을 무인 배포하지 않는다. 자유 질문 원문 수집, 자동 후보 합성, 예약 AI 분석, 벡터 검색은 추가하지 않았다. 매번 AI를 호출하는 전처리보다 저렴한 로컬 집계·사람의 검토를 먼저 운영할 수 있도록 했다.

## 결과 해석

- `same-error`: 동일한 오류 종류와 메시지. 수정 여부에 따라 `sameAfterEdit` / `sameWithoutEdit`를 분리한다.
- `different-error`: 다른 오류로 바뀜. 전체 해결로 세지 않는다.
- `completed`: 런타임 EXIT 관찰. 학습 성공이나 정답임을 뜻하지 않는다.
- `surface-ended`: 그림/게임 화면 생성 후 EXIT. 일반 계산 코드의 완료와 구분한다.
- `unknown`: 다른 실행 대상으로 이동, 정지, 런타임 연결 유실 등. 완료로 세지 않는다.
- 강제 브라우저 종료/통신 실패의 전달은 보장하지 않는다. 누락을 성공으로 추정하지 않으며, 자동 재시도하지 않는다.
- 학생의 `helpful` 응답과 실행 완료의 교집합도 별도 집계한다. 이해를 증명하는 성취 점수로 사용하지 않는다.
- 같은 코드에 여러 원인이 있거나 셀 순서를 바꾼 경우 탭 내 연결은 제한적이다. 노트북에서 다른 셀을 실행하면 이전 도움은 관찰 불가로 마감한다.

## 데이터·비용 경계

- `studioCoachLearningControl/config` 기본값은 꺼짐. 관리자 수집 설정 확인과 학생의 탭 내 선택이 모두 필요하다.
- 관찰 payload는 고정된 ID/enum/boolean/시간 구간만 허용한다. 소스·원문 질문·traceback·파일명·학생 이름 필드는 거절한다.
- 인증 UID는 서버 권한 확인 및 비밀 salt를 사용한 기여 제한 해시에만 사용한다. OpenAI로 보내지 않는다.
- 계정당 하루 30개, 같은 유형 하루 5개, 전역 하루 3,000개 관찰 상한. 이벤트 ID 중복은 트랜잭션으로 차단한다. 클라이언트 조작으로 통계를 완전히 진실하게 만들 수는 없으므로 자동 승격은 금지한다.
- 대표 사례는 관리자 `samplesEnabled`와 요청의 별도 `learningSamplesConsent`가 모두 참일 때만 기록한다. 일반 참여 선택 후 관리자가 나중에 사례 보관을 켜도 기존 탭에는 사례 동의가 추가되지 않는다.
- 이미 지불한 정상 응답의 **구조 토큰 + 원래 이름으로 복원하기 전 답변**만 유형별 하루 최대 3개 슬롯에 보관한다. 표본은 전체 사례를 대표한다는 보장이 없다.
- 실제 입력/출력 토큰 수는 참여한 정상 유료 응답만 집계한다. 캐시 응답은 중복 계산하지 않는다. 실패·비참여 요청은 이 보고서에서 제외되므로 전체 청구액으로 해석하지 않는다. 기록 실패는 학생 답변을 막지 않고 최대 1초만 기다린다.
- 개선 분석을 위한 유료 AI 호출은 0회. Firebase의 함수·읽기·쓰기·삭제 비용은 발생할 수 있다. 관리자 보고서는 요청 시 제한된 문서만 조회한다. 자동 polling 없음. 세션 manifest는 탭/계정당 한 번 조회한다.
- 비용 계산기는 현재 운영 단가와 예상 회피 **유료 요청 수**, 개발·검토·운영 비용을 직접 입력한다. 원시 오류 수를 API 절감 건수로 쓰지 않는다. 작은 표본은 경고한다.

## 버전·배포·회수

- 서버에서 생성한 24자리 버전 ID, 진단기 버전, 실행기 버전, 적용 모드를 고정한다. 문구 수정은 새 버전을 만든다.
- 원격 설명은 이미 알려진 진단 ID의 보충 설명만 제공한다. 함수·정규식·새 판정 조건·코드 실행은 내려보내지 않는다. 일반 오류 그룹에는 특정 원인을 단정하는 카드를 만들지 않는다.
- 진단기/실행기 버전이 다른 카드는 무시하며 재승격을 금지한다. 각 버전의 통계도 서로 합치지 않는다.
- `tested` 검사는 기존 진단기의 합성 양성 13개와 반례 1개 회귀다. 교사가 새 설명의 의미·예제·오진 가능성을 별도로 검토해야 한다. 예제의 Python 실행/교육적 적합성을 자동 인증한다는 뜻이 아니다.
- `shadow`: 새 설명은 표시하지 않고 해당 규칙·모드와 일치하는 관찰 수만 기록한다. 새 진단 규칙의 정확도를 측정하는 기능은 아니다.
- `limited`: 탭 내 고정 무작위 버킷으로 약 10%에 노출한다. 정확한 학생 수 10% 또는 엄밀한 인과 실험을 보장하지 않는다.
- 같은 규칙·겹치는 모드의 두 버전을 동시에 배포할 수 없다. 기존 버전을 회수한 뒤 새 버전을 관찰/적용한다.
- 회수 시 기본 카드로 복귀한다. **현재 열린 탭은 새로고침해야 새 manifest를 받으며, 이미 표시한 오류의 설명은 바뀌지 않는다.** 관리자 화면에도 이 조건을 표시한다. 긴급 안내는 담당 교사가 새로고침을 안내한다.
- 회수한 버전을 다시 쓰려면 내용을 새 초안으로 만들고 검증·검토한다. 이력을 덮어쓰지 않는다.

## 저장과 삭제

| 컬렉션 | 내용 | 삭제 기준 |
|---|---|---|
| studioCoachLearningReceipts | 중복 방지 해시 | 7일 |
| studioCoachLearningQuotas | 계정 해시별/전역 기여 수 | 7일 |
| studioCoachLearningStats | 내용 없는 유형·버전별 집계 | 90일 |
| studioCoachLearningCosts | 참여 요청 토큰 집계 | 90일 |
| studioCoachLearningSamples | 제한된 변환 사례/답변 | 14일 |
| studioCoachLearningCards | 합성 문구·예제·승인 이력 | 운영 지식으로 유지 |

직접 클라이언트 Firestore 접근을 전부 차단한다. 학생은 인증 callable의 manifest/observe만 이용하며, 보고서·사례·편집은 admin 역할만 가능하다. 통계와 사례의 추가 관리자 역할 분리는 아직 하지 않았다.

일일 삭제 함수는 컬렉션당 최대 8 × 400개의 만료 문서를 삭제한다. 기한 정각 삭제를 보장하지 않는다. 적체/실패는 후속 일일 실행에서 처리하고 운영자는 스케줄 성공 및 만료 잔량을 점검한다. 미배포 상태에서는 스케줄도 동작하지 않는다.

## 검증과 출시 절차

- `npm run test:studio-coach-learning`: 정책/권한/경합 중복/상한/버전/검토/샘플/삭제/추적 및 기존 전처리·유료 경로 회귀.
- `node scripts/qa-studio-coach-learning.mjs`: 실제 브라우저 WASM 파일/노트북 실행, 원문 없는 결과, 로컬 질문, 참여 선택, 원격 카드, 합성 관리자 전송 경계, 태블릿 화면과 비용 계산.
- `node scripts/qa-studio-private-coach.mjs`: 구조 코드 미리보기·별명 복원·예정 정책 페이지 회귀.
- 빌드와 관련 ESLint를 수행한다. 합성 Firestore 테스트는 실제 Firebase emulator/배포 검증을 대체하지 않는다.

출시 시 기존 구조형 코치 변경과 함께 프런트, `studioErrorCoach`, 새 함수 4개(`studioCoachLearningManifest/Observe/Admin/Cleanup`), Firestore 규칙을 배포해야 한다. 다른 작업의 미커밋 변경은 별도로 검토한다. 배포 후에도 수집은 기본 꺼짐으로 유지하며, 관리자 화면·권한·일일 삭제의 실제 배포 상태를 점검한 뒤 필요한 고지·운영 준비를 확인하고 켠다. AI 학생용 준비 플래그는 별도다. 이 문서는 배포 완료 기록이 아니다.
