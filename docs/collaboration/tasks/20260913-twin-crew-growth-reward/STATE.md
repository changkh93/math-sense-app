- Original goal: 스터디 크루 T.W.I.N.이 20명에 도달했는데 1,000광석이 지급되지 않은 원인을 규명하고 재발하지 않도록 개선한다.
- Coordinator: Codex (local implementation and production remediation; no external relay)
- Phase: DONE (data repaired, UI deployed, scheduled policy clock running)
- Last updated: 2026-09-13 KST
- Baseline: 작업 시작 당시 dirty working tree의 기존 사용자 변경은 보존했다.
- Acceptance criteria:
  - 실제 T.W.I.N. 정회원 수와 보상 인정 인원을 분리해 확인한다.
  - 누락된 V2 참여 잠금을 충돌 기록을 덮어쓰지 않고 복구한다.
  - 같은 결함이 있는 다른 크루도 같은 정책으로 보정한다.
  - 목록 및 상세 화면에서 정회원 수와 보상 인정 인원을 혼동하지 않게 한다.
  - 관련 단위 테스트, 린트, 빌드를 통과하고 UI를 배포한다.

## 원인

- 크루 성장 이벤트 V2는 사용자별 `crewGrowthParticipantLocks/crew_growth_v2_2026_{uid}` 문서를 보상 자격의 기준으로 사용한다.
- V2 도입 전에 가입해 있던 운영 크루 구성원에 대한 프로덕션 백필이 실행되지 않았다.
- 기존 백필 스크립트는 충돌이 하나라도 있으면 전체 적용을 중단해, 정상적으로 복구 가능한 누락 건까지 처리하지 못했다.
- 그 결과 T.W.I.N.은 정회원 20명이지만 `eligibleCount=0`이었고, t10 검증조차 시작되지 않아 t20 보상이 열릴 수 없었다.

## 구현 변경

- `functions/crewGrowthBackfillPolicy.cjs`에 백필 판정 정책을 분리했다.
  - 현재 사용자 `crewId`가 대상 크루와 일치하고 잠금이 없는 경우에만 생성한다.
  - 같은 크루의 활성 잠금은 유지한다.
  - 다른 크루 잠금, 몰수 잠금 등 모든 기존 충돌은 덮어쓰지 않고 개별 제외한다.
- `scripts/backfill-crew-growth-v2-locks.mjs`를 개선했다.
  - `--crew-id` 범위 지정과 캠페인 확인 인자를 지원한다.
  - 충돌 때문에 전체 작업을 중단하지 않고 안전한 후보만 트랜잭션으로 생성한다.
  - 적용 뒤 승인 크루의 성장 이벤트 집계를 재계산한다.
  - Functions와 동일한 Firebase Admin SDK 인스턴스를 사용한다.
- 성장 이벤트 화면 문구를 `우리 크루 인원`에서 `보상 인정 인원`으로 바꾸고, 현재 정회원 수와 48시간 대기·이동 이력 등 제외 수를 함께 표시한다.
- 크루 상세 헤더도 전체 정회원 수가 아니라 `인정 X / 40명`으로 표시한다.
